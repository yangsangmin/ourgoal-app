# #TASK-ES-033 기존 카카오 로그인 사용자의 구글 로그인 시도 시 세션 파괴 및 로그인 불능 먹통 버그 근본 해결 (2차 정밀수정)

## 목표
카카오 로그인으로 사용하던 기존 사용자가 구글 로그인을 시도했을 때 세션이 파괴되거나 계정 충돌·오염으로 인해 구글·카카오 모두 로그인이 불가능해지거나 랜딩 화면에 갇히는 치명적 결함을 원천 해결하고, 로그인 화면의 '상민클론' 문구를 완전 삭제한다.

## 근본 원인 정밀 규명 결과 (5대 결함)
1. **OAuth 콜백 복귀 시 랜딩 화면 은폐 누락 (`enterApp` 결함)**:
   - `enterApp()`(2096라인)에서 `authScreen`만 숨기고 `landingScreen.style.display = 'none'` 처리가 누락되어, `#appShell.active`가 켜져도 DOM 상단의 `#landingScreen`(`min-height: 100vh; display: flex;`)에 가려져 사용자는 계속 랜딩 화면을 봄 (먹통 증상).
2. **`startOAuthLogin('kakao')` 호출 전 이전 세션 미정리로 인한 계정 충돌**:
   - 구글 로그인 시도 등으로 로컬에 세션/토큰이 남아있는 상태에서 카카오 OAuth를 호출하면 Supabase GoTrue가 이미 로그인된 세션에 카카오 Identity Linking을 시도하다가 `identity_already_exists` 에러를 반환하며 카카오 로그인이 원천 거부됨.
3. **구글 로그인 시 비정규 가짜 비밀번호 `signUp`으로 인한 계정 파편화**:
   - Supabase 콘솔에서 Google Provider가 미활성화된 상태에서 가짜 비밀번호로 `signUp`을 때려 동일 이메일 충돌 에러를 일으키거나 엉뚱한 빈 깡통 유저 세션을 생성하여 기존 카카오 데이터 접근 차단.
4. **`checkRemoteSessionRevoked` 오탐으로 인한 세션 즉시 강제 종료 (로그인 직후 튕김)**:
   - 로컬 스토리지에 남아있던 과거 `remoteLogoutTimestamp`와 `myLogin` 대조 시 오탐으로 인해 방금 로그인 성공한 카카오 세션을 즉시 `performLogout()`시켜버림.
5. **로그인창 상민클론 문구 배포 미반영**:
   - `index.html:20413`에 남아있던 `상민클론 원격 지휘 파이프라인 가동 중` 문구 완전 삭제.
