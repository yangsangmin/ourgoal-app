# [작업계획서] #TASK-ES-049: Gemini 3.1 Flash-Lite 초가성비 비전 모델 교체 및 사진 기반 만화 얼굴 동적 폴백 이중 방어망 구축

## 1. 배경 및 문제 상황
- **현상**: 사용자가 서로 다른 사진을 업로드하여 아바타를 제작해도 계속 동일한 만화 얼굴(살구색 피부 + 흑발 댄디컷 + 둥근 눈)만 출력되는 버그 발생.
- **근본 원인**:
  1. 서버(`api/promptgen.js`)의 아바타 비전 엔드포인트에 지정된 모델(`gemini-2.5-flash`, `gemini-2.0-flash`, `gemini-1.5-flash`)이 구글에서 지원 중단(deprecated)되어 **HTTP 404 (NOT_FOUND)** 반환.
  2. 구글 API 키 크레딧 전파 지연/소진(429) 시 서버가 고정된 기본값(`getSmartFallbackFeatures`)을 강제 반환.
  3. 클라이언트(`js/avatar-system.js`)가 서버 응답만 믿고, 실패 시 사진 픽셀을 분석하는 동적 추출기(`extractPersonalFeatures`)를 실행하지 않아 어떤 사진을 넣어도 100% 동일한 고정 얼굴 출력.
- **상민님 지시**: "3.1 라이트가 가장 가성비 있지? 그걸로 병합까지 진행해봐"

## 2. 해결 목표 및 범위
1. **Gemini 3.1 Flash-Lite 최우선 캐스케이드 탑재**:
   - `gemini-3.1-flash-lite` (1순위 가성비/초고속) ➔ `gemini-3.5-flash` (2순위) ➔ `gemini-3.6-flash` (3순위) 캐스케이드 구성.
   - 구버전 404 모델 완전 퇴출.
2. **클라이언트 사진 픽셀 기반 동적 자가 분석 폴백 이중 방어망**:
   - 서버 응답이 `fallback: true`이거나 오류 발생 시, 클라이언트가 즉시 사진 캔버스 픽셀을 스캔하여 **실제 피부톤, 헤어컬러, 모발기장/스타일**을 감지하여 고유한 만화 얼굴을 생성.
   - 사진마다 완전히 다른 고유한 피부톤과 머리색이 100% 반영되도록 보장.
3. **무봉제 5단계 샌드위치 렌더링 유지 및 검증**:
   - 목선 12px 침투, 턱선 그림자, 옷깃 오버랩 100% 유지.
4. **테스트 및 병합**:
   - `npm test` 218개+ 전수 통과, `essence-gate` 무결성 확인 후 PR 생성, Squash Merge, 프로덕션 배포.
