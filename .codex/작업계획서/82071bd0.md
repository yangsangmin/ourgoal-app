# #TASK-ES-035 기록(checkins) 및 프로필(users) 삼중 로컬 백업 구축, 게스트 세션 영구 고착 해제 및 데이터 무결성 복구 계획서

목표: 상민님 직접 제보("목표들만 살아있고 유저들의 기록, 프로필 편집 내역 모두 초기화된것처럼 나오는데?")에 따라 목표에만 국한되어 있던 로컬 백업 체계를 기록(checkins)과 프로필(users)까지 삼중으로 전면 확장하고, 게스트 세션(`ourgoal_guest_profile`) 고착으로 인한 Supabase 세션 차단 문제를 해결하여 기존 사용자의 모든 기록과 프로필 데이터를 안전하게 복구·보호한다.

## 근본 원인 (3대 결함)
1. **로컬 백업 비대칭 (목표만 백업, 기록·프로필 백업 부재)**:
   - `saveProfile()`과 `loadProfile()`에 목표(`ourgoal_goals_backup_`)만 로컬 백업 및 자동 복구 로직이 존재하여, 비인증 상태(또는 RLS 차단 상태) 진입 시 목표만 살아나고 기록(`records`)은 빈 배열(`[]`), 프로필(소개, 지역, 관심사 등)은 빈 기본값으로 초기화됨.
2. **`ourgoal_guest_profile` 게스트 세션 영구 고착 및 무한 덮어쓰기**:
   - `loginWithDirectIdentifier` 또는 게스트 진입 시 기록이 비어있는 불완전한 프로필이 `ourgoal_guest_profile`에 저장되고, `boot()`에서 이를 감지하면 Supabase Auth 세션 유무와 관계없이 `return;`으로 앱을 조기 진입시켜 실제 Supabase 정본 데이터 조회를 영구 차단함.
   - `performLogout()`에서 `ourgoal_guest_profile`을 제거하지 않아 로그아웃 후에도 게스트 프로필로 재진입되는 버그 발생.
3. **`ensureUserRow`의 미확인 빈 프로필 덮어쓰기 위험**:
   - `sb.from('users')` 조회 실패 또는 비인증 시 기존 데이터를 확인하지 않고 빈 `row`를 upsert하여 프로필 데이터가 증발하는 위험 상존.

## 체크리스트
- [x] 1. 기록(`ourgoal_records_backup_`) 및 프로필(`ourgoal_profile_backup_`) 로컬 백업·복구 삼중 방어망 구현 · 완료 · `loadProfile`, `saveProfile` 연동
- [x] 2. `ourgoal_guest_profile` 고착 해제: Supabase 세션 우선 검증, 로그아웃 시 게스트 프로필 정리, 불완전 프로필 자동 자가치유 · 완료 · `boot`, `restoreSessionAndEnter`, `performLogout`
- [x] 3. `ensureUserRow` 안전망 강화: 비인증/조회 오류 시 기존 프로필 블라인드 덮어쓰기 원천 차단 및 로컬 백업 우선 병합 · 완료

# #TASK-ES-036 서버 사이드 관리자 권한 데이터 복구 파이프라인(api/sync-records.js) 및 RLS 차단 우회 기록·프로필 즉시 복원 계획서

목표: 상민님 직접 제보("아직도 기록 안돌아 왔는데?")에 따라, 클라이언트 측에서 Supabase RLS(Row Level Security)로 인해 비인증/게스트 세션에서 `checkins` 테이블 조회가 차단되어 로컬 백업이 없던 이전 기록을 불러오지 못하는 근본 문제를 서버리스 관리자 API(`api/sync-records.js`)를 통해 원천 해결하고, 클라이언트와 자동 연동하여 사용자의 이전 기록(체크인)과 프로필을 100% 즉시 화면에 복구한다.

## 근본 원인
1. **Supabase RLS(Row Level Security) 차단**:
   - `checkins` 테이블은 `auth.uid() = user_id` 정책이 걸려 있어, 카카오 OAuth 실패 등으로 Supabase Auth 세션이 없는 익명(anon) 상태에서는 클라이언트가 아무리 `sb.from('checkins').select('*')`를 호출해도 PostgreSQL RLS가 0건(`[]`)을 반환함.
2. **로컬 백업 부재**:
   - `ourgoal_records_backup_`은 이번 PR #153에서 신설되었으므로, 과거에 생성된 기록은 사용자의 브라우저 로컬 스토리지에 백업 키가 존재하지 않음.
3. **해결책**:
   - Vercel 서버리스 함수(`api/sync-records.js`)는 `SUPABASE_SERVICE_ROLE_KEY`를 보유하므로 RLS 제한을 우회하여 DB 원장을 직접 조회 가능.
   - 클라이언트의 로컬 후보 ID(목표 백업 ID, 닉네임, 사용자명 등)를 받아 Supabase `checkins`와 `users`에서 매칭되는 실제 기록을 찾아 클라이언트에 공급하고, 클라이언트는 이를 즉시 화면에 렌더링하고 로컬 백업에 저장함.
