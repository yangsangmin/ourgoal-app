# [실전 가이드] NotebookLM 활용 아워골 헌법 & 시스템 프롬프트 고도화 질의서

이 문서는 NotebookLM에 소스를 업로드한 후, 단계별로 복사하여 입력할 수 있도록 설계된 **실전 프롬프트 템플릿 세트**입니다.

---

## 📌 Step 0. NotebookLM 소스 업로드 구성

새 Notebook을 생성하고 아래 소스들을 업로드합니다:
1. `01_OURGOAL_SUPREME_CONSTITUTION_FULL.md` (아워골 최고 헌법 15대 조문 전문)
2. `02_CONSTITUTION_EVOLUTION_AND_ORDERS.md` (헌법 개정 역사 및 상민님 명령 원문·의도 총람)
3. `03_MASTER_PLAN_AND_DESIGN_PHILOSOPHY.md` (기획정본 및 상민님의 5대 제품 설계 공식)
4. **[추가 소스]**: 상민님께서 보유하고 계신 최신 시스템 프롬프트 레퍼런스 파일들 (Claude Code, DeepSeek, OpenAI o1, Gemini CLI 등)

---

## 💬 Step 1. 상민님 의도 및 맥락 학습 검증 질의

가장 먼저 NotebookLM이 아워골의 특수성과 상민님의 철학을 제대로 파악했는지 확인합니다.

```markdown
[질문 1]
내가 업로드한 '02_CONSTITUTION_EVOLUTION_AND_ORDERS.md'와 '01_OURGOAL_SUPREME_CONSTITUTION_FULL.md'를 정독해줘.
1. 아워골 헌법이 탄생하고 v2026.09.11부터 v2026.10.02까지 개정되어 온 역사적 배경에서, 최고결정권자 상민님이 가장 분노하셨던 AI의 고질적 기만행위 3가지와 그에 대응해 만든 핵심 조항을 매핑해서 설명해줘.
2. 특히 '판정 분리(Verdict Separation)' 원칙이 왜 탄생했고, 왜 작업 AI의 자가채점을 영구 금지했는지 그 본질적 이유를 서술해줘.
```

---

## 💬 Step 2. 기존 헌법의 중복·모순·토큰 비효율 정밀 감찰 질의

15대 조문 내의 사각지대와 군더더기를 적발합니다.

```markdown
[질문 2]
'01_OURGOAL_SUPREME_CONSTITUTION_FULL.md'를 심층 분석해줘.
1. 15대 조문 체계 내에서 서로 내용이 중복되거나, 표현이 미세하게 상충되어 AI 에이전트가 코딩할 때 인지적 혼선을 일으킬 수 있는 조항들을 찾아내줘.
2. 조문이 800줄 이상으로 길어지면서 발생할 수 있는 '주의력 분산(Attention Degradation / Lost in the Middle)' 위험 요소를 지적하고, 의미와 구속력을 100% 보존하면서 정보 밀도를 높일 수 있는 구체적 압축 포인트를 제시해줘.
```

---

## 💬 Step 3. 최신 시스템 프롬프트 구조(Syntax)와의 무손실 융합 질의

글로벌 최신 프롬프트 문법을 가져오되, 아워골 헌법의 구속력을 지키는 핵심 질의입니다.

```markdown
[질문 3]
함께 업로드된 [최신 시스템 프롬프트 레퍼런스]의 구조적 장점(예: XML 태그 계층화, <thinking> 추론 강제, 실패 시 롤백 프로토콜, 명확한 가드레일 정의 등)을 분석해줘.
그리고 아워골 최고 헌법의 핵심 규범을 이 현대적인 시스템 프롬프트 구조로 리팩토링한 프로토타입을 작성해줘.

※ 절대 주의 조건:
1. '02_CONSTITUTION_EVOLUTION_AND_ORDERS.md'에 명시된 상민님의 불변 원칙들(판정 분리, GitHub 법정 단일 판정서, 확인 못 함의 합법화, 5대 승인선 엄수, 0 Dead-Click, 껍데기 UI 영구 금지, 3대 본질 루프 귀속)을 절대로 일반론적이거나 완곡한 표현("Be careful", "Try to avoid")으로 희석시키지 말 것.
2. 구체적인 금지 정규식과 물리적 집행 기준을 100% 보존할 것.
```

---

## 💬 Step 4. 조선소 블록형 모듈화에 맞춘 헌법 아키텍처 재편 질의

헌법 제3조 제9항(조선소 모듈화)을 프롬프트 시스템 자체에도 적용하는 질의입니다.

```markdown
[질문 4]
아워골 헌법 제3조 제9항은 '조선소 3계층 블록 모듈화 및 800줄 상한'을 명시하고 있어.
현재 단일 파일로 834줄에 달하는 아워골 시스템 프롬프트 역시 이 원칙에 따라 모듈화할 수 있을까?
1. 모든 턴과 세션에서 반드시 1초 만에 인지해야 하는 '핵심 불변 커널(Core Kernel: 5대 승인선, 판정 분리, 절대 금지 10대 행위)'과,
2. 특정 작업 상황(기획/IA 단계, UI/컴포넌트 구현 단계, 스토리지/DB 마이그레이션 단계, 법정 심사/PR 단계)에만 동적으로 주입되는 '도메인 특화 헌법 모듈'로 분리하는 아키텍처 청사진을 제시해줘.
```
