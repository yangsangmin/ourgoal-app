## [총괄 요약] 아워골 최고 헌법 11대 조문 체계 (The 11 Supreme Articles)

1. **제1조 (3대 본질 루프 및 인프라 헌법)**: E1(체크인 루프), E2(기록 회고), E3(동류 소통), INFRA(기반 인프라), FIX(버그 수정) 5대 축 필수 귀속. 5대 표준 유지보수 카탈로그는 [기본값: INFRA]로 무중단 직진.
2. **제2조 (2중 8원칙 및 핫픽스 헌법)**: REQ 요구서 → PLAN 계획서 2단계 필수. 무축약(// ..., TODO 금지). 10줄 이하 단순 버그는 QUICK-FIX 패스트트랙 허용 (인증/권한 수정 시 패스트트랙 제외, 동일함수 3회 살라미 감시).
3. **제3조 (껍데기 UI 방지 4위 1체 배선 및 격리 헌법)**: 모든 UI는 [HTML + 리스너 + 핸들러 + 피드백/에러] 4위 1체 완전 배선. 백엔드 미완성 UI는 hidden 또는 피처 플래그 격리 필수 (PR 시 1회 확인).
4. **제4조 (절대 금지 6대 행위 및 스타일 규격 헌법)**: ①위조 숫자, ②파괴적 삭제(.delete().not(), TRUNCATE), ③도구 언어 UI 노출, ④main 직접 커밋 및 승인 없는 gh pr merge/main 푸시, ⑤검증 없는 완료, ⑥아이디어 즉시 구현 전면 금지. 스타일 가이드(ui.css) 일치 미세 보정은 [FIX]로 즉시 수정 허용.
5. **제5조 (승인선 8대 통제 및 자동 커밋 분할 헌법)**: 돈, 개인정보, 기능 삭제, 바깥 행위(원격 main 배포 포함), 규범 변경, 본질 무관, 위조 숫자 감지 시 즉시 중단 후 [결심 필요] 보고. 프로덕션 코드 500줄 초과 시 작업을 멈추지 않고 3계층(DB/로직/UI) 자동 커밋 분할(Auto-Split) 통과.
6. **제6조 (1티켓 1PR 및 피처 플래그 헌법)**: 1 PR = 1 티켓 엄수, 4블록 PR 설명 작성. 거대 에픽 브랜치 격리를 금지하고 피처 플래그 비활성화 상태로 1티켓 단위 로컬 메인에 매일 순차 병합.
7. **제7조 (5대 무결성 전수 검증 및 스크립트 헌법)**: 전수 클릭, 전 UX 회귀, 10종 페르소나 데이터 무손실 딥이퀄, 화면 연동 전파, npm test 236개+ 100% PASS 필수. AI의 픽스처 손수정 금지 및 마이그레이션 스크립트 작성 의무화.
8. **제8조 (직관적 작업 상태 6단계 보고 및 프리뷰 배포 헌법)**: 1단계(기획)부터 6단계(실운영 확인)까지 물리적 구동 의미 명시. 4단계(로컬 메인 병합) 완료 즉시 Vercel 프리뷰 배포(5A) 자동 실행 후 실기기 URL 제공 및 상민님 실서버 프로덕션 배포 승인 요청. 승인 없는 5단계 프로덕션 배포는 위헌 차단.
9. **제9조 (용어 헌법: '히트맵' 강제 및 글로벌 I/O 헌법)**: 코드, UI, 주석, 문서 전 영역에서 금지 단어 사용 전면 영구 금지, '히트맵(Heatmap)'으로만 표기. 외부 유입 데이터는 글로벌 I/O 인터셉터로 '히트맵' 자동 매핑.
10. **제10조 (Tri-Sync 3자 상호 동기화 및 미디어 통제 헌법)**: Notion - Obsidian - Command Center 3자 실시간 상호 동기화 및 3-Way 자동 중재. 미디어 자동생성은 오직 아워골 아바타 제작만 허용, 영상/쇼츠/릴스는 전면 차단.
11. **제11조 (지시 의도 스코프 및 단계별 멈춤 헌법)**: 모드 1(탐색형 질문), 모드 2(구상 한정), 모드 3(단계 한정), 모드 4-A(완곡한 요청 및 로컬 완결 4단계), 모드 4-B(명시적 프로덕션 배포). 상민님의 "배포"/"1" 승인 없이 5단계 배포 진입 엄격 금지.

## 제1장 총칙 및 제정 배경

### 제1조 (목적)
본 헌법은 아워골의 기능 추가, 수정, 삭제, UI/UX 개편, 백엔드 및 데이터베이스 변경 등 모든 개발 작업 시 발생해 온 고질적인 결함(되던 버튼 먹통, 껍데기 버튼 방치, 연계 기능 상호연동 불발, 유저 데이터 유실, 뷰 간 상태 불일치, AI 코드 축약)을 원천 방지하고, 사용자가 어떠한 업데이트 이후에도 신뢰와 안정성을 체감할 수 있도록 무결성 작업 표준을 확립함을 목적으로 한다.

### 제2조 (적용 범위)
아워골 코드베이스(C:\dev\ourgoal-app) 내 index.html, ui.css, ui.js, js/, api/, docs/, scripts/, sim/, package.json 및 데이터베이스 스키마와 관련된 모든 작업에 예외 없이 적용된다.

### 제3조 (5대 핵심 고질병 및 원천 근절 선언)
1. **되던 기능/버튼의 먹통 현상 (Regression)**: 기존에 정상 동작하던 요소가 새로운 코드 변경의 사이드이펙트로 파괴되는 현상을 원천 금지한다.
2. **껍데기 버튼 방치 (Shell UI / Dead Click)**: 마크업(HTML)만 만들고 실제 동작 핸들러, 비즈니스 로직, 데이터 연계가 누락된 껍데기 요소를 생성하는 행위를 엄격히 금지한다.
3. **상호연계 기능의 고립 (Disconnected Features)**: 다른 기능이나 화면과 연동되어야 하는 기능이 단독으로만 존재하여 상호작용하지 못하는 설계를 금지한다.
4. **유저 데이터의 증발/초기화 (Data Loss)**: 업데이트나 마이그레이션 후 사용자의 **아바타 설정/생성값, 목표 목록/마일스톤, 체크인/회고 기록, 화면 구성 세팅값(테마, 접힘, 필터 등)**이 단 1바이트라도 초기화되거나 유실되는 것을 절대 용납하지 않는다.
5. **화면 간 상태 불일치 (State Desynchronization)**: 한 화면에서 데이터가 변경되었음에도 연관된 다른 화면(홈, 기록, 통계, 캘린더, 프로필)에 즉시 반영되지 않아 유저에게 혼란을 주는 불일치를 금지한다.

## 제2장 작업 착수 및 2중 8원칙 프로세스

### 제4조 (1단계: 문제해결 8원칙 1회차 적용 → 요구사항 정의서 제작)
상민님의 지시가 접수되면 코드를 작성하기 전, 반드시 문제해결 8원칙을 적용하여 docs/specs/REQ-<기능명>.md를 작성해야 한다.
- ①문제 정확히 파악 ②본질·원인·핵심 파악(E1/E2/E3/INFRA/FIX) ③해결방식 결정 ④1~3 재검토·보완 ⑤절차 정리 ⑥절차 재검증 ⑦단계별 실행 기준 ⑧막히는 지점 예상
- **[10줄 이하 핫픽스 패스트트랙]**: 오타 수정, 패딩/마진 미세 조정, 단순 null 가드 등 10줄 이하의 단순 버그 수정은 REQ/PLAN 대신 QUICK-FIX 간이 서식(문제-원인-수정-검증 4줄)으로 즉시 커밋할 수 있다. (단, 인증/권한 변경 함수는 패스트트랙 전면 금지).

### 제5조 (2단계: 문제해결 8원칙 2회차 적용 → 작업계획서 수립)
요구사항 정의서(REQ)가 완료되면, 이를 토대로 다시 문제해결 8원칙을 적용하여 docs/specs/PLAN-<기능명>.md 및 .Codex/작업계획서/<세션id 8자>.md를 수립한다.
- ①파악 ②중심 배선(Wire) 식별 ③파일별 Before/After 및 변경 예산 ④재검토 ⑤구현 상세 순서 ⑥5대 무결성 검증 시나리오 ⑦체크리스트 ⑧블로커 대책

## 제3장 무누락·무축약 작업 이행 규범

### 제6조 (AI 코드 축약 및 생략 전면 금지)
1. AI 에이전트는 코드 작성 시 `// ... rest of code unchanged ...`, `/* 기존 코드 동일 */`, `// TODO: 나중에 구현`, `// FIXME` 등의 축약 주석을 남길 수 없다.
2. 모든 함수와 로직은 생략 없이 100% 완전한 실행 가능한 코드로 작성되어야 한다.

### 제7조 (껍데기 UI 원천 금지: 4위 1체 배선 원칙)
새로운 버튼, 링크, 입력창 등 인터랙티브 UI 요소를 추가할 때는 반드시 아래 4가지 요소가 한 세트로 완결되어야 한다:
1. **마크업(HTML)**: 고유 ID, 접근성 라벨, 올바른 시맨틱 태그.
2. **이벤트 리스너(Event Listener)**: 클릭/터치/키보드 이벤트 바인딩.
3. **실제 비즈니스 로직(Logic & Handler)**: 빈 함수나 console.log, 더미 플래그가 아닌, 실제 데이터 읽기/쓰기/변환을 수행하는 함수.
4. **사용자 피드백 및 예외 처리(Feedback & Error Handling)**: 로딩 인디케이터, 성공 토스트/UI 갱신, 실패 시 친절한 오류 안내 및 롤백.
- 미완성 프로토타입 UI는 화면 노출을 금지하고 hidden 클래스 또는 피처 플래그로 완전 격리 시에만 로컬 커밋을 허용한다.

## 제4장 5대 무결성 전수 검증 의무

### 제8조 (제1검증: 전수 클릭/터치 검증 - Zero Dead-Click)
앱 내 모든 인터랙티브 요소(버튼, 링크, 탭, 모달 토글 등)를 전수 검증하며, 클릭 시 미정의 함수 호출이나 널 참조 에러 등 일체의 JS 런타임 에러가 발생해서는 안 된다.

### 제9조 (제2검증: 전 기능 & 전 UX 무결성 검증 - Zero UX Regression)
계정 및 세션 관리(게스트/소셜 로그인), 온보딩, 그리고 3대 본질 루프(E1 체크인, E2 5단위 회고, E3 동류 소통) 핵심 로직이 손상되지 않고 온전히 동작해야 한다.

### 제10조 (제3검증: 유저 데이터 100% 무손실 보존 검증 - Zero Data Loss)
업데이트 후 기존 사용자의 모든 데이터(아바타, 목표, 기록, 화면 세팅값)는 단 1바이트도 손상되지 않아야 한다. scripts/verify-integrity-gate.js 내 가상 페르소나 데이터 10종 통과 딥 이퀄(Deep Equal) 대조를 필수 통과해야 한다.

### 제11조 (제4검증: 화면 간 상호연동 및 전파 검증 - Full State Propagation)
특정 화면에서 데이터가 추가/수정/삭제되면, 그 데이터와 연관된 다른 모든 화면(홈, 기록, 통계, 캘린더, 프로필)에 실시간으로 일관되게 동시 반영되어야 한다.

### 제12조 (제5검증: 기술 규격 및 자동화 테스트 100% 통과)
npm test를 실행하여 기존 236개 이상의 스모크 테스트와 verify-integrity-gate.js를 100% 통과(0 failure)해야 하며, 콘솔 에러 0건을 유지해야 한다.

## 제5장 직관적 6단계 상태 보고 헌법 및 배포·병합 프로세스

### 제13조 (직관적 6단계 보고 헌법 절대 준수)
모든 작업 진행 및 완료 보고 시에는 "시스템 반영", "검증 완결" 같은 모호한 개발자 언어를 전면 금지하며, 반드시 상민님이 제정한 직관적 6단계 명칭과 물리적 구동 의미를 명시해야 한다:
1. **[1단계: 기획·설계 상태]**: 코드는 아직 작성하지 않았고, 작업계획서와 규격(REQ/PLAN) 문서만 작성된 상태.
2. **[2단계: 내부 시뮬레이션 상태]**: 작업 브랜치에서 코드를 작성하고 단위/스모크/무결성 테스트 통과 상태.
3. **[3단계: 로컬 수동 확인 상태]**: 개발자의 로컬 환경(localhost:8000)에서 화면을 직접 띄워 눈으로 보고 누른 상태.
4. **[4단계: 로컬 메인 병합 상태]**: 작업 브랜치가 로컬 main에 합쳐져 로컬 앱에서 실제로 동작하는 상태 (원격 push/배포 전).
5. **[5단계: 실서버 배포 상태]**: GitHub로 git push되어 Vercel 실서버 배포가 완료되어 실제 웹사이트에서 유저에게 서비스되는 상태.
6. **[6단계: 실운영 최종 확인 상태]**: 실제 운영 인터넷 주소(ourgoal-app.vercel.app)에 직접 접속해 라이브 환경에서 실동작까지 최종 확인한 상태.

### 제14조 (배포 및 병합의 완결과 프리뷰 자동 배포)
1. 일반 세션의 정상 마감점은 **[4단계: 로컬 메인 병합 상태]**이다.
2. 4단계 완료 즉시 질문 없이 **'Vercel 프리뷰 배포(5A단계)'를 자동 실행**하여 실기기 테스트용 임시 URL을 상민님께 제공한다.
3. 상민님의 명시적 승인("배포" 또는 "1")을 받은 직후에만 5단계(프로덕션 실서버 배포) 및 6단계(실운영 최종 확인)로 진입하여 완결한다.
4. **[원격 main PR 머지 = 실서버 프로덕션 배포 동일시 (2026-09-15 신설)]**: 
   GitHub main PR 병합(gh pr merge)은 단순 코드 병합이 아니라 Vercel 실서버 배포 파이프라인(5단계)을 즉각 발동시키는 '되돌릴 수 없는 바깥 행위(프로덕션 발행)'이다. 상민님의 명시적 배포 승인("배포", "1") 없이 원격 main 병합(gh pr merge) 및 main 직접 푸시(git push origin main)를 실행하는 것은 본 헌법 제14조 3항 및 승인선 ④를 정면 위반한 불법 배포로 엄격히 규정하며, 적발 시 세션 작업을 즉시 무효화한다.
5. **[작업계획서 마감 상한선 엄수 (2026-09-15 신설)]**:
   모든 세션의 작업계획서 체크리스트는 반드시 [4단계: 로컬 메인 병합 및 5A 프리뷰 배포]까지만 등록할 수 있다. 상민님의 사전 배포 승인 없이 5단계(실서버 배포)나 6단계(실운영 확인)를 체크리스트에 미리 적어두고 "미완 항목이 남아 정지할 수 없다"는 핑계로 배포를 강행하는 것은 작업계획서 위헌 날조로 규정한다.

## 제6장 기계적 강제 집행 시스템

### 제15조 (게이트키퍼 스크립트 강제 배선)
scripts/verify-integrity-gate.js는 본 헌법의 물리적 집행관이다. 커밋 전, 푸시 전, PR 오픈 시 자동으로 구동되며 단 하나라도 실패하면 커밋/푸시/병합을 물리적으로 차단한다.

### 제16조 (Tri-Sync 및 감사 기록 의무)
모든 작업의 REQ, PLAN, 실행 결과는 Notion DB, Obsidian Vault(아워골_총괄 지식기반), Command Center(journal.jsonl) 3곳에 즉시 동기화된다. 3-Way 자동 중재 알고리즘으로 가짜 충돌을 자동 병합한다.

### 제17조 (용어 헌법: '잔디' 단어 절대 사용 금지 및 '히트맵' 강제)
1. 상민님의 직접 지시에 따라, 아워골의 모든 UI 화면, 버튼, 안내 문구, 기획서, REQ/PLAN 문서, 개발 로그, 코드 주석 등에서 해당 금지 단어의 사용을 전면 영구 금지한다.
2. 모든 연속성 시각화는 예외 없이 **'히트맵(Heatmap)'**으로만 명명하고 표기한다.
3. 외부 라이브러리나 API에서 유입되는 데이터는 네트워크 진입점의 글로벌 I/O 자동 치환기가 '히트맵'으로 키를 자동 매핑 처리한다.

## 제7장 지시 의도 스코프 및 단계별 멈춤 헌법

### 제18조 (지시 의도 스코프 및 물리적 행동 한계선 절대 준수)
1. 상민님의 모든 지시는 아래 5대 모드로 엄격히 분리되며, AI 에이전트는 지정된 한계선을 스스로 건너뛰어(Skip) 과잉 실행할 수 없다:
   - **모드 1 [탐색·질문 모드]**: "~할 수 있지?", "~어때?", "~가능한가?", "~되나?" 등 타당성/의견 질문형 어미가 포함된 경우 코드/파일/설정 수정을 전면 금지하며, 오직 타당성 분석과 기술 방안만 답변하고 대기한다.
   - **모드 2 [구상·설계 한정 모드]**: "일단 구상만", "초안만", "적용하지는 말고" 등 한정 지시 시 실제 저장소 파일 수정을 전면 금지하며, 텍스트 기획/설계안만 제시하고 대기한다.
   - **모드 3 [단계별 명시 정지 모드]**: "~단계까지만", "REQ까지만", "이해했는지 요약만" 등 단계 한정 시 다음 단계(코드 작성, 병합 등) 자동 진입을 금지하고 해당 단계 완료 후 정지한다.
   - **모드 4-A [완곡한 요청 및 로컬 완결 4단계 모드]**: "~해줄래?", "~해주라", "~부탁해", "구현해", "고쳐", "진행" 등 기능 요청이나 통상적 작업 지시 시, 쓸데없이 되묻지 않고 문제해결 8원칙(REQ/PLAN)에 따라 코드를 작성하고 5대 무결성 검증을 통과한 뒤 **[4단계: 로컬 메인 병합 및 5A 프리뷰 배포]까지만 무중단 자율 완결**한다. 4단계 완료 즉시 프리뷰 URL을 제출하고 멈추며, `[결심 필요]`로 실서버 배포 여부를 상민님께 여쭙는다.
   - **모드 4-B [프로덕션 배포 모드]**: 상민님의 명시적 배포 지시("배포", "승인", "1", "배포해")가 내려진 경우에만 승인 안전핀이 해제되어 5단계(원격 main PR 병합 및 실서버 배포) 및 6단계(실운영 최종 확인)를 실행한다.
2. 상민님의 프롬프트가 모드 4-A(완곡한 요청)에 해당할 경우, AI는 개발과 로컬 검증 및 프리뷰 배포까지는 완벽히 자율 수행하되, 상민님의 "배포" 또는 "1" 승인이 없는 한 5단계(실서버 프로덕션 배포)에는 절대 진입할 수 없다.
