## [총괄 목차] 아워골 최고 헌법 14대 조문 체계 (The 14 Supreme Articles)

1. **제1조 (3대 본질 루프 및 인프라 헌법)**: 헌법의 목적, 적용 범위, E1/E2/E3/INFRA/FIX 5대 축 귀속 및 6대 고질병 근절 선언.
2. **제2조 (2중 8원칙 및 핫픽스 헌법)**: 문제해결 8원칙 1회차(REQ) 및 2회차(PLAN) 필수, 10줄 이하 QUICK-FIX 패스트트랙 규격.
3. **제3조 (껍데기 UI 및 가짜 실제구현 방지 4위 1체 배선 헌법)**: AI 코드 축약 전면 금지, [HTML + 리스너 + 비즈니스 로직 + 피드백] 4위 1체 완전 배선, 미완성 UI 피처 플래그 격리, 외부 앱 의존 껍데기 링크 영구 금지.
4. **제4조 (절대 금지 7대 행위 및 스타일 규격 헌법)**: ①위조 숫자 날조, ②파괴적 데이터 삭제, ③도구 언어 UI 노출, ④main 직접 커밋/푸시, ⑤검증 없는 완료 보고, ⑥아이디어 즉시 구현, ⑦가짜 실제구현(상대 계정 연동 없는 가상 봇) 전면 금지 및 스타일 통일.
5. **제5조 (승인선 8대 통제 및 자동 커밋 분할 헌법)**: 5대 필수 승인선(돈, 개인정보, 기능삭제, 바깥행위, 규범변경) 및 추가 통제 엄수, 500줄 초과 시 3계층(DB/로직/UI) 자동 커밋 분할(Auto-Split).
6. **제6조 (1티켓 1PR 및 피처 플래그 헌법)**: 1 PR = 1 Ticket 원칙 및 4블록 설명문 규격 엄수, 거대 에픽 브랜치 격리 금지 및 일일 순차 병합.
7. **제7조 (5대 무결성 전수 검증 및 스크립트 헌법)**: 전수 클릭(Dead-Click 0), 전 UX 회귀(UX Regression 0), 10종 페르소나 데이터 무손실(Data Loss 0), 화면 연동 전파, npm test 263개+ 및 무결성 게이트(verify-integrity-gate.js) 물리적 통과 의무화.
8. **제8조 (직관적 작업 상태 6단계 보고 헌법)**: 1단계(기획)부터 6단계(실운영 확인)까지 물리적 구동 의미 명시, 모호한 개발자 언어 전면 금지.
9. **제9조 (배포 안전핀 및 프리뷰 자동 배포 헌법)**: 4단계 완료 즉시 Vercel 프리뷰 배포(5A) 자동 실행 및 URL 제공, 원격 main PR 머지=실서버 프로덕션 배포 동일시, 작업계획서 4단계 마감 상한선 엄수.
10. **제10조 (용어 헌법: '히트맵' 강제 및 글로벌 I/O 헌법)**: '잔디' 단어 절대 사용 금지, '히트맵(Heatmap)' 단일 표기 강제, 네트워크 진입점 글로벌 I/O 자동 치환.
11. **제11조 (Tri-Sync 3자 상호 동기화 및 미디어 통제 헌법)**: Notion - Obsidian - Command Center 실시간 동기화 및 3-Way 자동 중재, 미디어 생성은 아바타만 허용(영상/쇼츠/릴스 전면 차단).
12. **제12조 (지시 의도 스코프 및 단계별 멈춤 헌법)**: 모드 1(탐색), 모드 2(구상), 모드 3(단계정지), 모드 4-A(완곡한 요청·로컬 4단계), 모드 4-B(명시적 배포). 상민님 승인 없는 5단계 프로덕션 배포 위헌 차단.
13. **제13조 (실 사용자 계정 상호 연동 헌법)**: 2인 이상 상호작용은 실제 등록 사용자들의 상대 계정과 서버 물리 연동만 인정, 가짜 실제구현(가상 봇, 로컬 루프) 영구 금지, 콜드스타트 투명 안내 및 게스트 모드 보호.
14. **제14조 (외부 연동 E2E 무결성 및 헌법 독점주의 헌법)**: 외부 앱 의존 껍데기 링크 금지 및 인앱 완결, 클라우드 환경변수 3자 사전 동기화(No Silent Failure), PWA 캐시 강제 무효화, 6단계 2중 물리적 증거 확보, [조 ➔ 항 ➔ 호 ➔ 목] 단일 위계 확립, 헌법 밖 사설 규칙 제정 전면 금지(헌법 독점주의), 신규 규칙 헌법 직접 편입 및 최고결정권자 승인 의무.

## 제1조 (3대 본질 루프 및 인프라 헌법)

### 제1항 [헌법의 목적 및 무결성 표준]
본 헌법은 아워골의 기능 추가, 수정, 삭제, UI/UX 개편, 백엔드 및 데이터베이스 변경 등 모든 개발 작업 시 발생해 온 고질적인 결함(되던 버튼 먹통, 껍데기 버튼 방치, 연계 기능 상호연동 불발, 유저 데이터 유실, 뷰 간 상태 불일치, AI 코드 축약)을 원천 방지하고, 사용자가 어떠한 업데이트 이후에도 신뢰와 안정성을 체감할 수 있도록 무결성 작업 표준을 확립함을 목적으로 한다.

### 제2항 [적용 범위]
아워골 코드베이스(`C:\dev\ourgoal-app`) 내 `index.html`, `ui.css`, `ui.js`, `js/`, `api/`, `docs/`, `scripts/`, `sim/`, `package.json` 및 데이터베이스 스키마와 관련된 모든 작업에 예외 없이 적용된다.

### 제3항 [3대 본질 루프 및 5대 축 귀속 의무]
1. 아워골의 모든 개발 및 유지보수 작업은 반드시 아래 5대 축 중 하나에 명시적으로 귀속되어야 한다:
   - **E1 (체크인 루프)**: 목표 실천, 체크인, 스트릭 유지.
   - **E2 (기록 회고 루프)**: 5단위 회고, 주간/월간 반추, AI 피드백.
   - **E3 (동류 소통 루프)**: 동반자 맺기, 1:1 대화, 팀 목표, 응원 및 피드.
   - **INFRA (기반 인프라)**: PWA, 인증, DB 마이그레이션, 성능, CI/CD, Tri-Sync.
   - **FIX (버그 수정)**: 회귀 결함 복구, UI 깨짐 수습, 무결성 보완.
2. 5대 표준 유지보수 카탈로그에 부합하는 작업은 `[기본값: INFRA]`로 지정하여 불필요한 질의 없이 끝까지 무중단 자율 실행한다.

### 제4항 [6대 핵심 고질병 원천 근절 선언]
1. **1호 (되던 기능/버튼의 먹통 현상 - Regression)**: 기존에 정상 동작하던 요소가 새로운 코드 변경의 사이드이펙트로 파괴되는 현상을 원천 금지한다.
2. **2호 (껍데기 버튼 방치 - Shell UI / Dead Click)**: 마크업(HTML)만 만들고 실제 동작 핸들러, 비즈니스 로직, 데이터 연계가 누락된 껍데기 요소를 생성하는 행위를 엄격히 금지한다.
3. **3호 (상호연계 기능의 고립 - Disconnected Features)**: 다른 기능이나 화면과 연동되어야 하는 기능이 단독으로만 존재하여 상호작용하지 못하는 설계를 금지한다.
4. **4호 (유저 데이터의 증발/초기화 - Data Loss)**: 업데이트나 마이그레이션 후 사용자의 **아바타 설정/생성값, 목표 목록/마일스톤, 체크인/회고 기록, 화면 구성 세팅값(테마, 접힘, 필터 등)**이 단 1바이트라도 초기화되거나 유실되는 것을 절대 용납하지 않는다.
5. **5호 (화면 간 상태 불일치 - State Desynchronization)**: 한 화면에서 데이터가 변경되었음에도 연관된 다른 화면(홈, 기록, 통계, 캘린더, 프로필)에 즉시 반영되지 않아 유저에게 혼란을 주는 불일치를 금지한다.
6. **6호 (가짜 실제구현 및 로컬 자가발전 눈속임 - Fake Real-Implementation)**: 다자간 소통 및 협업 기능에서 실제 다른 사용자의 계정과 통신하지 않고, 클라이언트 로컬스토리지 자가 저장, setTimeout 가상 타이머 봇 자동답장, 하드코딩 가상 유저 배열로 상호작용을 흉내 내며 "실제 구현 완료"로 위장하는 기만행위를 엄격히 금지한다.

## 제2조 (2중 8원칙 및 핫픽스 헌법)

### 제1항 [1단계: 문제해결 8원칙 1회차 적용 → 요구사항 정의서 제작]
상민님의 지시가 접수되면 코드를 작성하기 전, 반드시 문제해결 8원칙을 적용하여 `docs/specs/REQ-<기능명>.md`를 작성해야 한다.
- ①문제 정확히 파악 ②본질·원인·핵심 파악(E1/E2/E3/INFRA/FIX) ③해결방식 결정 ④1~3 재검토·보완 ⑤절차 정리 ⑥절차 재검증 ⑦단계별 실행 기준 ⑧막히는 지점 예상

### 제2항 [2단계: 문제해결 8원칙 2회차 적용 → 작업계획서 수립]
요구사항 정의서(REQ)가 완료되면, 이를 토대로 다시 문제해결 8원칙을 적용하여 `docs/specs/PLAN-<기능명>.md` 및 `.Codex/작업계획서/<세션id 8자>.md`를 수립한다.
- ①파악 ②중심 배선(Wire) 식별 ③파일별 Before/After 및 변경 예산 ④재검토 ⑤구현 상세 순서 ⑥5대 무결성 검증 시나리오 ⑦체크리스트 ⑧블로커 대책

### 제3항 [10줄 이하 핫픽스 패스트트랙 요건]
오타 수정, 패딩/마진 미세 조정, 단순 null 가드 등 10줄 이하의 단순 버그 수정은 REQ/PLAN 대신 QUICK-FIX 간이 서식(문제-원인-수정-검증 4줄)으로 즉시 커밋할 수 있다. (단, 인증/권한 변경 함수는 패스트트랙 전면 금지).

## 제3조 (껍데기 UI 및 가짜 실제구현 방지 4위 1체 배선 헌법)

### 제1항 [AI 코드 축약 및 생략 전면 영구 금지]
1. AI 에이전트는 코드 작성 시 `// ... rest of code unchanged ...`, `/* 기존 코드 동일 */`, `// TODO: 나중에 구현`, `// FIXME` 등의 축약 주석을 남길 수 없다.
2. 모든 함수와 로직은 생략 없이 100% 완전한 실행 가능한 코드로 작성되어야 한다.

### 제2항 [껍데기 UI 원천 금지: 4위 1체 배선 원칙]
새로운 버튼, 링크, 입력창 등 인터랙티브 UI 요소를 추가할 때는 반드시 아래 4가지 요소가 한 세트로 완결되어야 한다:
1. **1호 (마크업 - Markup)**: 고유 ID, 접근성 라벨, 올바른 시맨틱 태그.
2. **2호 (이벤트 리스너 - Listener)**: 클릭/터치/키보드 이벤트 바인딩.
3. **3호 (실제 비즈니스 로직 - Handler & Logic)**: 빈 함수나 console.log, 더미 플래그를 금지함은 물론, 소통·협업·공유(E3) 및 관계형 기능에서는 반드시 '실 사용자 계정 상호 연동'이 수반되어야 한다.
4. **4호 (사용자 피드백 및 예외 처리 - Feedback & Error Handling)**: 로딩 인디케이터, 성공 토스트/UI 갱신, 실패 시 친절한 오류 안내 및 롤백.

### 제3항 [미완성 UI 피처 플래그 격리 의무]
미완성 프로토타입 UI는 화면 노출을 금지하고 `hidden` 클래스 또는 피처 플래그로 완전 격리 시에만 로컬 커밋을 허용한다.

### 제4항 [외부 앱 의존 껍데기 링크 전면 금지]
앱 내 버튼 및 링크에서 `mailto:` 등 기기 외부 이메일 앱이나 외부 클라이언트를 강제 호출하는 의존성 링크의 신설을 전면 금지한다.

## 제4조 (절대 금지 7대 행위 및 스타일 규격 헌법)

### 제1항 [절대 금지 7대 행위]
1. **1호 (위조 숫자 날조 금지)**: 데이터베이스나 로컬 스토리지에 실존하지 않는 수치, 가짜 스트릭 카운트, 하드코딩된 더미 통계 숫자를 화면에 렌더링하는 행위를 엄격히 금지한다.
2. **2호 (파괴적 데이터 삭제 금지)**: `.delete().not()`, `TRUNCATE`, 조건 없는 `DELETE` 등 기존 유저의 기록이나 설정을 일괄 파괴할 수 있는 쿼리 및 로직 작성을 전면 금지한다.
3. **3호 (도구/개발자 언어 UI 노출 금지)**: 유저 대면 화면에 프레임워크 에러 메시지, 내부 DB 컬럼명, "Supabase Error" 등의 개발자 전용 용어가 노출되는 것을 금지한다.
4. **4호 (main 직접 커밋 및 승인 없는 머지/푸시 금지)**: 로컬 `main` 브랜치에 직접 커밋하거나, 상민님의 명시적 승인 없이 `gh pr merge` 또는 원격 `main`으로 푸시하는 행위를 전면 금지한다.
5. **5호 (기계적 검증 없는 작업 완료 보고 금지)**: 단위 테스트, 스모크 테스트, 게이트키퍼 스크립트를 실제로 실행하여 `ALL PASS`를 확인하지 않은 채 주관적 판단만으로 작업을 완료 보고하는 것을 금지한다.
6. **6호 (상민님 승인 없는 아이디어 즉시 구현 금지)**: 상민님께서 단순 아이디어를 묻거나 탐색형 질문을 하셨을 때 임의로 코드를 작성하여 반영하는 월권행위를 금지한다.
7. **7호 (가짜 실제구현 전면 금지)**: 상대방 계정과 연동 없는 가상 봇 눈속임이나 로컬 자가 순환 루프를 실제 구현으로 보고하는 행위를 영구 금지한다.

### 제2항 [스타일 및 디자인 컴포넌트 일관성 규격]
1. 모든 신규 UI는 `ui.css`에 정의된 CSS 전역 변수(`--bg-primary`, `--text-primary`, `--accent-primary` 등)와 기존 버튼/카드 디자인 토큰을 엄격히 계승해야 한다.
2. 인라인 하드코딩 색상값(#123456)의 남발을 금지하며, 다크/라이트 테마 전환 시 텍스트나 배경이 보이지 않는 시각적 결함을 원천 차단한다.

## 제5조 (승인선 8대 통제 및 자동 커밋 분할 헌법)

### 제1항 [5대 필수 승인선 통제]
아래 5대 승인선에 해당하는 변경 사항은 AI 에이전트가 임의로 집행할 수 없으며, 반드시 작업을 즉시 멈추고 상민님께 `[결심 필요]`로 보고하여 명시적 승인을 받아야 한다:
1. **1호 (돈 - Financial Impact)**: 유료 API 호출 증설, 결제 로직 변경, 클라우드 과금 인프라 증설.
2. **2호 (개인정보 - Privacy & Security)**: 유저 이메일, 닉네임, 프로필, 로그인 자격증명 수집 및 보안 정책 변경.
3. **3호 (기존 기능 삭제 - Feature Deletion)**: 기존에 제공되던 기능, 화면, API 엔드포인트의 영구 제거.
4. **4호 (되돌릴 수 없는 바깥 행위 - Irreversible External Actions)**: 원격 main PR 머지(`gh pr merge`), 프로덕션 실서버 배포, 외부 Webhook 발송, 외부 이메일/메시지 실발송.
5. **5호 (규범 변경 - Governance & Rules)**: 본 헌법 조·항 신설·수정·삭제, 전역 `AGENTS.md` 지침 개정.

### 제2항 [추가 승인선 통제]
1. 본질 무관 기능(E1/E2/E3 외 사족 기능) 신설 감지 시.
2. 위조 숫자 및 가짜 페르소나 데이터 삽입 요구 감지 시.
3. 3개 이상 도메인에 걸친 대규모 아키텍처 개편 시.

### 제3항 [500줄 초과 시 3계층 자동 커밋 분할]
단일 PR 또는 작업의 프로덕션 코드 변경량이 500줄을 초과할 경우, 작업을 멈추지 않고 3계층(①DB/API ➔ ②비즈니스 로직 ➔ ③UI 마크업/스타일)으로 자동 커밋 분할(Auto-Split)하여 점진적으로 병합 통과한다.

## 제6조 (1티켓 1PR 및 피처 플래그 헌법)

### 제1항 [1 PR = 1 Ticket 원칙 및 4블록 설명 규격]
1. 모든 작업은 단 하나의 명확한 목적을 가진 티켓 단위로 분기 브랜치를 생성하여 작업한다.
2. 모든 PR 설명문은 아래 4개 블록을 필수로 포함해야 한다:
   - [블록 1]: 작업 배경 및 목적 (Problem & Context)
   - [블록 2]: 주요 변경 내역 (Key Changes - 파일별 요약)
   - [블록 3]: 5대 무결성 검증 결과 (Verification Results)
   - [블록 4]: 영향 범위 및 롤백 대책 (Impact & Rollback Plan)

### 제2항 [에픽 브랜치 격리 금지 및 일일 순차 병합]
장기간 머지되지 않는 거대 에픽 브랜치를 금지하며, 피처 플래그 비활성화 상태로 1티켓 단위 로컬 메인에 매일 순차 병합한다.

## 제7조 (5대 무결성 전수 검증 및 스크립트 헌법)

### 제1항 [제1검증: Zero Dead-Click 전수 인터랙션 검증]
앱 내 모든 인터랙티브 요소(버튼, 링크, 탭, 모달 토글 등)를 전수 검증하며, 클릭 시 미정의 함수 호출이나 널 참조 에러 등 일체의 JS 런타임 에러가 발생해서는 안 된다.

### 제2항 [제2검증: Zero UX Regression 전 기능 & 전 UX 무결성 검증]
계정 및 세션 관리(게스트/소셜 로그인), 온보딩, 그리고 3대 본질 루프(E1 체크인, E2 5단위 회고, E3 동류 소통) 핵심 로직이 손상되지 않고 온전히 동작해야 한다.

### 제3항 [제3검증: Zero Data Loss 유저 데이터 100% 무손실 보존 검증]
업데이트 후 기존 사용자의 모든 데이터(아바타 설정값, 목표 목록/마일스톤, 체크인/회고 기록, 화면 세팅값)는 단 1바이트도 손상되지 않아야 한다. `scripts/verify-integrity-gate.js` 내 가상 페르소나 데이터 10종 통과 딥 이퀄(Deep Equal) 대조를 필수 통과해야 한다.

### 제4항 [제4검증: Full State Propagation 화면 간 상호연동 및 전파 검증]
특정 화면에서 데이터가 추가/수정/삭제되면, 그 데이터와 연관된 다른 모든 화면(홈, 기록, 통계, 캘린더, 프로필)에 실시간으로 일관되게 동시 반영되어야 한다.

### 제5항 [제5검증: 기술 규격 및 자동화 테스트 100% 통과]
`npm test`를 실행하여 기존 263개 이상의 스모크 테스트와 `verify-integrity-gate.js`를 100% 통과(0 failure)해야 하며, 콘솔 에러 0건을 유지해야 한다.

### 제6항 [게이트키퍼 스크립트 강제 배선 및 마이그레이션 스크립트 의무화]
1. `scripts/verify-integrity-gate.js`는 본 헌법의 물리적 집행관이며 단 하나라도 실패하면 커밋/푸시/병합을 물리적으로 차단한다.
2. 스키마 변경 시 AI 에이전트의 픽스처 임의 손수정을 엄격히 금지하며 반드시 멱등성이 보장되는 마이그레이션 스크립트를 작성하여 데이터를 승계해야 한다.

## 제8조 (직관적 작업 상태 6단계 보고 헌법)

### 제1항 [직관적 6단계 상태 정의]
모든 작업 진행 및 완료 보고 시에는 모호한 개발자 언어를 전면 금지하며, 반드시 상민님이 제정한 직관적 6단계 명칭과 물리적 구동 의미를 명시해야 한다:
1. **1호 [1단계: 기획·설계 상태]**: 코드는 아직 작성하지 않았고, 작업계획서와 규격(REQ/PLAN) 문서만 작성된 상태.
2. **2호 [2단계: 내부 시뮬레이션 상태]**: 작업 브랜치에서 코드를 작성하고 단위/스모크/무결성 테스트 통과 상태.
3. **3호 [3단계: 로컬 수동 확인 상태]**: 개발자의 로컬 환경(`localhost:8000`)에서 화면을 직접 띄워 눈으로 보고 누른 상태.
4. **4호 [4단계: 로컬 메인 병합 상태]**: 작업 브랜치가 로컬 main에 합쳐져 로컬 앱에서 실제로 동작하는 상태 (원격 push/배포 전).
5. **5호 [5단계: 실서버 배포 상태]**: GitHub로 git push되어 Vercel 실서버 배포가 완료되어 실제 웹사이트에서 유저에게 서비스되는 상태.
6. **6호 [6단계: 실운영 최종 확인 상태]**: 실제 운영 인터넷 주소(`ourgoal-app.vercel.app`)에 직접 접속해 라이브 환경에서 실동작까지 최종 확인한 상태.

### 제2항 [보고 시 물리적 의미 명시 의무]
"시스템에 반영되었습니다", "완결되었습니다" 등의 모호한 표현을 금지하고, 반드시 `[4단계: 로컬 메인 병합 상태 - 브랜치가 로컬 main에 합쳐져 로컬에서 실제 동작함]`과 같이 단계 번호와 실제 구동 의미를 함께 표기해야 한다.

## 제9조 (배포 안전핀 및 프리뷰 자동 배포 헌법)

### 제1항 [4단계 로컬 메인 병합 마감 및 Vercel 프리뷰(5A) 자동 실행]
1. 일반 세션의 정상 마감점은 **[4단계: 로컬 메인 병합 상태]**이다.
2. 4단계 완료 즉시 질문 없이 **'Vercel 프리뷰 배포(5A단계)'를 자동 실행**하여 실기기 테스트용 임시 URL을 상민님께 제공한다.
3. 상민님의 명시적 승인("배포" 또는 "1")을 받은 직후에만 5단계(프로덕션 실서버 배포) 및 6단계(실운영 최종 확인)로 진입하여 완결한다.

### 제2항 [원격 main PR 머지 = 실서버 프로덕션 배포 동일시 규정]
GitHub main PR 병합(`gh pr merge`)은 단순 코드 병합이 아니라 Vercel 실서버 배포 파이프라인(5단계)을 즉각 발동시키는 '되돌릴 수 없는 바깥 행위(프로덕션 발행)'이다. 상민님의 명시적 배포 승인("배포", "1") 없이 원격 main 병합(`gh pr merge`) 및 main 직접 푸시(`git push origin main`)를 실행하는 것은 본 헌법 및 승인선 4호를 정면 위반한 불법 배포로 엄격히 규정하며, 적발 시 세션 작업을 즉시 무효화한다.

### 제3항 [작업계획서 4단계 마감 상한선 엄수]
모든 세션의 작업계획서 체크리스트는 반드시 [4단계: 로컬 메인 병합 및 5A 프리뷰 배포]까지만 등록할 수 있다. 상민님의 사전 배포 승인 없이 5단계(실서버 배포)나 6단계(실운영 확인)를 체크리스트에 미리 적어두고 "미완 항목이 남아 정지할 수 없다"는 핑계로 배포를 강행하는 것은 작업계획서 위헌 날조로 규정한다.

## 제10조 (용어 헌법: '히트맵' 강제 및 글로벌 I/O 헌법)

### 제1항 ['잔디' 단어 절대 사용 금지]
상민님의 직접 지시에 따라, 아워골의 모든 UI 화면, 버튼, 안내 문구, 기획서, REQ/PLAN 문서, 개발 로그, 코드 주석 등에서 해당 금지 단어의 사용을 전면 영구 금지한다.

### 제2항 ['히트맵(Heatmap)' 단일 표기 강제]
모든 연속성 시각화는 예외 없이 **'히트맵(Heatmap)'**으로만 명명하고 표기한다.

### 제3항 [네트워크 진입점 글로벌 I/O 자동 치환]
외부 라이브러리나 API에서 유입되는 데이터는 네트워크 진입점의 글로벌 I/O 자동 치환기가 '히트맵'으로 키를 자동 매핑 처리한다.

## 제11조 (Tri-Sync 3자 상호 동기화 및 미디어 통제 헌법)

### 제1항 [Notion - Obsidian - Command Center 실시간 동기화 및 3-Way 자동 중재]
1. 모든 작업의 REQ, PLAN, 실행 결과는 Notion DB, Obsidian Vault(아워골_총괄 지식기반), Command Center(journal.jsonl) 3곳에 즉시 동기화된다.
2. 3-Way 자동 중재 알고리즘으로 가짜 충돌을 자동 병합하며, 세션 종료 전 반드시 동기화 무결성(`node C:/dev/command-center/lib/tri-sync.js check`)을 검증한다.

### 제2항 [미디어 생성 통제: 아바타만 허용]
미디어 자동생성은 오직 아워골 아바타 제작만 허용하며, 영상/쇼츠/릴스 등의 불필요한 미디어 생성은 전면 차단한다.

## 제12조 (지시 의도 스코프 및 단계별 멈춤 헌법)

### 제1항 [5대 지시 모드 분리]
상민님의 모든 지시는 아래 5대 모드로 엄격히 분리되며, AI 에이전트는 지정된 한계선을 스스로 건너뛰어(Skip) 과잉 실행할 수 없다:
1. **1호 (모드 1 [탐색·질문 모드])**: "~할 수 있지?", "~어때?", "~가능한가?", "~되나?" 등 타당성/의견 질문형 어미가 포함된 경우 코드/파일/설정 수정을 전면 금지하며, 오직 타당성 분석과 기술 방안만 답변하고 대기한다.
2. **2호 (모드 2 [구상·설계 한정 모드])**: "일단 구상만", "초안만", "적용하지는 말고" 등 한정 지시 시 실제 저장소 파일 수정을 전면 금지하며, 텍스트 기획/설계안만 제시하고 대기한다.
3. **3호 (모드 3 [단계별 명시 정지 모드])**: "~단계까지만", "REQ까지만", "이해했는지 요약만" 등 단계 한정 시 다음 단계(코드 작성, 병합 등) 자동 진입을 금지하고 해당 단계 완료 후 정지한다.
4. **4호 (모드 4-A [완곡한 요청 및 로컬 완결 4단계 모드])**: "~해줄래?", "~해주라", "~부탁해", "구현해", "고쳐", "진행" 등 기능 요청이나 통상적 작업 지시 시, 쓸데없이 되묻지 않고 문제해결 8원칙(REQ/PLAN)에 따라 코드를 작성하고 5대 무결성 검증을 통과한 뒤 **[4단계: 로컬 메인 병합 및 5A 프리뷰 배포]까지만 무중단 자율 완결**한다. 4단계 완료 즉시 프리뷰 URL을 제출하고 멈추며, `[결심 필요]`로 실서버 배포 여부를 상민님께 여쭙는다.
5. **5호 (모드 4-B [프로덕션 배포 모드])**: 상민님의 명시적 배포 지시("배포", "승인", "1", "배포해")가 내려진 경우에만 승인 안전핀이 해제되어 5단계(원격 main PR 병합 및 실서버 배포) 및 6단계(실운영 최종 확인)를 실행한다.

### 제2항 [승인 없는 5단계 프로덕션 배포 위헌 차단]
상민님의 프롬프트가 모드 4-A(완곡한 요청)에 해당할 경우, AI는 개발과 로컬 검증 및 프리뷰 배포까지는 완벽히 자율 수행하되, 상민님의 "배포" 또는 "1" 승인이 없는 한 5단계(실서버 프로덕션 배포)에는 절대 진입할 수 없다.

## 제13조 (실 사용자 계정 상호 연동 헌법)

### 제1항 [실제 구현의 절대 정의]
아워골에서 1:1 다이렉트 메시지(DM), 동반자(친구/팔로우), 팀 목표 초대·대화(팀 톡), 팀원 찌르기 및 모임장 반응, 댓글, 피드 등 **2인 이상의 상호작용이 수반되는 모든 기능의 '실제 구현'이란, "실제 등록된 사용자들의, 상대방 계정(들)과 서버(DB / Realtime API / Push)를 통하여 물리적으로 상호 연동(Mutual Inter-Account Sync)되는 상태"만을 의미한다.**

### 제2항 [가짜 실제구현(Fake Implementation)의 정의 및 영구 금지]
1. 실제 사용자가 아닌 하드코딩된 가상 페르소나 풀(`MOCK_PEOPLE`, `ALL_SEARCHABLE_USERS` 등)을 실 유저처럼 위장하여 매칭하거나, `setTimeout` 등의 타이머로 상대방의 답변을 날조하는 로직을 "실제 구현"으로 보고하거나 배포하는 행위를 영구 금지한다.
2. 클라이언트 로컬스토리지에만 저장하고 상대방 계정으로 데이터가 전파되지 않는 폐쇄적 자가 순환 루프는 '실제 구현'이 아닌 '가짜 실제구현'으로 규정한다.
3. 화면에 먼저 띄우는 낙관적 UI(Optimistic UI)는 정당한 사용자 경험 최적화로 전면 허용하되, 해당 메시지가 최종적으로 서버 DB 원장에 영속화되고 상대방 계정으로 도달하는 종단간(End-to-End) 파이프라인이 필수로 배선되어야 한다.

### 제3항 [투명한 시스템 안내 및 게스트 모드 보호 (무충돌 안전핀)]
1. **콜드스타트 완충재 보호**: 앱 초기 피드 활성화를 위한 AI 예시 글 등은 반드시 `[AI 봇]` 또는 `[시스템 안내]` 공식 뱃지를 달고 투명하게 공개되는 경우에 한하여 헌법상 정당한 시스템 인프라로 인정한다.
2. **게스트 온보딩 보호**: 비로그인 게스트가 1:1 DM이나 동반자 맺기를 시도할 경우, 시스템 충돌이나 화면 먹통을 유발하지 않고 "실제 동료와 대화하려면 로그인이 필요해요"라는 우아한 소프트 로그인 가이드(Soft Auth Gate)를 제공해야 한다.

### 제4항 [E3 동류소통 기능의 3대 필수 백본 및 자동화 검증]
모든 실 사용자 소통 기능은 반드시 아래 3대 백본이 실제 가동되어야만 "구현 완료"로 인정한다:
1. **1호 (영속성 원장 - Database Engine)**: Supabase 테이블(`direct_messages`, `user_companions` 등)에 발송자 UID(`sender_id`)와 수신자 UID(`receiver_id`)가 영속 기록되어야 한다.
2. **2호 (실시간 양방향 전파 - Realtime Engine)**: 상대방 사용자가 로그인해 있을 때, 페이지 새로고침 없이 즉각 메시지와 알림이 화면에 반영되는 실시간 채널(`sb.channel`)이 배선되어야 한다.
3. **3호 (실사용자 식별 - Identity Engine)**: 실제 Supabase `users` 테이블에 가입된 회원들의 닉네임과 프로필을 기반으로 검색, 친구 맺기, 1:1 대화가 이루어져야 한다.
4. **4호 (기계적 정합성 검증 의무)**: 모든 소통 기능은 `scripts/verify-integrity-gate.js` 및 `scripts/smoke-test.js`에서 2개 이상의 실제 계정 세션 기반 상호 송수신 통합 테스트를 통과해야 한다.

## 제14조 (외부 연동 E2E 무결성 및 헌법 독점주의 헌법)

### 제1항 [외부 앱 의존 껍데기 링크 전면 금지 및 인앱 완결 의무]
1. 앱 내 '문의', '제보', '신고', '피드백' 등 사용자의 입력을 받는 모든 창구는 특정 화면의 메인 버튼뿐만 아니라, **푸터(Footer), 서브메뉴, 모달 내부 링크 일체에서 `mailto:` 등 외부 앱 의존 링크의 사용을 전면 영구 금지**한다.
2. 모든 고객 접수 창구는 반드시 앱 내에서 즉시 열리는 인앱 모달(In-App Modal)로 단일화되어야 하며, 미개설 도메인 이메일이나 외부 메일 클라이언트로 사용자를 내몰아 '발송 실패'의 불쾌감을 주는 행위를 헌법 위반으로 규정한다.

### 제2항 [클라우드 환경변수·자격증명 3자 사전 동기화 의무 (No Silent Failure)]
1. 백엔드 서버리스 함수 및 API가 외부 서비스(Notion, Telegram, Supabase, Gemini, VAPID 등)와 통신할 때, **로컬 환경(`.env`)에 존재하는 필수 토큰/키는 5단계 실서버 배포 전 반드시 프로덕션 클라우드(Vercel, Supabase 등)에 기계적으로 사전 동기화(`vercel env ls` 확인)**되어야 한다.
2. 토큰 누락으로 인해 백엔드가 에러도 뱉지 않고 조용히 작업을 스킵하는 '침묵형 실패(Silent Failure)' 로직을 엄격히 금지하며, 필수 자격증명 부재 시 즉각적인 경고 로깅 및 프론트엔드 실패 피드백이 반환되도록 방어 코드를 작성해야 한다.

### 제3항 [PWA·브라우저 캐시 강제 무효화 의무 (Cache Invalidation Gate)]
1. `index.html` 또는 프론트엔드 핵심 인터랙션 로직이 변경될 때마다, **반드시 `sw.js`의 `CACHE_NAME`을 당일 날짜 또는 신규 티켓 버전으로 즉시 갱신**해야 한다.
2. 서비스워커 캐시 네임이 갱신되지 않은 채 배포되어, 기존 사용자가 구버전 HTML/JS를 캐시로 바라보며 버그를 겪게 만드는 행위를 무결성 검증 탈락 사유로 규정한다.

### 제4항 [6단계 실운영 최종 확인의 종단간(E2E) 실측 의무]
1. 제8조 제1항 제6호의 **[6단계: 실운영 최종 확인 상태]**는 단순히 프로덕션 URL의 메인 웹페이지가 로드(HTTP 200)되는 것만으로는 결코 성립될 수 없다.
2. 6단계 완료 보고를 위해서는 반드시 **실제 프로덕션 라이브 엔드포인트에 실제 테스트 요청을 전송하고, 최종 도착지(노션 DB의 실제 행 생성, 텔레그램 봇의 실제 알림 수신, Supabase 실제 테이블 적재)에 데이터가 정상 도달했음을 확인하는 '2중 물리적 증거(Evidence)'를 보고서에 명시**해야만 완료로 인정한다.

### 제5항 [법체계 위계의 단일화 (조·항·호·목 원칙)]
1. 모든 규범과 규칙의 제정·개정 시 법체계 위계는 반드시 **[조(Article) ➔ 항(Paragraph) ➔ 호(Item) ➔ 목(Sub-item)]**의 4단계 표준으로만 표기한다.
2. 조(Article)는 헌법 대원칙의 고유 단위이며 본 헌법은 오직 **제1조부터 제14조까지의 조문만을 인정**한다. 조의 하위 세부 법조문은 반드시 항(Paragraph: 제1항, 제2항... 또는 ①, ②...)으로 규정하고, 항 아래의 세부 나열은 호(Item: 1호, 2호...) 및 목(Sub-item: 가목, 나목...)으로만 위계화한다. 하나의 조문 안에서 조 번호를 중복 생성하거나 이중으로 넘버링하는 행위를 영구 금지한다.

### 제6항 [헌법 독점주의 (사설 규칙 제정 전면 금지 / Constitutional Exclusivity)]
1. 아워골 및 관련 전 시스템(코드베이스, 커맨드센터, 옵시디언, 노션)에서 유효한 모든 개발·운영·협업 규범은 **오직 본 최고 헌법(`OURGOAL_ABSOLUTE_INTEGRITY_RULES.md`) 안에 직접 편입·등재된 14개 조문과 세부 항만을 인정**한다.
2. 본 헌법 밖에서 AI 에이전트나 개발자가 독자적으로 작성한 어떠한 별도 규칙 문서, 가이드라인, 관행, 주석 규범도 법적 효력을 가질 수 없으며 전면 무효로 한다.

### 제7항 [신규 규칙 제정의 헌법 편입 의무]
1. 향후 프로젝트 진행 중 새로운 규칙, 기술 제약, 개발 가이드라인, 운영 절차가 필요한 경우, 별도의 마크다운 파일이나 문서를 파편화하여 만들지 않고 **반드시 본 헌법의 기존 조문의 '항'으로 증설하거나 헌법 본문에 직접 편입하여 상민님의 명시적 승인을 거쳐서만 제정**할 수 있다.
2. 헌법 외부에 규칙을 분산시키는 모든 시도는 '사설 규범 분열 행위'로 규정하여 커밋과 배포를 물리적으로 차단한다.

### 제8항 [규범 변경의 절대 승인선 엄수 및 기계적 무결성 게이트 강제]
1. 본 헌법의 '조'를 신설·삭제하거나 '항'을 추가·수정하는 모든 행위는 5대 승인선(승인선 5호: 규범 변경)에 해당하며, 최고결정권자(상민님)의 명시적 승인 없이는 단 1글자도 임의로 변경할 수 없다.
2. 본 헌법의 14대 조문과 모든 핵심 항은 `scripts/verify-integrity-gate.js`에 기계적 단언문(Assertion)으로 영구 배선되어야 하며, CI/CD 게이트에서 단 하나라도 누락되거나 위반될 시 빌드와 배포를 물리적으로 즉각 차단한다.
