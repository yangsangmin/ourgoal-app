# 아워골의 본질 — 판정 잣대 (규칙 원본 AGENTS.md 0절의 전문)

정의 주체: 상민님 · 확정: 2026-09-11 · 버전: 2026.09.11-02 · 변경은 승인선 5(규범 변경)

## ① 체크인 루프
묻기 → 답하기 → 피드백 → 내 위치 확인 → 기록. 성취감이 동력.
판정할 때 보는 것: 다섯 단계가 한 흐름으로 도는가, 각 단계의 마찰이 줄었는가, 홈 화면이 이 순서를 지키는가.

## ② 기록 회고
무엇을 확인하나 — 다섯 단위 각각 별개로: 오늘의 기록 / 일주일의 기록 / 한 달의 기록 / 1년의 기록 / 내가 설정한 기간의 기록.
확인하면서 사용자 안에 생겨야 하는 것 — 세 가지 전부: 성취감 / 기록의 가치(내가 기록해 둔 것이 가치 있다는 체감) / 더 나은 기록을 해야겠다는 생각.
판정할 때 보는 것: 다섯 단위마다 기록을 볼 수 있는가, 그 화면이 데이터 나열이 아니라 세 가지 결과가 생기도록 만들어졌는가.

## ③ 동류 발견·소통
누구를 보나 — 비슷함의 기준 두 가지: 비슷한 목표(테마·카테고리) / 비슷한 관심사.
그 사람의 무엇을 보나: 체크인 기록 / 목표설정 상태 / 일주일간의 기록 피드 / 목표 템플릿 / 같은 성격의 다른 것.
보면서 무엇을 하나: 본인 목표에 대해 유익한 정보를 수집한다 / 비슷한 사람들의 라이프를 공개된 범위 안에서 확인한다 / 소통한다.
그 결과 느껴야 하는 것: "이 앱이 정말 본인의 목표달성, 일정관리, 생활습관 개선 등 사용자의 인생을 바로잡고 나아가는 데 유익한 앱이다" — 누가 말해줘서가 아니라 스스로, 앱을 사용하면서, 실질적으로.
판정할 때 보는 것: (a) 테마·카테고리·관심사로 비슷한 사람을 찾을 수 있는가 (b) 그 사람의 기록·목표 상태·주간 피드·템플릿이 공개 범위 안에서 보이는가 (c) 내 목표에 쓸 정보를 실제로 가져올 수 있는가 (d) 소통 수단이 있는가 (e) 이 경험이 "유익하다"는 체감으로 이어지는가. 과거 작업은 (a)~(e) 중 하나라도 전진시켰으면 ③ 기여, 앱 자체는 다섯이 다 있어야 충족.

## 세 축의 관계와 총괄 기준
①이 기록을 만들고, ②가 내 기록을 되돌아보게 하고, ③이 남의 기록과 라이프를 보게 한다. 기능이 있는 것과 사용자가 느끼는 것은 다르다 — 판정은 언제나 "기능 존재"가 아니라 "체감 기여"로 한다. 봇·가상유저·고정 숫자는 체감을 만들지 못하므로 기여로 인정하지 않는다.

## 판정 기호 (작업 로그 '본질 판정' 값)
기여 ① / 기여 ② / 기여 ③ / 전제(무결성·품질·인프라) / 무관(확장·장식) / 역행(위조·파괴·왕복·본질 차단)
