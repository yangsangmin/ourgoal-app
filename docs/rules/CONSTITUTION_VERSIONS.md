## 🔒 헌법 버전 관리 4대 불변 원칙

1. **비파괴 아카이브 원칙**: 헌법을 개정할 때는 기존 정본을 덮어쓰기 전에 반드시 `docs/rules/archive/`에 해당 버전 번호를 명시한 원문 사본을 영구 저장해야 한다.
2. **단일 위계 동기화 원칙**: 전역 정본(`C:/Users/HP/AGENTS.md`)과 저장소 정본(`docs/rules/OURGOAL_ABSOLUTE_INTEGRITY_RULES.md`)은 단 1글자의 불일치도 없이 100% 동일하게 동시 갱신되어야 한다.
3. **기계 집행의 법정·금고 소관 원칙**: 개정 조항의 기계 집행은 법정·금고 변경 절차로 올린다. 작업자가 게이트에 단언을 직접 넣지 않는다.
4. **승인 근거 기재 원칙**: 승인 근거는 작업자가 옮겨 적은 인용문이 아니라 작업자가 쓸 수 없는 기록의 주소다. 승인 근거 칸에는 그 개정을 담은 PR 의 병합 기록("PR #번호 병합 기록")을 적고, AI용 GitHub 계정이 분리된 뒤(2단)에는 상민님 계정의 승인 리뷰 id 를 함께 적는다. 상민님 말씀의 인용은 참고로만 붙이며 근거가 아니다. 개정의 효력은 그 PR 이 원격 main 에 병합된 때 발생한다(헌법 제14조 제8항 3호). 마지막 행의 근거 칸에 PR 번호가 없으면 `node court/appendix.js --check` 가 실패로 알린다. 이 원칙은 `v2026.09.21-VERDICT-SEPARATION` 행부터 적용하며 그 전의 행에는 소급하지 않는다(그 전의 행은 승인 근거를 지어내지 않고 '기재 없음(자기 기재)'으로 둔다).
