# 피드백 SLA 런북 — 치명 버그 24시간 (#T014)

> 로드맵 T014 · 단계 D0~2 지인 배포 · 제정 2026-09-21
> 피드백 DB: 노션 「아워골 고객 문의 및 오류 제보 원장」 https://app.notion.com/p/3dd598db9096816e8875c602c34d251f
> 도구: `node scripts/feedback-sla.js` (토큰은 환경변수 `NOTION_TOKEN` 또는 `FEEDBACK_SLA_ENV_FILE=<.env 경로>`)

## 1. 신고가 들어오는 길

| 경로 | 누가 원장에 넣나 | 접수 경로 값 |
| :--- | :--- | :--- |
| 앱 설정·푸터 「1:1 문의 / 오류 제보」 모달 | `/api/inquiry` 가 자동 입력 + 텔레그램 알림 | 비어 있음(분류할 때 `인앱`으로 채운다) |
| 오픈채팅 | 세션이 `add` 로 입력 | `오픈채팅` |
| 카카오톡 1:1 | 세션이 `add` 로 입력 | `카카오톡` |

오픈채팅·카톡 신고는 상민님이 세션에 그대로 붙여 주면 세션이 입력한다. **닉네임만 적는다.** 실명·전화번호·카톡 ID 는 원장에 넣지 않는다(개인정보 수집을 넓히지 않는다).

```
node scripts/feedback-sla.js add --type 버그 --channel 오픈채팅 --nick 닉네임 --content "체크인 저장을 누르면 화면이 멈춰요" --severity 상 --repro 항상 --received 2026-09-21T09:30:00+09:00
```

`--received` 는 **신고자가 말한 시각**이다. 입력한 시각이 아니다. SLA 시계는 신고 시각부터 돈다.

## 2. 분류 기준

**유형**: 버그(`버그/오류 제보`) · UX(`UX 불편`) · 요청(`새로운 기능 제안`) · 칭찬(`칭찬`). 그 외 기존 옵션(계정/보안, 기타, 앱 평가, 잇템 신고)은 API 가 쓰므로 그대로 둔다.

**심각도**

| 값 | 기준 | 처리 |
| :--- | :--- | :--- |
| 상 | 가입·로그인·체크인 저장이 **안 된다**. 기록이 사라진다. 앱이 열리지 않는다 | **접수 후 24시간 안에 수정 배포** |
| 중 | 핵심 흐름은 되지만 기능 하나가 틀리게 동작한다 | 주간 배치(매주 월요일 묶어서) |
| 하 | 문구·정렬·사소한 불편, 제안, 칭찬 | 주간 배치에서 검토 |

**재현성**: 항상 · 가끔 · 1회 · 미확인. 세션이 같은 절차로 재현해 본 결과를 적는다. 재현을 안 해 봤으면 `미확인`이다.

```
node scripts/feedback-sla.js triage <pageId> --severity 상 --repro 항상
```

분류는 접수 후 **12시간 안**에 한다. 분류 안 된 행은 SLA 시계가 보이지 않는다 — `check` 가 12시간 넘은 미분류 건수를 따로 센다.

## 3. 심각도 상 — 24시간 절차

1. `triage --severity 상` 으로 시계를 켠다. SLA 판정이 `진행중`이 된다.
2. 재현 → 원인 → 수정. 아워골 헌법의 핫픽스 절차(티켓·REQ/PLAN·`npm test`)를 그대로 따른다. 24시간은 절차를 건너뛸 이유가 아니다.
3. 운영 배포가 끝나고 실서버에서 고쳐진 것을 확인한 뒤 기록한다. `--link` 없이는 기록되지 않는다.
   ```
   node scripts/feedback-sla.js resolve <pageId> --link https://github.com/yangsangmin/ourgoal-app/pull/<번호>
   ```
   수정 배포일시가 들어가면 노션 수식이 `리드타임(시간)` 과 `SLA 판정`(준수 / 위반)을 계산한다.
4. 신고자에게 개인 답장(아래 5절). 보낸 뒤 `replied <pageId>`.

24시간 안에 못 고칠 것 같으면 **12시간 시점에** 상민님께 알린다: 무엇이 막혔는지, 임시 우회(기능 잠금·이전 버전 되돌리기)가 가능한지.

## 4. 점검

```
node scripts/feedback-sla.js check          사람이 읽는 요약. SLA 위반(미수정)이 있으면 종료코드 1
node scripts/feedback-sla.js check --json   기계가 읽는 요약
```

지인 배포 기간에는 세션이 아워골 작업을 시작할 때마다 한 번 돌린다. 출력 항목: 미분류, 심각도 상 남은 시간, 위반 건수, 답장 필요, 리드타임 건수·중앙값·최대. 수정 배포 기록이 0건이면 리드타임은 `측정불가` 로 나온다(0시간이 아니다).

## 5. "고쳤어요" 답장

답장은 **상민님이 직접 보낸다**(바깥으로 나가는 말이다). 세션은 문안을 준비한다.

> ○○님, 어제 알려주신 "체크인 저장이 멈추는 문제" 방금 고쳐서 올렸어요. 앱을 한 번 껐다 켜면 반영됩니다. 덕분에 다른 분들은 같은 문제를 안 겪게 됐어요. 고맙습니다!

규칙: 무엇을 고쳤는지 신고자의 말로 한 줄 · 반영 방법 한 줄 · 고맙다는 말. 고치지 않기로 한 건은 이유를 한 줄로 정직하게 적는다.

## 6. 하지 않는 것

- Usersnap 등 외부 위젯은 쓰지 않는다. 인앱 모달이 같은 역할을 하고, 화면 캡처를 제3자에게 보내는 것은 개인정보 수집 확대라 상민님 결심 사항이다.
- 원장의 기존 속성명·옵션명을 바꾸지 않는다(`/api/inquiry` 가 그 이름으로 쓴다). 추가만 한다.
- 수정 링크 없이 "고쳤다"고 기록하지 않는다.
