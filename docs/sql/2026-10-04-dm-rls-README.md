| :-- | :-- | :-- |

## 1단계 (오늘, 먼저)

1. 브라우저에서 https://supabase.com/dashboard 에 로그인한다.
2. 아워골 프로젝트를 누른다.
3. 왼쪽 메뉴에서 **SQL Editor** 를 누른다.
4. 오른쪽 위 **+ New query** 를 누른다.
5. `2026-10-04-dm-rls-check.sql` 의 **[사전-1]** 블록(첫 select 문)만 붙여넣고 **Run** → 나온 표를 캡처해 둔다(지금 정책 기록).
6. 같은 창을 비우고 **[사전-2]** 블록을 붙여넣고 **Run** → `rls_켜짐` 이 두 줄 다 `true` 인지 본다. `false` 가 있으면 멈추고 세션에 알린다.
7. 창을 비우고 `2026-10-04-dm-rls-step1.sql` **전체**를 붙여넣고 **Run**.
8. 맨 아래 결과가 `anon 으로 보이는 행 수` **0, 0** 이고 `es347 1단계 정책 수` **2** 면 성공.
9. 앱 확인(카카오 로그인한 폰/PC): 소통 탭 → DM 목록·대화 열림, 피드 댓글 보임, 마니또 화면 열림, 팀 채팅 열림.
   - 이상하면 `2026-10-04-dm-rls-step1-rollback.sql` 전체를 붙여넣고 **Run** → 원래대로.

알아 둘 영향: 로그인 세션이 없는 입장(게스트, 구글 직접 로그인, "빠른 계정 복구" 입장, 테스터 B 직통 입장)은 이 두 표를 더는 못 읽는다(DM·피드 댓글·마니또·팀 채팅이 비어 보임). 이들은 이미 피드 글(feed_posts)도 못 읽는 상태다. 몇 명인지는 [사전-4] 로 잴 수 있다(건수만 나옴).

## 2단계 (1단계 뒤 앱이 정상인 것을 확인한 다음)

1. SQL Editor → **+ New query** → `2026-10-04-dm-rls-check.sql` 의 **[사전-5]** 를 Run(행 종류별 건수 기록).
2. 창을 비우고 `2026-10-04-dm-rls-step2.sql` **전체**를 붙여넣고 **Run**.
3. 결과에서 정책 수 `team_ping_replies 5`, `team_pings 5`, anon 행 수 **0, 0** 을 확인.
4. **[사후-2]** 를 Run → 나온 첫 줄의 `sender_id` 를 A, `receiver_id` 를 C 로 정하고, B 는 그 둘이 아닌 다른 로그인 계정 id 로 정한다.
5. **[사후-3]** 의 `<A_ID>`·`<B_ID>`·`<C_ID>` 를 그 id 로 바꿔 Run →
   - A 가 보는 A-C DM ≥ 1, B 가 보는 A-C DM **0**, B 가 보는 A-C 대화방 부모 행 **0**
   - 피드 댓글·마니또 풀 수가 A·B 모두 같다
6. 앱 확인(실제 계정 2개): A 가 C 에게 DM → C 화면에 도착·읽음 표시, 피드 댓글 쓰기·지우기, 마니또 참여·응원, 팀 채팅 보내기.
   - 이상하면 `2026-10-04-dm-rls-step2-rollback.sql` 전체 Run → 1단계 직후 상태로 돌아간다.

2단계가 더 막는 것: 세션 없는 입장(게스트 등)의 **쓰기**(팀 채팅·체크인 인증·댓글 서버 저장)도 실패한다(화면에는 그 기기에만 남음). 남의 이름(sender_id)으로 DM·댓글을 써 넣는 위조를 막기 위해서다.
