> **기준 화면**: 양비스 「아워골 지휘실」(이 PC 의 로컬 화면). 2026-10-09 기준 실제 화면 코드와, 준비 담당이 같은 날 18:33(KST) 에 운영 화면을 읽기 전용으로 관측한 기록을 근거로 썼습니다. 화면 코드가 바뀌면 문구가 달라질 수 있습니다.

## 0. 화면 한눈에 보기

- **왼쪽 세로 메뉴 5개**: 「아워골 지휘」 · 「작업 흐름」 · 「작업 상세」 · 「세포 연결」 · 「지식 · 개선」. 맨 아래에 「새 지시 쓰기 ↗」 단추와 「기존 관측 화면 ↗」 링크가 있습니다.
- **위쪽 띠**: 연결 표시(「연결 확인 중」 → 「작업 자료 연결」, 문제가 있으면 「연결 확인 필요」)와 ↻ 「최신 상태 불러오기」 단추. 화면은 창이 보이는 동안 20초마다 스스로 새로 읽습니다.
- **아래 지시창**: 「양비스에게 말하세요」. 여기서 모든 지시·질문이 시작됩니다.
- **작업 상세 창**: 작업 하나를 누르면 뜹니다. 머리에 「아워골 / 작업번호 · 개정 N」, 상태 배지, 「담당 …」, 「관측 …」가 있고, 탭이 넷입니다: 「작업」 · 「설정 · 선택」 · 「검증 · 결과」 · 「변경 기록」. 닫기는 × 또는 창 바깥 누르기.
- **맨 아래**: 「관측 (시각)」. 이 시각이 화면 전체 값의 기준입니다. 「관측 시각 미확인」이면 아직 읽어 오지 못한 것입니다.
- **「보관 기록 · 읽기 전용」 알림이 보이면** 옛 시점의 보관 화면입니다. 지시·선택·제어 단추가 모두 꺼져 있으며, 새 지시는 기본 지휘실에서 합니다.
- 연결이 끊기면 위에 「지휘: …」 「작업: …」처럼 어느 자료를 못 읽었는지와 「다시 연결 ↻」 단추가 보이고, 마지막으로 읽은 자료는 그대로 남습니다. 인터넷이 끊기면 「네트워크 연결이 끊겼습니다. 작성 중인 지시를 유지합니다.」가 뜹니다.

**읽는 원칙 세 가지**
1. 화면의 값은 모두 **관측값**입니다. 「미확인」은 미확인이지 "아마 이럴 것"이 아닙니다. 양비스는 진행률·예상 시각을 추정해 채우지 않습니다.
2. **요청한 것**과 **실제로 확인된 것**은 다른 칸에 있습니다. 같은 값처럼 보여도 칸이 다르면 뜻이 다릅니다.
3. 한 작업은 「접수 → 설정 확인 → 실행 조건 확인 → 실행 → 실행 종료 → 결과 검증 → 작업 완료 → 정본 동기화」를 **각각 따로** 확인받습니다. 앞 단계가 됐다고 뒤 단계를 미루어 믿지 않습니다.

## 1단계. 지시하기

### 어디를 누르나
1. 왼쪽 맨 아래 「새 지시 쓰기 ↗」를 누르거나, 화면 아래 「양비스에게 말하세요」 칸을 바로 누릅니다.
2. 칸 아래 **지시 방식** 세 단추 가운데 하나를 고릅니다(기본은 「실행 지시」).
   - 「실행 지시」 — 실제로 일을 시킵니다. 누르면 안내 문구가 「실행 지시는 접수 후 실행 조건을 확인합니다.」로 바뀝니다.
   - 「상태 질문」 — 지금 어떤지 묻기만 합니다. 안내 문구: 「상태를 묻습니다. 실행 지시를 보내지 않습니다.」
   - 「계획만」 — 어떻게 할지 계획만 받습니다. 안내 문구: 「계획만 요청합니다. 실행 지시를 보내지 않습니다.」
3. 「도구 선택 ⌄」을 열면 첫 칸이 「지시할 대상」입니다. 「아워골」이 기본이고, 양비스 자체 운영을 시킬 때만 「양비스 · 아워골 지원」으로 바꿉니다. 아워골 일이면 손대지 않아도 됩니다.
4. 지시를 한국어로 적고 「지시 보내기 ↗」를 누릅니다(칸 안에서 Ctrl+Enter 도 됩니다).

### 무엇을 읽나
- 빈 채로 보내면 「지시나 질문을 먼저 적어주세요.」가 뜨고 칸으로 돌아갑니다.
- 보내는 동안 단추 글자가 「접수 확인 중…」으로 바뀌고 안내는 「지시를 저장하고 접수 응답을 기다립니다.」입니다.
- 접수되면 방식에 따라 안내가 바뀝니다.
  - 실행 지시: 「지시가 접수됐습니다. 실제 실행은 설정과 실행 조건 확인 후 시작합니다.」
  - 상태 질문: 「상태 질문이 접수됐습니다. 작업 실행은 요청하지 않았습니다.」
  - 계획만: 「계획 요청이 접수됐습니다. 작업 실행은 요청하지 않았습니다.」
  - 함께 작은 알림 「접수 기록을 저장했습니다.」가 뜨고, 새 작업의 상세 창이 저절로 열립니다.
- 실패하면 오류 문구 뒤에 「작성한 지시와 요청 번호를 유지합니다.」가 붙습니다. 적은 글은 지워지지 않고, 같은 내용으로 다시 보내면 같은 요청 번호로 보내서 두 번 접수되지 않게 합니다. 「응답 시간이 초과됐습니다…」가 뜨면 먼저 「작업 상세」 목록에서 접수됐는지 확인한 뒤 다시 보냅니다.

### 어떤 확인을 기다리나
- 상세 창 머리의 **작업번호**(예: TASK-ES-6xx)와 「개정 N」을 봅니다. 이 번호로 이후 모든 기록을 찾습니다.
- 「작업」 탭의 **「다음 행동」** 상자를 읽습니다. 양비스가 지금 무엇을 기다리는지가 한 줄로 적혀 있습니다.
- 상태 배지는 「설정 선택 대기」 → 「실행 대기」 → 「실행 조건 확인」 → 「실행 중」 순서로 바뀔 수 있습니다. **접수와 실행 시작은 별개**입니다. 접수는 "지시가 저장됐다"는 뜻이고, 실행이 시작된 것은 「변경 기록」 탭에 「실행 시작」·「담당 실행 관측」 사건이 남고 「작업」 탭 「실행 관측」 칸에 시작 시각이 보일 때입니다.
- 상태 질문·계획만으로 보냈으면 「작업」 탭에 「양비스의 답변」 또는 「양비스의 계획」 섹션이 생깁니다. 아직이면 「답변 확인」 아래 「아직 확인된 답변이 없습니다.」가 보입니다. 답변 아래의 「현재 지시 개정의 답변입니다. 실제 작업 실행 결과와 구분합니다.」는 "답변일 뿐 실행 결과가 아니다"라는 뜻입니다.

### 꼭 알아둘 것
- **아워골 대상**: 「지시할 대상」이 「아워골」이면 아워골 작업으로 접수됩니다. 「양비스 · 아워골 지원」은 양비스 운영 작업입니다.
- **세 방식의 차이**: 「실행 지시」만 실제 작업을 만듭니다. 「상태 질문」은 답변을, 「계획만」은 계획을 돌려받습니다.
- **질문과 계획은 실제로 실행하지 않습니다.** 두 방식 모두 "실행 지시를 보내지 않습니다"가 화면에 적혀 있고, 접수 안내에도 "작업 실행은 요청하지 않았습니다"가 붙습니다. 그래서 이 작업에는 보류·중단·재개 단추가 꺼져 있고 그 이유로 「상태 질문·계획만 요청은 실행하지 않으므로 중단·재개가 없습니다.」가 적힙니다.
- **접수와 실행 시작은 별개입니다.** 「접수 기록을 저장했습니다.」는 저장 알림입니다. 실행 시작은 「변경 기록」의 사건과 「실행 관측」의 시작 시각으로 확인합니다.
- **작업번호와 다음 행동**을 먼저 확인하고 다른 화면으로 넘어갑니다.

## 2단계. 도구·모델·노력 선택

양비스가 일을 시킬 **실행 도구**(예: Claude Code · Codex · Antigravity), 그 도구의 **모델**, 그리고 **노력 설정**을 고르는 단계입니다. 두 곳에서 할 수 있습니다.

### (가) 보내기 전에 고르기 — 지시창 「도구 선택 ⌄」
1. 「도구 선택 ⌄」을 누르면 「지시할 대상」 · 「실행 도구」 · 「모델」 · 「노력 설정」 네 칸이 펼쳐집니다.
2. 「실행 도구」(첫 줄은 「선택 후 확인」)를 고르면 「모델」 칸이 열립니다. 도구를 고르기 전에는 「도구를 먼저 선택」, 고른 뒤에는 「모델 선택」이라고 적혀 있습니다.
3. 「모델」을 고르면 「노력 설정」 칸이 열립니다(「모델을 먼저 선택」 → 「설정 선택」). 그 모델에 노력 설정이 없으면 「지원 설정 없음」입니다.
4. 회색으로 흐린 항목은 고를 수 없습니다. 이름 뒤에 「· 미지원」 또는 「· 지원 미확인」이 붙어 있습니다.
5. 도구를 바꾸면 모델·노력이 비워지고, 모델을 바꾸면 노력이 비워집니다. 다시 고르면 됩니다.
6. 칸 아래 설명: 「확인된 도구와 설정만 선택할 수 있습니다. 선택하지 않으면 접수 후 설정을 확인합니다. 노력 설정은 내부에서 얼마나 생각했는지에 대한 측정이 아닙니다.」 도구 근거가 하나도 없으면 「실행 도구의 지원 근거가 아직 없습니다. 지시를 먼저 접수하고 설정 확인을 기다립니다.」가 대신 보입니다.
7. 아무것도 고르지 않고 보내도 됩니다. 그러면 접수 뒤 (나) 에서 고릅니다.

### (나) 접수 뒤에 고르기 — 작업 상세 창 「설정 · 선택」 탭
- 맨 위 표 **「요청한 설정과 실제 설정」**: 칸이 「설정」 · 「요청」 · 「실제 근거」 셋입니다. 줄은 「실행 도구」 · 「모델」 · 「노력 설정」. 값이 없으면 「미확인」으로 적힙니다. 표 아래에 「실제 설정 관측 (시각). 노력 설정은 실행기에 전달된 설정이며 내부 사고량의 측정이 아닙니다.」와, 있으면 「설정 근거 열기 ↗」 링크가 있습니다.
- 양비스가 설정을 물어볼 때는 **「실행 설정을 선택해주세요」** 상자가 보입니다. 「현재 작업의 선택 질문에 답합니다. 요청한 설정의 지원 확인이 끝나야 실행으로 넘어갑니다.」 아래에 권장 설정 근거(없으면 「이 작업에 대한 권장 설정 근거는 아직 없습니다.」), 그리고 (가)와 같은 세 칸과 「이 설정으로 선택」 단추가 있습니다. 물어볼 것이 없으면 「현재 답할 설정 선택 질문이 없습니다.」만 보입니다.
- 그 아래 **「도구별 확인된 지원」** 표: 도구 이름, 지원 확인에 쓴 「출처 문서 ↗」, 「지원 확인」 · 「미지원」 · 「지원 미확인」 가운데 하나, 확인한 시각, 그 도구에서 확인된 모델 이름표.

### 어떤 확인을 기다리나
- 「이 설정으로 선택」을 누르면 「선택 저장과 개정 확인 중…」이 보였다가, 되면 알림 「설정을 선택했습니다. 실제 실행 조건을 확인합니다.」가 뜹니다.
- 확인되지 않은 도구·모델을 고르면 「지원이 확인된 실행 도구와 모델을 선택해주세요.」가 뜨고 저장되지 않습니다. 확인된 도구가 하나도 없으면 단추가 꺼지고 「지원이 확인된 실행 도구가 없어 선택할 수 없습니다.」가 적힙니다.
- 선택 뒤에는 상태 배지가 「실행 조건 확인」 · 「실행 대기」 등으로 바뀌는지, 「변경 기록」에 「설정 선택」 또는 「설정 선택 확인」 사건이 남는지 봅니다. 「막힌 이유」가 생기면 그 문구를 읽습니다. 예: 「다른 작업들이 실행 자리를 사용 중입니다. 사용하지 않는 작업창을 닫거나 해당 작업이 끝나면 재개할 수 있습니다」.

### 꼭 알아둘 것
- **지원 확인 · 미지원 · 지원 미확인의 뜻**: 「지원 확인」은 그 도구의 공식 도움말·설정 문서로 "이 모델·노력 값을 전달할 수 있다"가 확인됐다는 뜻입니다. **실제로 실행에 성공했다는 뜻이 아닙니다.** 준비 당시 기록에서 확인된 모델들은 모두 "실행 성공 확인 아니오", "계정에서 그 모델을 쓸 수 있는지 미확인"이었습니다. 「미지원」은 전달할 수 없음이 확인된 것, 「지원 미확인」은 아직 근거가 없는 것입니다.
- **요청(requested) · 전달 설정(configured) · 실제 근거(actual)의 구분**: 요청은 상민님이 고른 값, 전달 설정은 양비스가 실행기를 띄울 때 넘긴 값, 실제 근거는 실행 중이나 실행 뒤에 관측된 값입니다.
- **화면의 비교표는 「요청」과 「실제 근거」 두 칸뿐입니다.** 전달 설정은 별도 칸이 아니라 「실제 근거」와 「설정 근거 열기」 링크로 읽는 개념입니다. 세 번째 칸이 있는 것처럼 상상해 읽지 않습니다.
- **「실제 근거」의 「미확인」을 요청값으로 채워 읽지 않습니다.** 준비 당시 관측에서 한 작업은 요청 노력이 high 인데 실제 근거 노력은 미확인이었고, 다른 작업은 실제 모델·노력이 모두 미확인이었습니다. 미확인은 "실행기가 그 값을 썼다는 근거가 없다"는 뜻 그대로입니다.
- **노력 설정은 전달 설정입니다.** 실행기에 넘기는 설정값이지, 실제로 얼마나 깊이 생각했는지를 잰 값이 아닙니다. 화면에도 「내부 사고량의 측정이 아닙니다」라고 적혀 있습니다.
- **선택 저장 뒤에도 실행 조건 확인이 남아 있습니다.** 「설정을 선택했습니다. 실제 실행 조건을 확인합니다.」가 그 뜻입니다. 실행 자리가 없으면 「막힌 이유」에 나타납니다.
- **비용**: 기존 구독 범위 안에서만 실행합니다. 추가 API 과금, 새 사용량 구매, 추가 사용량(extra usage) 설정 변경은 허용되지 않았고 이 화면에서 하지 않습니다. 잔여 사용량과 비용은 측정하지 않았으므로 미확인입니다.

## 3단계. 진행과 다음 행동 읽기

### 어디를 보나
- **「아워골 지휘」**(첫 화면): 지금 먼저 볼 작업 하나와 이어지는 행동.
- **「작업 흐름」**: 작업마다 실제로 남은 사건을 시간순으로.
- **「작업 상세」**: 전체 작업 목록과 검색·거르기.
- **작업 상세 창 「작업」 탭**: 한 작업의 다음 행동·막힌 이유·실행 관측.

### 「아워골 지휘」에서 읽는 것
- 머리 오른쪽에 「마지막 관측 (시각)」과 「확인되지 않은 진행률·예상 시각은 추정하지 않습니다.」가 늘 있습니다.
- 큰 상자가 **먼저 볼 작업**입니다. 상자 위 작은 글이 왜 먼저인지 말합니다: 「선택하면 다음으로」(설정 선택 대기) · 「풀어야 할 막힘」(막힘) · 「중단을 확인하는 중」 · 「결과를 확인할 차례」(결과 검증 대기) · 「지금 진행하는 일」(실행 중) · 그 밖에는 「먼저 볼 작업」.
- 상자 안: 제목, 막힌 이유(없으면 목표), 상태 배지, 대상, 「담당 …」, 「예상 종료 …」(근거가 없으면 「미확인」), 다음 행동 한 줄, ↗(상세 열기).
- 오른쪽 「이어지는 행동」: 다음 작업 최대 3개의 다음 행동. 없으면 「추가로 관측된 다음 작업이 없습니다.」
- 「필수 가동 조건: …」 띠: PC 가동·실행 조건. 측정이 없으면 「현재 조건 측정 미확인」이 덧붙습니다.
- 「진행과 결과」 표(최근 3개, 「전체 작업 보기 →」): 칸은 「작업 / 다음 행동」 · 「현재 상태」 · 「실제 도구 · 모델」 · 「관측 시각」. 「실제 도구 · 모델」은 요청이 아니라 실제 근거 칸의 값입니다.

### 「담당」을 읽는 법
- 「Claude Code · 세션 1a2b3c4d… · 실행 종료 확인」처럼 **도구 이름 · 세션 앞 8자 · 실행 관측 상태** 세 토막입니다. 상태 토막은 「실행 관측 중」 · 「실행 종료 확인」 · 「실행 상태 미확인」 중 하나입니다. 아무 기록이 없으면 「미확인」입니다.

### 「작업 흐름」에서 읽는 것
- 머리글 「EVENTS, NOT ESTIMATES — 일이 흘러온 길.」 아래 범례: 「기록된 사건」 · 「대기 · 요청」 · 「실패」 · 「병렬·선후 관계는 기록된 연결만 표시」.
- 작업마다 카드: 제목, 작업번호 · 「담당 …」, 상태 배지, 그리고 사건 줄. 사건 이름은 「지시 접수」 · 「지시 접수·보관」 · 「설정 선택」 · 「설정 선택 확인」 · 「실행 담당 확인」 · 「실행 시작 요청」 · 「실행 시작」 · 「담당 실행 관측」 · 「실행 종료」 · 「실행 실패」 · 「결과 확인」 · 「지휘 변경 접수」 · 「실행 조건 확인 필요」 · 「시작 확인 실패」 · 「담당 확인 필요」 · 「이전 실행 기록 보존」 · 「수신 공백·현재 지시 확인」 · 「권장 설정 확인」 · 「답변·계획 확인」 · 「지휘 개정 충돌 확인」 · 「설계 검토 확인」 · 「독립 검증 단계」 · 「후속 담당에게 이관」 같은 쉬운 말입니다.
- 「담당 실행 관측」이 연달아 있으면 「실행 관측 N회 · 마지막 확인」으로 묶여 보입니다.
- 실패 사건은 빨간 표시, 대기·요청 사건은 다른 색입니다. **재시도**가 있었는지는 같은 종류의 사건이 다시 나타나는지로 읽습니다(예: 「시작 확인 실패」 뒤에 다시 「실행 시작 요청」). 화면은 기록된 사건만 보여 주고 추정하지 않습니다.
- 「선행 작업 …」 · 「병렬 연결 …」 줄은 기록된 연결이 있을 때만 보입니다. 사건이 하나도 없으면 「이 작업의 실제 단계 사건이 아직 관측되지 않았습니다.」입니다.

### 「작업 상세」에서 읽는 것
- 거르기 단추: 「전체」 · 「확인 필요」(막힘 · 설정 선택 대기 · 중단/보류 요청 · 결과 검증 대기 · 실행 실패) · 「진행 · 대기」 · 「작업 완료」 · 「양비스 운영」. 검색 칸은 「제목이나 지시 원문으로 찾기」.
- 아래 띠: 「완료된 작업과 정본 동기화 상태를 각각 표시합니다. 실행 종료만으로 작업 완료를 선언하지 않습니다.」

### 작업 상세 창 「작업」 탭에서 읽는 것(위에서 아래 순서)
1. (보류·중단을 요청했으면) 그 요청이 아직 확인 전이라는 알림.
2. **「다음 행동」** 상자.
3. **「막힌 이유」** — 있을 때만. 양비스가 쉬운 말로 바꿔 적습니다.
4. 「처음 받은 지시」 — 지시 원문.
5. 「끝났다고 말할 기준」 — 목표와 완료 기준 목록. 없으면 「측정 가능한 완료 기준 미확인」.
6. **「실행 관측」** — 「실행 담당」 · 「프로세스 생존 확인」(「살아 있음 · 관측됨」 / 「종료 관측됨」 / 「미확인」) · 「시작 / 종료」 시각 · 「진행률 / 예상 종료」(「진행률 미확인」 / 「예상 종료 미확인」이 기본). 「실행 담당의 기술 근거 펼치기」로 원문을 볼 수 있습니다.
7. 「작업 지휘」 단추들(4단계).
8. 맨 아래 **정본 동기화 한 줄**(아래 참고).

### 꼭 알아둘 것
- **담당 · 막힌 이유 · 다음 행동 · 관측 시각** 네 가지를 항상 함께 읽습니다. 관측 시각이 오래됐으면 ↻ 를 누릅니다.
- **작업 흐름은 실제로 남은 사건**입니다. 병렬·선후 관계는 기록된 연결만 표시하고, 대기·실패·재시도도 가리지 않고 그대로 보여 줍니다.
- **「진행률 미확인」 · 「예상 종료 미확인」은 미확인입니다.** 양비스는 퍼센트와 예상 시각을 추정하지 않습니다. 준비 당시 관측된 작업 3개도 모두 진행률·예상 종료가 없었습니다.
- **실행 종료 · 결과 검증 대기 · 작업 완료는 다른 말입니다.** 「실행 종료」(또는 「종료 관측됨」)는 실행기가 끝났다는 관측, 「결과 검증 대기」는 산출물을 아직 확인하지 않았다는 상태, 「작업 완료」는 완료 기준이 확인됐다는 상태입니다. 「자동화 종료 · 제품 미확인」과 「기존 완료 보고 · 검증 미확인」도 완료가 아닙니다.
- **작업 완료와 정본 동기화는 별개입니다.** 맨 아래 한 줄이 「정본 동기화 대기 · 작업 상태와 별도로 확인합니다.」이면 노션·지도 같은 정본에 아직 반영 확인이 없는 것입니다. 「정본 동기화 확인 · (시각)」 또는 「정본 되읽기 기록 · (시각)」이 되어야 반영이 확인된 것이고, 「정본 동기화 미확인」은 기록이 없는 것입니다.

## 4단계. 보류·중단·재개·지시 변경

### 어디를 누르나
- 작업 상세 창 「작업」 탭 맨 아래 **「작업 지휘」** 묶음: 「보류 요청」 · 「중단 요청」(빨간 테두리) · 「재개 요청」 · 「지시 변경」.
- 꺼진 단추에 마우스를 올리면 「현재 상태에서 지원하지 않는 제어입니다.」가 뜹니다. 단추 아래 한 줄이 왜 꺼졌는지 말합니다.

### 언제 켜지나(화면 코드의 규칙을 쉬운 말로)
- **공통 조건**: 「작업 완료」가 아니고, 「기존 정본을 읽는 작업」(옛 기록을 읽기만 하는 작업)이 아니고, 머리에 「개정 N」 번호가 있어야 합니다. 보관 기록 화면에서는 모두 꺼집니다.
- **「지시 변경」**: 공통 조건만 맞으면 언제나 켜집니다. 상태 질문·계획만 작업에서도 됩니다.
- **「보류 요청」 · 「중단 요청」**: 상태 질문·계획만 작업에서는 꺼집니다. 이미 「보류 확인」 · 「중단 확인」 · 「보류 요청 · 확인 전」 · 「중단 요청 · 확인 전」이면 꺼집니다. 그 밖에는 실행이 살아 있을 때(종료 시각이 없을 때), 또는 상태가 「실행 대기」 · 「설정 선택 대기」 · 「막힘」 · 「실행 조건 확인」일 때 켜집니다. 실행이 이미 끝난 「결과 검증 대기」 작업에서는 꺼집니다.
- **「재개 요청」**: 상태가 「보류 확인」 · 「중단 확인」 · 「막힘」일 때만 켜집니다.
- 준비 당시 관측(2026-10-09 18:33 KST): 실행이 끝난 「결과 검증 대기」 작업에서 보류·중단·재개는 꺼져 있고 「지시 변경」만 켜져 있었습니다. 위 규칙과 같습니다.

### 단추 아래 이유 문구 다섯 가지
- 「기존 정본을 읽는 작업입니다. 현재 실행을 제어하는 작업이 아니므로 제어할 수 없습니다.」
- 「개정 번호가 확인되지 않아 제어할 수 없습니다.」
- 「완료된 작업은 제어할 수 없습니다. 후속 지시는 새 작업으로 접수합니다.」
- 「상태 질문·계획만 요청은 실행하지 않으므로 중단·재개가 없습니다.」
- 「실행이 없거나 해당 상태에서 허용되지 않는 제어는 비활성화됩니다. 요청과 실제 확인은 구분됩니다.」

### 누르면 무엇이 보이나
- 누르는 즉시 단추 아래에 「요청 저장과 상태 확인 중…」이 보입니다.
- **보류 요청**: 알림 「보류 요청을 접수했습니다. 실제 확인을 기다립니다.」 → 상태 배지 「보류 요청 · 확인 전」 → 「작업」 탭 맨 위 「보류를 요청했습니다. 실행이 멈췄다는 근거는 아직 확인되지 않았습니다.」 → 확인되면 배지가 「보류 확인」으로.
- **중단 요청**: 알림 「중단 요청을 접수했습니다. 실제 종료 확인은 작업 상태에서 읽습니다.」 → 배지 「중단 요청 · 확인 전」 → 「작업」 탭 맨 위 「중단을 요청했습니다. 실제 실행 종료는 아직 확인되지 않았습니다. 이미 반영된 결과와 기록은 보존됩니다.」 → 확인되면 「중단 확인」.
- **재개 요청**: 알림 「변경 요청을 접수했습니다.」(지시 변경과 같은 알림). 그다음 상태는 양비스가 다시 확인해 정합니다. 배지 · 「막힌 이유」 · 「변경 기록」을 다시 읽습니다.
- **지시 변경**: 단추를 누르면 「변경할 지시」 칸과 「변경 접수」 단추가 펼쳐집니다. 빈 채로 누르면 「변경할 지시를 적어주세요.」, 되면 「변경 요청을 접수했습니다.」가 뜨고 칸이 닫힙니다. 그 뒤 머리의 「개정 N」과 「변경 기록」을 다시 읽어 어느 지시가 최신인지 확인합니다.
- 세 요청 모두 「변경 기록」에 「지휘 변경 접수」 사건으로 남습니다.
- 실패하면 단추 아래 빨간 글로 오류 문구와 「상태를 다시 읽어 확인해주세요.」가 보입니다.

### 꼭 알아둘 것
- **보류 요청과 보류 확인은 다릅니다.** 「보류 요청 · 확인 전」은 부탁을 저장한 것이고, 「보류 확인」이 되어야 실제로 멈춘 근거가 있는 것입니다.
- **중단 요청과 중단 확인도 다릅니다.** 「중단 요청 · 확인 전」에서 「중단 확인」이 될 때까지 실행기가 아직 돌고 있을 수 있습니다.

## 6단계. 법정과 완료 확인

### 어디를 보나

### 근거의 네 가지 종류를 구분하기
1. **작업자 측정** — 일을 한 세션이 스스로 남긴 측정 기록과 주장. "했다"는 말이지 판정이 아닙니다.
2. **native 수신** — 양비스가 실행기에서 받은 결과와 관측(실행 종료, 산출물 위치 등). "받았다"는 사실이지 "맞다"는 판정이 아닙니다.
3. **독립 검토** — 작업자와 다른 세션이 결과 근거를 따로 본 기록. 「변경 기록」에 「독립 검증 단계 — 실행 담당과 별도로 결과 근거를 확인합니다」로 남습니다. 의견이지 판정이 아닙니다.
4. **GitHub Court(법정)** — 작업자가 손댈 수 없는 GitHub 에서 돌아가는 독립 판정. **정본은 법정 실행이 남긴 artifact(court-verdict 의 verdict.json)에 적힌 verdict(판정) · verdictId · head(심사한 커밋)와 그 실행 링크**입니다. PR 댓글이 늦거나 빠져도 artifact 가 정본입니다. 판정은 「통과」 · 「확인 부족」 · 「돌려보냄」 · 「심사 못 함」 넷 중 하나이고, 「확인 부족」은 통과가 아닙니다.

### 어떤 확인을 기다리나
- 「검증과 결과」 목록에서 각 줄의 제목 · 요약 · 링크를 보고 위 넷 중 어느 종류인지 가립니다. 법정 줄이면 링크로 들어가 **head 가 그 PR 의 최신 커밋과 같은지** 봅니다. 다르면 옛 커밋의 판정입니다.
- 상태 배지가 「결과 검증 대기」에서 「작업 완료」로 바뀌는지 봅니다. 「작업 완료」는 완료 기준이 확인됐다는 양비스 기록입니다.
- 그다음 **배포(운영 반영) · 원격 검증(실서버·실계정 확인) · 지도 동기화(세포지도·노션 정본)** 는 각각 따로 확인합니다. 맨 아래 정본 동기화 한 줄이 「정본 동기화 확인 · (시각)」이 되어야 지도·정본 반영이 확인된 것입니다.

### 꼭 알아둘 것
