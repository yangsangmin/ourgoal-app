## 1. 왜 새 방식이 필요한가

`index.html` 인라인 IIFE(미분화 덩어리) 4,147줄을 줄 종류별로 나눴다. 그 결과 생성기로 **옮길 수 있는 함수 본문은 1,398줄(34%)뿐**이다. 나머지는 이미 옮긴 함수를 다시 이어 붙이는 **배선**이다.

| 종류 | 줄 | 지금 하는 일 |
|---|--:|---|
| 가져오기 `var x = _kit.x` (키트 17종) | 527 | 세포가 window 에 단 키트에서 이름을 IIFE 스코프로 끌어온다 |
| `OurgoalAppScope.expose('index.html', {get …})` (48회, getter 446 · setter 30) | 542 | 끌어온 이름과 IIFE 상태를 다시 `L.` 통로로 다른 세포에 내준다 |
| window 노출 (이름 199개) | 320 | 끌어온 이름을 다시 window 에 단다(마크업의 `on*="…"` 처리기·바깥 파일용) |

## 2. 방식 — 새 기관을 추가하고, 대조하고, 옛 배선을 철거한다

1. **새 기관 추가 (동작 변화 0)**
   - 각 세포가 자기 이름을 등록 기관에 **스스로** 등록한다.
   - 대조 모드에서 등록 기관은 값을 덮어쓰지 않고 기록만 한다.
2. **대조**
   - 부팅이 끝난 뒤 탐침이 옛 경로가 만든 값과 새 경로가 등록한 값을 이름마다 `===` 로 전수 비교한다.
   - 비교 범위는 `OurgoalAppScope.scope` 의 모든 이름과 window 노출 199개다.
   - 로드 중 호출은 호출 순서 기록을 나란히 비교한다.
3. **철거**
   - 불일치 0인 구역(키트 단위)부터 옛 가져오기·getter·window 줄을 지운다.
   - 지우는 일은 손으로 하지 않는다. 생성기의 「배선 철거 모드」(5절)로만 한다.

이 방식은 CELL_SPLIT(옮기기)을 바꾸지 않는다. PR 종류가 둘 늘 뿐이다: **새 기관 추가 PR**과 **배선 철거 PR**. 증명 하한은 4절에 적었다.

## 3. 구성 요소

### 3.1 등록 기관 `js/core/cell-registry.js`

```js
OurgoalCellRegistry.provide(owner, { name: value, … }, { window: ['name', …] })
OurgoalCellRegistry.mode            // 'compare'(대조) | 'own'(소유) — 이름 단위
OurgoalCellRegistry.report()        // 대조 결과: { mismatches:[{name, owner, kind}], missing:[…], extra:[…] }
```

- **compare 모드**: 등록 값만 보관한다. `OurgoalAppScope` 와 window 는 건드리지 않는다. 이중 등록·이중 처리기는 0이다. (B1 #883 · B2 #885 로 병합됨. B2 대조 결과: 등록 438 · 불일치 0 — 작업자 측정 `reports/TASK-ES-611/cell-registry-compare.json`)
- **own 모드**: 등록된 이름에 대해 `OurgoalAppScope.expose(owner, …)` 와 window 대입을 등록 기관이 직접 한다.
  - 함수 값은 getter 로 감싸지 않고 값으로 둔다.
  - 다시 대입되는 상태는 등록 기관이 아니라 상태 기관(3.3)이 맡는다.
- **own 적용 시점 — IIFE 직전 한 번(commit) [개정]**
  - 등록 기관은 세포가 `provide` 를 부르는 순간에 통로·window 에 쓰지 않는다. IIFE 바로 앞에서 한 번 적용한다.
  - 이유(조사): window 이름 199개 중 13개를 IIFE 밖 파일도 대입한다. `js/components.js`(2252행 태그, 세포들보다 뒤)가 그중 6개를 대입하고, 지금은 IIFE 가 나중에 다시 덮는다. 기관이 세포 로드 때 바로 대입하면 철거 뒤 승자가 뒤집힌다.
  - 방식: 마지막 바깥 태그와 **같은 줄**에 동기 `<script src>` 태그 하나를 붙여 그 파일이 commit 을 부른다(index.html 순증가 0 · 인라인 스크립트 추가 0 · 새 전역 0). commit 과 IIFE 사이에 다른 태그를 두지 않는다. 구체 파일 이름과 13개 이름의 재측정 표는 own 전환 PR(#TASK-ES-614)이 정한다.
- **own 전환과 철거는 PR 을 나눈다 [개정]**
  - 법정의 생성기 재실행 대조는 설정 `cells` 에 없는 `js/**`·`index.html` 변경을 「Disallowed source file changed」로 거부하고, `cells` 의 파일은 생성기 산출과 바이트 단위로 같아야 한다(`court/lib/preserve-source.js` 52~60행). unwire 모드는 세포 파일을 쓰지 않으므로 철거 PR 에서 `js/core/cell-registry.js` 는 기준과 같아야 한다.
  - 그래서 own 전환(등록된 모든 이름을 기관이 내준다)은 철거보다 먼저 별도 PR 로 병합하고, 철거 PR 은 `index.html` 만 바꾼다. 그 사이에는 같은 값의 이중 노출이 된다.
  - 이것은 법정 코드를 읽은 해석이다. 실제 철거 PR 의 판정으로는 아직 확인하지 않았다.
- 로드 순서: 바깥 스크립트 102개는 모두 IIFE 앞에서 로드된다(측정). 예외는 `defer` 인 `/ui.js` 와 구글 GSI(`async defer`) 둘이다. 이 두 파일의 이름은 own 모드 대상에서 뺀다.

### 3.2 대조 탐침 `court` 밖, `scripts/probes/cell-registry-compare.js`

- 브라우저에서 게스트로 진입해 부팅을 끝낸 뒤 `OurgoalCellRegistry.report()` 를 받아 JSON 으로 쓴다.
- 이름마다 `oldValue === newValue` 를 본다. 함수는 참조가 같아야 하고, 상태는 getter 가 같은 값을 돌려줘야 한다.
- **로그인 경로와 무관하다.** 배선은 부팅 때 전부 놓이므로 게스트 상태에서 이름 전수 비교가 가능하다. 로그인 뒤 *동작*은 별도 주장(`unverified` `needs-login`, L045)으로 분리한다.
- **이름 목록은 철거 전 커밋에서 뽑아 고정 입력으로 준다 [개정]**
  - 탐침은 window 이름을 현재 `index.html` 에서 뽑는다(`windowNamesOf`). 철거 PR 에서는 지운 이름이 목록에서 사라져 검사 대상에서 빠진다.
  - 철거 PR 의 대조는 철거 전 커밋에서 뽑은 통로·window 이름 목록을 입력으로 받아, 지운 이름도 통로와 window 에 그대로 있는지 본다.

### 3.3 상태 기관 `js/core/app-state.js` (가칭, B9) [개정]

**대상(조사)**
- 그 밖의 var 82문은 이름 80개다. 재대입 31개 · DOM 참조 40개 · 상수·별칭 9개.
- 통로에 노출된 상태 이름 63개(getter 66줄 · setter 30개)만 기관 대상이다.

**원칙 — 맨이름 참조가 0 이 된 이름만 소유를 옮긴다**
- strict IIFE 의 맨이름을 바깥 저장소에 살아 있게 묶으려면 모든 참조를 바꿔 써야 한다(`state` 하나만 116곳 — 조사). 그것은 함수 본문을 고치는 일이라 하지 않는다.

- 조사: 지금 조건을 만족하는 노출 이름은 63개 중 55개다. 기다려야 하는 8개는 `sb` · `state` · `MOCK_GROUPS` · `pendingCapturePhoto` · `capturePhotoInput` · `capturePhotoPreview` · `USER_SESSION_CHANNEL` · `shareContent` 이고, 함수 이전·감싸기가 끝나면 풀린다.

**기관 API(손으로 쓰는 새 기관, B1 과 같은 PR 종류)**

```js
OurgoalAppState.define(name, value)      // 통로에 getter 만 달고 값을 넣는다
OurgoalAppState.defineVar(name, value)   // get/set 짝을 달고 값을 넣는다
```

- 접근자는 그 이름의 첫 define 때 한 번만 단다. 그래서 이전 PR 은 `index.html` 만 바뀐다(3.1 의 법정 제약과 같은 이유).

**생성기 `"mode": "unstate"` — 지정한 이름에 대해 (줄 종류는 5절 X4·X5·X6)**

| 기호 | 줄 종류 | 동작 |
|---|---|---|
| S1 | 그 이름의 expose getter/setter 속성 줄 | 삭제(unwire 의 getter 삭제와 같은 꼴, 대상이 상태 이름) |
| R1 | 선언문 `var X = <초기값>;` | `window.OurgoalAppState.define('X', <초기값 원문>);` 로 1:1 바꿔 쓴다. 지우기 직전 **마지막 노출 줄**에 `set X` 가 있었으면 `defineVar` |
| R2 | 자기 일회 window 복사 줄 `window.X = X;`(조사: 7줄) | 오른쪽만 `window.OurgoalAppScope.scope.X` 로 바꿔 쓴다. 자리와 시점 유지 |

- 초기값 대입이 **원래 자리에 그대로** 남는다. 그래서 `sb` 초기값 직후의 `bindSupabaseAuthStateListener()` 같은 순서가 보존된다. 초기값을 기관 파일 로드 시점으로 당기지 않는다.

### 3.4 부팅 — 연속 구역 감싸기 (B10) [개정]

새 부팅 기관을 만들어 대조하는 대신, 이미 쓰고 있는 「감싸기」 이음매(INLINE-HARD-SPLIT-DESIGN 2-3: 본문은 세포 함수로, 원래 자리에 부르는 한 줄)를 연속 구역 단위로 넓힌다.

- 근거(조사): IIFE 최상위에는 분기도 `return` 도 없다. 실행 순서가 곧 소스 순서다. 연속 구역을 순서 그대로 함수 하나로 감싸 원래 자리에서 부르면 순서가 보존되고, 법정의 바이트 대조가 그대로 걸린다.
- 로드 중 문은 99문 360줄이다(조사). 4줄 이상 17문 266줄과 함수식 window 대입 2문 61줄은 지금의 감싸기로도 옮길 수 있다(묶음 W1~W7, 6절).

**생성기 `"mode": "region"` — 구역 경계는 줄 번호가 아니라 구획 주석 제목으로 지정한다 (줄 종류는 5절 X7)**

| 기호 | 구역 안 줄 종류 | 동작 |
|---|---|---|
| M1a | 호출문 · if · try · 그 밖의 식 문(3줄 이하 포함, window 리터럴 대입 포함) | 세포 함수 본문으로 옮김. 구역 밖 IIFE 이름은 `L.` 접두 |
| M1b | 3.3 이 바꿔 쓴 `OurgoalAppState.define…` 줄 | 그대로 옮김 |
| M1c | 노출되지 않은 var 선언(모든 참조가 구역 안) | 그대로 옮겨 그 함수의 지역 변수가 됨 |
| M1d | 아직 남은 `window.X = X;` 줄 | `window.X = L.X;` 로 옮김(시점 유지) |
| M1e | 구역 안 주석·빈 줄 | 따라감 |
| – | 원래 자리 | 부르는 한 줄 + 머리에 가져오기 한 줄(기존 감싸기와 같음) |

- 구역 안에 있으면 정지: 함수 선언 · 키트 가져오기·손잡이 · expose 문 · 노출된 이름의 var 선언(3.3 이 먼저) · 구역 밖에서 참조되는 var · 최상위 `this`/`arguments`/`return` · 줄 중간에서 시작하거나 끝나는 구역.
- 예외 동작: 단계마다 try/catch 를 새로 넣지 않는다. 지금은 예외 하나가 IIFE 나머지를 중단시키고, 구역 함수도 똑같이 중단된다.

**`"mode": "sweep"` (5절 X8)** — 문이 하나도 없는 구획의 주석·빈 줄만 지운다. 함수 이전(A 트랙) 생성기가 기대는 자리 표지·구획 주석·「1차 이음매」 주석은 건드리지 않는다.

**`"mode": "finalize"` — 마지막 PR (5절 X2·X9)**
- 전제(아니면 정지): IIFE 최상위 문이 키트 손잡이, 구역 함수 가져오기, 구역 함수 호출문뿐이다.
- 하는 일:
  1. `js/app/boot.js` 를 생성한다(구역 함수를 같은 순서로 부른다).
  2. 남은 주석·빈 줄, 손잡이, 가져오기, 호출 줄을 지운다.
  3. IIFE 껍데기 3줄과 `<script>`·`</script>` 2줄을 지운다.
  4. 앞 태그 줄 끝에 `<script src="js/app/boot.js"></script>` 를 붙인다. `defer` 없이 같은 자리, 동기 태그다.

**호출 순서 대조**
- 정적: 구역 함수 본문의 문 순서 = 이전 전 줄 순서. 법정의 생성기 재실행 바이트 대조가 증명한다.
- 동적(설계안, **미검증**): 탐침이 IIFE 첫 줄(마지막 PR 뒤에는 부팅 파일 첫 줄)에 중단점을 걸고, 그때 모든 키트 객체의 함수를 `OurgoalCellRegistry.note(키트, 이름)` 기록 래퍼로 감싼 뒤 재개한다. 기준과 작업의 `report().callOrder.recorded` 를 비교한다. 제품 코드 변경은 0 이다.
- 옛 자리에 `note` 호출을 넣는 방식은 IIFE 에 줄을 더해야 하므로 쓰지 않는다.

## 5. 생성기가 다루는 줄 종류 — 닫힌 목록

법정의 「동작 보존 확인」(`court/lib/preserve-source.js` `recomputeSplit`)은 **기준 커밋의** `docs/design/harness/module-split/gen-inline-hard.js` 를 PR 의 설정으로 다시 돌린다. 그 결과가 PR 의 `index.html` 및 세포 파일과 바이트 단위로 같아야 한다. 손으로 지운 PR 은 이 대조를 통과할 수 없다.

생성기는 금고(`court/`) 밖에 있지만 법정이 이 생성기를 다시 돌린다. 모드를 더하면 「동작 보존 확인」이 받아 주는 변경의 범위가 넓어진다. 그래서 생성기가 지우거나 옮기거나 바꿔 쓰는 **줄 종류**는 상민님 결심으로만 늘린다. **이 목록 밖의 줄 종류는 다시 결심이다.**

### 5.1 처음 허용된 세 종류 — `"mode": "unwire"` (2026-10-10 결심 ⑤, DIR-003, B1 #883 구현)

```json
{ "task": "TASK-ES-6xx", "slot": "HO", "mode": "unwire",
  "cells": [{ "file": "js/core/cell-registry.js" }],
  "unwire": { "kitVar": "_settingsKit",
              "imports": true, "exposeGetters": true, "windowAssign": true,
              "names": ["…등록 기관 대조에서 불일치 0 인 이름만…"] } }
```

| 기호 | 줄 꼴 | 동작 | 정지 조건 |
|---|---|---|---|
| U1 | 지정한 키트의 가져오기 줄 `var X = _kit.X;` | 삭제 | 이름과 키트 속성이 다름 · 여러 줄 · 다른 글자와 한 줄 · 지운 줄 밖에 그 이름의 참조·대입이 남음 |
| U2 | `expose` 객체의 해당 getter/setter 속성 줄 | 삭제. 새로 마지막이 된 속성의 쉼표 한 글자와, 속성이 모두 지워진 expose 문의 껍데기 포함 | 한 줄에 여러 이름 · 여러 줄 · 머리·꼬리 줄과 한 줄 |
| U3 | `window.X = X;` 줄(오른쪽이 이름), 그런 줄만 담은 if 블록 | 삭제. 줄이 모두 지워진 블록의 껍데기 포함 | 오른쪽이 이름이 아님(정의문) · 쉼표 연쇄 · 여러 줄 · 다른 글자와 한 줄 |

- 그 밖의 글자는 바꾸지 않는다. `names` 에 없는 이름은 지우지 않는다. 함수 본문을 옮기거나 고치지 않는다.
