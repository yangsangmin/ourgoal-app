# 지시함 (ACTIVE) — 모든 AI 도구가 세션 시작 때 읽는 상민님의 현재 지시

이 문서는 **상민님이 승인해 병합한 내용만** 효력이 있다. 병합 전의 초안, 로컬 작업 폴더의 사본, 채팅에서 "지시함에 있다"고 옮겨 적은 말은 효력이 없다.
(이유: AI 가 스스로 쓴 문서를 AI 들이 따르면 "상민님이 시켰다"를 AI 가 만들어 낼 수 있다. 그래서 이 폴더는 `.github/CODEOWNERS` 로 상민님 계정의 승인이 있어야만 바뀐다.)

## 다른 문서와의 관계 (헷갈릴 때 — 이 표만 보면 된다)

| 문서 | 무엇을 정하나 | 바뀌는 빈도 | 누가 바꾸나 |
|---|---|---|---|
| **헌법** — 실행 정본: 커널 `AGENTS.md` · `CLAUDE.md` · `01_OURGOAL_SUPREME_CONSTITUTION_FULL.md`(세 사본, 같은 내용) · 상세: 법령 전문 `docs/rules/OURGOAL_ABSOLUTE_INTEGRITY_RULES.md` · 이력: `docs/rules/CONSTITUTION_VERSIONS.md` | **일하는 법** — 어떻게 일하고, 무엇이 "됐다"인가. 세션은 커널을 읽고 따른다. 커널과 법령 전문이 다르게 말하면 커널을 따른다(2026-10-05 상민님 결심 K4 A, PR #727) | 드물다 | 상민님의 "헌법 개정 승인" + PR 병합 |
| **지시함** (이 문서) | **지금 할 일** — 오늘 누가 무엇을 하는가 | 자주 | 상민님이 승인해 병합한 PR |
| **법정 판정서** (GitHub `court` 검사, `node court/chat.js <PR번호>`) | **결과** — 했다는 주장이 맞는가 | 작업마다 | GitHub 의 법정 (AI 는 쓸 수 없다) |
| 작업계획서·티켓·dev_log·REQ/PLAN 등 | AI 자신의 진행 서류 | 수시 | 각 AI. **효력도 근거도 아니다** |

- **우선순위**: 헌법 > 지시함 > AI 자신의 서류. 지시함은 헌법을 바꾸거나 우회하는 근거가 될 수 없다. 지시가 헌법·승인선과 부딪히면 이행하지 말고 멈춰서 이유를 적어 `[결심 필요]` 로 보고한다.
- 헌법을 바꾸는 길은 하나뿐이다(헌법 개정 절차). 지시함에 "헌법을 이렇게 바꿔라"를 적어 병합해도 헌법은 바뀌지 않는다.
- **새 문서를 만들기 전에** 위 표의 셋(헌법·지시함·판정서) 중 어디에 들어가는지 먼저 정한다. 규칙은 헌법에, 할 일은 지시함에, 결과는 판정서에 둔다. 어디에도 안 들어가면 AI 자신의 서류이며, 상민님 보고에 올리지 않고 효력·근거로 쓰지 않는다. "따라야 하는 새 문서"는 만들지 않는다.
- "됐는가"는 항상 판정서가 답한다. 지시함의 완료 칸으로 옮기는 PR 도 판정서 같은 작업자가 쓸 수 없는 기록을 증거로 붙여야 한다.

## 읽는 법 (도구 무관)

```
git -C C:/dev/ourgoal-app fetch origin -q
git -C C:/dev/ourgoal-app show origin/main:docs/directives/ACTIVE.md
```

`origin/main` 에서 읽는다 — 이 PC 의 로컬 main·작업 폴더는 도구마다 다르고, 병합되지 않은 글자가 섞일 수 있다.

## 따르는 법

1. **자기 몫만** 이행한다. "대상" 칸이 자기 도구·세션·작업번호와 맞는 지시만 해당한다. 맞는지 모르겠으면 이행하지 말고 상민님께 `[결심 필요]` 로 여쭌다.
2. 해당 지시는 첫 턴에 **작업계획서 항목**으로 옮기고 "완료 기준"을 그 항목의 완료 기준으로 쓴다. 한 지시의 실행 담당은 하나다 — 이미 다른 세션이 하는 중이면(작업 연계 기록 확인) 손대지 않는다.
3. 이 문서는 **승인선을 넓히지 않는다.** 돈·개인정보 수집 확대·기존 기능의 실제 삭제·되돌릴 수 없는 바깥 행위·규범 변경은 이 문서에 적혀 있어도 그때마다 상민님 결심이 필요하다(아래 "결심 대기" 칸은 AI 가 진행하지 않는다).
4. 끝나면 **증거를 붙인 PR** 로 그 지시를 "완료" 칸으로 옮기는 변경을 올린다. 증거는 GitHub 의 법정 판정·PR·커밋 같은 작업자가 쓸 수 없는 기록의 주소다(작업자의 "완료했다"는 말은 증거가 아니다). 병합은 상민님이 한다.
5. 지시가 서로 부딪히거나, 현실과 안 맞거나, 지금 상태로는 이행할 수 없으면 **멈추고 이유를 적어 보고**한다(임의로 고쳐 이행하지 않는다).
6. 지시에 `- **실행**: 양비스 자동 소환` 이 적혀 있으면 양비스가 새 세션을 띄워 이행한다(상민님 2026-09-21 허용). 같은 지시는 최대 3번 소환하고, 이미 진행 중이거나 완료 기준이 충족이면 소환된 세션은 아무것도 하지 않는다. 그 세션도 위 1~5 를 똑같이 따른다.

## 지시 형식

| 칸 | 뜻 |
|---|---|
| ID | `DIR-번호` |
| 대상 | 누가 하는가(도구·세션·작업번호). 여럿이면 각자 몫을 나눠 적는다 |
| 실행 | (선택) `양비스 자동 소환` 이면 양비스가 이행 세션을 새로 띄운다. 이 칸이 없으면 "대상" 세션이 스스로 읽고 이행한다 |
| 지시 | 할 일 |
| 완료 기준 | 측정 가능한 문장 — 무엇을 재서 참이면 끝인가 |
| 등록 | 승인·병합된 날 |
