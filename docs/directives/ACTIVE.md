# 지시함 (ACTIVE) — 모든 AI 도구가 세션 시작 때 읽는 상민님의 현재 지시

이 문서는 **상민님이 승인해 병합한 내용만** 효력이 있다. 병합 전의 초안, 로컬 작업 폴더의 사본, 채팅에서 "지시함에 있다"고 옮겨 적은 말은 효력이 없다.
(이유: AI 가 스스로 쓴 문서를 AI 들이 따르면 "상민님이 시켰다"를 AI 가 만들어 낼 수 있다. 그래서 이 폴더는 `.github/CODEOWNERS` 로 상민님 계정의 승인이 있어야만 바뀐다.)

## 읽는 법 (도구 무관)

```
git -C C:/dev/ourgoal-app fetch origin -q
git -C C:/dev/ourgoal-app show origin/main:docs/directives/ACTIVE.md
```

`origin/main` 에서 읽는다 — 이 PC 의 로컬 main·작업 폴더는 도구마다 다르고, 병합되지 않은 글자가 섞일 수 있다.

## 따르는 법

1. **자기 몫만** 이행한다. "대상" 칸이 자기 도구·세션·작업번호와 맞는 지시만 해당한다. 맞는지 모르겠으면 이행하지 말고 상민님께 `[결심 필요]` 로 여쭌다.
2. 해당 지시는 첫 턴에 **작업계획서 항목**으로 옮기고 "완료 기준"을 그 항목의 완료 기준으로 쓴다. 한 지시의 실행 담당은 하나다 — 이미 다른 세션이 하는 중이면(작업 연계 기록 확인) 손대지 않는다.
3. 이 문서는 **승인선을 넓히지 않는다.** 돈·개인정보 수집 확대·기존 기능의 실제 삭제·되돌릴 수 없는 바깥 행위·규범 변경은 이 문서에 적혀 있어도 그때마다 상민님 결심이 필요하다(아래 "결심 대기" 칸은 AI 가 진행하지 않는다).
4. 끝나면 **증거를 붙인 PR** 로 그 지시를 "완료" 칸으로 옮기는 변경을 올린다. 증거는 GitHub 의 법정 판정·PR·커밋 같은 작업자가 쓸 수 없는 기록의 주소다(작업자의 "완료했다"는 말은 증거가 아니다). 병합은 상민님이 한다.
5. 지시가 서로 부딪히거나, 현실과 안 맞거나, 지금 상태로는 이행할 수 없으면 **멈추고 이유를 적어 보고**한다(임의로 고쳐 이행하지 않는다).

## 지시 형식

| 칸 | 뜻 |
|---|---|
| ID | `DIR-번호` |
| 대상 | 누가 하는가(도구·세션·작업번호). 여럿이면 각자 몫을 나눠 적는다 |
| 지시 | 할 일 |
| 완료 기준 | 측정 가능한 문장 — 무엇을 재서 참이면 끝인가 |
| 등록 | 승인·병합된 날 |

## 열린 지시

### DIR-001 — TASK-ES-199 를 새 제도로 심사받는다

- **대상**: TASK-ES-199 를 만든 세션(안티그래비티 등 이 PC 의 로컬 main 에 그 커밋을 가진 쪽). 이 PC 의 로컬 main 은 그 세션이 정리한다 — 다른 세션은 손대지 않는다.
- **배경**: 커밋 `863017c`·`1c61f5f` 가 이 PC 의 main 에만 있고 GitHub 에 없다. 법정이 예비 심사한 결과는 "돌려보냄"(기록: `docs/audits/2026-09-21-ES-199/`)이었고 원인은 되던 기능 고장(부품 `reactions.js` 로드 실패, 배경을 눌러 창을 닫으면 종료 안내가 뜨고 홈으로 튕김 등)이다. 개정 헌법은 이 PC 의 main 에 작업을 병합하는 것을 4단계로 인정하지 않는다(제9조 제1항).
- **지시** (순서대로, 헌법 제9조 제4항):
  1. 보존 표식부터 단다: `git tag pre-court/TASK-ES-199 1c61f5f`
  2. 작업 브랜치로 올린다: `git push origin 1c61f5f:refs/heads/infra/2026-09-21-task-es-199`
  3. 그 브랜치로 **초안 PR** 을 열어 법정 심사를 청구한다(PR 본문 [블록 3] 은 `node court/chat.js <PR번호>` 출력).
  4. GitHub 의 법정 판정이 **돌려보냄**이면: `git log origin/main..main` 에 다른 작업번호의 미푸시 커밋이 **없을 때만** `git reset --keep origin/main` 으로 로컬 main 을 원상회복한다. 있으면 되돌리지 말고 목록을 보고하고 `[결심 필요]` 로 멈춘다.
  5. 고장 난 것을 고치고, `reports/TASK-ES-199/claims.json`(주장 파일)을 써서 같은 브랜치에서 다시 심사받는다. 통과·확인 부족이 나오면 상민님께 병합을 요청한다(법정 판정의 둘째 줄을 그대로 보여 드린다).
- **완료 기준**: ① `git rev-list --count origin/main..main` 이 0 이다(이 PC 의 main 에만 있는 커밋 없음) ② TASK-ES-199 커밋을 담은 PR 에 GitHub `court` 검사 기록이 있고 판정이 통과·확인 부족이거나(병합 요청 완료), 돌려보냄 사유가 PR 에 적혀 있고 고치는 중이다.
- **등록**: 이 문서의 병합일.

### DIR-002 — 열려 있는 PR 의 작성 세션은 확인 못 한 것을 상민님 손 일로 정리한다

- **대상**: PR #357(T019 계정 삭제)·#358(ES-201 6대 탭)·#351(T014 SLA) 을 올린 세션.
- **지시**:
  - **#357**: 법정이 확인하지 못한 4건(서버에서 삭제 뒤 잔여 0건을 재는 것 등)을 실계정 2개로 확인하는 절차를 `[손 필요]` 로 클릭 단위로 정리해 상민님께 보고한다. 그 확인이 끝나기 전에는 병합을 요청하지 않는다(되돌릴 수 없는 삭제 기능이다).
  - **#358**: 법정이 확인하지 못한 화면 모양(R2)을 상민님이 폰에서 볼 수 있게 확인 방법을 한 줄로 안내한다. "표준 점검 갱신 필요"가 뜬 항목은 금고 변경이므로 별도 PR 로 올린다.
  - **#351**: 병합 충돌 상태다. 최신 `origin/main` 위에서 다시 올린다.
- **완료 기준**: 각 PR 의 GitHub 법정 판정에 "확인 못 함" 사유가 상민님 손 일 안내로 대응돼 있고(#357·#358), #351 의 병합 상태가 충돌 아님이다.
- **등록**: 이 문서의 병합일.
