제 1 장
💡 한 줄 핵심 요약
아워골은 자극적인 쇼츠 영상이나 남들과 비교하며 피폐해지는 인스타그램의 피로에서 벗어나, "내가 올바른 방향으로 잘 살아가고 있는가?"라는 불안을 지워주고 매일의 성장을 게임처럼 체감하게 해주는 순수한 무공해 성장 쉼터입니다.
🌱 비유로 쉽게 이해하기
기존의 습관 앱이 '아무도 보지 않는 독서실에서 혼자 외롭게 O/X를 치는 체크리스트'였다면, 아워골은 '내가 오늘 한 걸음 내딛을 때마다 경험치가 팡팡 터지고, 옆에서 비슷한 고민을 가진 다정한 친구들이 말없이 하이파이브를 건네주는 따뜻한 성장 놀이터'입니다.

1. 아워골이 엄격하게 지키는 3대 철학 심사

아워골에 추가되는 모든 기능은 아래 3가지 질문에 "그렇다"고 답할 수 있어야만 만들어질 수 있습니다:

① 무공해성 (도파민 차단)
자극적인 알림으로 유저를 홀리거나, 남들에게 잘난 척 과시하게 만들어 마음을 피폐하게 만들지 않는가?
② RPG식 성장 체감
오늘 물 한 잔 마시고 책 5쪽 읽은 사소한 실천이 내 인생의 큰 꿈과 연결되어 즉시 성취감(경험치)을 주는가?
③ 동류의 무공해 연대
타인과의 비교로 박탈감을 주는 게 아니라, "나랑 비슷한 목표를 가진 친구도 오늘 해냈구나" 확신을 주는가?

2. 앱을 지탱하는 3가지 핵심 바퀴 (3대 본질 루프)

구분비개발자를 위한 쉬운 설명앱 안에서 실제로 겪는 경험
E1. 체크인 루프 매일 3초 만에 오늘의 실천을 기록하고 즉각 보상을 받는 과정 홈 화면에서 오늘의 질문에 답하고, 연속 실천 스트릭 불꽃과 히트맵이 예쁘게 채워지는 경험

E3. 동류 소통 루프 나와 같은 목표를 가진 친구들과 자극 없이 다정하게 응원을 주고받는 과정 비슷한 고민을 가진 동료와 1:1 대화를 나누고, 버튼 한 번으로 부담 없이 따뜻한 응원을 보내는 경험

3. 사용자에게 절대 주지 말아야 할 6가지 고질병 근절

1. 되던 기능 먹통: 어제까지 잘 되던 버튼이 업데이트하고 나서 갑자기 안 눌리는 답답함 근절.
2. 껍데기 버튼: 화면엔 그럴듯하게 버튼이 있는데 눌러도 아무 일도 안 일어나는 가짜 버튼 박멸.
3. 연결 끊긴 기능: 목표를 만들었는데 홈 화면이나 캘린더에 연동되지 않고 따로 노는 결함 차단.

6. 가짜 로봇 눈속임: 실제 사람도 없으면서 컴퓨터 가짜 봇으로 유저를 속이는 기만행위 영구 퇴출.

제2장: 아워골은 어떻게 돈을 버는가? (사업 기획과 수익화 4대 원칙)

제 2 장
💡 한 줄 핵심 요약
아워골은 사용자에게 돈을 내라고 윽박지르거나 화면을 가리는 강제 광고를 절대 띄우지 않습니다. 서비스의 핵심 기능은 평생 100% 무료로 열어두며, 사용자가 진심으로 원해서 결제하는 착한 비즈니스 모델만 추구합니다.
☕ 비유로 쉽게 이해하기
동네의 아늑한 무료 도서관을 떠올려보세요. 누구나 책을 편하게 읽고 공부할 수 있습니다(기본 무료). 하지만 내가 원하면 예쁜 북마크를 사거나(아바타 꾸미기), 옆자리 선배가 공부할 때 쓰던 편한 펜을 추천받아 사거나(잇템), 우등생의 비법 요약 노트를 감사의 마음을 담아 복사해오는 것(템플릿 마켓)에만 지갑이 열리는 원리입니다.

1. 선을 넘지 않는 착한 수익화 4대 절대 원칙

아워골은 돈을 벌기 위해 유저의 성장을 방해하지 않습니다. 오직 아래 4가지 방법으로만 수익을 만듭니다:

1. 아바타 꾸미기 (순수 자기만족)
내 캐릭터를 더 개성 있게 꾸미고 싶은 사람만 결제합니다. 기본 캐릭터로도 아워골의 모든 목표 설정, 통계, 대화 기능을 100% 평생 무료로 쓸 수 있습니다.
2. 타 유저의 잇템 (자발적 추천 커머스)
매일 10km를 달리는 러너를 보고 "저 사람은 무슨 러닝화를 신을까?" 궁금할 때, 그 사람이 프로필에 등록해둔 물건을 내가 원해서 살 때만 결제가 연결됩니다.
3. 템플릿 복사 리워드 광고 (윈-윈 구조)
서울대 합격생의 1년 루틴처럼 남이 잘 만들어둔 훌륭한 목표 구조를 내 앱에 그대로 쏙 가져올 때만, 감사의 뜻으로 자발적으로 15초 짧은 광고를 시청합니다.
4. 크리에이터 생태계 상생 재투자
좋은 목표 템플릿을 만들어 다른 사람들에게 영감을 준 유저에게 수익을 나누어주어, 더 훌륭한 루틴이 앱 안에 넘쳐나도록 유도합니다.
⚠️ 서비스 런칭 초기 "무광고(Zero-Ads)" 절대 선언
앱을 처음 켰을 때 광고부터 뜨면 마음이 식어버립니다. 아워골은 초기 사용자들이 완전히 편안하게 안착할 때까지 일체의 배너/팝업 광고를 전면 배제합니다. 광고 도입 시점은 대표(상민님)가 심사숙고하여 결정합니다.

제4장: 완벽한 기획을 만드는 2중 8원칙과 감찰 체계

헌법 제2조 · 문제해결 8원칙 1회차(REQ) 및 2회차(PLAN) 필수 적용
제 4 장
💡 한 줄 핵심 요약
생각 없이 대충 코딩을 시작하면 100% 버그가 터집니다. 아워골은 일을 시작하기 전 기획 단계에서 1번(REQ), 개발 설계 단계에서 또 1번(PLAN) 문제를 8개 렌즈로 집요하게 파고드는 2중 방패를 가동합니다.
🏗️ 비유로 쉽게 이해하기
건물을 지을 때 설계도도 없이 벽돌부터 쌓으면 결국 무너집니다. REQ는 "이 건물이 왜 필요하고 누구를 위한 것인가?"를 따지는 건축 기획서이고, PLAN은 "철근은 어디에 넣고 배관은 어떻게 연결할 것인가?"를 따지는 상세 시공 도면입니다.

1. 상민님의 문제해결 8원칙 (2중 순환 구조)

원칙1회차: 기획 단계 (REQ 문서에 적는 것)2회차: 시공 단계 (PLAN 문서에 적는 것)
원칙 ① 문제파악 상민님의 지시 원문을 그대로 적고, 겉으로 드러난 증상 뒤에 숨은 3단계 근본 원인을 파헤친다. 이 기능을 만들 때 고쳐야 할 프로그램 파일 목록을 한 줄도 빠짐없이 찾아낸다.
원칙 ② 4대분석 본질(무공해인가?), 원인(왜 고장 났나?), 중심(병목), 핵심(안전장치) 4개로 분리한다. 전체 데이터 흐름도를 그리고, 데이터가 바뀌었을 때 영향을 받는 모든 곳을 지도화한다.
원칙 ③ 방식결정 '하지 말아야 할 것'과 '할 것'을 선긋고, 서버 저장 방식 3가지를 명시한다. 각 파일마다 몇 줄을 추가하고 지울지 예산을 세우고, 버튼 배선 계획을 세운다.

아워골이 엄벌하는 절대 금지 9대 행위

금지 조항무슨 행동을 금지하는가?왜 금지하는가? (이유와 철학)
1. 가짜 숫자 날조 & 자가채점 금지 실제 기록도 없는데 "연속 10일 달성!" 거짓말하기. 자기가 시험 문제 내고 자기가 백점 주는 짓(자가채점) 금지. 숫자를 조작하는 순간 서비스의 모든 신뢰가 무너집니다. 채점은 중립적인 제3자(AI 법정)만 할 수 있습니다.
2. 파괴적인 데이터 일괄 삭제 금지 프로그램 업데이트한다고 기존 유저들의 체크인 기록이나 목표를 한 번에 싹 밀어버리는 쿼리 금지. 사용자가 한 땀 한 땀 쌓아온 기록은 돈으로 환산할 수 없는 소중한 인생 자산이기 때문입니다.
3. 사용자 화면에 외계어 노출 금지 에러 났을 때 유저 화면에 "Supabase Error 500" 같은 해괴한 개발자 전문 용어 띄우기 금지. 사용자를 겁주지 말고 "잠시 인터넷 연결을 확인해주세요"처럼 친절한 일상 언어로 안내해야 합니다.
4. 결재 없는 메인 서버 반영 금지 상민님의 최종 승인 도장도 안 찍혔는데 메인 프로그램(main 브랜치)에 멋대로 코드를 합치는 행위. 회사의 최종 결정권자는 오직 상민님뿐이며, AI나 개발자가 월권을 행사할 수 없습니다.
5. 테스트 숫자만 믿고 완료 보고 금지 "기계 테스트 100점 맞았습니다!" 해놓고 정작 스마트폰으로 열어보면 글자가 다 짤려 있는 엉터리 보고 금지. 기계 검사는 구문 오류가 없다는 뜻일 뿐, 실제 사람이 만졌을 때 편안한지는 눈으로 확인해야 합니다.
6. 아이디어 질문에 멋대로 개발 금지 상민님이 "이 기능 넣으면 어떨까?" 물어보셨는데 지레짐작으로 코드부터 뜯어고치는 성급한 행동 금지. 질문에는 생각과 타당성을 먼저 보고하고, 결심이 내려졌을 때만 질서 있게 개발에 착수합니다.

제8장: 상민님 결재선과 타협 없는 코드 품질

제 8 장
💡 한 줄 핵심 요약
아워골에서는 돈, 개인정보, 기능 삭제, 세상 밖 배포, 법 개정의 5가지 중대 사안은 오직 상민님만이 결정합니다. 반면 코드를 짤 때는 "몇 줄 안에 끝내라"는 형식적 제한을 없애고 최고의 품질을 위해 끝까지 책임집니다.

1. 반드시 멈추고 결재를 받아야 하는 5대 승인선

AI가 혼자 신나서 달려가다 사고를 치지 않도록 설치된 가장 중요한 안전 브레이크입니다:

승인선어떤 상황인가?AI의 행동 수칙
① 돈 (수익화 & 비용) 결제 기능을 붙이거나, 유료 서버 API를 증설하거나, 광고 도입 시기를 정할 때. 작업을 즉각 멈추고 비용과 수익 영향을 정리하여 [결심 필요]로 보고한다.

③ 기존 기능 삭제 유저들이 이미 잘 쓰고 있던 기능이나 화면을 영구적으로 없애버릴 때. 기존 유저들이 불편하지 않을지 대체 동선을 증명하고 결재를 기다린다.
④ 세상 밖 행위 (배포) 실제 인터넷 서버에 프로그램을 배포하거나, 진짜 회원들에게 단체 메일을 보낼 때. 법정 심사를 통과한 후 상민님이 명시적으로 "배포" 또는 "1"을 승인해야만 실행.
⑤ 규범 변경 (헌법 수정) 아워골 헌법 조문을 고치거나, 일하는 규칙을 바꿀 때. 일반 업무와 분리된 전용 결재 문서를 올려 상민님의 서명을 받는다.

🚀 왜 줄 수 제한을 없앴는가? (품질 절대주의)

[블록 4] 혹시 문제 생기면 어떻게 되돌릴 것인가? (Impact & Rollback)
기존 다른 기능에 영향은 없는지, 만약의 사태에 대비한 1초 비상 복구 대책을 적습니다.

제10장: 무결성을 지키는 AI 법정 (Court 단일 판정 체계)

헌법 제7조 · 7대 무결성 전수 검증 및 작업자와 판정의 분리
제 10 장
💡 한 줄 핵심 요약
개발자나 AI가 스스로 "저 완벽하게 다 만들었어요!"라고 우기는 것은 아무런 증거가 되지 못합니다. 합격 여부는 오직 GitHub 클라우드에서 엄격하게 작동하는 공정한 심판관, 'AI 법정(Court)' 한 곳만이 판정합니다.

운전면허를 딸 때 응시자가 "저 운전 진짜 잘해요"라고 백날 말해봤자 면허를 주지 않습니다. 반드시 국가 공인 시험관(AI 법정)이 옆에 타고 정해진 코스를 돌며 신호위반은 없는지, 브레이크는 잘 밟는지(7대 검증) 점수를 매겨야만 정식 합격증이 나오는 원리입니다.

1. AI 법정이 들이대는 7대 무결성 잣대

검증 항목시험관이 직접 확인하는 내용합격 기준
1. 먹통 버튼 0건 (Dead-Click 0) 앱 안의 모든 버튼을 실제로 가상 마우스로 꾹꾹 눌러봅니다. 단 하나의 버튼도 에러가 나거나 먹통이 되지 않고 기능이 실행되어야 함.
2. 이전 기능 손상 0건 (Regression 0) 새 기능을 넣으면서 옛날에 잘 되던 로그인이나 기록 기능이 망가졌는지 검사. 과거에 통과했던 모든 정밀 시험지 점수가 단 1점도 떨어지지 않아야 함.
3. 데이터 손실 0건 (Data Loss 0) 10가지 가상 인물의 복잡한 기록 데이터를 넣고 업데이트를 돌려봅니다. 업데이트 후에도 데이터가 1바이트의 오차도 없이 100% 똑같이 살아남아야 함.
4. 4대 화면 동시 전파 홈 화면에서 체크인을 했을 때 통계와 캘린더 화면도 똑같이 바뀌는지 검사. 한 곳에서 바뀐 내용이 다른 3개 화면에도 0초 만에 동시에 반영되어야 함.
5. 자동화 문법 방화벽 코드가 문법적으로 완벽한지, 에러를 억지로 숨기는 꼼수는 없는지 검사. 시스템 린터와 자동화 테스트를 에러 없이 완전 통과해야 함.
6. 좁은 화면 글자 짤림 방어 가장 좁은 스마트폰(아이폰 미니, 375px) 크기로 화면을 줄여서 확인. 글자가 박스 밖으로 삐져나오거나 강제로 쪼개져 흉하게 개행되지 않아야 함.
7. 모바일 물리 환경 적응 폰 뒤로가기 버튼, 가상 자판 돌출, 화면 130% 확대 상태를 시험. 어떤 기기 환경에서도 버튼이 가려지거나 앱이 튕기지 않아야 함.

2. 확인 수준 6단계 (얼마나 깊이 있게 확인했는가?)

법정은 "확인했다"는 말을 6가지 등급으로 엄격하게 나누어 평가합니다:

1단계 [확인 못 함]: 아직 테스트 못 해봄.
2단계 [글자만 봄]: 코드 파일에 글자가 적힌 것만 확인.
3단계 [조각만 돌려봄]: 프로그램 일부분만 떼어서 실행.
4단계 [PC 화면 실클릭]: 실제 브라우저 띄워서 마우스로 눌러봄.
5단계 [진짜 계정 송수신]: 서버에서 계정 2개로 진짜 대화해봄.
6단계 [진짜 스마트폰]: 실제 갤럭시/아이폰 실물 기기에서 터치해봄.

3. 손댈 수 없는 절대 금고([별표 3]) 제도

헌법 제8조 · 직관적 작업 상태 6단계 정의 및 확인 못 함 규정
제 11 장
💡 한 줄 핵심 요약

제12장: 배포 안전핀과 돌려보낸 작업의 원상회복

1. 일반 작업의 마감점은 반드시 "4단계(심사 청구)"이다

AI 개발자는 코드를 다 짜고 초안 PR을 올려 법정 시험지와 임시 미리보기 주소(5A)를 받아오는 [4단계]까지만 진행하고 작업을 멈추어야 합니다. 상민님의 승인도 없이 체크리스트에 5단계(배포)를 미리 적어놓고 "할 일이 남아있어서 배포했습니다"라고 변명하는 행위는 위헌입니다.

2. 퇴짜(돌려보냄) 맞은 코드의 안전한 원상회복 6대 수칙

법정에서 불합격 판정을 받은 코드가 메인 폴더에 묻어있으면 다른 작업까지 오염됩니다. 이를 깨끗이 치우는 규칙입니다:

수칙 번호원상회복 집행 규칙왜 이렇게 해야 하는가?
1. 공식 판정 확인 법정의 공식 거부 판정서가 나왔을 때만 원상회복을 시작한다. 자가 판단으로 멀쩡한 코드를 임의로 되돌리는 혼선을 방지.
2. 보존 이름표 부착 실패한 커밋에도 고유 보존 태그(court-rejected/...)를 붙인다. 아무리 실패한 작업이라도 소중한 작업물이 영구 유실되지 않도록 보존.
3. 안전한 리셋 실행 다른 세션의 작업물이 없을 때만 메인 폴더를 깔끔하게 되돌린다. 남이 열심히 작업하던 파일을 실수로 지워버리는 참사 차단.
4. 강제 삭제 영구 금지 명령어에 --hard나 강제 푸시(force push)를 쓰지 않는다. 되돌릴 수 없는 파일 파괴 행위를 원천적으로 막기 위함.
5. 이미 올라간 코드 처리 원격 서버에 이미 올라간 것은 되돌림 전용 PR을 통해 정식 결재를 받는다. 외부 깃허브 기록과의 무결성을 투명하게 유지하기 위함.
6. 재작업 브랜치 이관 고치는 작업은 메인 폴더가 아니라 이름표를 단 격리 브랜치에서 진행한다. 메인 프로그램은 항상 100% 정상 작동하는 깨끗한 상태를 유지.

3. 단 하나의 배포 고속도로 (배포 단일 경로)

🚫 컴퓨터에서 몰래 직접 배포 금지:

제14장: 진짜 사용자들끼리 통하는 소셜 네트워크

제 14 장
💡 한 줄 핵심 요약
친구가 없는 것처럼 보일까 봐 컴퓨터 로봇을 심어두고 사람인 척 답장하게 만드는 눈속임은 사기입니다. 아워골의 모든 소통 기능은 실제 가입한 진짜 사용자들끼리 서버를 통해 물리적으로 메시지와 응원을 주고받는 진짜 소셜입니다.
📱 비유로 쉽게 이해하기
카카오톡을 보냈는데 카카오 서버로 날아가지 않고 내 폰 안에서만 빙글 돌다가 컴퓨터가 가짜 답장을 보낸다면 기만입니다. 내가 보낸 메시지가 상대방의 진짜 폰 화면에 '1' 표시와 함께 실시간으로 팝업이 떠야 진짜 메신저인 것과 같습니다.

1. "가짜 실제구현(Fake Implementation)"의 영구 퇴출 선언

개발자가 귀찮다고 하드코딩된 가짜 유저 목록을 만들어두고 컴퓨터 타이머(setTimeout)로 3초 뒤에 자동 답장이 오게 만드는 짓을 헌법상 중대한 사기행위로 규정하여 박멸했습니다.

2. 사람과 사람을 잇는 3가지 진짜 기둥 (E3 필수 백본)

필수 기둥무엇을 하는 기둥인가?비개발자가 확인하는 방법
1. 영구 장부 (Database Engine) 대화 내용과 응원 기록이 서버 안전 금고에 보낸 사람, 받는 사람 이름표와 함께 영구 저장됨. 폰을 껐다 켜거나 앱을 다시 깔아도 지난 대화 내용이 그대로 보존됨.
2. 실시간 고속도로 (Realtime Engine) 화면을 새로고침하지 않아도 상대방이 글을 쓰면 내 화면에 0.1초 만에 뿅 나타남. 카카오톡처럼 대화창을 열어두고 있으면 실시간으로 말풍선이 올라옴.
3. 실사용자 신분증 (Identity Engine) 진짜 회원 가입을 마친 실존 유저들의 닉네임과 320종 아바타를 바탕으로 매칭됨. 친구 검색창에 친구 닉네임을 치면 실제 친구의 프로필이 정확히 뜸.

3. 메시지가 살아서 날아가는 4단계 여정 (연결 생존성)

1단계: 내 화면에 즉시 표시 (0초)
메시지를 보내자마자 내 화면에 말풍선이 먼저 떠서 답답함이 없습니다.

2. 내 데이터를 평생 지켜주는 3계층 스마트 스토리지

스마트폰 용량이 부족하다고 에러가 뿜어져 나오거나 앱이 튕기지 않도록 3단계로 분리 보관합니다:

1계층: 원격 클라우드 금고
내가 만든 고화질 캐릭터와 모든 체크인 기록 원본을 서버 금고에 영구 저장. 폰을 잃어버려도 안전!
2계층: 스마트폰 대용량 캐시
스마트폰 내부의 무제한 공간(IndexedDB)에 고화질 이미지를 쏙 담아두어, 인터넷 없이도 0초 만에 번쩍 렌더링!
3계층: 초경량 이름표 보관함
가장 좁은 저장소(localStorage)에는 무거운 사진 대신 가벼운 번호표(1KB 미만)만 넣어 '용량 초과 에러' 원천 차단!

3. 비회원에서 회원가입할 때 데이터 100% 합치기 (합집합 보존)

로그인 안 하고 게스트 모드로 아바타를 만들고 목표를 실천하다가 나중에 카카오나 구글로 로그인했을 때, 게스트 시절에 쌓아둔 데이터가 단 1바이트도 증발하지 않고 새 계정 속으로 100% 안전하게 합쳐지는 '합집합 병합(Union Merge)'을 물리적으로 강제합니다.
