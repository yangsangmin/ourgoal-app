## Executive Summary (총평 및 긴급 조치 요약)

6시간 뒤 지인들에게 앱 링크를 전달하기 전, **"지인이 앱을 처음 열어서 사용하고, 다시 들어오는 전체 여정(User Journey)"**을 엔지니어링 관점에서 전수 감사했습니다.  
현재 아워골 앱은 스모크 테스트 217개가 전원 통과할 만큼 탄탄한 백본을 갖추고 있으나, **실제 지인들이 접속했을 때 즉각적인 거부감이나 당혹감을 줄 수 있는 4대 치명적 결함(P0)**과 **완성도를 떨어뜨리는 5대 마찰점(P1)**이 확인되었습니다.

### 🚨 배포 전 즉시 해결해야 할 4대 쇼스토퍼 (P0)
1. **[데이터 시각화] `computeStreakDays` 스트릭 리셋 버그**:  
   - 어제까지 10일 연속 체크인한 사용자라도 **오늘 아직 체크인을 안 한 상태(예: 오늘 아침)로 앱을 열면 스트릭이 0일로 표시**됩니다. 지인이 "어제 분명 체크인했는데 왜 0일로 리셋됐지? 버그 났네" 하고 성취감을 잃게 됩니다.
2. **[보이고/설정] 상민님 개인 이메일(`ysm0422@naver.com`) 하드코딩 노출**:  
   - 게스트나 이메일이 없는 사용자가 설정 탭에 들어가면 계정 이메일에 상민님의 개인 네이버 이메일이 그대로 노출됩니다. (개인정보 노출 위험 및 해킹/계정 꼬임 오인).
3. **[기록되고] 게스트 작성 후 소셜 로그인(카카오/구글) 시 데이터 유실**:  
   - 지인이 앱 둘러보기로 목표와 첫 체크인을 작성한 뒤 마음에 들어서 "카카오로 계속하기"를 눌렀을 때, 기존 로컬 목표/체크인이 카카오 계정 DB로 병합되지 않고 빈 DB가 로드되어 **방금 쓴 글이 증발**합니다.
4. **[반응하고] 첫 체크인 시 `http://localhost:7777` 호출로 인한 Mixed Content/네트워크 차단**:

## 1. [보이고] 시각적 렌더링, 첫인상, 레이아웃, 모바일 뷰포트

### 1-1. 메인 랜딩 화면에서 '게스트로 바로 체험하기' 버튼 부재 (P1)
- **현상**: 지인에게 메인 도메인(`https://ourgoal.kr/` 등) 링크를 보냈을 때 `landingScreen`이 뜹니다. 현재 랜딩 화면에는 [카카오로 시작하기], [Google로 계속하기], [이메일로 가입하기] 버튼만 존재합니다.
- **UX 마찰**: 지인에게 "앱 한번 써봐"라고 보냈는데 첫 화면부터 회원가입이나 소셜 로그인을 강제하면 70% 이상의 지인이 이탈합니다.
- **해결 방안**: 랜딩 화면 하단에 `[로그인 없이 바로 둘러보기]`(게스트 입장) 버튼을 배치하여 1초 만에 홈 화면과 체크인 루프를 경험할 수 있도록 마찰을 없애야 합니다.

### 1-2. 금지 4-3(도구 언어 노출) 위반: 체크인 토스트의 'AI 노션 DB' 문구 (P1)
- **현상**: 홈 화면에서 체크인을 저장하면 `AI 노션 DB로 자동 기록 완료! (완료 · 5km)` 토스트가 뜹니다.
- **UX 마찰**: 지인은 노션을 연동하지도 않았는데 내부 개발/도구 언어인 "노션 DB"라는 표현이 화면에 튀어나와 "노션이랑 연결됐다는 건가? 내 노션이 어딨지?" 하고 혼란을 겪습니다. (AGENTS.md 규칙 4-3 "화면은 사용자 언어 '오늘 한 일 한 줄'").
- **해결 방안**: `오늘의 체크인이 안전하게 기록되었어요` 등 사용자 친화적 문구로 정돈.

### 1-3. 금지 6-1(위조 데이터) 및 가짜 더미 데이터 노출 (P1)
- **현상**: 
  1. 소통 탭 > 모임: `MOCK_GROUPS`에 `2026 하반기 전략 워크숍 TF`, `멤버 6명`, `상민님이 워크숍...`이 고정 노출됨.
  2. 소통 탭 > DM: `MOCK_PEOPLE` 가상 봇 샘플 대화 상대로 `데모용 대화 상대예요 · 실제 다른 사용자와의 대화는 아니에요` 문구가 박혀 있음.
  3. 설정 탭 > 잇템 통계: `MOCK_ITEM_STATS`에 기반하여 `전체 클릭 1,248회`, `이번 주 214회` 등 가짜 사회적 숫자가 노출됨.
- **UX 마찰**: 지인이 앱을 켰을 때 실제 서비스가 아니라 개발 중인 테스트 더미 사이트라는 인상을 주게 됩니다.
- **해결 방안**: 데이터가 없으면 비워두거나(Empty State), 정식 템플릿 모임(예: '매일 아침 10분 독서', '주 3회 런닝 크루')으로 깔끔하게 정돈하고 실데이터 기반으로 렌더링.

## 2. [누르고] 터치 인터랙션, 모달, 연타 방지

### 2-1. 체크인 저장 및 목표 추가 버튼 연타/더블클릭 방어 부재 (P1)
- **현상**: 홈 화면의 `captureSave`(저장) 버튼이나 목표 추가 버튼에 `isSubmitting` 또는 `disabled` 처리가 없습니다.
- **UX 마찰**: 네트워크 상태가 느린 모바일 환경에서 지인이 버튼을 "어? 안 눌렸나?" 하고 2~3번 연속 터치할 경우, 동일한 체크인이 2개, 3개 중복 생성되거나 백엔드 AI 피드백 요청이 중복 발송됩니다.
- **해결 방안**: 클릭 즉시 버튼 비활성화(`saveBtn.disabled = true`, 로딩 스피너) 처리 및 작업 완료 후 해제.

### 2-2. 카카오톡 인앱 브라우저에서 Google 로그인 시 403 차단 안내 부재 (P1)
- **현상**: 지인들에게 카카오톡 메시지로 링크를 보내면 대다수가 카카오톡 인앱 웹뷰로 열립니다. 이 상태에서 [Google로 계속하기]를 누르면 구글 OAuth 보안 정책상 `403: disallowed_useragent` 에러 화면이 뜨며 로그인이 완전히 차단됩니다.
- **UX 마찰**: 카톡으로 링크 받은 지인이 구글 로그인하려다 첫 진입부터 403 에러를 맞닥뜨립니다.
- **해결 방안**: 카카오톡 인앱 브라우저 감지 시 상단에 "사파리/크롬 외부 브라우저에서 열기" 안내를 띄우거나, 카카오 로그인을 1순위로 강조.

### 2-3. 모바일 하단 6개 탭바 터치 영역 및 엄지 피로도 (P2)
- **현상**: 하단 탭이 [홈, 목표, 일정, 기록, 소통, 설정] 총 6개로 꽉 차 있습니다. 가로 360~375px 소형 기기에서 탭 1개당 가로 폭이 약 58~62px 수준입니다.
- **UX 권장**: 아이콘과 텍스트 간격, 터치 패딩이 최적화되어 있으나, 탭 전환 시 상단 스크롤이 자동으로 최상단으로 리셋되도록 보장 필요.

## 3. [반응하고] 상태 변화, 피드백, 로딩, 에러 처리

### 3-1. 첫 체크인 시 `http://localhost:7777` 호출 차단 (P0)
- **현상**: `triggerFirstCheerResponse` 함수에서 상민님의 로컬 커맨드센터 포트(`http://localhost:7777/api/sim/first-cheer`)로 직접 요청을 보냅니다.
- **UX 마찰**: 지인의 스마트폰에는 7777 포트가 없으며, HTTPS 운영 도메인에서 비암호화 HTTP를 호출하므로 브라우저가 즉각 차단하고 콘솔에 빨간 에러를 찍습니다.
- **해결 방안**: `if(location.hostname === 'localhost' || location.hostname === '127.0.0.1')` 가드를 추가하여 운영 환경에서는 즉시 로컬 폴백을 실행하도록 방어.

### 3-2. 체크인 완료 직후 홈 화면 잔디/스트릭 즉각 리렌더링 누락 (P1)
- **현상**: 홈 화면에서 체크인을 작성하고 '저장'을 누르면 AI 피드백 카드는 뜨지만, **홈 화면 상단의 잔디 요약(`renderHomeGrassSummary()`)과 스트릭 배지가 즉시 갱신되지 않습니다.**
- **UX 마찰**: 체크인을 끝냈는데도 상단의 오늘 날짜 잔디 칸에 불이 안 들어오고, 다른 탭(기록 탭 등)을 갔다가 다시 홈으로 와야만 초록색으로 바뀝니다. "내 체크인이 왜 바로 반영 안 되지?"라는 의문을 줍니다.
- **해결 방안**: `captureSave` 핸들러 완료 시점에 `renderHomeGrassSummary()` 및 스트릭 배지 즉각 갱신 호출.

## 4. [기록되고] 데이터 보존, 세션 전환, 스토리지 무결성

### 4-1. 게스트 모드 작성 후 소셜 로그인 시 데이터 병합(Merge) 부재 (P0)
- **현상**: 게스트 사용자로 들어와서 목표 1개를 만들고 첫 체크인을 남긴 뒤 "카카오로 로그인"을 진행하면, `restoreSessionAndEnter` -> `loadProfile`이 실행되면서 새 계정의 DB만 조회합니다. 이때 로컬의 `ourgoal_guest_profile`에 있던 기존 목표와 체크인이 새 계정 DB로 이전되지 않아 화면에서 증발합니다.
- **UX 마찰**: 사용자가 "앱 괜찮네, 가입해야지" 하고 가입했는데 방금 쓴 목표와 기록이 싹 사라져서 허탈함을 느끼고 이탈합니다.
- **해결 방안**: `restoreSessionAndEnter` 시점에 `ourgoal_guest_profile`이 존재하고 목표/기록이 있다면, 새 사용자의 `goals` 및 `checkins`로 즉시 마이그레이션(Upsert)하는 브릿지 배선 필수.

### 4-2. 오프라인 상태 저장 및 새로고침 유지 (검증 완료 - 양호)
- 오프라인 상태에서 체크인 시 `OfflineSyncManager.enqueue`로 로컬에 보관되고, 온라인 복구 시 자동 동기화되는 로직이 완비되어 있습니다.

## 5. [데이터가 실질적으로 맞게 시각화되고] 계산식, 스트릭, 날짜 정합성

### 5-1. `computeStreakDays`의 당일 미체크인 시 스트릭 즉시 0일 리셋 버그 (P0)
- **현상**:
  ```javascript
  // 현재 코드
  var streak = 0;
  var cursor = new Date(); cursor.setHours(0,0,0,0);
  while(days[cursor.getFullYear()+'-'+pad(cursor.getMonth()+1)+'-'+pad(cursor.getDate())]){
    streak++;
    cursor.setDate(cursor.getDate()-1);
  }
  return streak;
  ```
- **치명적 결함**:
  - `cursor`가 무조건 **오늘(`new Date()`)**부터 시작합니다.
  - 사용자가 어제까지 14일 연속 체크인을 했더라도, **오늘 아직 체크인을 안 한 아침 9시에 앱을 켜면 `days[오늘]`이 false**가 되어 루프가 첫 턴에 끝나버리고 **`streak = 0`**이 반환됩니다!
  - 오늘 체크인을 마쳐야만 비로소 15일로 표시됩니다.
- **올바른 UX 로직**:
  - 오늘 이미 체크인했으면 오늘부터 역산 (N일).
  - 오늘 아직 안 했더라도 **어제 체크인했으면 어제부터 역산하여 스트릭(N일)을 유지**해야 합니다! (화면에는 "오늘 체크인하면 N+1일 연속!" 또는 "🔥 N일 연속 유지 중"으로 표시되어야 사용자가 오늘 체크인을 하러 들어옵니다).

### 5-2. 목표 진행률 및 통계 계산식 (검증 완료 - 양호)
- `goalProgress(goal)`: 마일스톤이 0개일 때 `0`을 반환하여 `NaN%` 방어 완료.
- `records-stats.js`: 총 체크인 수가 0일 때 `total > 0 ? ... : 0`으로 분모 0 나눗셈 방어 완료.

## 6. [설정에서 고치면 고치는대로 잘 반응하고] 설정 변경 즉각 반응

### 6-1. 설정 화면 상민님 개인 이메일(`ysm0422@naver.com`) 하드코딩 노출 (P0)
- **코드 위치**: `index.html` 내 `renderSettingsScreen`
  ```javascript
  emailEl.textContent = (state.user && state.user.email) || (state.profile && state.profile.email) || 'ysm0422@naver.com';
  ```
- **문제점**: 이메일이 없는 게스트 유저나 카카오 유저에게 상민님의 개인 네이버 이메일이 내 계정 이메일인 것처럼 노출됨.
- **해결 방안**: `|| '게스트 모드 (로그인 후 연동)'` 또는 `|| '연동된 이메일 없음'`으로 수정.

### 6-2. 테마 변경(8대 테마) 실시간 반응 (검증 완료 - 양호)
- 설정 탭에서 테마 카드를 클릭하면 `applyTheme(tid)`가 호출되어 `document.body`의 `data-theme`이 즉시 바뀌고 모든 화면에 실시간 적용됩니다. 로컬스토리지 저장도 정상 작동합니다.

### 6-3. 프로필 닉네임/아바타 변경 시 전파
- 프로필 모달에서 닉네임을 변경하면 `saveProfile()`이 호출되나, 홈 화면의 환영 인사(`homeGreeting`: "○○님 안녕하세요")가 즉시 바뀌지 않고 탭을 다시 눌러야 갱신되는 마찰이 있습니다. 프로필 저장 직후 `renderAll()` 또는 `renderHomeScreen()` 동기화가 권장됩니다.
