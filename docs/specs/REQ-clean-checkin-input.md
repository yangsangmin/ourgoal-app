## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
- **상민님 지시 원문**: "오늘의 3초 체크인 글자를 채워넣지 말라니까? 그럼 또 지우고 사용자가 써야하잖아? 이해를 못했어?"
- **현재 발생하는 문제 및 한계 (표면적 현상)**: 홈 화면 "오늘의 3초 체크인" 섹션에서 커닝페이퍼 칩이나 퀵 칩을 클릭했을 때 `textarea#captureInput`에 긴 완성형 텍스트가 강제로 주입되어(`inp.value = ...`), 사용자가 본인의 실천을 쓰기 위해 기존 글자를 일일이 백스페이스로 지워야 하는 번거로움과 피로감이 발생함. 또한 placeholder 끝에 커서 모양 파이프(` |`)가 붙어 있어 글자가 이미 채워진 듯한 오인을 유발함.
- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**: 칩 클릭 시 `inp.value`에 긴 예시 문장을 그대로 할당하여 사용자의 실제 입력 공간을 점유함.
  - **2층 (구조/프로세스 부재)**: 가이드/영감 칩의 역할을 "완성 문구 자동 삽입"으로 잘못 정의하여, 사용자가 지우고 쓰는 번거로움을 고려하지 못함.
  - **3층 (시스템/유저 체감 괴리)**: 사용자는 "내 글을 바로 빠르게 3초 만에 쓰고 싶은데 왜 내가 안 쓴 남의 긴 글이 채워져 있어서 지워야 하지?"라는 심각한 사용성 저하를 느낌.
- **사용자 상황 및 페르소나**: 홈 화면에 들어와 오늘 한 일을 빠르게 3초 체크인하려는 모든 사용자 (게스트 및 정식 회원).

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축 (Essence Axis)**: E1(체크인 루프) / FIX
- **[본질] (Essence)**: 3초 체크인의 본질은 "최소 마찰로 사용자가 즉시 자기 실천을 타이핑하는 것"이며, 입력창은 항상 깨끗한 빈 상태여야 하고 영감 칩은 지울 필요 없는 '플레이스홀더 힌트'로 기능해야 함.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. **원인 1**: `index.html` 188~190행 정적 칩의 인라인 `onclick`에서 `inp.value = '...'`로 텍스트를 강제 대입함.
  2. **원인 2**: `renderQuickCheckinGuideChips()` 이벤트 리스너에서 `inp.value = btn.dataset.cunningtext;`로 텍스트를 강제 채워넣음.
  3. **원인 3**: `textarea#captureInput`의 placeholder 끝에 ` |` (파이프 문자)가 있어 시각적으로 텍스트가 이미 타이핑된 것처럼 오해 유발.
- **[중심] (Core Bottleneck & Anchor)**: `captureInput`에는 어떤 인터랙션에서도 긴 텍스트를 강제 주입하지 않고 빈 문자열(`value = ''`)을 유지하며, 힌트는 `placeholder`로만 제시하여 사용자가 타이핑 즉시 자연스럽게 사라지도록 하는 것.
- **[핵심] (Critical Safety & Termination)**: 기존 스모크 테스트의 단언문(`renderQuickCheckinGuideChips()`, `내 목표 맞춤 커닝페이퍼`, `data-cunningtext=`, `placeholder="예: `)을 100% 보존하면서 입력창 피로도 제로를 달성하는 파이프라인.
- **체감 가설 (User Experience Hypothesis)**:
  > *"사용자가 홈 화면에서 체크인을 할 때, 입력창이 항상 깨끗하게 비어 있고 가이드 칩을 눌러도 예시가 플레이스홀더로만 안내되어, 백스페이스를 누를 필요 없이 즉시 키보드로 자기 실천을 3초 만에 기록하게 된다."*
- **기존 전체 기능 영향도 분석**:
  - 계정/로그인: 영향 없음.
  - 홈 화면 및 스트릭: 체크인 저장 및 히트맵 갱신, EXP 획득 로직 100% 보존.
  - 기록/통계/캘린더 탭: 저장된 체크인이 정상 전파되므로 영향 없음.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**: `inp.value = '...'`로 긴 완성형 텍스트를 사용자의 동의 없이 입력창에 덮어쓰는 행위 금지.
- **해야 할 것 (Action)**: `inp.placeholder`를 통해 영감 힌트를 제공하고, 입력창은 순수한 빈 상태(`value = ''`)로 유지하여 즉시 포커스.
- **왜 이 방식이어야만 하는가 (Why this approach)**: placeholder는 사용자가 글자를 입력하기 시작하면 브라우저 기본 동작으로 즉시 사라지므로, 사용자가 단 1개의 백스페이스도 누를 필요 없이 바로 자기 기록을 작성할 수 있는 가장 우아하고 표준적인 UX임.

### 3-1. 스토리지 원장화 3대 명세 (헌법 제2조 제4항 준수)
- **1호 (원격 DB 스키마 명세)**: 기존 `records` 테이블 스키마 변경 없음.
- **2호 (스마트 스토리지 분기 설계)**: 체크인 텍스트 저장 시 기존 LocalStorage / Supabase 이중화 파이프라인 그대로 유지.
- **3호 (4대 뷰 전파 배선도)**: 체크인 저장 후 `renderHome`, `renderRecordsScreen`, `renderStatsScreen`, `renderCalendar` 정상 전파 유지.

### 3-2. 전수 인터랙션(버튼/클릭/입력) 명세표 (Zero-Dead-Click)
| UI 요소 (ID / Name) | 위치/화면 | 사용자 액션 | 기대 동작 (비즈니스 로직) | 예외 처리 및 사용자 피드백 |
| :--- | :--- | :--- | :--- | :--- |
| `.btn-quick-chip` (정적 칩) | 홈 체크인 카드 | 클릭 | `inp.value` 채우지 않고 `inp.placeholder` 힌트 변경 후 `inp.focus()` | 지울 필요 없이 바로 타이핑 가능 |
| `[data-cunningtext]` (커닝페이퍼 칩) | 홈 체크인 카드 | 클릭 | `inp.value` 채우지 않고 `inp.placeholder` 힌트 변경 후 `inp.focus()` | `예시 힌트가 적용되었습니다. 지울 필요 없이 바로 적어보세요 ✨` 토스트 |
| `#captureInput` | 홈 체크인 카드 | 포커스 / 타이핑 | 순수 빈 상태에서 사용자 입력 수신 | placeholder 자동 숨김, 글자수 카운트 갱신 |
| `#captureSave` | 홈 체크인 카드 | 클릭 | 입력된 텍스트 저장 후 `inp.value = ''` 클리어 | 저장 토스트 및 히트맵 반영 |

### 3-3. 유저 데이터 100% 무손실 보존 규격 (Zero-Data-Loss Schema)
- **아바타 보존**: 기존 아바타 설정 및 보관함 100% 무손실 보존.
- **목표 데이터 보존**: 기존 목표, 마일스톤 데이터 100% 무손실 보존.
- **기록 데이터 보존**: 과거 체크인, AI 피드백, 스트릭 100% 무손실 보존.
- **화면 구성 세팅값 보존**: 테마, 위젯 세팅값 100% 보존.

## 4. [원칙 ④] 1~3 재검토 및 보완 (Review & Edge Cases)
- **비판적 자기 검토 및 약점/한계 인정**: 커닝페이퍼 칩을 눌렀을 때 사용자가 그 텍스트 그대로 저장하고 싶어하는 극단적 케이스가 있을 수 있으나, 이번 지시의 본질은 "남의 글이 채워져서 지우고 써야 하는 고통"을 없애는 것이므로 힌트 적용 방식이 압도적으로 올바름.
- **기존 기능과의 충돌 가능성 검토**: 스모크 테스트 7100~7102행의 `data-cunningtext=`, `renderQuickCheckinGuideChips();`, `내 목표 맞춤 커닝페이퍼` 단언문과 충돌 없이 100% 호환됨.
- **엣지 케이스 (Edge Cases)**:
  - 사용자가 이미 타이핑 중일 때 칩을 누른 경우: 사용자가 기입력한 글자가 지워지지 않도록 `inp.value`를 건드리지 않고 placeholder만 변경 후 포커스.
  - 브라우저 캐시 복원: `renderHome()` 시점에 사용자가 입력 중이 아닌 경우 `inp.value = ''`를 보장.

## 5. [원칙 ⑤] 해결 절차 정리 (Procedure & State Propagation)
- **구체적 실행 시퀀스**:
  1. 1단계: `index.html` 188~190행 정적 칩 인라인 스크립트 수정 (`inp.value` 주입 배제, `placeholder` 힌트화).
  2. 2단계: `index.html` 193행 textarea placeholder 파이프 문자 제거.
  3. 3단계: `renderQuickCheckinGuideChips()` 함수 내 클릭 리스너 수정 및 안내 문구 개선.
  4. 4단계: `renderHome()` 초기화 시 순수 빈 입력창 보장.
- **화면 간 상호연동 전파 규격**:
  - 체크인 저장 완료 시:
    1. 홈 화면 (`renderHome`): 히트맵 갱신, 스트릭 배지 갱신, `captureInput` 깨끗하게 비움.
    2. 기록 탭 (`renderRecordsScreen`): 신규 체크인 카드 즉시 노출.
    3. 통계 탭 (`renderStatsScreen`): 주간/월간 통계 반영.
    4. 캘린더 탭 (`renderCalendar`): 당일 날짜에 체크인 도트 표시.

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)
> *(주의: 본 원칙은 절차 정리(⑤)와 단계별 실행(⑦) 사이에 반드시 독립적으로 존재해야 하며, 생략하거나 타 원칙과 합치는 것은 위헌입니다)*
- **단일 실패점 (SPOF) 점검**: 칩 클릭 리스너에서 `inp` 요소를 찾지 못해도 `if(inp)` 가드가 있어 JS 에러가 전파되지 않음.
- **가정의 타당성 검증**: 스모크 테스트 단언문이 `inp.value`에 텍스트가 들어가 있는지를 검사하는지 확인 -> 단언문은 `data-cunningtext=` 속성의 존재만 확인하므로 완벽히 호환됨.
- **재검증 결과 도출된 절차 수정/보완사항**: 안내 문구를 `(탭하면 입력창에 자동 채워져요)`에서 `(탭하면 지울 필요 없이 힌트 적용)`으로 변경하여 사용자에게 명확하고 신뢰성 있는 인터랙션을 안내함.
