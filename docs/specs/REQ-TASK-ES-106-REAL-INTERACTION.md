## 1. 문제 정확히 파악 (문제해결 8원칙 ①)
- 기존 DM 및 동반자 기능에서 ALL_SEARCHABLE_USERS, MOCK_PEOPLE과 같은 하드코딩 배열을 대상으로 닉네임 검색이 이루어졌고, 메시지 전송 시 setTimeout 가상 타이머로 자동답장을 생성하는 로컬 자가 순환 루프가 존재했다.
- 상민님께서 "내가 말하는 아워골의 실제구현이란 실제 사용자들의, 상대방 계정(들)과 상호 연동되는 거야"라고 명확히 정의하셨으며, 이에 따라 헌법 제19조가 신설되었다.
- 따라서 실제 가입된 사용자 계정 간의 상호 통신(Supabase DB 원장 영속화, 실시간 Realtime 양방향 수신 전파, 실제 회원 검색 및 친구 맺기/삭제)을 구현해야 한다.

---

## 2. 본질·원인·핵심 파악 (문제해결 8원칙 ②)
- **본질 축**: **E3 (동류 발견 및 상호작용 소통)**
- **원인**: 초기 프로토타입 단계에서 UI 동작을 시뮬레이션하기 위해 사용된 모의 데이터와 가상 타이머 봇이 잔류하여, 실제 계정 간 상호작용 파이프라인이 미배선된 상태였음.
- **핵심**: "두 개 이상의 실제 계정이 서로 다른 브라우저/기기에서 접속했을 때, 상대방에게 보낸 메시지가 서버 DB에 저장되고 새로고침 없이 상대방 화면에 즉시 도달해야 한다."

---

## 3. 해결 방식 결정 (문제해결 8원칙 ③)
1. **Supabase 영속성 원장 (DB Engine)**:
   - Supabase 테이블(실시간 지원되는 1:1 대화 테이블)을 활용하여 발송자 UID(sender_id)와 수신자 UID(receiver_id), 내용(message), 전송시간(created_at)을 확실하게 영속화.
   - 클라이언트에서 내가 보낸 메시지 및 상대방이 보낸 메시지를 정렬 조회.
2. **실시간 양방향 수신 전파 (Realtime Engine)**:
   - sb.channel을 통해 상대방이 메시지를 전송하면 Realtime 이벤트를 감지하여, 내가 열고 있는 대화방에 즉각 수신 메시지를 렌더링.
3. **실사용자 식별 및 검색 (Identity Engine)**:
   - Supabase users 및 가입된 회원 데이터를 대상으로 닉네임 검색 실행.
4. **동반자(Companion) 상호 관계 관리**:
   - 실제 상대방의 UID를 동반자로 등록 및 해제.
   - 동반자 목록에서 아바타 클릭 시 실제 프로필 정보 표시, DM 클릭 시 실시간 1:1 대화방 즉시 연결.
5. **무충돌 안전핀 준수 (제19조 제3항)**:
   - 비로그인 게스트 접속 시: "실제 동료와 소통하려면 로그인이 필요해요" 소프트 로그인 안내 제공.
   - 콜드스타트 완충재는 [AI 봇] 뱃지를 공식 부착하여 투명성 보장.
