## 1. 문제해결 8원칙 1회차 분석

### ① 문제 정확히 파악
- 사용자가 아바타(초록 로봇 또는 AI 3등신 만화형 아바타)를 제작/설정한 뒤:
  1. **앱 업데이트 또는 프로필/데이터 업데이트 발생 시** 아바타가 기본값으로 초기화되거나 유실되는지 확인.
  2. **로그아웃 후 다시 로그인했을 때**(게스트, 이메일, 구글, 카카오) 기존에 제작한 아바타가 그대로 유지되는지 확인.
  3. **앱을 완전히 나갔다가(브라우저 종료 또는 탭 닫기) 다시 들어왔을 때** 아바타가 정상 유지되는지 확인.
- 만약 이 과정에서 아바타가 사라지거나 유실되는 취약점이 있다면 원인을 규명하고 무결성을 완벽히 보장하도록 배선 및 검증.

### ② 본질·원인·중심·핵심 (E1/E2/E3/INFRA/FIX)
- **본질**: 사용자의 자아 표현(Identity)인 아바타 데이터가 세션 라이프사이클(부트, 로그인, 로그아웃, 업데이트) 전반에서 100% 영속화되어야 함.
- **원인 분석 대상**:
  1. 아바타 저장 경로: `js/avatar-system.js`에서 생성된 아바타(`customAvatarUrl`, `avatarType`, `avatarThemeId`)가 `state.profile.settings`에만 저장되고, DB `users` 테이블이나 `state.profile.avatarUrl`에는 연동되지 않아 다른 기기/세션 복원 시 누락될 위험성.
  2. 게스트 -> 소셜 로그인 마이그레이션: 게스트 상태에서 아바타를 만든 후 소셜 로그인을 진행했을 때 목표와 기록만 병합(`goals`, `records`)되고 `settings.customAvatarUrl`이나 `avatarType`이 이전되지 않아 유실될 위험성.
  3. 상단 네비게이션 바(`topAvatar`)와 레벨 뱃지(`levelBadgeRow`) 간의 렌더링 불일치: `topAvatar`는 `state.profile.avatarUrl`을 참조하고, `levelBadgeRow`는 `state.profile.settings.customAvatarUrl`을 참조하여 화면 간 상태 불일치 발생 여부.
  4. 로그아웃(`performLogout`) 시 `localStorage` 정리 범위: `ourgoal_guest_profile`, `ourgoal_current_user` 삭제 시 `ourgoal_settings_<uid>`와의 관계 및 복구 가능 여부.

### ③ 해결방식 결정
- [점검 및 실측 시뮬레이션]:
  1. 실제 로컬 환경에서 아바타 생성 -> 새로고침(F5) -> 유지 확인.
  2. 아바타 생성 -> 목표 추가/프로필 수정/saveProfile -> 유지 확인.
  3. 아바타 생성 -> 로그아웃 -> 동일 계정 재로그인 -> 유지 확인.
  4. 게스트 상태에서 아바타 생성 -> 로그인 전환 -> 게스트 아바타 설정 승계 확인.
  5. 캐시 삭제/새 기기 접속 시 서버 DB(`users`)와의 영속성 연동 확인 및 취약점 발견 시 3중 안전망 구축.
  6. 상단바(`topAvatar`), 프로필 카드(`profile-avatar`), 레벨 뱃지(`levelBadgeRow`) 전 영역에서 신규 아바타 시스템이 완전 동기화되도록 배선 확인.

### ④ 1~3 재검토 및 보완
- 아바타 이미지가 base64 데이터일 경우 Supabase `users.avatar_url`에 저장 가능한 크기인지(256x256 canvas 축소 시 약 30~50KB), DB 컬럼 타입(TEXT)과 완벽 호환되는지 확인.
- 게스트 데이터 병합 시 목표/기록뿐 아니라 아바타 세팅(`settings.customAvatarUrl`, `settings.avatarType`, `settings.avatarThemeId`)도 새 UID의 세팅으로 마이그레이션 보장.
