## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)

### 1-1. 상민 대표님 지시 원문
> "가다듬어지긴했는데, 아직도 혁신적으로 너가 보여준 그래픽처럼 바뀌지 않았는데? 작업하지 말고 원인과 해결책만 먼저 말해봐."  
> "아래사항 이해했는지 대답해. 해결위한 요구사항정의서와 그에 맞는 각 화면의 그래픽 다시 보고해. 순차적으로 진행할게. 요구사항 정의서와 그래픽화면 통과되면 작업계획서로 넘어가고, 그 이후에 코드작업 시작한다."

### 1-2. 기저 3층위 심층 분석
1. **1층 (표면적 현상: Visual Stacking Clutter)**:
   - 다크 모드 색상(`--bg: #0B0F17`)과 글래스모피즘 CSS 속성은 선언되었으나, 홈 화면 상단에 `게스트 인사말 박스`, `아바타 경험치 박스`, `3일 연속 스트릭 배너`, `오늘의 카드 아코디언 박스`, `오늘 기록하기 박스` 등 **무려 5개의 육중한 구형 직사각형 박스가 수직으로 빽빽하게 적체**되어 있음.
   - 이로 인해 시안에서 제시된 핵심인 **`[14일 활동 발광 캡슐]`**과 **`[목표 현황 트윈 카드]`**가 첫 뷰포트(430×932) 밖으로 밀려나 보이지 않고, 사용자 체감상 "다크 색상만 칠한 옛날 게시판"으로 인식됨.
2. **2층 (구조적 결합: Fear of Regression & Non-modular DOM)**:
   - 기존 28개 기능 모듈(`js/*.js`)과 무결성 게이트키퍼 20개 검증(`scripts/verify-integrity-gate.js`)이 특정 DOM ID(`homeGreeting`, `levelBadgeRow`, `todayMissionCard`, `customFeedbackBtn` 등)를 직접 참조하고 있어, 코드를 다치지 않게 하려는 소극성으로 인해 구형 위젯 마크업을 화면 한가운데에 그대로 노출 방치함.
   - **"핵심 성소 뷰"**와 **"상세 부가기능 서브 레이어"**의 시각적 분리(Modularity & Containment) 아키텍처가 결여됨.
3. **3층 (시스템 괴리: Mockup-Code Visual Disconnection)**:
   - 20장의 그래픽 시안은 토스(Toss) 및 애플(Apple) 수준의 미니멀한 단일 뷰포트 성소 조형감(Single Viewport Focus Sanctuary)을 지향하고 있으나, 실제 코드는 레거시 웹 페이지의 나열식 스크롤 뷰에 머물러 있어 '그래픽 시안(이상향)'과 '실제 브라우저 렌더링(실물)' 간 10배 이상의 조형적 괴리가 발생함.

### 1-3. 대상 사용자 페르소나 및 발생 상황
- **러너/목표 실천자(예: 320종 아바타를 장착하고 매일 1줄 체크인을 하는 갓생 실천가)**:
  - 앱을 열자마자 3초 안에 시원하고 영감을 주는 성소에서 오늘의 행동(`[5km 러닝]` 등)을 체크인하고 성취감을 느껴야 함.
  - 현재는 잡다한 배너와 복잡한 툴바가 시야를 가로막아 피로감을 유발하고 앱의 프리미엄 가치를 느끼지 못함.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)

### 2-1. 본질 (Essence)
- 본 개편의 본질은 "단순 다크 테마 덧칠(Cosmetic Patch)"이 아니라, **"모바일 9:16 단일 뷰포트 안에 14일 활동 캡슐과 3초 체크인 영감만 순수하게 남기는 성소 조형 혁신(Architectural Sanctuary Redesign)"**이다.

### 2-2. 원인 (Root Causes)
1. **위젯 수직 적체**: 한 화면에 최대 1~2개 카드만 수용할 수 있는 모바일 화면에 5개의 육중한 위젯이 층층이 쌓여 시각적 숨통이 막힘.
2. **시각적 수납(Containment) 부재**: 부가 기능(테마 변경, 음성 녹음, 사진 업로드, AI 피드백 상세 등)이 메인 화면에 적나라하게 나열되어 정보 과부하 초래.
3. **하단 내비게이션의 구형 플랫 구조**: 시안의 시그니처인 중앙 돌출형 `(+)` 플로팅 액션 버튼(FAB)과 에메랄드 네온 글로우가 구현되지 않아 모바일 앱다운 프리미엄 감성이 반감됨.

### 2-3. 중심 (Core Bottleneck)
- **"430px 폭 단일 뷰포트 내 3단 성소 구조 확립"**:
  - 스크롤을 내리지 않고도 첫 화면에서 `[14일 활동 캡슐] ➔ [3초 체크인 Hero 카드] ➔ [오늘의 갓생 퀘스트 2열 그리드]` 3단 요소가 하나의 예술 작품처럼 완벽히 렌더링되어야 함.

### 2-4. 핵심 (Critical Anchor)
- **Zero Regression (28개 기능 모듈 & 20개 게이트키퍼 100% 무손실 보존)**:
  - 시각적 레이아웃을 전면 개편하되, 기존의 320종 아바타, 14일 체크인 데이터, 마일스톤, 크레딧, 타이머, 게이트키퍼 검증 ID는 단 1개도 삭제하거나 파괴하지 않고, 백그라운드/서브 드로어 레이어로 100% 온전히 유지해야 함.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)

### 3-1. 하지 말 것(금지선) vs 할 것(해결선)
* **하지 말 것**:
  - 기존 DOM ID(`homeGreeting`, `levelBadgeRow`, `todayMissionCard` 등)를 임의로 삭제하거나 이름을 변경하는 행위 (게이트키퍼 및 기존 JS 파괴 방지).
  - 기존 비즈니스 로직(체크인 저장, 아바타 렌더링, 타이머 연동)을 재작성하여 회귀 결함을 유발하는 행위.
* **할 것**:
  - 홈 화면의 시각적 진입 레이어를 20대 시안과 1:1로 일치하는 **3단 성소 뷰**로 전면 재편.
  - 레거시 위젯은 우측 상단 `[⋯ 더보기]` 드로어 또는 모달 내부로 안전하게 수납 격리.
  - 하단 내비게이션 바에 입체적인 중앙 돌출 `(+)` 액션 버튼 및 에메랄드 네온 인디케이터 배선.

### 3-2. 스토리지 원장화 3대 명세 (헌법 제2조 제4항)
1. **1호 (원격 DB 스키마 명세)**:
   - Supabase `profiles` (theme: `focus-sanctuary`, active_sanctuary_layout: `v2_pure`) 컬럼 및 `checkins`, `goals` 기존 스키마 100% 무손실 유지. 신규 DDL 불필요 (기존 컬럼 완전 호환).
2. **2호 (로컬 캐시/스토리지 동기화 명세)**:
   - `localStorage.setItem('ourgoal_current_theme', 'focus-sanctuary')` 초기화 강제.
   - 레거시 캐시 키(`ourgoal_home_layout_v1`)와 격리된 안전한 최신 뷰포트 상태 보존.
3. **3호 (오프라인/동시성 충돌 해결 명세)**:
   - 오프라인 시 `state.checkins` 로컬 배열 선반영 후 온라인 복구 시 Supabase Upsert 단방향 동기화.

### 3-3. 전수 인터랙션(Zero-Dead-Click) 명세표
| UI 요소 | 트리거 | 연결 동작 / 비즈니스 로직 | 피드백 / 시각 연출 |
| :--- | :--- | :--- | :--- |
| **상단 우측 아바타 뱃지** | `click` | `openAvatarModal()` 호출 (기존 320종 아바타 변경) | 골드 네온 펄스 애니메이션 |
| **14일 활동 캡슐 (14개 필)** | `click` | 해당 일자 체크인 상세 팝오버 노출 | 에메랄드/앰버 글로우 하이라이트 |
| **3초 체크인 프리셋 칩 3종** | `click` | `#captureInput`에 텍스트 주입 (`5km 러닝`, `독서 30분` 등) | 칩 활성화 앰버 보더 전환 |
| **체크인 완료 버튼** | `click` | `#captureSave` 트리거 ➔ DB 저장 및 14일 캡슐 즉시 착화 | +10 EXP 팝업 & 축하 폭죽 연출 |
| **하단 중앙 (+) FAB** | `click` | 빠른 목표 추가 / 빠른 체크인 모달 호출 | 회전 애니메이션 & 바텀시트 업 |
| **오늘의 퀘스트 트윈 카드** | `click` | 해당 목표 상세 화면(`#screen-goals`)으로 즉시 라우팅 | 카드 살짝 눌림(Scale 0.98) 트랜지션 |

## 4. [원칙 ④] 1~3 재검토 · 보완 (Critical Review & Edge Cases)

1. **키보드 활성화 시 모바일 뷰포트 찌그러짐 방지**:
   - 모바일 기기에서 `#captureInput` 포커스 시 가상 키보드가 올라와 14일 캡슐과 하단 탭바를 압박하는 현상 대비: `interactive-widget=resizes-content` 메타태그 및 고정 최소 높이(`min-height: 520px`) 안전 가드 배선.
2. **게스트 모드 & 첫 진입 사용자 경험**:
   - 로그인하지 않은 상태에서도 쇼케이스 목데이터가 즉시 바인딩되어 빈 화면이나 깨진 레이아웃이 노출되지 않도록 보장.
3. **기존 게이트키퍼(20개 검증)와의 완전 정합성**:
   - 게이트키퍼가 검증하는 20대 핵심 항목(빈 핸들러 0건, 데이터 무손실 10종 페르소나, 화면 연동)이 100% PASS 되도록 보장.

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)

- **단일 실패점(SPOF) 점검**: CSS 클래스명이 기존 클래스와 충돌하여 타 화면이 깨질 가능성 차단 ➔ `.sanctuary-v2-container` 등 고유 스코프 접두어 사용.
- **절차 수정사항**: 기존에는 코드를 먼저 수정하고 확인했으나, 이제는 **[요구사항/시안 컨펌 ➔ 작업계획서 컨펌 ➔ 코드 구현 ➔ 실측 캡처 대조]**의 완벽한 4단계 통제 절차로 전면 개편함.

## 8. [원칙 ⑧] 막히는 지점 예상 및 재검증 트리거 (Blockers & Triggers)

- **예상 블로커**: 게이트키퍼 스크립트가 숨겨진 구형 DOM 요소를 "렌더링 누락"으로 오인하여 실패할 가능성.
- **대응 및 재검증 트리거**: 만약 게이트키퍼가 요소를 찾지 못할 경우, `display: none` 대신 접근성 친화적인 `visibility: hidden; position: absolute; height: 0; width: 0; overflow: hidden;` 기법(SR Only / Safe Stash)을 사용하여 DOM 트리 내 존재성을 100% 보장하면서 시각적 노출만 완벽히 통제하도록 즉시 피봇.
