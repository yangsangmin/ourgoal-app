## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
- **상민님 지시 원문**:
  *"목표탭의 ‘ai현황’(최종결과 밑에 있는)을 ‘현상태 분석 ai 조언’으로 바꿔. 그리고 분석하여 결과를 보여주고도 진행상황 분석중… 안내가 계속 나타나있음. 분석할때만 띄우고 결과값 나오면 ‘분석완료’ 안내하도록 해 그리고 다른 창을 갔다가 다시 목표탭으로 돌아오거나"*
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  1. 목표 탭 내 'AI 조언' 영역의 헤더 및 스니펫 플레이스홀더에 'ai현황'/'AI 종합현황' 잔재 문구가 혼재되어 상민님 지시 문구인 '현상태 분석 AI 조언'으로의 단일화가 미흡함.
  2. 기저 캐시(`goalStatusCache`)에 분석 결과 텍스트가 이미 도출되어 정상 표시되고 있음에도 불구하고, 날짜 변경(`dateKey !== todayKST`)이나 초기 렌더링 시 조건 플래그(`goalStatusStale`)로 인해 상단 뱃지가 영구히 '진행 상황 분석 중…'으로 오표기되어 사용자에게 미완결된 상태라는 혼란을 줌.
  3. 사용자가 목표 탭에서 타 탭(홈, 일정, 기록, 소통, 설정)으로 이동했다가 다시 목표 탭으로 돌아왔을 때, 목표 데이터 변경이 없었음에도 무조건 재분석 비동기 요청(`refreshGoalStatusSummary`)이 트리거되거나 뱃지가 '분석 중…'으로 번쩍거려 불필요한 Gemini API 쿼터 낭비 및 화면 깜빡임 피로도를 유발함.
- **기저 층위 심층 분석**:
  - **1층 (미작동/표기 결함)**: 상태 뱃지 렌더러가 실제 비동기 분석 진행 여부(`isPending`)가 아닌 정적 캐시 유효성 플래그에 의존하여 결과가 존재함에도 '분석 중…' 뱃지를 노출함.
  - **2층 (구조/프로세스 부재)**: 탭 활성화 시 목표 해시(`goalStatusHash`) 변경 여부를 엄밀히 비교하지 않고 단순 날짜 경과만으로 억지 재호출을 수행하는 로직 구조.
  - **3층 (시스템 괴리)**: 텍스트 스니펫과 툴팁에서 레거시 용어('AI 종합현황')가 여전히 남아 UX 정합성을 저해함.
- **대상 사용자 페르소나 및 발생 상황**:
  - 자신의 목표와 마일스톤을 수시로 점검하며 목표 탭과 타 탭을 오가는 모든 사용자.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축 (Essence Axis)**: `E1/UX` & `FIX` (목표 관리 및 AI 조언의 정직하고 안정적인 피드백 제공)
- **[가목] 본질 (Essence)**:
  - 1. **정직성 (Truthfulness)**: 실제로 분석 중일 때만 '진행 상황 분석 중…'을 띄우고, 결과가 있으면 즉시 '분석완료'를 명시하여 상태를 거짓 없이 표시함.
  - 2. **무마찰성 (Frictionless)**: 탭을 이동했다 돌아와도 기존 분석 결과를 즉시 유지하여 로딩 지연이나 깜빡임 없는 쾌적함 보장.
  - 3. **자원 보존성 (Resource Economy)**: 목표·마일스톤 실질 변경(`hash` 변경)이 없는 한 불필요한 AI 호출을 원천 방어하여 Rate Limit 429 방어.
- **[나목] 원인 (Root Causes)**:
  - **원인 1**: `goalStatusStale` 변수가 `dateKey !== todayKST`를 포함하고 있어, 목표 내용이 그대로여도 날짜만 바뀌면 즉시 stale 처리되고 뱃지가 '분석 중…'으로 덮어써짐.
  - **원인 2**: `refreshGoalStatusSummary` 함수 내에 목표 해시 일치 시 재호출을 차단하는 멱등성 가드가 취약함.
  - **원인 3**: 스니펫 기본 텍스트에 '탭하여 AI 종합현황 보기'라는 레거시 표현이 잔존함.
- **[다목] 중심 (Core Bottleneck)**:
  - `goalStatusBadge`의 텍스트 및 스타일 결정 로직을 `isPending`과 `hasResult` 기반으로 정밀 재설계하고, 탭 전환 시 재분석 방지 가드를 확립하는 것.
- **[라목] 핵심 (Critical Anchor)**:
  - '현상태 분석 AI 조언' 명칭 전수 단일화, 분석 완료 즉시 초록색 '분석완료' 뱃지 확정, 해시 불변 시 재호출 영구 차단.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**:
  - 목표가 바뀌지도 않았는데 매 렌더링마다 `/api/goalstatus`를 호출하는 행위 금지.
  - 이미 도출된 분석 결과 요약 텍스트를 감추거나 초기화하는 행위 금지.
- **해야 할 것 (Action)**:
  - `goalStatusBadge` 렌더링 조건문 재정립:
    - 마일스톤이 없을 때 ➔ `마일스톤 필요` (회색)
    - 실제 비동기 분석 진행 중(`isPending`)이거나 결과가 전혀 없는 상태에서 분석 중일 때 ➔ `진행 상황 분석 중…` (주황색)
    - 분석 결과 텍스트가 존재할 때 ➔ `분석완료` (초록색)
  - `refreshGoalStatusSummary`에 해시 불변 가드 보강 (`c && c.text && c.hash === hash` 시 return).
  - 스니펫 기본 문구를 `탭하여 현상태 분석 AI 조언 보기`로 일원화.

## 4. [원칙 ④] 구현과정 가상 시뮬레이션 (Simulation)
1. **시나리오 A: 마일스톤이 등록된 목표 열람**:
   - 기존 캐시 텍스트가 있으면 즉시 초록색 `분석완료` 뱃지와 함께 조언 요약본이 펼쳐짐.
   - '진행 상황 분석 중…'이 번쩍거리거나 재호출되지 않음.
2. **시나리오 B: 타 탭 이동 후 복귀**:
   - 홈 탭 ➔ 목표 탭 복귀 시, 해시 변경이 없으므로 API 호출 0건, 즉시 `분석완료` 상태 유지.
3. **시나리오 C: 마일스톤 또는 할 일 수정/추가 시**:
   - 해시(`computeGoalStatusHash`)가 변경됨을 감지하여 비동기 분석 개시 ➔ 뱃지가 `진행 상황 분석 중…`으로 전환 ➔ 응답 도착 시 `분석완료`로 전환.

## 5. [원칙 ⑤] 예외 · 엣지케이스 · 실패조건 대비 (Edge Cases)
- **엣지케이스 1: 네트워크 장애 또는 API 429 발생 시**:
  - `generateGoalStatusSummary` 내의 fallback(`localGoalStatusSummary`)이 즉시 가동되어 정교한 규칙 기반 조언을 도출하고 뱃지를 `분석완료`로 마감 처리.
- **엣지케이스 2: 마일스톤이 0개인 신규 목표**:
  - `마일스톤 필요` 뱃지 노출 및 `마일스톤을 추가하면 분석을 시작해요` 스니펫 노출로 무리한 API 요청 원천 차단.

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)
- **단일 실패점 (SPOF) 점검**: 비동기 네트워크 장애 시에도 fallback 조언이 즉시 도출되어 뱃지가 '분석완료'로 정상 마감됨을 보증.
- **가정의 타당성 검증**: 목표 해시 불변 시 재호출을 차단하더라도, 사용자가 1글자라도 수정하면 해시가 바뀌어 자동 재분석이 정상 가동됨을 확인.
- **재검증 결과 도출된 절차 보완**: 탭 전환 시 캐시가 유효하면 즉시 렌더링하고 비동기 호출을 건너뛰도록 2중 멱등성 가드(UI 렌더러 + refresh 함수) 배치.
