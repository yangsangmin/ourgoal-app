## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 배선 식별 (Architecture & Wiring)
- **[본질] (Engineering Essence)**:
  - 텍스트 설명의 한계를 극복하고, 실제 모바일 기기 화면 목업과 인터랙티브 스와이프 카드를 통해 10초 만에 홈 화면에 앱을 설치하도록 유도하는 **'시각 중심형 온보딩 파이프라인'**.
- **[원인] (Technical Causes)**:
  - 웹 기반 PWA의 경우 브라우저 표준 설치 프롬프트(beforeinstallprompt)가 브라우저나 사용자 상호작용 조건에 따라 가변적으로 뜨기 때문에, 명시적인 수동 메뉴(점 3개 -> 홈 화면에 추가) 조작법을 시각적으로 알려주는 정적 가이드가 필수적임.
- **[중심 배선] (Core Wire & State)**:
  - `install-guide.html`: 터치 스와이프 이벤트(`touchstart`, `touchend`), 좌우 네비게이션 버튼, 인디케이터 점, 클립보드 복사 API(`navigator.clipboard.writeText`), 아워골 앱 실행 앵커.
  - `index.html`: 인앱 모달 열기/닫기 이벤트 배선(`openInstallGuideModal`, `closeInstallGuideModal`).
- **[핵심 안전장치] (Critical Safety & Persistence)**:
  - 기존 세션, 목표, 아바타, 체크인 데이터에 일체 관여하지 않는 격리된 뷰로 제작하여 무손실 보장.
  - 외부 네트워크 단절 시에도 로컬 캐시된 에셋으로 카드뉴스가 100% 렌더링되도록 서비스워커에 프리캐싱 배선.
- **종단간 데이터 흐름 다이어그램 (End-to-End Data Pipeline)**:
  `[공유 링크/인앱 버튼] -> [카드뉴스 뷰어 로드] -> [카드 1~5 스와이프/확인] -> [클립보드 복사/앱 바로가기] -> [바탕화면 PWA 설치 완결]`

## 6. [원칙 ⑥] 절차 재검증: 5대 무결성 검증 시나리오 설계
> *(주의: 본 원칙은 구현 순서(⑤)와 체크리스트(⑦) 사이에 반드시 독립적으로 존재해야 하며, 생략하거나 합치는 것은 위헌입니다)*
- **시나리오 A (Zero Dead-Click)**:
  - `install-guide.html` 및 인앱 모달 내 모든 버튼(`prev`, `next`, `copy`, `launch`, `close`) 클릭 시 콘솔 에러 0건 및 즉각 반응 확인.
- **시나리오 B (Zero Data Loss)**:
  - 가이드 모달 열람 및 링크 복사 후에도 기존 사용자 아바타, 목표, 기록, 화면 설정 데이터가 1바이트도 변경되지 않음을 딥이퀄 검증.
- **시나리오 C (Zero UX Regression)**:
  - 기존 홈 화면의 목표 추가, 체크인, 회고, 캘린더, 아바타 변경 흐름이 100% 정상 유지됨을 스모크 테스트로 확인.
- **시나리오 D (Full State Propagation)**:
  - 모달 열기/닫기 시 4대 뷰의 렌더링 상태가 왜곡되지 않고 정상 보존됨을 확인.
- **시나리오 E (자동화 게이트 통과)**:
  - `node scripts/verify-integrity-gate.js` 및 `npm test` 100% 통과 (0 failure).
