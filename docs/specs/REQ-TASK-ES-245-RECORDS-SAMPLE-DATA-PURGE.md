## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)

- **상민님 지시 원문**:
  > *"90번 완료처리하고, 89번부터. 번호대로 계속 하나씩 간다"*  
  > ➔ 노션 '💡 아워골 생각 메모장 (명령대기 & 아이디어 DB)' 115번 항목:  
  > **"기록탭의 샘플 데이터 1초 체험 후 원클릭 완전 삭제/초기화 기능 구현 및 신규 유저 편의성 제고"** 착수.
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  1. 신규 사용자가 통계 차트와 대시보드 미리보기를 위해 샘플 데이터를 로드했을 때, 이후 본인의 실제 기록을 시작하려 해도 샘플 데이터만 골라서 한 번에 지우는 기능이 기록 탭 첫 화면에 드러나지 않음.
  2. 샘플 데이터가 실제 유저 기록과 섞여 통계 왜곡이나 데이터 관리 불안감을 야기함.
  3. 샘플 데이터 정리 후 남은 기록이 없을 때 신규 유저를 진짜 첫 기록으로 안내하는 온보딩 가이드 연계가 부족함.
- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**:
    - 기록 탭 상단에서 `isSample: true`인 샘플 데이터의 존재를 실시간 감지하여 노출하는 상시 배너 및 원클릭 정화 파이프라인 부재.
  - **2층 (구조/프로세스 부재)**:
    - 정화 승인 시 실제 사용자 기록(`!isSample`)을 100% 무손실 보존하면서 샘플만 원천 분리 삭제하는 트랜잭션 및 4대 뷰 동시 전파 체계 미비.
  - **3층 (시스템/유저 체감 괴리)**:
    - 사용자는 안심하고 샘플 데이터를 체험한 후, 언제든 버튼 한 번으로 깨끗한 백지 상태로 복귀하여 진짜 성장을 기록할 수 있다는 확신을 원함.
- **사용자 상황 및 페르소나**:
  - 앱의 강력한 다차원 통계 기능을 미리 확인해보고 싶어 샘플을 넣었다가, 이제 자신의 진짜 운동/공부 기록을 시작하기 위해 손쉽게 초기화하고 싶은 신규 가입 유저.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)

- **본질 축 (Essence Axis)**: E2 & DATA (E2 기록·회고 루프 온보딩 무결성 및 샘플 데이터 원클릭 자가 정화)
- **[본질] (Essence)**:
  - 이 기능의 본질은 **"기록 탭 내 샘플 데이터를 능동 감지하여 상단 콤팩트 배너를 띄우고, 원클릭으로 실제 유저 기록 손실 없이 체험용 샘플 데이터만 1초 만에 완전 분리 정화하여 백지 온보딩으로 전환하는 자가 정화 무결성 엔진"**이다.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. **원인 1 (상단 감지 배너 부재)**:
     - `state.profile.records`에 샘플 데이터가 있어도 기록 탭 첫 화면에서 이를 시각적으로 인지하고 즉시 정리할 수 있는 진입점이 모달 깊숙이 숨겨져 있었음.
  2. **원인 2 (원클릭 삭제 배선 단절)**:
     - 4위 1체(감지 배너 + 확인 모달 + 무손실 삭제 로직 + 4대 뷰 리프레시 토스트)가 기록 탭 메인에 직결되지 않았음.
  3. **원인 3 (정화 후 빈 상태 온보딩 미연계)**:
     - 샘플 삭제 후 기록이 0건이 되었을 때 "이제 나만의 첫 실천을 기록해보세요! ✨" 격려 카드로의 매끄러운 유도가 미흡했음.
- **[중심] (Core Bottleneck & Anchor)**:
  - `#recSamplePurgeBanner` 슬롯 및 `purgeSampleRecordsOneClick()` 함수를 기록 탭 최상단에 배선하여, `sampleCount > 0`일 때만 즉각 노출하고 확인 후 1초 정화 및 4대 뷰 동시 전파.
- **[핵심] (Critical Safety & Termination)**:
  - 사용자가 직접 작성한 기록(`!r.isSample`)은 1비트도 유실되지 않는 100% 무손실 보존(Zero Data Loss).
  - `npm test` 337개 이상 전체 PASS 및 38대 헌법 게이트, Zero Dead-Click 100% ALL PASS.
- **체감 가설 (User Experience Hypothesis)**:
  > *"샘플 데이터를 넣어 마음껏 앱을 둘러본 뒤, 상단 정리 버튼을 누르자 1초 만에 샘플만 깨끗이 지워지고 첫 실천 격려 카드가 떠서 가벼운 마음으로 나만의 진짜 기록을 시작한다."*
- **기존 전체 기능 영향도 분석**:
  - 기록 탭 상단 샘플 감지 배너 및 정화 함수 추가 외 기존 기록 로직 100% 보존.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)

- **하지 말아야 할 것 (Avoid)**:
  - 실제 사용자 기록까지 일괄 삭제하는 위험한 전체 초기화를 수행하지 않는다.
  - 확인 팝업 없이 1터치로 즉시 날려버려 사용자의 오작동을 유발하지 않는다.
- **해야 할 것 (Action)**:
  - `state.profile.records` 내 `r.isSample === true` 개수를 실시간 연산하여 배너 조건부 렌더링.
  - 안전 확인 다이얼로그(샘플 N건만 삭제, 본인 기록 100% 안전 보존 안내) 후 필터링 정화.
  - `saveProfile()`, `dispatchFullViewPropagation()`, `renderRecordsScreen()`, `toast()` 순차 실행.
  - 기록 0건 도달 시 온보딩 격려 메시지 노출.

### 3-1. 스토리지 원장화 3대 명세 (헌법 제2조 제4항 준수)
- **1호 (원격 DB 스키마 명세)**: 변경 없음 (기존 records 스키마의 isSample 필드 활용).
- **2호 (스마트 스토리지 분기 설계)**: `state.profile.records = keptRecs` 후 로컬 삼중 백업 동기화.
- **3호 (4대 뷰 전파 배선도)**: `dispatchFullViewPropagation()` 및 `renderRecordsScreen()` 호출로 홈, 캘린더, 통계 즉시 동기화.

### 3-2. 전수 인터랙션(버튼/클릭/입력) 명세표 (Zero-Dead-Click)
| UI 요소 (ID / Name) | 위치/화면 | 사용자 액션 | 기대 동작 (비즈니스 로직) | 예외 처리 및 사용자 피드백 |
| :--- | :--- | :--- | :--- | :--- |
| `#recSamplePurgeBtn` | 기록 탭 상단 배너 | 클릭 | 확인 후 샘플 데이터 일괄 정화 | confirm 취소 시 무동작, 정화 완료 시 토스트 피드백 |

### 3-3. 유저 데이터 100% 무손실 보존 규격 (Zero-Data-Loss Schema)
- `state.profile.records.filter(r => !r.isSample)`를 통해 사용자의 진짜 기록은 1건도 훼손되지 않음.
