## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
- **상민님 지시 원문**: "90번 완료처리하고, 89번부터. 번호대로 계속 하나씩 간다." (노션 생각 메모장 95번: `동시 접속 급증 대비 Gemini API 분당 쿼터(Rate Limit 429) 방어 및 백오프 큐 구축`)
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  - 다중 사용자가 동시에 체크인을 하거나 트래픽이 일시적으로 급증할 때, Gemini API 분당 호출 제한(RPM Rate Limit 429 Too Many Requests)에 도달할 경우, 적절한 재시도 큐 없이 즉시 에러가 발생하거나 로딩이 장시간 멈춰 사용자 경험이 훼손될 위험이 존재함.
- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**: 429 상태코드 수신 시 체계적인 지수 백오프(Exponential Backoff: 1초, 2초, 4초) 및 요청 재시도 큐가 부재함.
  - **2층 (구조/프로세스 부재)**: 서버 및 클라이언트 양단에서 429 발생 시 즉각적으로 고품질 로컬 피드백으로 그레이스풀 폴백(Graceful Degradation)하는 안전망이 단절되어 있음.
  - **3층 (시스템/유저 체감 괴리)**: 외부 API의 쿼터 이슈로 인해 사용자는 "앱이 고장 났다"고 느끼며 이탈하게 됨.
- **사용자 상황 및 페르소나**:
  - 특정 시간대(출근 시간, 밤 10시~12시)에 일제히 체크인을 남기는 다수의 유저.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축 (Essence Axis)**: INFRA (가용성 인프라) / FIX (무결성 안전)
- **[본질] (Essence)**:
  - 외부 AI 공급사의 분당 쿼터 제한(429) 및 트래픽 폭주 환경에서도 클라이언트 UI가 결코 멈추지 않고, 3단계 지수 백오프 큐와 30종 프리미엄 로컬 폴백 엔진을 통해 0.3초 무중단 응답을 보장하는 고가용성 서킷 브레이커.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. **원인 1**: Gemini API 호출부에 RPM Throttling 및 429 감지 지수 백오프 스케줄러 부재.
  2. **원인 2**: 429 상태 수신 시 재시도 중단 후 사용자에게 친화적인 프리미엄 로컬 피드백으로의 0.3초 즉각 전환 파이프라인 결여.
  3. **원인 3**: 클라우드 에러 발생 시 사용자 피드백 안내("AI 응답량이 많아 고품질 추천 엔진으로 즉시 보답해 드렸습니다 ✨") 부재.
- **[중심] (Core Bottleneck & Anchor)**:
  - `GeminiQuotaDispatcher`를 구축하여 API 호출을 큐잉하고, 429 감지 시 지수 백오프(1s, 2s, 4s) 자동 재시도 및 한도 초과 시 30종 맞춤 프리미엄 로컬 엔진으로 0.3초 내 결함 없이 완결하는 분기 제어.
- **[핵심] (Critical Safety & Termination)**:
  - 헌법 제14조 제2항(No Silent Failure), 제3조(AI 실패 시 멈추지 않는 그레이스풀 폴백 4위 1체 배선)를 엄수하여, 429 에러 팝업 0건, 로딩 멈춤 0건, 무중단 100% 응답 달성.
- **체감 가설 (User Experience Hypothesis)**:
  > *"트래픽이 폭주하여 Gemini API 429 쿼터에 걸리더라도 사용자는 에러 창을 보지 않고 0.3초 만에 유려한 맞춤 코칭을 받아 체크인의 보람을 즉시 느낀다."*
- **기존 전체 기능 영향도 분석**:
  - 정상 상태(API 키 정상 및 쿼터 여유): 기존과 동일하게 실시간 Gemini AI 분석 결과 표출.
  - 429 발생 시: 지수 백오프 후 복구되면 정상 표출, 실패 시 즉각 30종 프리미엄 로컬 피드백으로 폴백 및 안내 토스트 노출.
  - 전 기능 및 전 UX 회귀 0건 보장.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**:
  - 429 에러 발생 시 사용자에게 브라우저 경고창(alert)이나 기술적 에러 메시지를 노출하는 행위 금지.
  - 백오프 재시도를 무한정 루프로 돌려 브라우저를 프리징시키는 행위 금지 (최대 3회, 최대 7초 제한).
  - 아무 내용도 없는 빈 피드백 카드를 노출하는 행위 금지.
- **해야 할 것 (Action)**:
  - `GeminiQuotaDispatcher` 구축:
    - 429 감지 시 지수 백오프(1초 -> 2초 -> 4초, 최대 3회) 재시도.
    - 재시도 실패 또는 쿼터 소진 시 30종의 상황별(공부, 운동, 업무, 멘탈, 일정 등) 맞춤 프리미엄 로컬 피드백 0.3초 렌더링.
    - 친절한 전환 토스트: "AI 응답량이 많아 고품질 추천 엔진으로 즉시 보답해 드렸습니다 ✨" 표출.
  - 서버 `api/feedback.js`에도 429 백오프 및 폴백 안전망 동시 탑재.

### 3-1. 스토리지 원장화 3대 명세 (헌법 제2조 제4항 준수)
- **1호 (원격 DB 스키마 명세)**:
  - 신규 컬럼 변경 없이 기존 `checkins`의 피드백 원장에 `source: "local_enhanced"`로 영구 보존.
- **2호 (스마트 스토리지 분기 설계)**:
  - 로컬 스토리지에 최근 429 백오프 타임스탬프를 보관하여 연속 호출 시 불필요한 네트워크 지연 방지.
- **3호 (4대 뷰 전파 배선도)**:
  - 피드백 생성 즉시 홈, 기록, 통계, 캘린더 4대 뷰에 안전하게 전파 동기화.

### 3-2. 전수 인터랙션(버튼/클릭/입력) 명세표 (Zero-Dead-Click)
| UI 요소 (ID / Name) | 위치/화면 | 사용자 액션 | 기대 동작 (비즈니스 로직) | 예외 처리 및 사용자 피드백 |
| :--- | :--- | :--- | :--- | :--- |
| 체크인 저장 버튼 | 홈/기록 화면 | 클릭/터치 | 체크인 저장 후 AI 피드백 요청 -> 429 시 백오프 후 프리미엄 폴백 | 로딩 인디케이터 부드러운 해제 및 토스트 안내 |

### 3-3. 유저 데이터 100% 무손실 보존 규격 (Zero-Data-Loss Schema)
- **아바타 보존**: 경험치 및 아바타 상태 100% 보존.
- **목표 데이터 보존**: 연결된 목표의 진행률 및 마일스톤 안전 보존.
- **기록 데이터 보존**: 체크인 텍스트와 시간, 생성된 프리미엄 피드백 영구 원장화.

## 4. [원칙 ④] 1~3 재검토 및 보완 (Review & Edge Cases)
- **비판적 자기 검토 및 약점/한계 인정**:
  - 백오프 시간이 너무 길면 유저가 체크인 화면에서 기다리다 지칠 수 있으므로, 클라이언트에서는 1회 백오프(1초) 후 여전히 429이면 즉각 프리미엄 로컬 엔진으로 0.3초 전환하여 체감 대기시간을 1.5초 이내로 극대화함.
- **기존 기능과의 충돌 가능성 검토**:
  - 기존 정상적인 Gemini 응답 처리 파이프라인과 완벽 호환.
- **엣지 케이스 (Edge Cases)**:
  - 네트워크 완전 단절: 즉각 로컬 프리미엄 피드백 전환.
  - 429 및 503 동시 발생: 서킷 브레이커 즉시 작동.

## 5. [원칙 ⑤] 해결 절차 정리 (Procedure & State Propagation)
- **구체적 실행 시퀀스**:
  1. `js/gemini-quota-dispatcher.js` 또는 `index.html`에 `GeminiQuotaDispatcher` 구축.
  2. 30종 고품질 맞춤 프리미엄 로컬 피드백 풀(`PREMIUM_FEEDBACK_CATALOG`) 정의.
  3. 429 상태 감지, 지수 백오프(1s -> 2s -> 4s) 및 폴백 디스패치 로직 배선.
  4. `requestGeminiFeedback` 및 `requestServerAIFeedback`에 디스패처 적용.
  5. 서버 `api/feedback.js` 429 핸들링 보강.
  6. 스모크 테스트 단언문 추가 및 전수 검증.
- **화면 간 상호연동 전파 규격**:
  - 데이터 변경 발생 지점: AI 피드백 수신 또는 폴백 완료.
  - 연계 화면 즉시 갱신:
    1. 홈 화면: 아바타 AI 코치 카드 피드백 즉시 표시
    2. 기록 탭: 오늘 기록 하단 AI 피드백 뱃지 표시

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)
- **단일 실패점 (SPOF) 점검**:
  - 외부 Google Gemini 서버가 전면 마비(Outage)되더라도 아워골 앱 자체는 영향을 받지 않는가?
  - -> 30종 프리미엄 로컬 피드백 엔진이 즉각 구동되므로 0% 장애 전파를 보증함.
- **가정의 타당성 검증**:
  - 429 감지 후 백오프 재시도 성공 시 정상 AI 피드백으로 자연스럽게 교체되는가?
  - -> 성공 시 정상 결과를 반환하고 실패 시에만 안전 폴백하므로 품질과 안정성을 양립함.
- **재검증 결과 도출된 절차 수정/보완사항**:
  - 429 폴백 발생 시 유저에게 "AI 응답량이 많아 고품질 추천 엔진으로 즉시 보답해 드렸습니다 ✨" 토스트를 명확히 띄워 투명성과 신뢰를 제공함.
