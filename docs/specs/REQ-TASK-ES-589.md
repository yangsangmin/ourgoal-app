# REQ-TASK-ES-589

## 1. [원칙 ①] 현상 파악 및 기준점
- **현재 상황**: PR #848에서 `CELL_SPLIT` 분열에 대한 "동작 보존 확인" 심사 경로를 법정에 신설하려 했으나, 명령 주입 취약점, DOM 비교 결함, worker JSON 무조건 신뢰 등의 중대한 결함이 발견되어 병합이 거절되었다.
- **기준점**: 결함이 포함된 #848의 구현을 폐기하고, origin/main의 안전한 법정을 기준으로 동작 보존 확인 경로를 완전히 재구현한다.

## 2. [원칙 ②] 근본 원인 분석
- 본질: 검증 신뢰도.
- 원인: 검증기가 작업자가 제출한 증명(worker JSON)에 과의존하고, 안전하지 않은 셸 실행(`execSync`)을 사용했으며, 동적 상태(DOM 내 `<script>`나 난수/시각 등)를 정교하게 발라내지 못함.
- 중심: 법정의 자체 검증 능력 강화.
- 핵심: 생성기 샌드박스 재실행 및 상태의 엄밀한 비교.

## 3. [원칙 ③] 핵심 해결 방안
- `court/lib/preserve.js` 및 `preserve-source.js` 재구현:
  - `execSync` 대신 `execFileSync`를 사용하여 명령 주입 원천 차단 및 파일 경로 상대성 검증 적용.
  - DOM 비교 시 `<script>` 태그를 걷어내고, 기준 2회차 실행에서 달라진 동적 값(난수, 시각 등)은 비교에서 제외(무시된 값으로 기록).
  - 작업자가 제출한 JSON 증명의 `ok: true`를 믿지 않고, 법정이 `docs/design/harness/module-split/gen-inline-hard.js`를 샌드박스에서 재실행하여 작업 커밋의 결과와 바이트 단위로 정확히 일치하는지 실측.
- `court/selftest/unit-preserve.js` 재작성:
  - 기존 35/35 통과 유지 및 신규 5종 단위 시험(정상 보존, 작업 실패, 기준 실패, 흔들림, DOM 불일치, 명령 주입 차단 등) 100% 통과 확보.
- 헌법 커널 3사본 및 법령 전문 정합성 개정:
  - `v2026.10.07-PRESERVATION`으로 버전 격상.
  - `MERGE_GATE` 1항 및 조문 9.3을 일관되게 수정하여 "동작 보존 확인(CELL_SPLIT 분열 한정)"이 위임 병합 허용 대상임을 명문화.
  - 발효 예정/WIP 등의 임시 문구를 배제하고, 기존 커널 형식에 맞춤.

## 4. [원칙 ④] 자기 비판 및 반론 격파
- 반론 1: "생성기를 재실행하는 과정에서 악의적인 스크립트가 실행되거나 법정 환경이 훼손될 수 있지 않은가?"
  - 격파: `execFileSync`로 인자를 엄격히 분리하고, 변경 허용 파일 목록과 경로 검증(`checkPathSafe`)을 통해 샌드박스 밖이나 시스템 명령 실행을 차단함.
- 반론 2: "DOM에서 동적 값을 무시하면 UI가 깨진 분열도 통과될 수 있지 않은가?"
  - 격파: 동적 값 무시는 '기준 커밋을 2회 실행했을 때 결과가 달라지는 속성'에만 한정되므로, 정적인 UI 구조나 클래스가 바뀌는 것은 잡아냄.
