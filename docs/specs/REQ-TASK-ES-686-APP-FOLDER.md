## 1. [원칙 ①] 문제를 정확히 파악한다

마지막 정리를 로컬 커밋까지 마치고 법정의 `recomputeSplit` 을 직접 불렀더니 `{"ok":false,"reason":"Unexpected file modified by generator: js/app/"}` 가 나왔다. `checkedFiles` 에는 `index.html`(196660바이트)과 `js/app/boot.js`(3686바이트)가 기준 생성기 재실행 결과와 길이까지 맞게 적혀 있었다 — 바이트 대조는 지나갔고 그다음 status 검사에서 걸린 것이다. 앞선 새 세포들(`js/core/…`)은 폴더가 이미 있어 걸린 적이 없다.

## 2. [원칙 ②] 본질·원인·중심·핵심

- **본질**: 법정이 읽는 `git status --short` 는 새 폴더를 파일이 아니라 폴더로 보여 준다.
- **원인**: git 의 기본값(`--untracked-files=normal`)과 법정의 글자 맞대기.
- **중심**: 폴더가 기준에 있기만 하면 된다 — 파일 하나.
- **핵심**: 부팅 파일의 경로는 바꿀 수 없다(생성기 사양 · 모듈 지표 · 시험이 고정). 법정 코드도 바꿀 수 없다(금고). 남는 길은 기준 쪽에 폴더를 먼저 두는 것이다.

## 3. [원칙 ③] 해결 방식

1. `js/app/README.md` 한 장을 쓴다. 빈 자리표시가 아니라 **쓸모 있는 설명**으로: 이 폴더가 무엇인지, 무엇을 두지 않는지, 관련 문서.
2. 재현 절차를 도구로 남긴다(`court-newdir-repro.cjs`): 임시 git 저장소에서 「이미 있는 폴더의 새 파일」과 「없던 폴더의 새 파일」을 만들고 status 를 법정과 같은 방식으로 읽는다 → 없던 폴더 쪽만 걸림 · `--untracked-files=all` 이면 안 걸림 · 폴더가 기준에 있으면 안 걸림.
3. 실제 커밋에서 본 결과 둘(폴더 없이 `ok:false`, 설명 한 장을 얹은 임시 커밋 위에서 `ok:true`)을 그 보고 파일에 글자 그대로 옮겨 적는다.
