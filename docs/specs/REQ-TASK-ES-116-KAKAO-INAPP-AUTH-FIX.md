## 1. 문제 정확히 파악 (문제해결 8원칙 ① - 사용자 시선)
- **실제 유저 행동**: 카카오톡에서 링크 클릭 → 카카오톡 자체 웹뷰로 인앱 진입 → 화면 중앙의 [카카오로 3초 만에 시작하기] 클릭 → 인앱 브라우저 제약/지연으로 로그인 실패 → 초기화면(랜딩)으로 무한 튕김.
- **기존 1차 계획의 한계**:
  1. 상단 배너에만 "다른 브라우저로 열기"를 두고 정작 유저가 누르는 **메인 카카오 버튼 자체의 인앱 처리 UX**가 고려되지 않음.
  2. 실패 시 띄우는 모달에 "세션 초기화"라는 **개발자 중심 기술 용어**가 노출되어 유저에게 불필요한 혼란을 줌.
  3. 이메일 가입이 완전히 숨겨져 있어 카카오 로그인이 안 되면 유저가 **우회할 수 있는 고속도로가 없음**.

## 2. 본질·원인·중심·핵심 파악 (문제해결 8원칙 ②)
- **본질**: 카카오톡 인앱 브라우저로 접속한 어떤 유저도 "로그인 실패로 인한 튕김과 좌절"을 단 한 번도 느끼지 않고, **어떤 상황에서든 3초 안에 원하는 목표 화면으로 들어갈 수 있는 무마찰 완결 UX**를 제공하는 것.
- **핵심 배선**:
  1. **[직관적 탈출]**: 카카오톡 인앱 감지 배너를 누르기 쉬운 플로팅 카드형으로 강화하고, Android는 Chrome intent 원클릭, iOS는 원클릭 주소 복사 + Safari 가이드 제공.
  2. **[메인 버튼 스마트 가드]**: 카카오 버튼 클릭 시에도 인앱 환경의 유실 방지 2중 백업(sessionStorage) 자동 가동.
  3. **[무음 자동 정화(Silent Auto-Clean)]**: 유저가 "세션 초기화"를 수동으로 누를 필요 없이, 오류 감지 시 시스템이 백그라운드에서 꼬인 스토리지를 100% 자동 소각.
  4. **[대체 고속도로 상시 노출]**: 카카오 버튼 직하단에 "또는 닉네임/이메일로 1초 시작" 링크를 제공하여 카카오 오류 시 즉각 1초 직통 입장 지원.
  5. **[용어 전면 순화]**: "세션 초기화" → "처음부터 다시 시도 / 캐시 비우기", "카카오 인증 연동 점검" → "카카오톡 인앱 브라우저 지연 시 닉네임으로 바로 입장".

## 3. 해결방식 결정 (문제해결 8원칙 ③)
- **사용자 만족 4대 배선 체계**:

  - B. **랜딩 화면 보조 진입로 복구**: `#landKakaoBtn` 하단에 `[카카오 대신 닉네임으로 1초 만에 시작하기]` 링크 배선 → 클릭 시 닉네임 입력 모달 즉각 오픈 후 바로 `enterApp()`.

  - D. **boot() 콜백 대기 루프 4초 + 로딩 UX**:

## 4. 1~3 재검토 및 보완 (문제해결 8원칙 ④)
- Q1: 안드로이드에서 intent로 크롬이 열리면 카카오 로그인이 잘 되는가?
  → A1: 완전한 크롬 브라우저 환경이므로 PKCE code_verifier 유실과 카카오톡 웹뷰 격리가 발생하지 않아 100% 정상 로그인됨.
- Q2: iOS 카카오톡 유저는 어떻게 되는가?
  → A2: 카카오톡 우측 상단 메뉴의 Safari 열기를 직관적으로 안내하고 원클릭 주소 복사를 제공하며, 탈출하지 않더라도 닉네임 1초 직통 입장으로 100% 진입 보장.
- Q3: 기존 사용자의 목표/기록 데이터가 손상될 위험은 없는가?
  → A3: `loginWithDirectIdentifier`는 기존 로컬 백업(`ourgoal_goals_backup_...`, `ourgoal_records_backup_...`)을 최우선 스캔하여 불러오므로 데이터 손실 0%.
