## 1. 문제 파악 (문제해결 8원칙 ①)
- 실제 유저가 카카오톡 채팅방에서 아워골 웹앱 URL을 전달받아 접속했을 때, 랜딩 화면에서 [카카오로 3초 만에 시작하기]를 누르면 간편/자동 로그인이 실패하고 지속적으로 초기화면(랜딩 화면)으로 튕기는 현상 발생.
- 복구 모달 또는 화면 하단의 [세션 초기화] 버튼을 누르고 이메일을 기입했을 때는 정상 진입됨.
- 신규 유저 진입로가 카카오로 100% 단일화된 상태에서 카카오톡 인앱 브라우저 로그인 실패는 치명적인 온보딩 블로커임.

## 2. 본질·원인·중심·핵심 (문제해결 8원칙 ②)
- **축**: FIX / INFRA
- **본질**: 카카오톡 인앱 브라우저의 웹뷰 격리로 인한 PKCE 검증키(`code_verifier`) 소실 및 1.2초 콜백 타임아웃 레이스 컨디션으로 인해 카카오 인증이 실패하고 랜딩 화면으로 강제 튕김.
- **핵심 배선**:
  1. `kakaotalk` 인앱 브라우저 감지 시 모바일 웹 표준 외부 브라우저(Chrome/Safari) 탈출(원클릭 및 안내) 배선.
  2. `boot()` 콜백 대기 루프를 1.2초(6회 x 200ms)에서 최대 4초(20회 x 200ms)로 확대하고 콜백 처리 중 로딩 UI 유지.
  3. OAuth 인가 실패 또는 `authErr` 발생 시 무한 튕김 방지 및 간이 이메일/닉네임 직통 진입 안내 우아한 폴백.
  4. 인앱 브라우저 상단 배너 문구를 "다른 브라우저로 열기" 유도로 전면 개편.

## 3. 해결방식 결정 (문제해결 8원칙 ③)
1. **인앱 브라우저 탈출 배선 (In-App Escape)**:
   - 카카오톡 인앱 브라우저(`navigator.userAgent`에 `KAKAOTALK` 포함) 감지 시:
     - Android: `intent://` 스킴을 통한 Chrome 자동/원클릭 호출 링크 지원.
     - iOS: 카카오톡 브라우저 상단/하단 메뉴를 통한 사파리 열기 가이드 모달 및 바로가기 CTA 제공.
     - 랜딩 상단 배너(`inAppBrowserNotice`)를 명확한 탈출 CTA 버튼형 배너로 개편.
2. **콜백 대기 시간 1.2초 → 4초 안전 확대 및 스피너 배선**:
   - URL에 `code=` 또는 `access_token`이 존재할 때 최대 20회(총 4.0초)까지 비동기 `getSession()` 대기.
   - 대기 중 랜딩 화면이 번쩍이며 노출되지 않도록 처리 중 오버레이/스피너 유지.
3. **PKCE 교환 실패 시 자동 세션 정화 및 복구 안전망**:
   - `code_verifier not found` 등 PKCE 에러 감지 시 꼬인 토큰을 즉각 자동 정리(`rescueLoginSession` 수준)하고 사용자에게 닉네임/이메일 직통 입장 모달 제공.
4. **헌법 제18조 줄 수 규격 준수**:
   - `index.html` 22,196줄 불변 규격 엄수 (빈 줄 상쇄 치환).
