## 1. [원칙 ①] 요구사항 정합성 및 배경 (Problem & Grounding)

### 1.1 상민님 원문 지시 (Ground Truth)
> **"사용자가 계정을 탈퇴할 때 안내되어야 하는 문구 모두 확인해서(법적책임, 데이터 분실 등등) 계정탈퇴 누르면 팝업창 띄워서 탈퇴전에 안내해야함"** (노션 생각 메모장 `[16]`번)

### 1.2 배경 및 현황 문제점
- 기존 설정 탭의 회원 탈퇴 인터랙션은 단순 확인창이나 개략적인 문구 수준에 머물러 있어, 탈퇴 시 영구 소멸되는 귀중한 사용자 데이터(목표, 타임라인 기록, 320종 커스텀 아바타, 피드 및 DM 소통 내역)에 대한 구체적 고지가 부족했습니다.
- 또한 개인정보보호법, 전자상거래법, 통신비밀보호법 등 관련 법령에 따른 법적 의무 보존 항목 및 파기 의무 안내가 누락되어 법적 리스크가 상존했습니다.
- 따라서 본 계획은 상민님의 원문 지시를 100% 충족하여, 사용자가 탈퇴 버튼 클릭 시 법적 책임·데이터 분실 사전 안내 전용 팝업창(`#withdrawModal`)을 호출하고 완벽한 4위 1체 배선과 30일 복구 유예 안내를 제공하는 것을 목표로 합니다.

## 2. [원칙 ②] 근본 원인 분석 (Root Cause Analysis)

- **문제의 본질**: 회원 탈퇴는 사용자의 모든 정체성과 자산이 비가역적으로 소멸되는 최후의 절차임에도 불구하고, 정보 제공이 간략하여 사용자의 오인에 의한 영구 데이터 손실 위험이 상존한다는 점입니다.
- **원인 분석**:
  1. 탈퇴 안내 문구가 체계화되지 못하고 단순 alert/confirm 수준에 의존하여 법령상 의무 고지 항목이 누락되었습니다.
  2. 데이터 분실 4대 영역(목표, 기록, 아바타, 소통)의 방대한 가치를 사용자에게 직관적으로 상기시키는 전용 모달 레이아웃이 부재했습니다.
- **해결의 중심**: 사용자가 자신의 소중한 실천 기록과 아바타 자산의 소멸을 명확히 인지하고, 관련 법률상 보존/파기 기준을 투명하게 확인한 후 명시적 동의 체크를 통해서만 탈퇴가 진행되도록 안전망을 중심에 두는 것입니다.
- **핵심 개선 방향**: 
  - 데이터 분실 4대 영역 및 법적 책임 3대 법령을 망라한 정밀 팝업 UI 구축.
  - 실수 방지를 위한 30일 소프트 딜리션 유예 및 원클릭 복구 안내 제공.
  - 동의 체크박스 연동 4위 1체 배선 완결.

## 3. [원칙 ③] 아키텍처 및 데이터 흐름 설계 (Architecture & Data Flow)

### 3.1 4위 1체 배선 구조
```
[설정 탭 내 회원 탈퇴 버튼 (#withdrawBtn)]
                 │ 클릭
                 ▼
[계정 탈퇴 전용 안내 팝업 (#withdrawModal)]
  ├── 데이터 분실 4대 영역 정밀 고지
  ├── 법적 책임 및 보존 3대 법령 고지
  ├── 30일 복구 유예 정책 안내
  │
  ├── [동의 체크박스 (#withdrawAgreeCheck)] ──(미체크: 비활성 / 체크: 활성화)──┐
  │                                                                            ▼
  ├── [닫기 / 취소 버튼 (#withdrawCancelBtn, #withdrawCloseBtn)]      [최종 탈퇴 확정 (#withdrawConfirmBtn)]
  │            │                                                               │
  │            ▼                                                               ▼
  │      [안전하게 모달 닫기]                                            [계정 세션/스토리지 정리 및 로그인 이동]
```

## 4. [원칙 ④] 구현 명세 (Implementation Details)

### 4.1 `index.html` 수정
1. `openWithdrawModal()` 함수 고도화:
   - 데이터 분실 4대 영역 상세 명시 (목표, 기록, 아바타, 소통)
   - 법적 보존 3대 법령 상세 명시 (개인정보보호법 21조, 전자상거래법 6조, 통신비밀보호법 15조의2)
   - 30일 복구 유예 및 자동 복구 안내
2. 전용 모달 컨테이너 및 4위 1체 요소 배선:
   - `#withdrawModal`: 전용 안내 팝업 모달
   - `#withdrawAgreeCheck`: 법적책임 및 분실 고지 확인 체크박스
   - `#withdrawConfirmBtn`: 최종 탈퇴 처리 버튼 (`disabled` 상태로 시작)
   - `#withdrawCancelBtn`, `#withdrawCloseBtn`: 안전 취소 버튼

### 4.2 `ui.css` 수정
1. `.withdraw-modal-container`: 375px 모바일 뷰포트에서 내용 잘림 방지 (`max-height: 85vh; overflow-y: auto;`)
2. `.withdraw-box-legal`, `.withdraw-box-danger`: 가독성 및 경고성 시각화

## 5. [원칙 ⑤] 예외 처리 및 방어적 설계 (Defensive Design)

- **오클릭 및 실수 방지**: 동의 체크박스를 체크하지 않으면 탈퇴 버튼이 클릭 불가능하도록 기본 `disabled` 속성 부여.
- **비파괴적 취소 보장**: 취소 버튼이나 모달 닫기 버튼 클릭 시 사용자 데이터와 세션에 어떠한 변경도 가하지 않고 모달만 안전하게 닫힘.
- **모바일 뷰포트 스크롤 보장**: 화면이 작은 디바이스(375px)에서도 안내 문구 전체를 확인하고 스크롤할 수 있도록 보장.

## 6. [원칙 ⑥] 절차 재검증: 5대 무결성 검증 시나리오 설계

1. **시나리오 1 (팝업 호출 무결성)**: 설정 탭에서 회원 탈퇴 클릭 시 `#withdrawModal`이 정상 표시되는지 검증.
2. **시나리오 2 (데이터 분실 4대 영역 고지)**: 목표, 기록, 아바타, 소통 4대 영역 소멸 안내 문구가 모달 내에 누락 없이 존재하는지 검증.
3. **시나리오 3 (법적 책임 3대 법령 고지)**: 개인정보보호법 제21조, 전자상거래법 제6조, 통신비밀보호법 제15조의2 법률 규정이 정밀하게 명시되었는지 검증.
4. **시나리오 4 (4위 1체 인터랙션 제어)**: `#withdrawAgreeCheck` 체크 전에는 `#withdrawConfirmBtn`이 비활성화되고, 체크 시 활성화되는지 검증.
5. **시나리오 5 (안전 취소 및 세션 방어)**: 취소 버튼(`#withdrawCancelBtn`, `#withdrawCloseBtn`) 클릭 시 모달이 안전하게 닫히고 세션이 보존되는지 검증.
