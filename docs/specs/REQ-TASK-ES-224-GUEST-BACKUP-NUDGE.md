## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
- **상민님 지시 원문**: "90번 완료처리하고, 89번부터. 번호대로 계속 하나씩 간다." (노션 생각 메모장 94번: `게스트(둘러보기) 3회 기록 시 안전 백업 넛지 및 1클릭 카카오 계정 무손실 병합`)
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  - 게스트(로그인 없이 둘러보기) 사용자가 열심히 목표를 세우고 체크인을 3회 이상 쌓았음에도, 브라우저 캐시 삭제, 시크릿 모드 종료, 기기 변경 등으로 인해 소중한 실천 데이터가 한순간에 영구 증발할 위험에 무방비로 노출됨.
  - 로그인 전환 유도 시점이 적절하지 않거나 카카오 로그인 전환 시 게스트 데이터 유실에 대한 불안감으로 이탈률이 증가함.
- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**: 게스트 상태에서 실천 기록 누적 3회 시점에 데이터 영구 보존의 필요성을 환기하는 적시 넛지(Nudge) 바텀시트가 부재함.
  - **2층 (구조/프로세스 부재)**: 게스트 상태에서 카카오 로그인으로 진입하기 직전, 최신 `state.profile`을 로컬 원장에 확정 영속화하지 않으면 리다이렉트 과정에서 직전 변경사항이 유실될 수 있는 구조적 틈새 존재.
  - **3층 (시스템/유저 체감 괴리)**: 사용자는 "로그인하면 내가 방금 쓴 3개의 기록이 날아갈까 봐 두렵다"는 심리적 저항감을 가짐.
- **사용자 상황 및 페르소나**:
  - 앱 설치나 복잡한 회원가입 없이 둘러보기로 가볍게 시작하여 3일간/3회 연속 체크인을 완료한 온보딩 초기 유저.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축 (Essence Axis)**: E1 (체크인 루프) / FIX (무손실 안전)
- **[본질] (Essence)**:
  - 게스트가 3회 체크인이라는 의미 있는 몰입 마일스톤에 도달했을 때, 데이터 증발 불안감을 안도감으로 바꾸어 1클릭 카카오 연동을 통해 평생 정회원으로 무손실 승격시키는 온보딩 리텐션 안전망.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. **원인 1**: 체크인 누적 횟수(3회)를 감지하고 게스트 여부를 판별하여 적시에 반응하는 백업 넛지 트리거 부재.
  2. **원인 2**: 게스트의 노력을 인정하고 카카오 1클릭 연동을 제안하는 375px 모바일 친화 바텀시트 UI 부재.
  3. **원인 3**: 소셜 로그인 전환 전 게스트 프로필의 동기화 보장 및 리다이렉트 복귀 후 신규 계정으로의 비파괴 합집합(Union Merge) 원장화 파이프라인의 완성도 미흡.
- **[중심] (Core Bottleneck & Anchor)**:
  - 게스트 체크인 3회 달성 감지 즉시 `openGuestBackupNudgeModal()`을 호출하고, 카카오 로그인 클릭 시 현재 게스트 데이터를 100% 로컬 원장에 스냅샷한 뒤 OAuth를 개시하는 무손실 연결고리.
- **[핵심] (Critical Safety & Termination)**:
  - 헌법 제1조 제4항 제4호(유저 데이터 증발 0%), 제13조 제4항(게스트 모드 안전 보호), 제15조(비파괴 합집합 원장화)를 엄수하여, 카카오 계정 연동 후 기존 게스트의 목표, 체크인 기록, 아바타, 스트릭이 단 1바이트도 유실되지 않음.
- **체감 가설 (User Experience Hypothesis)**:
  > *"게스트 사용자가 3번째 체크인을 마치는 순간, 벌써 소중한 3개의 실천이 쌓였어요!라는 축하와 함께 카카오 계정 평생 안전 보관 바텀시트가 뜨고, 1초 만에 카카오로 연동되어 방금 쓴 기록이 그대로 유지되는 것을 보며 안도와 신뢰를 체감한다."*
- **기존 전체 기능 영향도 분석**:
  - 계정/로그인: 일반 로그인 유저에게는 넛지가 절대 뜨지 않으며, 게스트 모드에서만 정확히 1회 넛지 표출.
  - 체크인 루프: 체크인 저장(`saveQuickCheckin`) 직후 후속 플로우로 자연스럽게 연결.
  - 기록/통계/캘린더 탭: 게스트 상태든 카카오 연동 후든 4대 뷰 동시 전파(`dispatchFullViewPropagation`) 완벽 유지.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**:
  - 게스트 사용자를 강제로 쫓아내거나 로그인하지 않으면 앱을 못 쓰게 막는 가혹한 강제 모달 금지.
  - 나중에 할게요 클릭 시 반복 팝업으로 유저 경험을 해치는 행위 금지 (세션당 1회 제한).
  - 기존 소셜 로그인 유저(`state.user.id`가 유효한 회원)에게 불필요한 넛지 노출 금지.
- **해야 할 것 (Action)**:
  - `checkGuestBackupNudge()` 트리거 함수 구현: `isGuest && records.length >= 3` 감지.
  - `openGuestBackupNudgeModal()` 바텀시트 UI: 375px 모바일 최적화, 12ms 미세 햅틱 피드백, 44px 터치 타깃.
  - `[🔒 1초 만에 안전 보관하기 (카카오 연동)]` (#btnGuestBackupKakao) 및 `[나중에 할게요]` (#btnGuestBackupLater) 2대 버튼 완전 배선.
  - 카카오 연동 직전 `localStorage.setItem("ourgoal_guest_profile", JSON.stringify(state.profile))` 무손실 스냅샷 보장.

### 3-1. 스토리지 원장화 3대 명세 (헌법 제2조 제4항 준수)
- **1호 (원격 DB 스키마 명세)**:
  - Supabase `goals`, `checkins`, `profiles` 테이블에 기존 게스트 목표 및 기록 upsert.
- **2호 (스마트 스토리지 분기 설계)**:
  - `localStorage.getItem("ourgoal_guest_profile")`에 최신 게스트 상태 스냅샷 저장.
  - `sessionStorage.setItem("ourgoal_guest_backup_nudged", "true")`로 세션 내 중복 방지.
- **3호 (4대 뷰 전파 배선도)**:
  - 계정 병합 후 `dispatchFullViewPropagation()` 호출을 통해 홈, 기록, 통계, 캘린더 4대 뷰 실시간 동기화.

### 3-2. 전수 인터랙션(버튼/클릭/입력) 명세표 (Zero-Dead-Click)
| UI 요소 (ID / Name) | 위치/화면 | 사용자 액션 | 기대 동작 (비즈니스 로직) | 예외 처리 및 사용자 피드백 |
| :--- | :--- | :--- | :--- | :--- |
| `#btnGuestBackupKakao` | 백업 넛지 바텀시트 | 터치/클릭 | 12ms 햅틱 후 게스트 프로필 스냅샷 저장, 카카오 OAuth(`startOAuthLogin("kakao")`) 시작 | 실패 시 토스트 안내 및 모달 유지 |
| `#btnGuestBackupLater` | 백업 넛지 바텀시트 | 터치/클릭 | 12ms 햅틱 후 모달 닫기, 세션 넛지 플래그 저장 | 안내 토스트("설정에서 언제든 보관 가능해요") |

### 3-3. 유저 데이터 100% 무손실 보존 규격 (Zero-Data-Loss Schema)
- **아바타 보존**: 게스트 모드에서 생성한 아바타 및 설정값을 회원 계정 `settings.savedAvatars` 및 `customAvatarUrl`로 100% 병합.
- **목표 데이터 보존**: 게스트 목표 ID와 마일스톤, 할 일을 신규 회원 원장으로 비파괴 합집합(Union Merge).
- **기록 데이터 보존**: 게스트 3개 이상의 체크인 기록을 신규 UID `checkins` 원장으로 100% 이관.
- **화면 구성 세팅값 보존**: 다크/라이트 테마 및 사용자 취향 설정 완전 계승.

## 4. [원칙 ④] 1~3 재검토 및 보완 (Review & Edge Cases)
- **비판적 자기 검토 및 약점/한계 인정**:
  - 체크인 즉시 모달이 뜨면 AI 코치 리포트나 축하 이펙트(폭죽 등)와 겹칠 수 있으므로, 400ms의 미세 딜레이를 두어 유저가 체크인 성공 피드백을 먼저 인지한 후 부드럽게 바텀시트가 올라오도록 설계함.
- **기존 기능과의 충돌 가능성 검토**:
  - 기존 로그인 유저는 `isGuest` 조건문에서 즉시 return되어 0% 영향.
- **엣지 케이스 (Edge Cases)**:
  - 네트워크 단절 상태: 오프라인에서도 게스트 데이터는 localStorage에 안전하게 보존되며, 카카오 연동 실패 시 안내 토스트 표출.
  - 카카오 로그인 취소 후 복귀: 기존 게스트 세션이 그대로 유지되어 데이터 유실 0건 보장.

## 5. [원칙 ⑤] 해결 절차 정리 (Procedure & State Propagation)
- **구체적 실행 시퀀스**:
  1. `checkGuestBackupNudge()` 함수 구현: 게스트 상태 및 기록 3개 이상 도달 시 백업 넛지 실행.
  2. `openGuestBackupNudgeModal()` 바텀시트 UI 마크업 및 스타일링.
  3. `#btnGuestBackupKakao`, `#btnGuestBackupLater` 12ms 햅틱 및 이벤트 리스너 배선.
  4. `saveQuickCheckin` 완료 시점에 `checkGuestBackupNudge()` 연동 (400ms 지연 호출).
  5. `restoreSessionAndEnter` 및 `loginWithDirectIdentifier`의 게스트 데이터 무손실 합집합 병합 로직 검증 및 보강.
- **화면 간 상호연동 전파 규격**:
  - 데이터 변경 발생 지점: 카카오 로그인 완료 및 게스트 데이터 마이그레이션.
  - 즉시 갱신되어야 할 연계 화면:
    1. 홈 화면 (`renderHome`): 회원 아바타 및 이관된 오늘 체크인 표시
    2. 기록 탭 (`renderRecordsScreen`): 게스트 3개 기록 온전 노출
    3. 통계 탭 (`renderStatsScreen`): 스트릭 및 카테고리 통계 즉시 반영
    4. 캘린더 탭 (`renderCalendar`): 이관된 일자별 체크인 닷 렌더링

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)
- **단일 실패점 (SPOF) 점검**:
  - 카카오 OAuth 팝업/리다이렉트 실패 시 게스트 데이터가 날아가지 않는가?
  - -> 리다이렉트 전 `ourgoal_guest_profile`에 온전히 스냅샷되므로 실패하거나 뒤로 가더라도 게스트 세션은 100% 안전함.
- **가정의 타당성 검증**:
  - 카카오 계정에 이미 과거 데이터가 있는 경우?
  - -> 게스트 데이터와 기존 계정 데이터가 비파괴 합집합(Union Merge)으로 합쳐져 단 1건도 덮어쓰여 삭제되지 않음.
- **재검증 결과 도출된 절차 수정/보완사항**:
  - 넛지 모달 표출 시 무조건 뜨는 대신 `sessionStorage`를 활용해 한 세션 내에서는 1회만 노출하여 유저 피로도 방지.

## 8. [원칙 ⑧] 막히는 지점 예상 및 재검증 트리거 (Blockers & Re-verification Triggers)
- **예상 블로커 1**: OAuth 리다이렉트 후 세션 복원 시 게스트 프로필 식별 지연 -> **대책**: `ourgoal_guest_profile`을 로컬스토리지에 불변 키로 보존하고 `restoreSessionAndEnter` 진입 시 즉각 대조.
- **예상 블로커 2**: 카카오 비즈니스 앱 미인가 환경에서의 테스트 -> **대책**: 미인가 환경에서도 폴백 모달 및 닉네임/이메일 안전 연동 브릿지 가동.
- **재검증 트리거**: 게스트 3회 달성 후 모달 미표출 또는 병합 시 데이터 누락 발생 시 즉시 원칙 ⑤로 돌아가 로컬스토리지 키 및 조건문 재검증.
