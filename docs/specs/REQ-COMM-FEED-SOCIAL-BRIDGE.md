## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
- **상민님 지시 원문**: "아워골 현재 시스템에서 이러한 문제들 모두 파악해봐" -> 전수 파악 후 1단계 착수 자동 승인.
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  - 소통 피드 화면에서 다른 회원이 작성한 멋진 실천 글과 사진이 올라와도, 작성자 아바타나 이름을 눌렀을 때 아무 반응이 없음 (`data-viewprof` 누락).
  - 피드 카드에서 취할 수 있는 액션이 [응원], [댓글], [신고], [차단]뿐이며, 해당 회원을 '동반자'로 추가하거나 '1:1 응원 DM'을 보내는 소셜 인터랙션이 전무함.
  - 모임장(팀장)이 피드에서 열정적인 유저를 발견해도 본인의 팀 목표로 영입(초대)할 수 없음.
  - 피드 카드 하단의 `🔗 공유` 버튼을 누르면 외부 OS 공유창이나 클립보드 복사만 실행되며, 인앱 동반자에게 DM으로 보내거나 활동 중인 팀 목표 톡방에 자랑하는 인앱 소셜 공유 파이프라인이 누락됨.
- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**: `feedPostHtml` 및 `renderCommFeed` 템플릿에서 아바타와 닉네임 엘리먼트에 프로필 모달 호출 리스너가 미배선되어 있고, 이미 구현된 `OurgoalTeamInviteComm.openUserProfileModal`과의 연동이 단절됨.
  - **2층 (구조/프로세스 부재)**: 피드와 동반자(Companion), 팀 목표(Team Goals)가 별개의 서브탭/모듈로 파편화되어 상호 연결 브릿지가 누락됨.
  - **3층 (시스템/유저 체감 괴리)**: 유저는 소셜 피드를 보며 "이 사람 대단하다! 친구 맺고 대화해보고 싶다"고 느끼지만, 막상 누르면 텍스트일 뿐이고 할 수 있는 것은 신고와 차단뿐이라 앱이 고립되고 삭막하게 느껴짐.
- **사용자 상황 및 페르소나**:
  - 실천 일지를 보고 동기부여를 얻어 함께 달릴 동반자를 찾고 싶은 일반 러너.
  - 열정적인 팀원을 영입해 팀 목표 완주율을 높이고 싶은 팀 모임장.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축 (Essence Axis)**: `E3 (동류 발견 · 소통)` / `FIX (상호작용 단절 복구)`
- **[본질] (Essence)**: 피드는 단순한 '읽기 전용 게시판'이 아니라 '동류를 발견하고 친구(동반자)를 맺고 팀으로 뭉치는 소셜 발화점'이어야 한다.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. 피드 카드 렌더링 시 아바타/닉네임에 클릭 이벤트나 시맨틱 버튼 속성이 누락됨.
  2. `viral-sharing.js`의 `shareContent`가 외부 Web Share API만 호출하도록 단방향 설계됨.
  3. 피드 카드 액션 바에 동반자 맺기, DM, 팀 초대 등의 빠른 소셜 액션 엔트리포인트 부재.
- **[중심] (Core Bottleneck & Anchor)**: 피드 아이템의 `user_id`, `name`, `avatar` 메타데이터를 기반으로 즉시 기존 `openUserProfileModal(user)`을 호출하고, 인앱 공유 모달(`openFeedShareModal`)을 배선하는 것.
- **[핵심] (Critical Safety & Termination)**: AI 가상 가이드 봇 글이나 익명 사용자 글에서도 에러 없이 안전하게 프로필을 열고(AI 봇 표시 및 친절 안내), 기존 329개 테스트와 헌법 13대 게이트 100% 무결성을 보존하는 것.
- **체감 가설 (User Experience Hypothesis)**:
  > *"사용자가 소통 피드에서 멋진 실천글을 발견하고 작성자 아바타나 이름을 탭했을 때, 즉시 그 사람의 목표와 히트맵을 보고 [동반자 추가]와 [1:1 DM]으로 연결되며, [공유]를 눌러 내 동반자나 팀 톡방에 바로 자랑할 수 있게 된다."*
- **기존 전체 기능 영향도 분석**:
  - 계정/로그인: 무영향 (게스트 모드 시 소프트 로그인 가드 정상 동작).
  - 홈 화면 및 스트릭: 무영향.
  - 기록/통계/캘린더 탭: 무영향.
  - 소통 탭(피드·동반자·모임): 고립되어 있던 3대 서브탭이 유기적으로 상호 연결됨.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**: 기존 피드 레이아웃이나 스타일을 임의로 깨거나 불필요하게 복잡한 다이얼로그를 추가하지 않는다.
- **해야 할 것 (Action)**:
  1. `feedPostHtml` 및 `renderCommFeed` 내 작성자 아바타/이름에 `data-viewprof="user_id"` 및 `cursor:pointer` 배선.
  2. 피드 카드 하단 액션에 `[🤝 동반자]` / `[✉️ DM]` 퀵 액션 또는 프로필 모달 연계.
  3. 모임장을 위한 `[👑 팀 초대]` 팝업 배선 (내가 운영하는 팀으로 원탭 스카우트).
  4. `🔗 공유` 클릭 시 인앱 공유 팝업 (`openFeedShareModal`):
     - ① 내 동반자에게 DM으로 공유
     - ② 내가 참여 중인 팀 목표 톡방에 공유
     - ③ 외부 SNS 공유 / 링크 복사 (기존 유지)

### 3-1. 스토리지 원장화 3대 명세 (헌법 제2조 제4항 준수)
- **1호 (원격 DB 스키마 명세)**: 기존 `companions`, `group_chat_messages`, `direct_messages` 테이블 및 profile settings를 그대로 활용 (스키마 변경 불필요).
- **2호 (스마트 스토리지 분기 설계)**: 공유 및 초대 시 텍스트/링크 메타데이터만 전송하므로 경량화 유지.
- **3호 (4대 뷰 전파 배선도)**: 동반자 추가 시 `renderCommScreen()` 및 동반자 탭 실시간 갱신.

### 3-2. 전수 인터랙션(버튼/클릭/입력) 명세표 (Zero-Dead-Click)
| UI 요소 (ID / Name) | 위치/화면 | 사용자 액션 | 기대 동작 (비즈니스 로직) | 예외 처리 및 사용자 피드백 |
| :--- | :--- | :--- | :--- | :--- |
| `[data-feedprof]` | 피드 카드 아바타/이름 | 클릭/탭 | 작성자 상세 프로필 모달(`openUserProfileModal`) 오픈 | 작성자 정보 누락 시 기본 프로필 생성 |
| `[data-feedcomp]` | 피드 카드 / 프로필 모달 | 클릭/탭 | 내 동반자로 즉시 추가 및 상태 저장 | 이미 동반자인 경우 "이미 등록된 동반자" 안내 |
| `[data-feeddm]` | 피드 카드 / 프로필 모달 | 클릭/탭 | 해당 유저와의 1:1 DM 채팅방 즉시 오픈 | 게스트인 경우 로그인 유도 |
| `[data-feedteamscout]` | 피드 카드 하단 | 클릭/탭 | 내가 운영 중인 팀 목표로 영입(초대) 모달 오픈 | 가입된 팀 없을 시 팀 개설 안내 |
| `[data-sharefeed]` | 피드 카드 푸터 | 클릭/탭 | 인앱 통합 공유 바텀시트(`openFeedShareModal`) 오픈 | 동반자 DM 전송 / 팀방 전송 / 외부 공유 선택 |

### 3-3. 유저 데이터 100% 무손실 보존 규격 (Zero-Data-Loss Schema)
- 기존 피드 글, 반응(Reactions), 댓글, 동반자 목록, 채팅 내역 100% 무손실 보존.

## 4. [원칙 ④] 1~3 재검토 및 보완 (Review & Edge Cases)
- **비판적 자기 검토**: 피드에 표시되는 사용자가 본인(나)인 경우 '동반자 추가'나 'DM' 버튼이 보이지 않도록 필터링 필수.
- **엣지 케이스**:
  - AI 가상 가이드 봇(SIM_PERSONAS): AI 봇 배지 정상 노출, 1:1 대화 시 AI 코칭 응답 모드로 자연스럽게 전환.
  - 게스트 모드 사용자: 동반자 추가나 DM 전송 시 `showGuestSoftAuthGate`로 안전하게 안내.
  - 참여 중인 팀이 없는 사용자: '팀 초대' 클릭 시 "내가 모임장인 팀 목표가 없습니다. 먼저 팀 목표를 개설해보세요!" 토스트 안내.

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)
