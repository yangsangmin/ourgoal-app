## 2. 본질 · 원인 · 중심 · 핵심 파악

- **본질**: 이것은 한 AI의 불성실이 아니라 **제도의 결함**이다. 헌법은 검증·판정·보고의 주어를 전부 "에이전트 스스로"로 적었고(제7조 제8항 L270·L276, 제4조 제1항 5호 L178), 독립 검증자 문구는 0건이다(측정: '스스로·자가·자체' 19회 — 주격 조사 "~자가" 오탐 10회를 뺀 값, '에이전트 스스로' 1회, 독립 검증자 0회). 합격 성적표가 기본값이고 실패를 적을 자리가 없는 제도에서는, 성실한 작업자도 거짓말쟁이가 된다.
- **원인** (헌법 정본 줄번호로 특정):
  1. **미리 채워진 합격**: [별표 1]을 "1글자도 바꾸지 말고 복제"(L321)하라면서 서식에 `100% 완결`·`PASS`×6·`PASSED`·`Errors: 0` 이 미리 적혀 있다(L336~367). 아무것도 안 재도 합격 성적표가 나온다.
  2. **실패 보고 금지**: 결함이 있으면 "보고서를 올리는 것을 즉시 중단하고 자체 수정·재캡처 후 보고"(L276). 제출되는 보고는 정의상 전부 PASS다.
  3. **미확인 금지**: `N/A·생략` 셀이 1개라도 있으면 반려(L371). '미확인·측정불가'는 정본에 0회. 헤드리스로 못 재는 칸(가상 키보드·폰트 130%)도 숫자를 지어내야 통과한다 → F9.
  4. **출제의 법적 위임**: 개정 즉시 작업 에이전트가 게이트에 단언을 넣도록 의무화(제14조 제8·9항 L511·L515, 버전대장 원칙 3). 게이트 assert 178개 중 57개는 "헌법에 그 제목 글자가 있는가"만 본다.
  5. **증거의 무결속**: 증거는 `file:///` 로컬 링크뿐. 해시·커밋·시각·URL 결속 규정 없음(L347·L352·L373) → F7·F8.
  6. **길목의 부재**: 검증기·헌법 정본은 승인선 보호 경로에 없고, 있어도 경고일 뿐 막지 않는다. 승인선 8개 전부 비차단.
- **중심**(병목): **"누가 합격을 말할 수 있는가"**. 지금은 작업자다. 이 한 점을 옮기면 나머지가 따라 움직인다.
- **핵심**(안전·종결 조건): 작업자가 쓸 수 있는 것은 **주장**(실행 가능한 형태)뿐이고, **판정**은 작업자가 고칠 수 없는 도구가 그 주장을 **다시 실행해서** 낸다. 증거는 "누가 만들었으니 믿는다"가 아니라 "법정이 재현했으니 믿는다".
- 3대 철학 심사: (무공해) 상민님께 가는 보고에도 도파민 낚시(100%·완벽·PERFECT)를 금한다. (RPG식 체감) 퀘스트 완료는 선언이 아니라 판정이다. (동류 연대) 결정권자와 수행자 사이의 신뢰는 검증 가능성 위에 선다.

## 3. 효과적 · 효율적 해결방식 결정

**하지 않는 것**: 금지 조항 추가(이미 금지돼 있었고 무력했다) · 더 큰 체크리스트 · 작업자에게 "정직하라"는 문장 · 같은 계열 LLM에게 제목만 보여주는 판정.

**하는 것 — 장치 5종 + 헌법 개정**. 새 코드는 전부 저장소 루트 `court/`(법정) 아래 신규 파일. 공유 대형 파일(index.html 등)은 건드리지 않는다.

### 장치 1. 판정 분리 — 법정(`court/judge.js`)
작업자는 `reports/<TASK>/claims.json` 에 **주장**만 쓴다. 법정이 base·head 두 커밋을 `git archive` 로 풀어 각각 구동하고 주장을 재실행해 판정한다.

| 주장 종류 | 법정이 하는 일 | 판정 |
|---|---|---|
| `fix`(결함 수정) | 시나리오를 base·head 양쪽에서 실행 | base 실패→head 통과 = **입증** / 양쪽 통과 = **기각(원래 결함 없음)** → F7 차단 / 양쪽 실패 = **미해결** |
| `feature`(기능 추가) | head 에서 실행(+base 대조) | head 통과 = 입증 / base 도 통과 = "이미 있던 기능" 표기 |
| `static`(설정값 등) | 구조 검사(JSON 경로 값·주석 제외 코드) | 최대 L1 |
| `unverified` | 실행 안 함 | **미확인**(합법) |

주장과 무관하게 항상 도는 **회귀 탐침**: ① 모듈 로드 탐침(vm, base 대비 새 예외=반려 → F5① 차단) ② 부팅 탐침(headless Chrome, base 대비 새 콘솔 예외=반려) ③ 표준 시나리오 묶음(모달 열고 닫기·탭 전환 등 → F5② 차단).

### 장치 2. 검증기 금고 — `court/vault.json` + `court/vault-check.js`
- **동결(frozen)**: `court/**`, 헌법 정본·AGENTS.md·rules.json·버전대장, `.github/workflows/**`, `.githooks/**`, `package.json` 의 scripts, `scripts/essence-gate.js`, `scripts/verify-*.js`. 제품 코드와 **같은 PR에서 바뀌면 반려**. 금고만 바꾸는 PR은 "금고 변경 — 상민님 결심 필요"로 표시.
- **추가 전용(append-only)**: `scripts/smoke-test.js` 등 테스트 파일. 검사 추가는 자유(TDD 흐름 보존), **기존 단언 삭제·완화는 반려** → F4 차단.
- **자가채점 검증기 불인정**: 제품 코드와 같은 PR에서 새로 생긴 `scripts/verify-*.js` 의 결과는 증거로 채택하지 않는다 → F1~F3 차단.
- CI는 **base 브랜치의 법정**으로 PR을 심사한다(`pull_request_target`, base 체크아웃의 `court/` 실행). PR이 잣대를 같이 고쳐도 소용없다 → F12 차단.

### 장치 3. 기계 증거 — `court/lib/scenario.js` + `court/evidence.js`
- 시나리오는 **닫힌 어휘**의 JSON이다: `goto·waitFor·click·type·key·back·setViewport·setOffline·seedLocalStorage·capture` 와 `expect`(visible·notVisible·textContains·count·attr·style·rect·noHorizontalOverflow·noExceptions·urlContains). **임의 JS 실행 없음** → 핸들러 직접 호출·스타일 주입 연출 불가(F8의 연출 차단).
- `click` 은 실제 마우스 입력(`Input.dispatchMouseEvent`)이고 대상이 화면에서 실제로 맞는지(`elementFromPoint`) 먼저 확인한다.
- 캡처마다 manifest 기록: 시나리오 id·단계·**커밋 SHA**·URL·뷰포트·시각·단언 결과·콘솔 예외·PNG sha256. 사후 교체는 해시 불일치로 드러난다. 더 근본적으로, 증거는 **법정이 재실행해 다시 만든다** — 작업자가 낸 PNG는 판정 근거가 아니다.

### 장치 4. 검증 등급 — `court/lib/grade.js` + `court/grade-floors.json`
| 등급 | 뜻(상민님용 표현) |
|---|---|
| L0 미확인 | 아직 확인 못 함 |
| L1 글자 확인 | 코드·설정에 그렇게 적혀 있음 |
| L2 실행 확인 | 그 코드를 실제로 돌려 봄 |
| L3 화면 확인 | 실제 브라우저에서 눌러 보고 결과를 확인 |
| L4 실계정 확인 | 실서버·계정 2개로 주고받아 봄 |
| L5 실기기 확인 | 실제 폰에서 해 봄 |

주장의 **분야(domain)**마다 필수 등급 하한이 있다(보안·RLS=L4, 다중 유저 실시간=L4, 성능=L3, 화면 동작=L3, 설정값=L1, 네이티브=L5). 하한 미달은 통과가 아니라 **"미확인(등급 미달)"**. 검증 스크립트의 최대 등급은 정적 분석으로 기계 산정한다(글자 검사뿐이면 L1 상한 — `classify118.js` 일반화). 보고서 첫 줄은 100%가 아니라 **등급 분포**다.

## 4. 1~3 재검토 및 보완

- **"같은 PC·같은 GitHub 계정이면 AI가 금고도 풀 수 있지 않나"** — 맞다. 단일 OS 계정·단일 gh 토큰 아래에서는 위조 불가능한 승인이 존재할 수 없다. 그래서 2단으로 나눈다. **1단(지금)**: 위협 모델은 악의적 공격자가 아니라 "압력 아래 가장 쉬운 길로 가는 LLM"이다. 정직한 길을 가장 쉬운 길로 만들고(미확인 합법화·보고서 자동 생성), 속이는 길은 시끄럽게 만든다(재실행 판정·금고·상태창 표시). **2단(`[손 필요]` 1회)**: AI용 GitHub 계정을 분리하고 CODEOWNERS 로 금고 경로에만 상민님 승인을 요구한다. 그러면 금고 변경 PR은 AI가 물리적으로 병합할 수 없다. 일반 기능 PR은 지금처럼 자동.
- **TDD 흐름을 막지 않는가** — smoke-test 는 추가 전용이라 검사 추가는 자유. 막는 것은 삭제·완화뿐.
- **법정이 거짓 합격을 내면?** — 법정 자체를 같은 방식으로 의심한다. `court/selftest/` 가 가짜 10종(가짜 Before, 로드 시 죽는 모듈, 금고 동시 수정, 단언 삭제, 등급 미달, 없는 브랜치, 금지 동작 시나리오, 증거 교체, 주석뿐인 구현, 정직한 수정 1건)을 주입해 **가짜는 전부 반려·정직은 통과**를 매 실행 확인한다. 법정 도구의 최대 등급도 같은 분류기로 산정해 보고서에 찍는다.
- **vm 탐침 오탐**(브라우저 API 부재로 원래 죽는 모듈) — 절대 기준이 아니라 **base 대비 회귀**만 반려. 양쪽 다 죽으면 "탐침 불충분(미확인)".
- **모든 주장에 시나리오를 요구하면 무겁지 않은가** — 시나리오 없는 주장은 자동으로 L0/L1 이 될 뿐 반려가 아니다. 정직하게 낮은 등급으로 보고된다. 반려는 거짓(기각)·회귀·금고 위반에만.
- **RLS·실시간·실기기** — 세션에서 못 잰다. 억지 PASS 금지, L0 로 남기고 필요한 손을 명시.

1. `court/` 기반 모듈: git·정적서버·Chrome CDP·시나리오 러너·증거 manifest.

## 6. 절차 재검증

- **단일 실패점**: Chrome 실행 실패 시 법정 전체가 죽으면 안 된다 → L3 항목만 "미확인(도구 불가)"로 강등하고 L1·L2·금고는 계속 판정. 종료코드 0=반려 사유 없음 / 1=반려 / 2=도구 오류(합격 아님).
- **도입 PR의 닭-달걀**: `pull_request_target` 은 base 의 워크플로를 쓰므로 법정을 도입하는 이 PR 자체는 법정 심사를 받지 않는다 → 도입 PR은 로컬에서 법정 자가시험 전수 통과 + 독립 검수로 갈음하고, 그 사실을 PR 본문에 적는다.
- **게이트 충돌**: `verify-integrity-gate.js` 검사 #12 는 '제16조' 신설을 금지 → 개정은 기존 조의 항 증설로만. 제목 문자열 단언 57개 중 개정 조항 제목에 걸리는 것은 같은 PR에서 갱신(금고 변경이지만 이 PR 자체가 상민님 결심 대상).
- **전역 AGENTS.md**: 에이전트들이 실시간으로 읽는 파일이므로 **채택 전에는 건드리지 않는다**. 저장소 3사본만 PR에 담고, 전역 동기화는 채택 직후 수행·cmp 로 확인.
- **안티그래비티와의 충돌**: main 작업트리·미푸시 커밋 2개는 읽기만 한다. ES-199 의 처리(되돌림·재작업)는 상민님 결심 사항으로 보고.

## 8. 막히는 지점 예상 및 재검증 트리거

- headless Chrome 이 CI(ubuntu-latest)와 로컬(Windows)에서 다르게 동작 → Chrome 경로 탐색을 환경변수·OS별로, 시나리오는 고정 뷰포트·외부 통신 차단·애니메이션 대기 상한.
- 앱 부팅이 Supabase 등 외부에 의존 → 외부 통신 차단 상태의 게스트 모드 부팅을 기준선으로. 차단 때문에 생기는 예외는 base·head 공통이므로 회귀 판정에 영향 없음.
- `gh pr merge`·브랜치 보호 변경은 분류기 차단 전례 → 우회하지 않고 `[손 필요]` 클릭 안내.
- essence-gate 의 티켓 게이트 → TICKETS.md 에 #TASK-ES-200 먼저 등록.
- 재검증 트리거: 자가시험에서 가짜가 1건이라도 통과하면 1절로 복귀해 그 구멍을 사실 표에 추가하고 설계를 고친다.
