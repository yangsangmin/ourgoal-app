## 1. 문제 정의 및 현상 파악 (문제해결 8원칙 ①)

### 1.1 현상
- 사용자가 아워골 앱의 [목표] 화면에서 상단의 [편집] 토글 버튼을 누르면 마일스톤 및 할 일의 편집 모드로 진입함.
- 마일스톤 제목, 날짜, 우선순위를 변경하거나 새로운 마일스톤/할 일을 추가하며 아래로 스크롤함.
- 편집을 완료한 후 저장을 확정하고 편집 모드를 빠져나가기 위해 화면 하단을 둘러보지만, **[완료] 또는 [저장] 버튼이 전혀 존재하지 않음.**
- 하단에는 오직 `[+ 마일스톤 추가]`, `[선택 삭제 / 전체 삭제]`, `[현 상태로 데이터 받기]`만 노출되어 사용자가 심리적 불안과 당혹감을 느낌.
- 상단으로 스크롤하여 올라가야만 상단 우측에 작은 회색/검정 알약 버튼으로 '완료'라는 글자가 보이나, 긴 목록에서 스크롤 이탈 시 인지하기 어렵고 직관적이지 않음.
- 또한, 목표 편집 모드임에도 불구하고 **목표 제목(Title)을 직접 수정할 수 있는 입력 필드가 전무**하여 제목 수정이 불가능함.
- 팀 연계 개인목표 및 팀 목표 화면 역시 편집 모드 진입 시 하단에 완료 버튼이 누락되어 있음.

## 2. 본질·원인·중심·핵심 파악 (문제해결 8원칙 ②)

### 2.1 본질
- 목표 관리는 아워골의 3대 본질 루프 중 하나인 **E1(목표 수립 및 체크인 루프)**의 기반 인프라임.
- 사용자가 목표와 마일스톤을 편집한 후 명확하고 안전하게 완료할 수 있어야 함.
- 헌법 제7조(4위 1체 배선 원칙: 마크업 + 리스너 + 비즈니스 로직 + 피드백)에 따라, 사용자가 언제 어디서든 편집을 완료하고 저장되었음을 즉시 확신할 수 있는 완결된 UX를 제공해야 함.

### 2.2 원인
1. **단일 상단 토글 의존**: 편집 토글이 상단 헤더(`goal-head-row`)에만 존재하고, 하단 또는 스크롤 추적 플로팅 완료 UI가 부재함.
2. **하단 액션바 결손**: 마일스톤 및 할 일 편집 후 자연스럽게 시선이 닿는 목록 하단에 완료 CTA가 없음.
3. **목표 제목 편집 인풋 누락**: 목표 칩 행(`goalChipRow`)에 순서 이동 버튼만 있고 제목 수정 인풋이 없어 목표 제목 변경이 불가능함.
4. **포커스 중 미반영 위험**: 입력창 타이핑 후 blur 이벤트 발생 전 상태에서 완료를 누를 때 최신 데이터 수집 로직 부재.

## 3. 해결 방식 및 아키텍처 (문제해결 8원칙 ③)

### 3.1 4대 핵심 해결책
1. **상단 완료 버튼 시인성 강화**:
   - 편집 모드 시 상단 버튼(`goalEditToggle`)의 텍스트를 `✓ 완료`로 변경하고 눈에 확 띄는 프라이머리 버튼 스타일로 즉시 식별 가능하도록 개선.
2. **목표 제목 직접 편집 필드 신설**:
   - 편집 모드 진입 시 화면 최상단(마감일시/공개범위 위)에 목표명 인풋 필드(`<input id="goalTitleInput" ...>`)를 제공하여 목표명 수정 즉시 지원.
3. **목록 하단 [✓ 편집 완료] 인라인 CTA 배치**:
   - 마일스톤 목록 바로 아래, `[+ 마일스톤 추가]` 버튼 옆/하단에 큼직한 프라이머리 `[✓ 목표 편집 완료]` 버튼을 배치하여 스크롤 종료 지점에서 원클릭 완료 지원.
4. **하단 고정 플로팅 완료 액션바 (Sticky Floating Action Bar) 탑재**:
   - 모바일 및 데스크톱에서 스크롤 위치와 무관하게 화면 하단에 항상 머무르는 `[✓ 편집 완료]` 플로팅 바 제공.
   - 현재 편집 중인 목표명 안내 문구와 함께 원터치 완료 버튼 제공.
5. **안전 저장 파이프라인 (Auto-Commit on Done)**:
   - 완료 버튼 클릭 시 활성화된 입력창의 값을 강제 커밋하고 `saveProfile()`을 호출하여 로컬스토리지 및 Supabase DB에 완벽 영속화.
   - 완료 즉시 `toast('목표 편집을 완료했어요')` 피드백 출력 및 편집 모드 해제(`state.goalEditMode = false`).
6. **팀 연계 개인목표 및 팀 목표 화면 전파**:
   - 팀 연계 개인목표(`teamLinkedGoalsView`) 및 팀 목표(`teamGoalsView`) 편집 모드에도 하단 완료 버튼 동일 배선.

## 4. 1~3 재검토 및 보완 (문제해결 8원칙 ④)
- **모바일 네비게이션 충돌 방지**: 플로팅 완료 바의 위치(`bottom`)를 하단 탭바(`nav`) 높이(약 64px)보다 위에 뜨도록 `bottom: 74px` 및 적정 `z-index` 설정.
- **데이터 유실 방지**: 완료 버튼 클릭 시 `document.activeElement.blur()`를 먼저 호출하고, 목표 제목 인풋 필드의 최신 값을 즉시 읽어 `goal.title`에 동기화.
