## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
- **상민님 지시 원문**:
  > 1. "맞춤 템플릿 기록 스톱워치 시간 옆에 ‘넣을 칸 누르고 ‘표에시간기입’누르면 바로입력됨’ 안내문구 추가. (빈칸에 사용자경험, 시인성 좋도록 알맞게 반영)"
  > 2. "맞춤 템플릿 스톱워치 표에 시간 기입(분:초 또는 초)할 수 있도록 안내문구 추가해"
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  1. 맞춤 템플릿 기록 모달에서 인앱 스톱워치로 시간을 측정한 후, 이 측정 시간을 표의 어느 칸에 어떻게 넣어야 하는지 초보 유저가 한눈에 알기 어려움.
  2. 스톱워치를 사용하지 않고 표의 시간 열에 손으로 직접 입력하려는 유저의 경우, 기입해야 하는 시간 형식(예: `분:초 또는 초`)이 빈칸(placeholder)에 안내되지 않아 어떤 형식으로 적어야 분석/통계에 연동되는지 혼란을 겪음.
  3. 셀을 선택하지 않은 상태에서 '표에 시간 기입' 버튼을 눌렀을 때 나타나는 안내 토스트와 화면 내 힌트 문구의 일관성이 부족함.
- **기저 층위 심층 분석**:
  - **1층 (인지 마찰)**: 스톱워치 시계와 조작 버튼 사이에 '선택한 셀로 들어간다'는 힌트가 즉각적으로 결합되어 있지 않음.
  - **2층 (입력 포맷 가이드 부재)**: 표의 시간 관련 컬럼 셀에 '분:초 또는 초 (예: 01:30 또는 90)' 형태의 친절한 placeholder가 없어 자유 텍스트 오입력 위험이 있음.
  - **3층 (안내 위계)**: 스톱워치 시계 옆 또는 컨트롤 바로 아래에 눈에 띄되 방해되지 않는 적절한 크기/색상의 안내 위계가 필요함.
- **대상 사용자 페르소나 및 발생 상황**:
  - 운동(세트별 휴식/수행시간), 공부(뽀모도로/순공시간), 업무(작업 소요시간) 맞춤 템플릿을 사용하는 모든 유저.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축 (Essence Axis)**: `[UI/UX & E1/E2]` (체크인/기록 루프 및 맞춤 데이터 측정 UX 완결)
- **[가목] 본질 (Essence)**:
  - 1. **직관적 가이드 (Intuitive Affordance)**: "넣을 칸 누르고 '표에시간기입' 누르면 바로입력됨" 원리를 1초 만에 이해하도록 시각 힌트 제공.
  - 2. **유연한 시간 형식 (Flexible Formats)**: 스톱워치 자동 입력뿐 아니라 수동 입력 유저를 위해 '분:초 또는 초' 형식을 명시.
  - 3. **안전한 피드백 (Safe Feedback)**: 타깃 셀 미선택 시 명확한 유도 토스트 및 타깃 셀 존재 시 즉시 하이라이트 플래시 피드백.
- **[나목] 원인 (Root Causes)**:
  - 스톱워치 조작부와 노션 스타일 표 영역이 분리되어 있어, 두 컴포넌트 간의 상호작용 연결고리가 시각적으로 충분히 설명되지 못함.
- **[다목] 중심 (Core Bottleneck)**:
  - `renderStopwatchWidgetHtml` 내 안내 힌트 텍스트 완결 및 `renderRowsHtml` 내 시간 관련 컬럼의 동적 placeholder 분기 로직.
- **[라목] 핵심 (Critical Anchor)**:
  - 원문 문구 정확성(`💡 넣을 칸 누르고 ‘표에시간기입’ 누르면 바로입력됨 (분:초 또는 초)`), 375px 모바일 레이아웃 무결성, 시간 컬럼 빈칸 placeholder 개선.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**:
  - 표의 기존 데이터 구조나 저장 로직을 뒤흔드는 무리한 스키마 변경 금지.
  - 모바일 화면을 과도하게 차지하는 거대한 경고창 팝업 금지.
- **해야 할 것 (Action)**:
  - `renderStopwatchWidgetHtml` 내에 `id="swInjectHint"` 안내 박스를 강화하고 원문 취지 반영:
    `💡 넣을 칸 누르고 ‘표에시간기입’ 누르면 바로입력됨 (분:초 또는 초 기입)`
  - `renderRowsHtml`에서 시간 관련 컬럼(컬럼명에 '시간', '타임', '휴식', '초', 'time', 'duration' 등이 포함)의 placeholder를 `분:초 또는 초 (예: 01:30)`로 스마트 분기하여 빈칸 사용자 경험 극대화.
  - 셀 미지정 시 토스트 안내문구를 힌트 문구와 100% 일치시켜 사용자가 즉시 인지하도록 배선.
  - `window.renderStopwatchWidgetHtml` 전역 노출.

## 4. [원칙 ④] 구현과정 가상 시뮬레이션 (Simulation)
1. **시나리오 A: 신규 유저가 스톱워치 템플릿 열람**:
   - 모달 상단 스톱워치 시계 옆/아래에 `💡 넣을 칸 누르고 ‘표에시간기입’ 누르면 바로입력됨 (분:초 또는 초 기입)`이 부드러운 톤(`var(--ink-faint)`)으로 노출됨.
2. **시나리오 B: 특정 셀 클릭 후 [표에 시간 기입] 클릭**:
   - 클릭된 셀에 스톱워치 현재 측정값이 즉시 기입되고, 1.4초간 `cell-highlight-flash` 효과로 기입 위치를 시각 확인.
3. **시나리오 C: 셀 미선택 상태에서 [표에 시간 기입] 클릭**:
   - 빈 시간 셀이 있으면 가장 첫 번째 빈 시간 셀에 자동 기입, 빈 셀이 없으면 `넣을 칸 누르고 ‘표에시간기입’ 누르면 바로입력됨 (분:초 또는 초)` 토스트 피드백 표출.
4. **시나리오 D: 유저가 표의 시간 셀을 직접 터치하여 수동 입력**:
   - placeholder에 `분:초 또는 초 (예: 01:30)`가 은은하게 안내되어 있어 어떤 형식으로 적어야 할지 즉시 파악.

## 5. [원칙 ⑤] 예외 · 엣지케이스 · 실패조건 대비 (Edge Cases)
- **엣지케이스 1: 375px 모바일 좁은 화면**:
  - `sw-inject-hint`에 `line-height: 1.4`, `font-size: 0.75rem`을 적용하여 텍스트 줄바꿈 시에도 오버플로우가 0px로 유지됨.
- **엣지케이스 2: 템플릿에 시간 컬럼이 없는 경우 (예: 체크리스트형)**:
  - 일반 컬럼은 기존 컬럼명 placeholder를 그대로 유지하고, 시간 관련 키워드가 매칭될 때만 특화 placeholder 제공.

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)
- **단일 실패점 (SPOF) 점검**: 안내문구 추가 및 placeholder 분기는 순수 렌더링 레이어의 개선으로, 기존의 데이터 동기화(`syncCurrentRowsFromDOM`)나 저장 로직(`executeSave`)에 아무런 부작용을 주지 않음.
- **가정의 타당성 검증**: 스톱워치 안내문구와 표의 빈칸 placeholder가 상호 보완되어, 스톱워치 자동 주입 유저와 수동 입력 유저 모두의 페인포인트를 해결함.
- **재검증 결과 도출된 절차 보완**: 독립 단위 테스트(`tests/stopwatch-table-hint.test.js`)를 통해 스톱워치 위젯 마크업, 안내 힌트 텍스트, 표 셀 placeholder 분기 조건을 엄밀히 단언함.
