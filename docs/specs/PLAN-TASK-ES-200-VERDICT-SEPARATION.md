## 1. 문제 정확히 파악

REQ 1절의 측정 사실(F1~F14)에 설계 검수 3종(우회로 17건·결정권자 체감 16건·마찰/실현성)의 결과를 더해, 개정이 닿아야 하는 곳을 확정한다.

- 안티그래비티는 `vercel --prod` CLI 로 PR·CI 를 건너뛰고 운영 서버에 직접 배포한 기록이 11일간 30건 있다(작업 로그 실측). 5A 프리뷰를 CLI 로 하라는 헌법(L381) 때문에 PC 에 Vercel 인증이 상시 남아 있어야 한다.

### 3-1. 신설 조문(전문)

**[A1] 제7조 제10항 [판정 분리 — 법정(Court)]** — 제9항 뒤에 신설
1. 1호: 작업자(사람·AI 불문)는 주장만 쓴다. 판정은 법정이 한다. 주장은 `reports/<작업번호>/claims.json` 에 실행 가능한 형태(지시 항목, 주장 문장, 걸린 파일, 시나리오)로 적는다.
2. 2호: 법정의 판정이란 작업 세션 밖에서 실행된 결과만을 말한다. 곧 GitHub 가 기준 브랜치(base)의 `court/` 로 실행한 court 검사 결과이며, 보조로 커맨드센터가 저장소 밖 고정본으로 실행한 결과다. 작업자가 자기 세션에서 돌린 법정 출력은 예비 점검이며, 어디에도 판정·통과라고 옮겨 적을 수 없다.
3. 3호: 법정과 금고([별표 3])의 파일을 고쳐서 돌린 결과는 어떤 용도로도 제출할 수 없다. 법정이 틀렸다고 보면 고치지 말고 주장 칸에 법정 이의를 적는다. 이의는 별도 PR 과 `[결심 필요]`로만 처리한다.
4. 4호: 작업이 되었다·안전하다·문제없다는 뜻을 전하는 모든 표현은 낱말과 무관하게 작업자 주장 칸에만 쓸 수 있다. 법정은 그 칸에 "아래는 작업자의 말이며 확인된 것이 아닙니다"를 붙인다.
5. 5호: 법정은 주장과 무관하게 기준 커밋과 작업 커밋을 나란히 띄워 되던 것이 고장 났는지(부품 로드·앱 띄우기·표준 점검)를 직접 본다. 결함 수정 주장은 같은 시험이 기준 커밋에서 지정한 증상으로 실패하고 작업 커밋에서 통과할 때에만 확인됨으로 판정한다. 기준 커밋에서도 통과하면 고칠 게 없었음으로 판정하며 이는 위반이 아니다. Before 증거는 법정이 만든다. 작업자는 Before 를 제출하지 않는다.
6. 6호: 법정 도구가 고장 나 심사하지 못하면 판정은 심사 못 함이다. 통과가 아니며 배포를 묻지 않는다.
7. 7호: 확인 수준은 작업자가 적는 값이 아니라 법정이 실제로 한 일에서 나온다([별표 2]). 주장 파일의 어떤 칸도 확인 수준을 올리지 못한다. 법정이 잴 수 없는 수준(진짜 계정끼리 주고받아 봄·진짜 폰에서 해 봄)은 `[손 필요]`로만 남긴다.
8. 8호: 금고와 제품 코드를 한 PR 에서 함께 바꾸는 예외는 법정을 도입하는 #TASK-ES-200 PR 1건뿐이며 선례가 되지 않는다.

**[A2] 제4조 제1항 1호 다목 [자가채점 금지]** — 나목 뒤에 신설
- 자기가 만든 검증 스크립트·시험으로 자기 작업의 합격을 선언하는 행위, 제품 코드와 채점 기준(금고)을 한 변경 묶음에서 함께 고치는 행위, 기존 단언을 지우거나 고쳐서 통과시키는 행위를 금지한다. 작업과 함께 새로 만든 검증 스크립트의 출력("N/N 통과" 등)은 증거로 채택하지 않는다. 테스트는 추가만 할 수 있다.

**[A3] 제9조 제4항 [돌려보낸 로컬 병합의 원상회복]**
1. 법정이 돌려보낸 커밋이 로컬 main 에만 있고 원격에 없으면 원상회복은 승인선에 해당하지 않는다. 묻지 않고 한다.
2. 주체는 그 커밋을 병합한 작업 세션이다. 그 세션이 끝났거나 15분 넘게 응답이 없으면 돌려보냄을 발견한 세션이 작업 연계 기록에 담당을 표시하고 한다. 한 시점에 한 세션만 한다.
3. 방법: 끝 커밋에 보존 표식(태그 `court-rejected/<작업번호>/<sha7>`)을 단다. 작업물은 지우지 않는다. main 작업 폴더에 커밋 안 된 추적 파일 변경이 있으면 건드리지 않고 목록을 보고한다(이 경우에만 `[결심 필요]`). 없으면 `git reset --keep origin/main` 을 실행한다. `--hard`, 강제 푸시, 브랜치 삭제는 금지한다.
4. 이미 원격 main 에 올라간 커밋의 되돌림은 바깥 행위다. `[결심 필요]`와 되돌림 PR 로만 한다.
5. 재작업은 보존된 브랜치에서 이어가고 재심을 통과한 뒤에만 다시 올린다.

**[A4] 제9조 제5항 [배포 단일 경로]**
- 프로덕션 배포는 원격 main 으로의 PR 병합(git 연동 배포)으로만 한다. `vercel --prod` 등 CLI·API 로 운영 서버에 직접 올리는 행위는 브랜치 보호와 법정을 건너뛰는 불법 배포다. 프리뷰(5A)는 작업 브랜치를 올렸을 때 Vercel 이 그 커밋에 대해 자동으로 만든 것만 쓴다. 작업용 PC 에는 Vercel CLI 로그인 상태를 두지 않는다.

**[A5] 제14조 제6항 3호** — 2호 뒤에 신설
- 법정의 확인 수준 하한표와 금고 목록은 제7조 제10항의 [별표 2]·[별표 3]으로 본 헌법에 싣는다. `court/grade-floors.json`·`court/vault.json` 은 그 기계 판독용 사본이며 별도 규칙이 아니다. 둘이 다르면 헌법이 우선하고 법정 자가시험은 불일치로 실패한다.

**[A6] [별표 2]·[별표 3]** — 제7조 제10항 바로 뒤
- [별표 2] 확인 수준(6단: 확인 못 함 / 글자만 봄 / 부품만 돌려 봄 / PC 화면에서 눌러 봄 / 진짜 계정끼리 주고받아 봄 / 진짜 폰에서 해 봄)과 분야별 하한 표 — `court/grade-floors.json` 의 domains·pathFloors·keywordFloors 를 그대로 표로 옮긴다.
- [별표 3] 금고 목록 — `court/vault.json` 의 frozen·frozenJsonKeys·appendOnly 를 그대로 옮긴다.

- `verify-integrity-gate.js` 검사 #12(제16조 금지)를 어기지 않는지, 제목 단언이 깨지지 않는지 `npm test` 로 확인한다.
- 법정 자가시험에서 가짜가 1건이라도 통과하면 구현으로 복귀한다.
- 도입 PR 자체는 `pull_request_target` 특성상 법정 심사를 받지 못한다 → 로컬 자가시험 전수 통과 + 독립 검수로 갈음하고 PR 본문에 그 사실을 적는다.

## 8. 막히는 지점 예상 및 재검증 트리거

- 제목 단언 57개 중 개정으로 깨지는 것이 많으면: 제목 문자열은 가급적 유지하고 본문만 바꾼다(B1 의 항 제목만 불가피하게 변경).
- 공개 저장소 + `pull_request_target`: 포크 PR 은 심사하지 않는다(필수 체크 미충족으로 병합 불가). 심사 잡은 시크릿·쓰기 권한이 없다.
- CODEOWNERS 는 단일 계정에서는 자기 승인이 불가능해 금고 PR 이 영구히 막힌다 → `require_code_owner_reviews` 는 **2단 완료와 동시에** 켠다. 그 전에는 branch-protection.json 에 값만 준비하고 적용하지 않는다.
- 재검증 트리거: 독립 검수가 "가짜가 통과하는 경로"를 1건이라도 재현하면 자가시험에 그 가짜를 추가하고 구현을 고친다.
