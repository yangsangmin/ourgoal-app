# REQ-ui-ux-radical-renewal: 아워골 UI/UX 진단 및 차세대 전면 개편 요구사항 정의서

- **문서 버전**: v1.0 (2026-09-18)
- **작성 기준**: 아워골 최고 헌법(AGENTS.md) 제2조 문제해결 8원칙 (REQ 1회차)
- **귀속 축**: E1 (체크인 루프) · E2 (기록 회고 루프) · E3 (동류 소통 루프) 전면 통합

---

## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)

### 1.1 상민님 지시 원문
> "아워골의 모든 지식기반을 활용해서, 현재 아워골의 ui/ux를 진단하고 획기적으로 전면 개선하기 위해서 개선된 아워골의 모습을 기획하고 그래픽화해줄 수 있어? 진행"

### 1.2 기저 층위별 심층 분석
- **1층 [시각적 피로도 및 정보 과밀]**: 
  현재 아워골 화면(홈, 기록/통계, 목표)은 수많은 기능 칩, 안내 배너(활용법, 홈구성, 평가해주기, 테스터B, 1초 복구, 데이터 가져오기 배너 등), 날 것의 이모지, 하드코딩된 인라인 스타일이 혼재되어 유저가 앱을 열었을 때 어디를 봐야 할지 모르는 인지 과부하(Cognitive Overload)를 유발함.
- **2층 [3대 본질 루프의 단절과 마찰]**:
  - E1 체크인 루프: 3초 만에 끝나야 할 체크인 영역에 AI 모드 버튼, 테마 선택 바, 음성/사진/불러오기 버튼이 엉켜 있어 체크인 진입 장벽이 높아짐.
  - E2 5단위 회고: 기록과 통계, 캘린더가 파편화되어 있고 성취감("기록이 만든 실질적 차이")을 직관적으로 증명하는 비주얼 피드백이 약함.
  - E3 동류 소통: 무공해 소셜의 가치인 "나와 같은 목표를 달리는 페이스메이커와의 연대"가 아닌 단순 게시판 형태로 노출됨.
- **3층 [아바타 및 히트맵 킬러 에셋의 소외]**:
  16개 MBTI × 20개 테마로 구축된 독보적 자산인 **320종 아바타 페르소나**가 상단바의 46px짜리 작은 원 안에 갇혀 있고, 유저의 일일 성취를 상징하는 **히트맵(Heatmap)**이 통계 탭 3번째 슬라이드 깊숙이 숨어 있어 매일 방문할 시각적 보상 동력이 반감됨.

### 1.3 페르소나 및 발생 상황
- **갓생을 꿈꾸며 작심삼일을 극복하려는 2030 유저**: 첫 화면의 복잡성에 질려 3일 이내에 앱을 이탈하는 현상 발생.
- **체계적인 자기 성취 궤적을 확인하고 싶은 파워 유저**: 히트맵과 5단위 성취 지표를 즉각 확인하고 자랑하고 싶으나 탐색 경로가 김.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)

- **[가목] 본질 (Essence)**:
  아워골의 본질은 "고립된 작심삼일을 끝내는 AI 페이스메이커이자 무공해 소셜 넛지"이다. 따라서 UI/UX의 본질은 복잡한 도구 나열이 아니라, **"열자마자 3초 만에 몰입하고, 기록 직후 확실한 도파민 보상을 받으며, 내 성장 궤적(아바타·히트맵)과 동료의 온기를 체감하는 평온한 성소(Focus Sanctuary)"**여야 한다.
- **[나목] 원인 (Root Causes 3가지)**:
  1. **기능 추가 누적형 UI 레이어링**: 신규 피처(테스터 버튼, 복구 링크, 다양한 가이드)가 생길 때마다 상단/하단에 배너로 덧붙여져 종합 IA(정보구조)가 붕괴됨.
  2. **도구 언어 및 개발자 중심 인터페이스 잔재**: '노션 DB 규격', 'AI 모드', '스토리지/샘플로드' 등 내부 기술 용어가 유저 대면 UI에 노출됨.
  3. **시각적 정체성 및 디자인 시스템 통제력 약화**: Pretendard 폰트와 일부 CSS 변수는 존재하나, 통일된 네오-글래스모피즘(Glassmorphism)과 반응형 마이크로 인터랙션 규격이 부재함.
- **[다목] 중심 (Core Bottleneck)**:
  체크인 루프의 마찰 계수와 홈 화면의 주의 분산. 사용자가 홈에 들어왔을 때 가장 먼저 해야 할 "단 하나의 행동(Single Primary Action)"이 시각적으로 명료하게 각인되지 않는 것이 핵심 병목.
- **[라목] 핵심 (Critical Anchor)**:
  기존 유저의 데이터(목표, 체크인, 아바타, 스트릭) 100% 무손실 보존과 3대 본질 루프(E1/E2/E3)의 완벽한 4위 1체 배선. 시각적 전면 개편이 기존 비즈니스 로직을 단 1개도 파괴하지 않는 '비파괴 진화(Non-destructive Evolution)'.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)

### 3.1 하지 말 것 (Exclusions & Prohibitions)
- 기존 Supabase DB 테이블 스키마나 RPC 함수 삭제/파괴 금지.
- 필수 기능(아바타, 히트맵, 5단위 회고, 템플릿 마켓, 크레딧 등)의 기능적 누락 금지.
- 화면에 또 다른 배너나 모달을 덧대는 땜질식 UI 수정 금지.

### 3.2 할 것 (Radical Redesign Strategy)
1. **아워골 3.0 "Focus, Flow & Spark" UI/UX 아키텍처 수립**:
   - **홈 (Focus Sanctuary)**: 살아있는 아바타 + 미니 히트맵 펄스 + 3초 원터치 체크인 + 오늘의 퀘스트 나침반 단일 흐름.
   - **기록 & 히트맵 (Achievement Gallery)**: 5단위 회고 세그먼트(오늘·주·월·년·직접) + 대형 인터랙티브 히트맵 + 성취 내러티브 카드 전진 배치.
   - **목표 & 로드맵 (Vision Roadmap)**: 산 정상 오르기 형태의 마일스톤 비주얼라이저 + C2C 템플릿 마켓.
   - **동류 라운지 (Peer Lounge)**: 실시간 무공해 레이더 + 1-Tap 응원 넛지 + 목표 구조 가져오기.
   - **마이 & 아바타 스튜디오 (Twin Studio)**: 320종 MBTI 아바타 룸 + 크레딧 지갑 + "앱을 내맘대로!" 위젯 커스텀.
2. **최고 화질 모바일 앱 그래픽 시안 생성 (AI High-Fidelity Mockup Generation)**:
   - 홈 화면, 히트맵/성취 화면, 아바타 스튜디오, 동류 라운지 고해상도 모바일 뷰 렌더링.
3. **인터랙티브 UI 컴포넌트 프로토타입 구현**:
   - 실제 동작 가능한 모던 토큰 기반의 시각적 프로토타입 아티팩트 제작.

### 3.3 스토리지 원장화 3대 명세 (헌법 제2조 제4항)
1. **원격 DB 스키마**: 기존 goals, checkins, users, direct_messages, team_pings 스키마 무손실 승계.
2. **스마트 스토리지 분기**: 신규 그래픽 및 시안 에셋은 관제센터 및 로컬 아티팩트 폴더 영속화.
3. **4대 뷰 전파 배선도**: renderHome, renderRecordsScreen, renderStatsScreen, renderCalendar 동시 동기화 파이프라인 준수.

## 4. [원칙 ④] 1~3 재검토 · 보완 (Critical Review & Edge Cases)

- **비판적 재검토**:
  - 화려한 UI 개편이 오히려 로딩 속도를 저하시키거나 저사양 스마트폰에서 버벅거리지 않는가?
  - ➔ CSS GPU 가속(transform: translate3d, backdrop-filter 최적화) 및 순수 CSS/SVG 기반의 경량화 유지.
- **엣지 케이스 점검**:
  - 비로그인 게스트 사용자 진입 시 빈 화면/에러 방지 ➔ 게스트 데모 데이터 및 온보딩 튜토리얼 뷰 제공.
  - 다크 모드 / 라이트 모드 전환 시 대비율(WCAG AAA) 100% 충족.
  - 320종 페르소나 아바타 중 미생성 유저에 대한 기본 아바타 폴백 보장.

## 5. [원칙 ⑤] 해결 절차 정리 (Implementation Procedure)

1. **[단계 1] 아워골 UI/UX 심층 진단서 및 IA 재구조화 명세서 작성** (현재 화면 5대 영역별 정밀 해부).
2. **[단계 2] 차세대 아워골 3.0 디자인 시스템 & 와이어프레임 설계** (색상 토큰, 타이포그래피, 컴포넌트 규격).
3. **[단계 3] 4대 핵심 화면 고해상도 그래픽 시안 생성** (generate_image를 통한 9:16 모바일 렌더링).
4. **[단계 4] 인터랙티브 UI 프로토타입 아티팩트 구현** (브라우저에서 직접 조작 가능한 인터랙티브 비주얼).
5. **[단계 5] Tri-Sync 3자 상호 동기화 & 관제센터 저널 기록** (옵시디언, 노션, 커맨드센터 정합성 완료).

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)

- **SPOF 점검**: 이미지 생성 모델 실패 시 그래픽 누락 위험 ➔ 정교한 프롬프트 및 폴백 이미지/SVG 인라인 렌더링 병행.
- **절차 수정사항 (재검증 반영)**:
  - 단순 텍스트 기획서로 끝내지 않고, 상민님이 시각적으로 즉각 체감할 수 있도록 **[1] 고화질 그래픽 렌더링 이미지 4종 + [2] 인터랙티브 Generative UI 아티팩트**를 동시에 산출물로 제공하도록 절차를 강화함.

## 7. [원칙 ⑦] 단계별 실행 기준 (Success Metrics & Criteria)

- **진단 충실도**: 현재 아워골 5대 탭 전수 해부 및 10대 핵심 결함/개선 포인트 도출 완료.
- **기획 완결성**: 3대 본질 루프(E1/E2/E3) 및 상민 대표 직접 설계 7대 피처가 100% 반영된 차세대 IA 완비.
- **그래픽 시안 퀄리티**: 최고 화질의 9:16 모바일 UI 렌더링 이미지 4종 생성 및 아티팩트 임베드 완료.
- **3자 동기화 무결성**: Tri-Sync check 100% PASS 및 journal.jsonl 해시 체인 보존.

## 8. [원칙 ⑧] 막히는 지점 예상 및 재검증 트리거 (Blockers & Re-verification Triggers)

- **블로커 시나리오 1**: 그래픽 생성 시 텍스트 왜곡이나 레이아웃 불일치 발생 ➔ 이미지 프롬프트에 UI 콤포지션 규칙 및 테마 명시, 보조 인터랙티브 웹 UI 아티팩트로 보완.
- **재검증 트리거**: UI 기획 내용 중 상민님의 7대 핵심 기능(크레딧 보상, 앱을 내맘대로 등)이 누락될 경우 즉시 [원칙 ③]으로 되돌아가 기획안 재보강.
