## 1. [원칙 ①] 문제 정확히 파악
- **상민님 지시 원문**: "아워골 소통창에서 동반자 닉네임검색시 실제 사용자의 닉네임을 검색해도 검색이 안되는데 원인파악하고, 관련된 문제사항 모두 확인하고 알기쉽게 표형태로 보고해." → 후속: "권장안 더 구체적으로 가져와 문제해결 8원칙 적용해서".
- **현재 발생하는 문제**: 소통탭 → 동반자 → 닉네임 검색에 실제 가입 회원의 정확한 닉네임을 입력해도 "찾지 못했어요"만 뜨고 항상 0건.
- **사용자 상황**: 실제 서비스 이용자가 지인의 아워골 닉네임을 알고 있어도 동반자로 추가할 방법이 없어 E3(동류 소통) 축의 핵심 진입점이 막혀 있다.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악
- **근본 원인**: `public.users` 테이블 RLS가 2026-09-03부터 `auth.uid() = 본인 id`(본인 행만 select 허용)로 설정되어 있음(dev_log.md 2026-09-03·2026-09-10 기록). 2026-09-15(#TASK-ES-104) 이후 추가된 검색 기능(`js/team-invite-comm.js`)이 이 RLS를 우회하는 서버 경로 없이 anon/authenticated 클라이언트 키로 `public.users`를 직접 `.from('users').or(display_name.ilike,...)` 조회 — DB가 타인 행 자체를 반환하지 않아 검색어 일치 여부와 무관하게 0건.
- **본질 축**: FIX (기존 본질 기능 E3의 결함 수정).
- **체감 가설**: "실제 사용자가 소통탭에서 지인의 정확한 닉네임을 입력했을 때, 검색 결과가 나와 동반자로 추가하고 상호 응원을 시작할 수 있어야 한다."
- **기존 전체 기능 영향도 분석**:
  - 계정/로그인: 영향 없음. `users` 테이블 RLS(본인 행만) 정책 자체는 그대로 유지.
  - 홈/스트릭: 영향 없음.
  - 기록/통계/캘린더: 영향 없음.
  - 컴플라이언스 테스트: `[#TASK-ES-106]`이 옛 결함 패턴(`from('users')` 존재, `display_name.ilike` 존재)을 "정상 배선"으로 잘못 검증하고 있었음 — 함께 갱신 필요.

## 3. [원칙 ③] 효과적·효율적 해결방식 결정

### 3-1. 세부 기능 요구사항
- **FR-01**: 기존 `users` 테이블 RLS(본인 행만 select)는 변경하지 않는다 — 전 컬럼(bio·region 등) 노출을 막기 위함.
- **FR-02**: 검색에 필요한 최소 필드(id, nickname, avatar_url, bio, interests)만 반환하는 `SECURITY DEFINER` RPC `search_users_by_nickname(p_query)`를 신설한다. 검색자 본인·`is_bot=true` 계정은 결과에서 제외한다. anon 실행 권한은 revoke, authenticated만 grant.
- **FR-03**: 클라이언트는 `.from('users')` 직접 select 대신 위 RPC만 호출한다.
- **FR-04**: 검색 실패를 "게스트(비로그인)", "쿼리 오류", "결과 없음" 3가지로 구분해서 사용자에게 보여준다(기존엔 전부 "찾지 못했어요"로 뭉뚱그려져 원인 진단 불가).

## 4. [원칙 ④] 1~3 재검토 및 보완
- **기존 기능과의 충돌 검토**: `showGuestSoftAuthGate`, `companions` 배열, `_userCache` 등 기존 동반자 추가/프로필조회 로직은 그대로 재사용 — 검색 결과 객체 shape(id/nickname/avatar/intro/level/streak/theme)를 그대로 유지해 하위 호출부(추가 버튼, 프로필 모달)를 건드리지 않는다.
- **엣지 케이스**:
  - 검색어에 `%`, `_`, `,` 등 특수문자 포함: RPC 내부에서 `%`/`_`를 이스케이프 처리(ilike escape 절)해 쿼리 파손 방지.
  - 빈 검색어로 RPC 직접 호출(비정상 경로): RPC 내부에 `length(trim(p_query))>=1` 가드로 전체 테이블 훑기 방지.
  - 게스트(비로그인) 사용자: RPC 실행 전 클라이언트에서 차단하고 로그인 안내(추가로 anon revoke가 이중 방어).
  - 봇 계정(`is_bot=true`): RPC에서 결과 제외.
  - 검색자 본인: RPC에서 결과 제외(기존엔 RLS 때문에 본인만 우연히 검색되던 혼란 해소).
