## 1. [원칙 ①] 문제를 정확히 파악한다

region 모드는 구역에 든 토큰 가운데 `OurgoalTemplateCredit` 이나 `OURGOAL_CONFIG` 가 있으면 설정과 무관하게 멈춘다(#919 — 「돈 근처는 글자 그대로 자리만」 한도와 결심 대기 때문에 걸어 둔 잠금). 그 두 곳이 IIFE 에 남아 finalize 의 전제를 막고, 초기화 블록은 `sb` · `state` 를 맨이름으로 읽어 그 둘의 상태 이전까지 막는다(설계 6.4 표 3 ①②). 결심 2 가 「접두 말고는 한 글자도 안 바꾸고 옮긴다」를 승인했으므로 잠금을 풀 근거가 생겼다. 다만 풀리는 방식이 문제다 — 설정 한 줄 없이 풀리거나, 다른 잠긴 이름까지 함께 풀리면 안 된다.

## 2. [원칙 ②] 본질·원인·중심·핵심

- **본질**: 잠금은 그대로 두고, 승인된 이름을 **이름과 근거를 적어야만** 지나가게 한다.
- **원인**: 잠금이 스위치 없이 코드에 박혀 있었다(풀 길이 없었다).
- **중심**: `allowGuarded` — 설정 맨 위의 `[{ name, approval }]`. 잠금 검사가 「잠긴 낱말이 든 토큰마다 허용 지도에 그 이름이 있는가」를 본다.
- **핵심**: 「조용히 풀리지 않는다」를 기계로 만드는 것 — ① 적지 않으면 예전 글자 그대로 멈춘다 ② 목록 밖 이름은 적어도 안 받는다 ③ 근거 글자가 없으면 안 받는다 ④ 쓰이지 않는 허용은 안 받는다 ⑤ 적은 것은 출력과 메타에 남는다 ⑥ 허용돼도 접두 밖의 글자가 바뀌면(줄임 속성 확장) 멈춘다.

## 3. [원칙 ③] 해결 방식 — 사양

```json
{ "task": "TASK-ES-6xx", "slot": "HO", "mode": "region", "label": "…",
  "allowGuarded": [
    { "name": "OURGOAL_CONFIG", "approval": "(승인 근거 글자 — 10자 이상, 한 줄)" },
    { "name": "OurgoalTemplateCredit", "approval": "…" } ],
  "cells": [ … 기존 region 설정 그대로 … ] }
```

| 꼴 | 예전 | 지금 |
|---|---|---|
| `allowGuarded` 칸이 없다 | 잠긴 이름이 든 구역에서 멈춤 | **같다**(같은 오류 글자) |
| 칸은 있는데 그 이름을 적지 않았다 | – | 멈춤(같은 오류 글자) |
| 이름과 근거를 적었다 | (칸 자체가 모르는 칸이라 멈춤) | 그 이름이 든 문을 구역에 넣는다. 바꿔 쓰기 규칙은 region 그대로(접두 `L.`) |
| 잠긴 이름 목록에 없는 이름 · 근거 글자 없음/10자 미만/여러 줄 · 같은 이름 둘 · 칸의 모르는 키 · 빈 배열 · 배열이 아닌 값 | – | 멈춤 |
| 적은 이름이 어느 구역에도 없다 | – | 멈춤(쓰이지 않는 허용) |
| 허용한 문에 줄임 속성 확장(`{a}` → `{a: L.a}`)이 필요하다 | – | 멈춤(한도는 접두뿐) |
| 다른 모드(sweep · finalize)의 설정에 `allowGuarded` | – | 멈춤(모르는 칸) |

- 허용해 옮긴 문마다 표준 출력에 `  guarded <이름> — 구역 <구역>(문 줄 N · 잠긴 낱말 N개) · 접두 N곳 · 승인 근거: <글자>` 한 줄, 메타 `guardedAllowed` 에 같은 내용. 해당이 있을 때만 생기므로 기존 설정의 출력·메타는 글자가 같다.
- 잠긴 이름 목록(`HOLD`)은 바꾸지 않았다. 새 이름을 잠그거나 푸는 것은 이 칸이 아니라 생성기 변경(=별도 PR)이다.

## 6. [원칙 ⑥] 절차 재검증 및 반론 격파

- **반론 1 「근거 글자는 아무 글자나 적어도 통과한다」** → 맞다. 생성기는 그 글자가 진짜 승인인지 알 수 없다. 생성기가 보장하는 것은 「적지 않으면 멈춘다 · 적은 것이 출력과 메타와 설정 파일(=PR 의 diff)에 남는다」까지다. 글자의 진위는 그 설정을 내는 PR 의 REQ·본문을 보는 법정과 사람이 본다. 한계로 적는다.
- **반론 2 「잠금을 코드에서 지우면 더 간단하다」** → 그러면 승인 없이도 구역에 들 수 있고, 다음에 잠긴 이름이 늘어도 같은 길로 새게 된다. 결심은 「이 두 곳」에 대한 것이다.

- **재검증**: 모의 적용의 시험 비교는 git 작업 폴더 둘에서 했다. 처음 비교에서 두 파일이 달랐는데(`tests/cell-map-export-es414.test.js` 와 그것을 부르는 `scripts/test-shipyard-modular.js`) 모의 폴더에 세포 설명 한 칸과 `git add` 가 빠져 있었기 때문이다 — 실제 PR 이 하는 그 두 가지를 하고 다시 재니 차이 0 이었다.
