## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)

- **상민님 지시 원문**:
  1. "최근 내가 개정한 새 헌법 알고있지?"
  2. "아워골 목표탭 상단의 배너들(5개)이 안보이고, 안눌러진다는데 문제 확인해"
  3. "이러한 문제 더 있는지 아워골 전체에 대해서 확인해"
  4. "모두 고쳐. 헌법대로 고치고, 헌법대로 보고해"

- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  1. **목표 탭 상단 서브탭 5종 (`#goalsSubtabs`)**: 스크롤 시 화면 밖으로 즉시 사라져 다른 서브탭(루틴, 팀 목표, 템플릿 등)으로 전환하려면 긴 목표 리스트를 다시 맨 위로 스크롤해야 함. 비활성 탭이 배경색 없이 투명하고 저대비 회색 글자로 렌더링되어 터치할 수 있는 버튼이 아닌 평문 라벨로 오인됨.
  2. **기록 탭 6대 모드 전환 칩 (`.s-rec-modes-wrap`)**: 연간 히트맵이나 회고 피드를 확인하기 위해 스크롤을 내리면 6개 모드 칩이 즉시 사라짐. 비활성 버튼 5개가 `background: transparent; border: none;`으로 평문 텍스트처럼 보임.
  3. **일정 탭 3대 모드 전환 칩 (`.s-cal-modes-wrap`)**: 월간 캘린더 일자 그리드를 스크롤할 때 상단 모드바와 새 일정 등록 액션이 화면 밖으로 사라짐. 비활성 버튼의 터치 어포던스 부재.
  4. **커뮤니티 탭 서브탭 (`.comm-subtabs`) 및 카테고리 필터 바 (`.feed-filter-bar`)**: 서브탭이 스크롤 시 사라지며, 11개 카테고리 칩 중 7개(`커리어·취업` ~ `독서·인문`)가 375px 모바일 뷰포트 우측 밖으로 잘려(Clipped) 나감에도 가로 스크롤 가능 여부를 알리는 시각적 힌트가 전무함.
  5. **빈 상태 네비게이션 증발**: 등록된 목표가 0건일 때 상단 필터 바(`.s-goal-pills-wrap`) 자체가 DOM에서 은닉되어 목표 분류 기능이 존재하지 않는 것처럼 보임.

- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**:
    - CSS `position: static` 부착으로 인해 부모 스크롤러(`.screens` 또는 `window`) 스크롤 시 상단 컨트롤이 뷰포트 상단 밖으로 소실.
    - 활성 클래스(`active`)에만 스타일이 집중되고 비활성 기본 상태에 카드형 컨테이너(`border`, `background`)가 누락되어 시각적 터치 어포던스 단절.
    - `overflow-x: auto; scrollbar-width: none;`만 선언되고 그라데이션 페이드 마스크가 없어 우측 오버플로우 인지 실패.
    - 조건부 렌더링 블록(`if (goals.length > 0)`)이 빈 상태 컨테이너를 대체하지 않고 통째로 스킵.
  - **2층 (구조/프로세스 부재)**:
    - 데스크톱 전체 화면 위주 테스트 시 375px 모바일 뷰포트의 실제 스크롤 및 터치 환경에서의 시각적 물리 검증 결여.
    - 6대 탭 전체에 대한 통일된 Sticky 헤더 및 서브탭 카드 스타일 가이드라인 부재로 각 컴포넌트별 파편화 발생.
  - **3층 (시스템/유저 체감 괴리)**:
    - 유저는 "상단 배너가 안 보이고 안 눌러진다"고 호소했으나, 실제 코드는 핸들러가 배선되어 있음에도 시각적 형태(Ghost 버튼)와 스크롤 위치 이탈 때문에 유저 멘탈 모델에서는 '망가진 앱'으로 인식됨.

- **사용자 상황 및 페르소나**:
  - 보통의 모바일 유저: 375×812 스마트폰에서 한 손 조작 중 스크롤을 내린 상태에서도 즉시 루틴이나 통계, 팀 목표로 이동하고자 하는 사용자.
  - 신규 가입 유저: 목표가 0건인 상태에서 첫 목표를 등록하고 앱의 탐색 구조를 파악하려는 사용자.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)

- **본질 축 (Essence Axis)**: `FIX & INFRA` (전 탭 네비게이션 시인성·접근성 일괄 복구 및 모바일 375px 조형 표준화)
- **[본질] (Essence)**:
  - 겉모습의 착시(버튼 코드가 존재하므로 정상이라는 개발자적 안도)를 걷어낸 이 문제의 진짜 실체:
  - **"유저의 손끝이 닿는 모든 전환 스위치가 스크롤 위치와 무관하게 언제나 손안에 머물고(Sticky), 누를 수 있는 물리적 실체(Tactile Card)로 분명히 인식되어야 한다"**는 모바일 네이티브 UX 철학의 결여.
  - **3대 철학 심사 기준 점검**:
    1. **무공해성 (Anti-Pollution)**: 스크롤을 다시 올리거나 숨겨진 칩을 찾기 위해 불필요한 탐색 피로를 겪지 않도록 직관적이고 군더더기 없는 조형 유지.
    2. **RPG식 체감 (Immediate Self-Efficacy)**: 목표, 루틴, 회고, 통계 간의 전환이 즉각적으로 이루어져 유저의 실천 루프가 끊김 없이 연속되도록 지원.
    3. **동류 연대 (Peer Accompaniment)**: 커뮤니티 탭에서 11개 카테고리를 한눈에 인지하고 동류의 피드에 원활하게 접근하도록 시각적 힌트 제공.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. **원인 1 (Sticky 미지정)**: `#goalsSubtabs`, `.s-cal-modes-wrap`, `.s-rec-modes-wrap`, `.comm-subtabs`가 모두 `position: static`으로 방치됨.
  2. **원인 2 (투명 비활성 스타일)**: 비활성 서브탭/칩에 `background: transparent; border: none; color: #94A3B8;`가 적용되어 어포던스 제로.
  3. **원인 3 (오버플로우 힌트 누락)**: `.feed-filter-bar`에 우측 클리핑을 안내하는 마스크 그라데이션이 미적용됨.
- **[중심] (Core Bottleneck & Anchor)**:
  - 각 화면의 메인 스크롤 컨테이너 내에서 상단 네비게이션 요소들이 스크롤 시 `top: 0`에 안정적으로 안착(Sticky)하면서도 본문 콘텐츠와 겹치지 않도록 적절한 z-index 및 블러 배경을 확보하는 것.
- **[핵심] (Critical Safety & Termination)**:
  - 기존 335개 테스트와 37개 무결성 게이트 및 743개 클릭 배선 단 1건도 파괴하지 않고, 기존 CSS 전역 변수 체계를 100% 계승하며 외과수술적으로 스타일 및 렌더링을 보강하는 것.
- **체감 가설 (User Experience Hypothesis)**:
  > *"사용자가 목표·일정·기록·커뮤니티 어느 화면에서든 긴 콘텐츠를 스크롤하는 도중에도 상단 서브탭이 시야에 고정되어 있고, 터치 가능한 알약 카드로 명확히 식별되어 1회의 탭으로 원하는 모드로 막힘없이 이동할 수 있다."*
- **기존 전체 기능 영향도 분석**:
  - 계정/로그인(세션, 게스트, 소셜)에 미치는 영향: 무관 (영향 없음).
  - 홈 화면 및 스트릭에 미치는 영향: 홈 탭 레이아웃 불파괴 보존.
  - 기록/통계/캘린더 탭에 미치는 영향: 스크롤 시 모드바 고정으로 사용성 대폭 향상.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)

- **하지 말아야 할 것 (Avoid)**:
  - 기존 마크업 구조나 클래스명을 임의로 대량 변경하여 기존 테스트를 깨뜨리는 행위 금지.
  - 인라인 하드코딩 색상 남발 금지 (반드시 CSS 변수 및 반투명 토큰 사용).
  - 기존 데이터 모델이나 스토리지 파이프라인 불필요한 수정 금지.
- **해야 할 것 (Action)**:
  1. **상단 네비게이션 Sticky 일괄 적용**:
     - `#goalsSubtabs`: `position: sticky; top: 0; z-index: 30; backdrop-filter: blur(16px); background: var(--bg-surface, rgba(15, 23, 42, 0.92));`
     - `.s-cal-modes-wrap`: `position: sticky; top: 0; z-index: 25; backdrop-filter: blur(16px); background: var(--bg-surface, rgba(15, 23, 42, 0.92));`
     - `.s-rec-modes-wrap`: `position: sticky; top: 0; z-index: 25; backdrop-filter: blur(16px); background: var(--bg-surface, rgba(15, 23, 42, 0.92));`
     - `#screen-comm .comm-subtabs`: `position: sticky; top: 0; z-index: 25; backdrop-filter: blur(16px); background: var(--bg-surface, rgba(15, 23, 42, 0.92));`
  2. **비활성 탭/버튼 터치 어포던스 부여**:
     - 목표 서브탭, 기록 모드 버튼(`.s-rec-mode-btn`), 일정 모드 버튼(`.s-cal-mode-btn`), 커뮤니티 서브탭 비활성 상태에 기본 카드 틴트 적용: `background: rgba(255, 255, 255, 0.05); border: 1px solid rgba(255, 255, 255, 0.08); color: #94A3B8;` (라이트 테마에서는 `rgba(0, 0, 0, 0.04); border: 1px solid rgba(0, 0, 0, 0.08); color: #475569;`).
  3. **피드 필터 바 스크롤 페이드 마스크 적용**:
     - `.feed-filter-bar`에 `-webkit-mask-image: linear-gradient(to right, black 0%, black calc(100% - 28px), transparent 100%);` 적용하여 잘린 칩들의 존재를 시각적으로 유도.
  4. **목표 0건 빈 상태 네비게이션 보존**:
     - `goals.length === 0`일 때도 `.s-goal-pills-wrap` 내에 `+ 새 목표 만들기` 액션 칩을 온전히 노출.
- **왜 이 방식이어야만 하는가 (Why this approach)**:
  - CSS 기반의 Sticky 및 어포던스 보강은 JS 런타임 오버헤드가 0이며, 브라우저 네이티브 하드웨어 가속 컴포지팅을 사용하여 초당 60fps 스크롤 성능을 완벽히 보장함.

### 3-1. 스토리지 원장화 3대 명세 (헌법 제2조 제4항 준수)

### 3-3. 유저 데이터 100% 무손실 보존 규격 (Zero-Data-Loss Schema)
- **아바타 보존**: 기존 아바타 이미지, 보관함, 설정값 100% 보존.
- **목표 데이터 보존**: 기존 목표 리스트, 마일스톤, 진행도 100% 보존.
- **기록 데이터 보존**: 과거 체크인, AI 피드백, 스트릭 100% 보존.
- **화면 구성 세팅값 보존**: 테마, 접힘 설정, 필터 100% 보존.

## 4. [원칙 ④] 1~3 재검토 및 보완 (Review & Edge Cases)

- **비판적 자기 검토 및 약점/한계 인정**:
  - `position: sticky`를 적용할 때 부모 컨테이너에 `overflow: hidden`이 걸려 있으면 sticky가 작동하지 않는 CSS 스펙 한계가 존재함. 점검 결과 `.screens` 컨테이너 및 각 `section.screen`의 overflow 동작을 확인하고 sticky가 정상 작동함을 사전 검증함.
  - 가로 스크롤 페이드 마스크는 최우측 끝까지 스크롤했을 때 마지막 칩의 오른쪽 끝이 살짝 흐려 보일 수 있으나, 가로 스크롤 어포던스를 유도하는 사용성이 훨씬 크므로 허용함.
- **기존 기능과의 충돌 가능성 검토**:
  - 기존 클래스 및 id 구조를 그대로 유지하므로 JS 이벤트 위임 및 스크립트 검증과 완벽히 호환됨.
- **엣지 케이스 (Edge Cases)**:
  - 첫 방문자(목표 0건): 상단에 `+ 새 목표 만들기` 알약이 보존되어 자연스러운 첫 액션 유도.

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)

- **단일 실패점 (SPOF) 점검**:
  - CSS sticky 속성이 지원되지 않는 구형 브라우저의 경우 일반 static으로 자연스럽게 폴백(Graceful Degradation)되어 기능적 마비가 발생하지 않음.
- **가정의 타당성 검증**:
  - "Sticky를 주면 본문 스크롤과 상단바가 겹칠 수 있다"는 우려에 대해 `z-index`와 `backdrop-filter` 및 배경색 불투명도(0.92)를 부여하여 본문 글자가 상단바 밑으로 비쳐서 난잡해지는 현상을 원천 방어함.
- **재검증 결과 도출된 절차 수정/보완사항**:
  - 목표 탭 서브탭(`#goalsSubtabs`) 상단에 `margin-top: 4px`가 있으면 sticky 시 상단에 미세한 틈이 생길 수 있으므로, sticky 시점의 오프셋을 `top: 0`으로 맞추고 패딩과 배경을 감싸 틈새 누출을 방지하도록 보정함.
