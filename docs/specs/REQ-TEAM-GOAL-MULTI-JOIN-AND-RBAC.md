## 1. 개요 및 추진 배경 (Overview & Background)

### 1.1 배경 및 문제 정의
1. **모임 가입 즉시 소통탭 목록 증발 결함 (Critical Bug)**:
   - 현재 아워골 앱의 소통 탭 모임 목록(`renderCommGroups`)에서 임의의 모임에 단 1개라도 가입(`gs.joined === true`)하면, 모임 카드를 렌더링하는 `visibleGroups.map` 내부에서 미정의 식별자 `checked`를 참조하여 **`Uncaught ReferenceError: checked is not defined`**가 발생합니다.
   - 이로 인해 렌더링이 중단되어 사용자의 소통 탭 모임 화면이 완전히 빈 백지로 표시되는 치명적인 결함이 존재합니다.
2. **기존 모임 보유 시 템플릿 모임 개설 실패 결함**:
   - 이미 가입한 모임이 존재하는 상태에서 팀 목표 상단의 활용 가이드 모달을 통해 `[✨ 이 템플릿으로 모임 개설]`을 누를 때, 내부 매개변수(`body`)가 `null`로 전달되거나 모임 개설 후 필터 칩 및 로컬 상태가 충돌하여 신규 모임 개설이 차단되거나 반영되지 않는 문제가 발생합니다.
3. **모임 다중 참여(최대 30개) 한도 규격 부재**:
   - 사용자가 운동, 독서, 업무, 여행 등 다양한 목표를 위해 여러 모임에 동시 참여하려 해도 개수 제한(30개)과 다중 참여에 최적화된 탐색/필터 UI가 부재하여 상태 혼선이 발생합니다.
4. **모임장의 세부 권한 위임 체계 부재 (All-or-Nothing의 한계)**:
   - 현재 권한 체계는 `role === 'owner' || role === 'manager'`라는 이분법적 검사로만 동작하여, 모임장이 팀원들에게 특정 업무(예: 세부할일 체크만, 일정 수정만, 마일스톤 관리만)를 선택적으로 분담할 수 없습니다.
   - 모임의 제목, 목표, 마일스톤, 세부할일, 일정 항목별로 추가(Add), 수정(Edit), 삭제(Delete) 권한을 세분화하여 개별 팀원에게 안전하게 위임하고 필요 시 즉시 회수할 수 있는 RBAC(Role-Based Access Control) 시스템이 필수적입니다.

### 1.2 체감 가설 (Essence Hypothesis)
> **"사용자가 관심 있는 다양한 모임에 최대 30개까지 자유롭게 가입·개설하고 오류 없이 탐색할 수 있으며, 모임장은 팀원들에게 모임 정보·목표·마일스톤·세부할일·일정의 추가·수정·삭제 권한을 핀포인트로 위임함으로써, 모임장은 자율적인 분업 리더십을 발휘하고 팀원들은 주도적으로 역할을 부여받아 목표를 끝까지 완수할 수 있음을 체감한다."**

### 1.3 시스템 범위 (Scope)
- **In-Scope**:
  - `renderCommGroups` 내 `checked` 참조 오류 근절 및 다중 가입 안정화
  - 가이드 모달을 통한 템플릿 모임 개설 시의 DOM/상태 충돌 완전 해결
  - 모임 가입 최대 개수 30개 상한선 적용 및 30개 도달 시 안내 토스트/가드
  - 소통 탭 내 `[내 모임 (N)]` 퀵 필터 및 30개 모임 대응 스크롤/탐색 UI
  - 모임장 전용 팀원 권한 관리 매트릭스 바텀시트 모달 (`openGroupPermissionModal`)
  - 5개 도메인(모임 정보, 목표, 마일스톤, 세부할일, 일정) × 3대 액션(추가, 수정, 삭제) 세부 권한 매트릭스
  - 권한 프리셋 4종 (총괄 매니저, 프로젝트 플래너, 실행 리포터, 일반 팀원) 및 커스텀 체크박스
  - 권한 부여 및 즉시 회수 기능, 로컬스토리지 및 Supabase 저장
  - 팀원 화면에서 위임받은 권한에 따른 인터랙티브 UI 동적 활성화 및 권한 안내 배너
- **Out-of-Scope (추후 확장)**:
  - 조직/기업 단위의 엔터프라이즈 계정 SSO 통합 권한
  - 모임 양도(Ownership Transfer) 절차 (별도 보안 승인 절차로 분리)

## 2. 사용자 페르소나 및 핵심 유저 스토리 (Personas & User Stories)

### 2.1 페르소나
1. **열정 리더 박지훈 (34세, 50인 IT 사이드프로젝트 모임장)**
   - 목표: 기획·개발·디자인 TF가 각자 마일스톤과 세부할일을 주도적으로 관리하게 하고 싶음.
   - 니즈: 모임장이 혼자 모든 태스크를 수정·삭제하기 벅참. 기획 리드에게는 '목표·마일스톤 추가/수정', 실무 팀원에게는 '세부할일 추가/체크' 권한만 딱 떼어주고 싶음.
2. **책임감 있는 부팀장 정다은 (29세, 모임원)**
   - 목표: 맡은 파트의 마일스톤 일정을 업데이트하고 세부 과제를 등록하고 싶음.
   - 니즈: 전체 관리자 권한은 부담스럽지만, 내가 맡은 마일스톤과 세부할일은 직접 추가하고 수정할 수 있는 권한이 주어지면 모임에 더 깊게 몰입할 수 있음.
3. **다재다능 프로 갓생러 최민호 (27세, 15개 모임 참여자)**
   - 목표: 러닝 모임, 자격증 스터디, 모닝 루틴, 단체여행 등 관심사별 소그룹을 10개 이상 참여 중.
   - 니즈: 모임을 여러 개 가입해도 소통 탭이나 목표 탭에서 모임이 튕기거나 사라지지 않고, 원하는 방을 1초 만에 찾아서 인증하고 싶음.

### 2.2 핵심 유저 스토리
- **US-01 (다중 모임 가입)**: 사용자는 최대 30개까지 원하는 모임에 가입할 수 있으며, 가입 후에도 소통 탭의 모임 목록이 완벽하게 표시된다.
- **US-02 (기존 모임 보유 시 템플릿 개설)**: 사용자는 이미 여러 모임에 가입되어 있어도 언제든지 가이드 템플릿으로 새 모임을 개설할 수 있다.
- **US-03 (30개 한도 가드)**: 사용자가 30개를 초과하여 가입을 시도하면 명확하고 친절한 안내를 받고 기존 모임을 정리할 수 있다.
- **US-04 (모임장의 권한 설정 진입)**: 모임장은 팀 목표 카드에서 `[🛡️ 팀원 권한 관리]` 버튼을 눌러 팀원별 권한 매트릭스를 열 수 있다.
- **US-05 (항목별 권한 부여)**: 모임장은 특정 팀원에게 목표, 마일스톤, 세부할일, 일정의 추가·수정·삭제 권한을 체크박스로 자유롭게 지정할 수 있다.
- **US-06 (원클릭 권한 회수)**: 모임장은 언제든지 `[권한 회수]`를 눌러 부여했던 권한을 즉시 기본 팀원 상태로 되돌릴 수 있다.
- **US-07 (권한 기반 실행)**: 팀원은 위임받은 항목에 한해 마일스톤/할일 추가·수정·삭제 버튼이 활성화되어 실제 작업을 수행할 수 있다.

## 3. 기능 요구사항 (Functional Requirements)

### FR-01: 모임 다중 가입 무결성 및 렌더링 버그 근절
- **FR-01-1 [참조 오류 완전 제거]**:
  - `renderCommGroups`의 `visibleGroups.map(function(g){ ... })` 블록 내부에 `var checked = groupCheckedToday(g.id);`를 선언하여 `Uncaught ReferenceError`를 원천 차단한다.
- **FR-01-2 [30개 다중 가입 상한선 관리]**:
  - 사용자가 참여 중인 모임 수(`myJoinedCount`)가 30개에 도달했을 때 신규 가입(`[참여하기]` 또는 `[템플릿으로 개설]`) 시도시:
    `toast('모임은 최대 30개까지 가입할 수 있어요. 참여 중인 모임을 먼저 정리해주세요 ⚠️')`
    메시지를 출력하고 가입 처리를 안전하게 중단한다.
- **FR-01-3 [소통 탭 필터 칩 강화]**:
  - 소통 탭 상단 필터 칩바에 `[내가 참여 중인 모임 (N)]` 전용 퀵 칩을 추가하여 수많은 모임 중 내가 활동 중인 방만 1초 만에 모아볼 수 있도록 지원한다.

### FR-02: 가이드 템플릿 개설 워크플로우 안정화
- **FR-02-1 [DOM 매개변수 폴백 보장]**:
  - `promptNewGroup(body, initialPreset)` 호출 시 `body`가 `null`이거나 모달 내부에서 호출되더라도 `document.querySelector('#commSubBody') || document.getElementById('goalsView')`를 자동 할당하여 스크립트 예외를 방어한다.
- **FR-02-2 [개설 모임 영구 보존]**:
  - 템플릿으로 새로 생성된 모임(`newGroup`)은 `state.profile.settings.customGroups` 배열에 JSON 형태로 안전하게 영구 저장되어 새로고침 후에도 유지된다.
- **FR-02-3 [개설 직후 뷰 자동 전환]**:
  - 템플릿 팀 목표가 포함된 모임 개설 완료 시 `state.activeTab = 'goals'`, `state.goalsSubTab = 'team'`, `state.teamGoalFilterGid = newGroup.id`로 설정하고 `renderGoalsScreen()`을 호출하여 방금 만든 모임의 목표 화면으로 정확하게 전환한다.

### FR-03: 모임장의 세부 권한 매트릭스 (Granular RBAC)
- **FR-03-1 [5개 도메인 × 3대 액션 권한 정의]**:
  1. **모임 기본 정보 (Group Info)**:
     - `group_info:edit`: 모임 이름, 소개, 아이콘, 규칙, 주기 수정
     - `group_info:delete`: 모임 폭파/해체 (모임장 전용 고유 권한, 위임 불가 안전장치)
  2. **팀 목표 (Team Goal)**:
     - `goal:create`: 신규 팀 목표 추가 (`promptNewTeamGoal`)
     - `goal:edit`: 팀 목표 제목, 설명, 상태 수정
     - `goal:delete`: 팀 목표 삭제
  3. **마일스톤 (Milestone)**:
     - `milestone:create`: 목표 내 새 마일스톤 추가
     - `milestone:edit`: 마일스톤 제목, 상태(todo/doing/done), 우선순위(high/med/low), 순서(▲/▼) 변경
     - `milestone:delete`: 마일스톤 삭제
  4. **세부 할 일 (Sub-task)**:
     - `task:create`: 마일스톤 내 새 세부할일 추가
     - `task:edit`: 세부할일 제목 수정 및 완료 체크박스 토글
     - `task:delete`: 세부할일 삭제
  5. **일정 및 마감일 (Schedule)**:
     - `schedule:edit`: 목표 마감일(DueDate), 마일스톤 마감일, 챌린지 기간 수정
- **FR-03-2 [역할 프리셋 템플릿]**:
  - 👑 **모임장 (Owner)**: 모든 권한 상시 보유
  - 🛠️ **총괄 매니저 (Manager)**: 모임 삭제를 제외한 모든 항목의 추가/수정/삭제 권한
  - 🎯 **프로젝트 플래너 (Planner)**: 목표·마일스톤·일정의 추가/수정/삭제 권한
  - 📝 **실행 리포터 (Reporter)**: 세부할일의 추가/수정/삭제 및 마일스톤 상태 체크 권한
  - 👤 **일반 팀원 (Member)**: 읽기 전용 및 본인 체크인/찌르기 권한
  - ⚙️ **직접 지정 (Custom)**: 12개 세부 체크박스를 개별 선택

### FR-04: 팀원별 권한 관리 바텀시트 모달 (`openGroupPermissionModal`)
- **FR-04-1 [진입 인터페이스]**:
  - 팀 목표 화면 모임 카드 우측 상단에 모임장 전용 `[🛡️ 권한 위임]` 버튼 배치.
  - 팀원 달성도 점검 상세 모달 내 각 팀원 행에 `[권한 설정]` 링크 배치.
- **FR-04-2 [모달 구성]**:
  - 상단: 모임명, 팀원 선택 드롭다운/리스트 (팀원 아바타 + 닉네임 + 현재 권한 뱃지).
  - 중단: 퀵 프리셋 칩 바 (`[총괄 매니저]`, `[플래너]`, `[리포터]`, `[일반 팀원]`).
  - 본문: 5개 항목별 체크박스 매트릭스 (항목별 아이콘 + 추가/수정/삭제 체크박스).
  - 하단: `[권한 초기화(회수)]` 버튼, `[권한 저장 및 적용]` 버튼.

### FR-05: 권한 기반 다이나믹 뷰 및 클라이언트 가드
- **FR-05-1 [권한 검사 헬퍼 `hasGroupPermission(gid, permKey)`]**:
  - 모임장(`owner`)인 경우 모든 `permKey`에 대해 무조건 `true` 반환.
  - 팀원인 경우 `groupState(gid).permissions[myId]`에 해당 `permKey`가 포함되어 있으면 `true`.
  - 권한이 없는 액션 버튼은 DOM에서 숨기거나 `disabled` 처리.
- **FR-05-2 [팀원 화면 권한 뱃지]**:
  - 권한을 위임받은 팀원이 해당 모임에 접속하면, 모임 카드 상단에 `[🛡️ 운영 권한 보유: 마일스톤·할일 편집 가능]` 안내 뱃지가 표시되어 권한 상태를 즉시 인지할 수 있도록 한다.

## 4. 데이터 모델 및 저장 규격 (Data Model Specification)

### 4.1 `groupState(gid)` 데이터 확장
```json
{
  "joined": true,
  "myRole": "owner",
  "checkins": ["2026-09-13"],
  "cheers": 5,
  "permissions": {
    "user_member_01": {
      "role": "planner",
      "updatedAt": "2026-09-13T02:15:00.000Z",
      "allows": [
        "goal:create", "goal:edit",
        "milestone:create", "milestone:edit", "milestone:delete",
        "schedule:edit"
      ]
    },
    "user_member_02": {
      "role": "reporter",
      "updatedAt": "2026-09-13T02:18:00.000Z",
      "allows": [
        "task:create", "task:edit", "task:delete",
        "milestone:edit"
      ]
    }
  }
}
```

### 4.2 `hasGroupPermission(gid, permKey)` 로직 명세
```javascript
function hasGroupPermission(gid, permKey){
  var gs = groupState(gid);
  if(gs.myRole === 'owner') return true;
  var myId = state.profile && state.profile.id;
  if(!myId || !gs.permissions || !gs.permissions[myId]) return false;
  var allows = gs.permissions[myId].allows || [];
  return allows.indexOf(permKey) !== -1 || allows.indexOf('*') !== -1;
}
```

## 6. 비기능 요구사항 (Non-Functional Requirements)

1. **승인선 8 및 index.html 경량화 원칙**:
   - 권한 매트릭스 비즈니스 로직 및 모달 렌더러는 기존 검증된 `js/team-leader-check.js` 모듈을 확장하거나 `js/group-permissions.js`로 분리하여 `index.html` 순증가를 50줄 이내로 억제한다.
2. **응답성 및 햅틱 피드백**:
   - 권한 저장 및 회수 시 햅틱 피드백(`triggerHaptic(10)`)을 제공하고, 즉시 로컬 스토어에 반영한 뒤 UI를 리렌더링한다.
3. **위조 지표 배제 (규칙 4-1)**:
   - 가짜 인원이나 권한을 표기하지 않으며 실제 가입된 로스터의 유저에게만 권한을 부여할 수 있도록 바인딩한다.

## 7. 엣지 케이스 및 예외 처리 (Edge Cases)

| 번호 | 예외 상황 | 대응 처리 |
| :---: | :--- | :--- |
| **EC-01** | 모임 가입 수가 정확히 30개인 상태에서 가입 시도 | 가입 차단 토스트 안내 및 현재 참여 중인 모임 목록으로 포커스 |
| **EC-02** | 모임장이 자기 자신의 권한을 회수하거나 낮추려 할 때 | 모임장은 항상 영구 `owner` 권한을 유지하며 변경 불가(Disabled) |
| **EC-03** | 권한을 위임받은 팀원이 모임에서 스스로 탈퇴할 때 | 탈퇴 시 해당 팀원의 `permissions` 엔트리를 자동 소멸 및 정리 |
| **EC-04** | 소통 탭에서 비로그인/게스트 상태로 모임 가입 시 | 로컬 게스트 프로필에 안전하게 기록되고 30개 한도 동일 적용 |
| **EC-05** | 팀원이 부여받지 않은 권한 버튼을 직접 조작 시도 시 | `hasGroupPermission` 가드가 차단하고 '모임장에게 권한을 요청하세요' 토스트 표시 |

## 8. 인수 기준 (Acceptance Criteria)

- [ ] **AC-01**: 임의의 모임에 가입한 직후 소통 탭 > 모임 탭 진입 시 `ReferenceError` 없이 모든 모임 목록이 정상 표시된다.
- [ ] **AC-02**: 기존 모임에 이미 가입된 상태에서도 팀 목표 화면 활용 가이드 모달에서 `[이 템플릿으로 모임 개설]` 클릭 시 새 모임이 정상 개설된다.
- [ ] **AC-03**: 최대 30개까지 모임에 중복 가입할 수 있으며, 30개 초과 시 친절한 가드 토스트가 출력된다.
- [ ] **AC-04**: 모임장은 팀 목표 카드에서 `[🛡️ 권한 위임]` 모달을 열어 팀원별로 5개 항목(모임 정보, 목표, 마일스톤, 할일, 일정)의 추가/수정/삭제 권한을 개별 선택할 수 있다.
- [ ] **AC-05**: 모임장이 `[권한 회수]`를 클릭하면 즉시 해당 팀원의 모든 추가/수정 권한이 회수된다.
- [ ] **AC-06**: 권한을 부여받은 팀원은 위임받은 항목(예: 마일스톤 수정 등)의 편집 버튼이 활성화되어 실제 조작이 가능하다.
- [ ] **AC-07**: `npm test` 205개 이상의 스모크 테스트가 100% 통과하며 회귀가 발생하지 않는다.
