## 1. 문제 정의 (Problem Definition)
1. **모호한 도구 언어 노출**: 목표 화면 상단 미니바 타이틀이 기계적인 'AI 현황'으로 표기되어 있어 사용자가 어떤 역할을 하는 기능인지 직관적으로 인지하기 어려움 (헌법 제4조 제1항 3호 도구 언어 노출 금지 위반 소지).
2. **상태 안내 고착 및 데드 배지**: AI 요약 분석이 완료되어 결과 텍스트가 화면에 도출된 후에도 상단 스니펫 또는 안내 배지가 '진행 상황 분석 중…'으로 계속 남아있거나, 완료 상태('분석완료')로 명확히 전환되지 않아 사용자가 분석이 끝났는지 로딩 중인지 혼란스러움.
3. **불필요한 API 중복 재호출 (비용 낭비 및 렉)**: 다른 창(탭)으로 이동했다가 다시 목표 탭으로 돌아오거나 페이지를 새로고침할 때, 기존 분석 결과가 있음에도 불구하고 클라이언트 유효성 검사(글자 수 80자 하한선 오류 등)로 인해 캐시 저장이 누락되어 매번 /api/goalstatus를 무한 재호출함.

---

## 2. 근본 원인 분석 (Root Cause Analysis)
1. **타이틀 하드코딩**: `index.html` L9824에 `<span class="minibar-title">AI 현황</span>`으로 고정되어 있음.
2. **완료 상태 DOM 배선 누락**: `refreshGoalStatusSummary` 함수 내부에서 `document.getElementById('goalStatusTag')`를 찾아 'AI 요약'으로 바꾸려 시도하나, 실제 마크업에는 `goalStatusTag` ID를 가진 태그가 존재하지 않음. 또한 완료 후 스니펫 및 헤더를 재렌더링하거나 '분석완료' 배지를 표시하는 UI 구조가 결여됨.
3. **클라이언트 글자 수 유효성 불일치로 캐시 누락**: `generateGoalStatusSummary`에서 `text.length < 80`이면 `null`을 반환하여 캐시에 기록하지 않음. 서버리스 스마트 로컬 폴백 문장의 평균 길이가 65~75자이므로, 폴백이 실행될 때마다 `null`로 폐기되어 `goalStatusStale`이 계속 `true`로 남아 탭 방문마다 무한 재호출 루프 발생.

## 3. 목표 및 해결 사양 (Goals & Specifications)
1. **라벨 명칭 표준화**:
   - 기존 'AI 현황' ➔ **'현상태 분석 AI 조언'** 단일 표기.
2. **직관적인 3단계 상태 배지 (`#goalStatusBadge`) 신설**:
   - **분석 중**: `<span class="minibar-status-tag status-analyzing" id="goalStatusBadge">진행 상황 분석 중…</span>` (요청 진행 시)
   - **분석 완료**: `<span class="minibar-status-tag status-completed" id="goalStatusBadge">분석완료</span>` (결과 텍스트 존재 시)
   - **마일스톤 부재**: `<span class="minibar-status-tag status-empty" id="goalStatusBadge">마일스톤 필요</span>` (마일스톤 0개 시)
3. **스니펫 및 본문 실시간 즉각 동기화**:
   - 분석 완료 즉시 DOM의 뱃지를 '분석완료'로 바꾸고, 본문 텍스트 및 요약 스니펫을 즉시 갱신.
4. **스마트 무손실 캐싱 및 무한 재호출 차단**:
   - 클라이언트 수용 글자 수를 30자 이상으로 현실화하여 폴백 텍스트도 정상 캐시되도록 조치.
   - 목표 데이터(마일스톤/할일) 해시가 변하지 않는 한, 탭 이동 및 단순 새로고침 시 API 재호출 전면 금지.
   - 실패/오프라인 시에도 쿨다운(최소 5분)을 부여하여 반복적인 폭풍 호출 방어.
