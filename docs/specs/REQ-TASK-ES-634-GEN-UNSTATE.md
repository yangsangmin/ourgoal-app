## 1. [원칙 ①] 문제를 정확히 파악한다

- 키트별 철거(B3~B8)가 끝나 `inlineScriptLines` 는 4003 → 3136 이다. 남은 배선 가운데 상태 변수의 getter/setter 줄(조사: 66줄)은 unwire 가 지울 수 없다 — 지우면 다른 세포가 `L.X` 로 읽고 쓰던 통로가 사라진다.
- 설계 3.3 은 소유를 상태 기관으로 옮기는 방식을 적었지만 구현이 없었고, 기관 API 는 두 줄짜리 뼈대뿐이었다.
- 법정은 기준 커밋의 생성기를 PR 설정으로 다시 돌려 바이트 대조한다. 그래서 상태 이전은 손이 아니라 생성기 모드로 해야 하고, 그 모드가 먼저 병합돼 있어야 한다.

## 2. [원칙 ②] 본질·원인·중심·핵심

- **본질**: 상태 변수 하나의 소유를 「IIFE 지역 변수 + 통로 getter/setter」에서 「기관이 보관 + 기관이 단 접근자」로 바꾸되, 값·자리·시점은 그대로 둔다.
- **원인**: strict IIFE 의 맨이름을 바깥 저장소에 묶으려면 모든 참조를 고쳐야 한다. 그것은 함수 본문 수정이라 하지 않는다. 그래서 맨이름 참조가 0 이 된 이름만 옮긴다.
- **중심**: 선언문을 지우지 않고 **제자리에서 바꿔 쓴다**(`var X = v;` → `…define('X', v);`). 초기값이 평가되는 자리와 순서가 그대로 남는다.
- **핵심**: 쓰기 가능 여부(define/defineVar)를 생성기가 마지막 노출 문에서 읽어 정한다. 사람이 고르면 L047(뒤 노출의 getter 전용이 앞의 setter 를 덮음)이 다시 생긴다.

## 3. [원칙 ③] 해결 방식

1. 생성기에 `runUnstate()` · `unstateOnce()` 를 **끼워 넣는다**(unwire 블록 뒤, 옮기기 경로 앞). 기존 줄은 한 줄도 고치지 않는다. 문서 파싱은 기존 `parseUnwireDoc()` 를 부른다.
2. 이름마다: 선언 하나·선언자 하나·`var`·초기값 있음·줄을 통째로 차지함을 확인 → expose 속성 줄 삭제(본문이 `return X;`·`X = v;` 꼴일 때만) → 마지막 노출 문의 종류로 API 선택 → 선언 머리(`var X =`)와 끝(`;`)을 토큰 자리로 바꿔 쓰기 → 일회 window 복사 줄의 오른쪽 바꿔 쓰기 → 남은 맨이름 참조가 있으면 정지.
3. 사후 대조: 결과를 다시 파싱해 토큰열이 「이전 − 지운 것, 바꿔 쓴 자리는 정해진 토큰열」과 같은지, 남은 주석이 그대로인지 본다.
4. 여러 실행: `unstate` 가 배열이면 차례로. 단계가 `{ "unwire": { … } }` 이면 기존 `unwireOnce()` 를 그대로 부른다.
5. 설계 3.3 에 기관 API 계약 표를 확정하고, 하네스에 그 계약대로 만든 견본 기관을 두어 진짜 `app-scope.js` 위에서 전·후 등가를 본다.
6. 실제 index.html 사본에서 노출된 상태 이름을 전부 뽑아 하나씩 돌려 옮길 수 있는 이름을 가르고(생성기 판단 그대로), 전부를 한 번에 돌려 줄 단위로 감사한다. 계획 파일로 남긴다.

## 4. [원칙 ④] 재검토 (반례·부작용)

- 노출 시점이 달라진다: 예전에는 통로 속성이 노출 문 자리에서 생겼고, 바뀐 뒤에는 선언 줄 자리에서 생긴다. 노출 문이 선언보다 앞이면 그 사이의 읽기는 전·후 모두 `undefined` 라 같다. 선언이 앞이면 그 사이에 값이 새로 읽힌다 → 그 사이에 실행되는 최상위 문이 있으면 멈추게 했다(Z21 · Z22). 지금 옮길 수 있는 50개는 전부 노출 문이 앞이다(조사 스크립트로 확인).
- 선언 줄보다 먼저 누가 `L.X = v` 로 쓰면: 예전에는 setter 가 지역 변수에 썼다가 선언 줄의 초기값이 덮었다. 바뀐 뒤에는 통로에 데이터 속성이 생겼다가 기관이 접근자로 다시 정의해 덮는다 → 계약 표에 「이미 있던 속성은 다시 정의해 덮는다」를 적었다. 실제 기관이 그렇게 구현됐는지는 다음 PR 이 잰다.
- getter 본문이 `return X;` 가 아니면 지우는 순간 동작이 바뀐다 → 꼴이 아니면 멈춘다(Z11 · Z12). 실제 대상 50개는 모두 표준 꼴이다(감사 P2 의 정규식이 전부 맞음).
- window 복사 줄을 지우지 않고 바꿔 쓰는 이유: 일회 복사의 **시점**(그때의 값)이 동작의 일부다. 기관이 window 에 달면 시점이 달라진다.
- 초기값 글자를 노드 범위가 아니라 토큰 자리(`=` 다음부터 `;` 앞까지)로 남긴다 → 괄호 친 식·주석·빈칸이 그대로다(R1 시험). `var X =` 사이에 주석이 끼면 멈춘다(Z18).
- unwire 의 expose 처리에는 「손대지 않은 expose 문의 끝 쉼표도 뗀다」는 옛 동작이 있다. unstate 는 그 문에서 지운 속성이 있을 때만 쉼표를 뗀다(S1 시험). unwire 쪽은 이번에 고치지 않았다(기존 경로 무변화).
- 메타·로그 꼴은 unwire 와 맞췄다(`runs` 배열, `step` 칸).
