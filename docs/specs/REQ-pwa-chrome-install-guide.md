## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
- **상민님 지시 원문**:
  > "아워골 주소를 통해서 정식 구글플레이 2주 테스트 하기전에 지인들한테 앱을 먼저 소개하려하는데, 크롬으로 아워골 앱 다운로드 받는 방법을 실제 아워골 화면과 크롬화면을 예시이미지를 들어서 바탕화면에 깔린 모습까지 카드뉴스형태로 설명서를 제공하고 싶어."
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  - 구글 플레이 20인 2주 비공개 테스트를 진행하기 전, 초기 테스터 및 지인들에게 웹 주소(`ourgoal-app.vercel.app`)를 공유하고 있으나 일반 사용자들은 웹 링크를 사파리나 카카오톡 인앱 브라우저 등으로 열어 단순 일회성 웹페이지로 인식함.
  - 모바일 크롬 브라우저를 통해 '홈 화면에 추가' 또는 '앱 설치'를 하면 정식 스토어 앱과 동일하게 독립된 앱 아이콘 및 전체화면(Standalone)으로 편리하게 실행할 수 있다는 사실을 알지 못함.
  - 지인들에게 텍스트로만 설명하면 "어디 눌러야 해?", "설치가 안 돼" 등의 피로감이 발생함.
- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**: 아워골 앱 내에 지인에게 바로 공유하거나 처음 들어온 지인이 직관적으로 따라 할 수 있는 '시각적 카드뉴스 형태의 설치 가이드' 부재.
  - **2층 (구조/프로세스 부재)**: 모바일 크롬 브라우저의 '홈 화면에 추가' 과정(주소 입력 -> 점 3개 메뉴 터치 -> 홈 화면에 추가 터치 -> 추가/설치 터치 -> 스마트폰 바탕화면에 앱 아이콘 생성)을 실제 캡처 화면과 목업으로 보여주는 온보딩 에셋 및 인앱/웹 뷰어 파이프라인 결여.
  - **3층 (시스템/유저 체감 괴리)**: 사용자는 "앱을 다운로드 받아야 한다"고 생각하는데, 스토어 출시 전이라 웹 링크를 보고 혼란을 겪음. 실제 스마트폰 바탕화면에 아워골 아이콘이 깔려 앱처럼 열리는 결과물까지 시각적으로 명확히 증명해 주어야 안심하고 설치함.
- **사용자 상황 및 페르소나**:
  - 상민님의 초대를 받아 아워골을 최초로 사용해보려는 지인/테스터 (안드로이드/PC 크롬 사용자 중심, iOS 사파리 안내 보조 포함).
  - 복잡한 IT 용어를 모르며, 카카오톡 등으로 받은 링크에서 직관적으로 5장의 카드뉴스만 넘겨보고 10초 만에 홈 화면에 앱을 설치하고자 하는 사용자.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축 (Essence Axis)**: INFRA (PWA 기반 배포, 온보딩 인프라 및 사용자 획득 경험 개선)
- **[본질] (Essence)**: 구글 플레이 심사 대기 기간 동안 지인들의 진입 장벽을 0으로 낮추고, 웹 링크를 실제 독립 실행형 모바일 앱으로 전환시키는 **'시각적 신뢰와 10초 설치 경험의 완성'**.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. **원인 1 (매체 단절)**: 텍스트 설명만으로는 크롬 메뉴 위치(우측 상단 ⋮)와 설치 버튼의 명칭 변화('홈 화면에 추가' vs '앱 설치')를 전달하기 어려움.
  2. **원인 2 (시각적 증거 부재)**: 설치 후 실제로 내 스마트폰 바탕화면/홈 화면에 예쁜 아워골 아이콘이 생성된다는 시각적 결과물을 보지 못해 행동 동기가 약함.
  3. **원인 3 (배포 채널 단절)**: 앱 내부에서도 가이드를 열 수 있고, 지인에게 카카오톡/문자로 링크 1개(`.../install-guide.html`)만 보내면 앱 미설치 상태에서도 곧바로 넘겨볼 수 있는 전용 카드뉴스 뷰어 부재.
- **[중심] (Core Bottleneck & Anchor)**:
  - 실제 아워골 모바일 화면과 크롬 브라우저 인터페이스가 100% 결합된 단계별 고화질 카드뉴스 그래픽 에셋(총 5장) 구축 및 지인 전달용 인터랙티브 웹 뷰어 완비.
- **[핵심] (Critical Safety & Termination)**:
  - 기존 아워골의 `index.html`, `manifest.json`, `sw.js` 및 사용자 데이터를 일절 손상시키지 않고, 지인에게 바로 전달할 수 있는 독립형 카드뉴스 웹페이지(`install-guide.html`)와 인앱 연계 모달/배너를 무결성 배선.
- **체감 가설 (User Experience Hypothesis)**:
  > *"지인이 링크를 클릭했을 때, 세련된 5장의 카드뉴스를 스와이프/클릭하며 '1. 크롬 접속 -> 2. 우측 상단 점 세 개 클릭 -> 3. 홈 화면에 추가 클릭 -> 4. 설치 확인 -> 5. 바탕화면 앱 아이콘 생성 완료!'를 눈으로 확인하고 즉시 10초 만에 바탕화면에 아워골을 설치하게 된다."*
- **기존 전체 기능 영향도 분석**:
  - 계정/로그인: 영향 없음 (순수 온보딩/가이드 인프라).
  - 홈 화면 및 스트릭: 홈 화면 상단/설정에 가이드 열기 버튼/링크 안전 배선.
  - 기록/통계/캘린더 탭: 기존 데이터 무손실 100% 보존.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**:
  - 기존 `manifest.json`, `sw.js`, `index.html` 핵심 로직 파괴 금지.
  - 텍스트만 나열된 성의 없는 설명문 금지.
  - 고해상도 그래픽 없이 뭉개진 저품질 화면 캡처 사용 금지.
- **해야 할 것 (Action)**:
  1. 실제 아워골 모바일 캡처 화면과 모바일 크롬 UI가 정교하게 반영된 **고화질 5단계 카드뉴스 그래픽(Card 1~5)** 제작.
     - **Card 1 (시작)**: 모바일 크롬 주소창에 `ourgoal-app.vercel.app` 접속한 실제 아워골 홈 화면.
     - **Card 2 (메뉴 열기)**: 우측 상단 더보기(점 3개 ⋮)를 누른 크롬 드롭다운 메뉴 화면 (빨간 원/화살표 가이드).
     - **Card 3 (설치 선택)**: 메뉴 항목 중 **[홈 화면에 추가]** (또는 **[앱 설치]**) 버튼 하이라이트.
     - **Card 4 (설치 확인)**: "홈 화면에 추가하시겠습니까?" 팝업에서 **[설치/추가]** 누르는 화면.
     - **Card 5 (완료)**: 스마트폰 바탕화면/홈 화면에 정식 앱처럼 깔린 아워골 아이콘(`아워골`) 및 탭 시 전체화면으로 실행되는 모습.
  2. **지인 배포용 인터랙티브 카드뉴스 웹페이지 (`install-guide.html`)**: 모바일에서 손가락 스와이프 또는 좌우 버튼으로 시원하게 넘겨볼 수 있고, [지금 아워골 바로가기], [설명서 링크 복사] 원클릭 지원.
  3. **인앱 가이드 모달 (`index.html`)**: 앱 내에서도 "앱 설치 방법 보기" 또는 "지인에게 설치법 공유" 버튼을 통해 언제든 열어볼 수 있도록 4위 1체 배선.
  4. 지인 카카오톡 묶음 사진 발송용 개별 카드 이미지 에셋 저장 (`assets/guide/card-1.png` ~ `card-5.png`).

### 3-1. 스토리지 원장화 3대 명세 (헌법 제2조 제4항 준수)
- **1호 (원격 DB 스키마 명세)**: 온보딩/설치 가이드 안내 기능으로 신규 DB 컬럼 신설 불요 (클라이언트 무상태 가이드).
- **2호 (스마트 스토리지 분기 설계)**: 카드뉴스 이미지 에셋은 `assets/guide/` 로컬 정적 디렉토리에 WebP/PNG 최적화 저장 및 Vercel 정적 캐싱 지원.
- **3호 (4대 뷰 전파 배선도)**: 인앱 가이드 모달 열기/닫기는 4대 뷰 렌더링에 부작용을 주지 않으며 필요 시 `renderHome()`의 상단 도움말 영역과 자연스럽게 연계.

## 4. [원칙 ④] 1~3 재검토 및 보완 (Review & Edge Cases)
- **비판적 자기 검토 및 약점/한계 인정**:
  - 안드로이드 크롬뿐만 아니라 기기 환경(삼성 인터넷, 네이버 앱, 카카오톡 인앱 브라우저 등)에 따라 UI가 조금씩 다를 수 있음.
  - 보완책: 메인은 가장 보편적인 **크롬(Chrome)**을 기준으로 명확히 설명하되, "카카오톡이나 다른 브라우저에서 열렸을 경우 우측 상단 메뉴에서 [다른 브라우저로 열기(Chrome)]를 먼저 눌러주세요"라는 팁 배너를 상단에 추가하여 이탈을 방지함.
  - 아이폰(iOS 사파리) 사용자를 위한 보조 팁("아이폰 사파리에서는 하단 공유 버튼 -> 홈 화면에 추가") 1줄 가이드 탭도 카드뉴스에 탭 전환으로 탑재.
- **기존 기능과의 충돌 가능성 검토**:
  - 신규 파일 `install-guide.html`과 정적 에셋 `assets/guide/`를 독립 구축하므로 기존 서비스 코드와의 결합도가 낮아 충돌 가능성 0%.
- **엣지 케이스 (Edge Cases)**:
  - 데스크톱 PC 크롬 접속 시: 주소창 우측의 '앱 설치' 아이콘을 통한 PC 바탕화면 바로가기 안내도 카드 4에 병기.
  - 오프라인 환경: PWA 캐시에 `install-guide.html` 및 에셋을 포함시켜 오프라인에서도 열람 가능하도록 보장.

## 5. [원칙 ⑤] 해결 절차 정리 (Procedure & State Propagation)
- **구체적 실행 시퀀스**:
  1. **1단계 (에셋 생성)**: 실제 아워골 화면과 크롬 모바일 브라우저 UI, 그리고 스마트폰 바탕화면 홈 아이콘을 고해상도 SVG/Canvas/HTML 기반으로 정교하게 렌더링 및 캡처하여 고화질 카드 이미지(Card 1~5) 제작.
  2. **2단계 (인터랙티브 웹 뷰어 구축)**: 지인 배포용 스탠드얼론 반응형 카드뉴스 페이지 `install-guide.html` 제작 (터치 스와이프, 진행률 인디케이터, 링크 복사, 원클릭 바로가기).
  3. **3단계 (인앱 연동 모달 배선)**: `index.html` 내 가이드 열기 버튼 및 모달 4위 1체 배선.
  4. **4단계 (서비스워커 캐시 갱신)**: `sw.js`의 `CACHE_NAME`을 신규 티켓 버전으로 갱신하여 즉각 반영 보장.
  5. **5단계 (무결성 및 스모크 테스트)**: `verify-integrity-gate.js` 및 스모크 테스트 실행하여 0 failure 확인.

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)
> *(주의: 본 원칙은 절차 정리(⑤)와 단계별 실행(⑦) 사이에 반드시 독립적으로 존재해야 하며, 생략하거나 타 원칙과 합치는 것은 위헌입니다)*
- **단일 실패점 (SPOF) 점검**:
  - 카드뉴스 이미지가 로딩되지 않는 네트워크 지연 환경에서도 CSS 기반 백업 UI와 텍스트 설명이 완벽하게 렌더링되도록 Fallback 시스템 구축.
- **가정의 타당성 검증**:

- **재검증 결과 도출된 절차 수정/보완사항**:
  - 카드뉴스 뷰어에 안드로이드 크롬뿐 아니라 iOS 사파리 탭을 서브로 포함시켜 어떤 기기로 접속해도 실패 없는 온보딩을 지원하도록 설계 보강.
