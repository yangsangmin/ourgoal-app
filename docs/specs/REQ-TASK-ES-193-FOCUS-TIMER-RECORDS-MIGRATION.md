## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
- **상민님 지시 원문**: "일정탭의 집중타이머를 기록탭쪽으로 옮기고 기록탭에 6개로 만들자, 2줄로 1줄당 3개씩"
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  - 일정 탭 상단 네비게이션에 미래 지향적 캘린더 모드(월간, 주간, 타임라인)와 현재 몰입 측정 도구인 "집중 타이머"가 혼재되어 사용자의 멘탈 모델 분산.
  - 기록 탭 서브탭 5종이 단일행 가로 스크롤로 나열되어 모바일 375px 화면에서 `[보관함]`, `[위클리 리캡]`이 화면 밖으로 잘리는 시각 조형 결함 발생.
  - 집중 타이머 세션 완료 시 생성되는 몰입 기록이 기록 탭 피드 및 히트맵과 탭 간 물리적 분리로 인해 즉각적인 누적 피드백 루프 약화.
- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**: 타이머와 기록 탭의 상호작용이 화면 전환 단계에서 물리적으로 단절되어 있음.
  - **2층 (구조/프로세스 부재)**: 캘린더 도메인과 트래킹 도메인의 경계가 불명확하여 UI 컴포넌트가 모드 바에 무차별 배치됨.
  - **3층 (시스템/유저 체감 괴리)**: 기록 탭에서 전체 기능을 한눈에 조망하지 못하고 스크롤해야만 숨겨진 탭을 발견할 수 있어 기능 인지율 저하.
- **사용자 상황 및 페르소나**: 집중 타이머로 공부/업무를 수행하고 자신의 히트맵 및 기록 피드에 즉시 반영되길 원하는 생산성 유저.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축 (Essence Axis)**: E2(기록 회고) 및 E1(체크인/실행 루프)
- **[본질] (Essence)**: 실시간 몰입 측정(타이머)과 과거 누적 회고(기록/히트맵/통계/보관함/리캡)의 100% 도메인 일체화 및 모바일 375px 무스크롤 3×2 대칭 조형 완성.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. **원인 1**: 캘린더 화면에 타이머를 임시 배치했던 초기 설계 잔재로 도메인 혼선 유발.
  2. **원인 2**: 기록 탭 서브메뉴의 1행 flex 가로 나열로 인한 모바일 375px 오버플로우 및 조형 파편화.
  3. **원인 3**: 타이머 상태 변경(시작, 일시정지, 완료) 시 기록 탭 렌더러와의 결속 부재.
- **[중심] (Core Bottleneck & Anchor)**: 기록 탭 서브탭 6종을 3×2 그리드로 구성하여 375px 모바일에서 터치 타겟 40px 및 가로스크롤 0건을 물리적으로 보증하고, 타이머 뷰를 기록 탭 내부로 완전히 이식하는 것.
- **[핵심] (Critical Safety & Termination)**: 기존 뽀모도로 타이머 로직 및 기록 적립 파이프라인의 100% 무손실 보존과, 일정 탭 호출 시 하위 호환 안전 라우팅 유지.
- **체감 가설 (User Experience Hypothesis)**:
  > *"사용자가 기록 탭에 진입했을 때 3×2 그리드로 배치된 6대 핵심 기능을 한눈에 인지하고, 집중 타이머를 통해 몰입을 완료한 즉시 같은 탭 내의 히트맵과 피드로 누적 성취를 확인하여 강력한 동기부여를 얻는다."*
- **기존 전체 기능 영향도 분석**:
  - 계정/로그인(세션, 게스트, 소셜)에 미치는 영향: 영향 없음 (순수 UI 레이아웃 및 뷰 엔진 재정돈).
  - 홈 화면 및 스트릭에 미치는 영향: 타이머 완료 후 기록 적립 시 홈 및 히트맵 동시 전파 정상 유지.
  - 기록/통계/캘린더 탭에 미치는 영향: 일정 탭은 3열 캘린더로 정돈되고, 기록 탭은 6종 3×2 그리드 및 타이머 모드 탑재.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**:
  - 기존 뽀모도로 타이머 엔진의 타이머 인터벌, 로컬스토리지 누적 키, 기록 생성 포맷을 불필요하게 변경하는 행위.
  - 기록 탭을 1행 6열로 우겨넣어 텍스트가 줄바꿈되거나 터치 타겟이 30px 이하로 뭉개지는 행위.
- **해야 할 것 (Action)**:
  - 일정 탭 모드 네비게이션을 3종(`month`, `week`, `timeline`) 3열 균등 그리드로 정돈.
  - 기록 탭 서브탭을 6종(`heatmap`, `feed`, `timer`, `stats`, `archive`, `recap`) 3×2 그리드로 정돈.
  - `OurgoalSanctuaryV3.setCalMode('timer')` 호출 시 기록 탭의 타이머 모드로 자동 안내하는 하위 호환성 보장.
  - 뽀모도로 세션 시작/일시정지/리셋/완료 시 기록 탭 렌더러와 양방향 동기화.
- **왜 이 방식이어야만 하는가 (Why this approach)**:
  - 모바일(375px) 기준 가로 너비에서 3열 그리드는 각 버튼당 약 110px의 안정적인 터치 영역을 제공하며, 2줄 구성으로 화면 상단 85px 내에 6대 기능을 100% 시각적으로 완벽하게 안착시킴.

### 3-1. 스토리지 원장화 3대 명세 (헌법 제2조 제4항 준수)
- **1호 (원격 DB 스키마 명세)**: 기존 `ourgoal_records`, `ourgoal_timer_state` 스키마 100% 유지 (추가 스키마 변경 불요).
- **2호 (스마트 스토리지 분기 설계)**: 로컬스토리지 및 IndexedDB의 뽀모도로 타이머 진행 시간, 목표 적립 로그 보존.
- **3호 (4대 뷰 전파 배선도)**: 뽀모도로 완료 시 `dispatchFullViewPropagation`을 통해 기록(`renderSanctuaryRecords`), 홈(`renderHome`), 히트맵(`renderSanctuaryRecords`), 캘린더(`renderSanctuaryCalendar`) 동시 전파.

## 4. [원칙 ④] 1~3 재검토 및 보완 (Review & Edge Cases)
- **비판적 자기 검토 및 약점/한계 인정**:
  - 기존 사용자가 일정 탭에서 타이머를 찾던 습관이 있을 수 있음.
  - 보완책: `setCalMode('timer')` 호출 시 에러 없이 기록 탭의 타이머 모드로 매끄럽게 전환되도록 폴백 및 안내 배선 완료.
- **기존 기능과의 충돌 가능성 검토**:
  - 기록 탭의 기존 5개 서브탭(`heatmap`, `feed`, `stats`, `archive`, `recap`)의 렌더링 로직과 완전히 격리된 `activeRecMode === 'timer'` 렌더링 브랜치를 신설하여 충돌 원천 차단.
- **엣지 케이스 (Edge Cases)**:
  - 타이머 작동 도중 사용자가 기록 탭 내 다른 서브탭(예: 통계)으로 이동했다가 복귀하는 경우: 전역 타이머 인터벌 상태를 유지하여 백그라운드 카운트 지속.
  - 모바일 초소형 뷰포트 (320px ~ 375px): 3열 그리드 버튼 내 패딩을 6px, 폰트 크기를 11px로 최적화하여 텍스트 잘림 및 줄바꿈 방지.

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)
> *(주의: 본 원칙은 절차 정리(⑤)와 단계별 실행(⑦) 사이에 반드시 독립적으로 존재해야 하며, 생략하거나 타 원칙과 합치는 것은 위헌입니다)*
- **단일 실패점 (SPOF) 점검**:
  - 기록 탭 내부에서 타이머 인터벌이 DOM 재렌더링 시 중복 생성되거나 소멸할 위험 점검.
  - 전역 `window._pomoInterval` 단일 인스턴스를 유지하여 재렌더링 시에도 타이머 카운트가 안전하게 이어지도록 방어.
- **가정의 타당성 검증**:
  - 기록 탭 6종 3×2 그리드가 모바일 375px 뷰포트에서 가로 스크롤을 유발하지 않는다는 가정: CSS `grid-template-columns: repeat(3, 1fr)` 및 `box-sizing: border-box`로 가로 375px 초과 원천 차단.
- **재검증 결과 도출된 절차 수정/보완사항**:
  - 타이머 완료 시 피드로 자동 전환되는 옵션을 제공하되, 타이머 뷰 자체에서도 즉시 완료 메시지를 표시하여 유저의 흐름이 끊기지 않도록 보완.
