- **현재 문제(표면)**: iOS 는 PWA 를 스토어에 직접 올릴 수 없다(R06). 안드로이드는 TWA/Capacitor 경로가 있으나 iOS 프로젝트(`ios/`)가 저장소에 없다. 예정일 2026-09-17 이 지났다(D+4).
- **표면 아래 기저 층위**:
  - **1층 (미작동/단절)**: `capacitor.config.json` 은 있는데 iOS 플랫폼이 추가된 적이 없다. 웹 코드는 네이티브 셸 존재를 모른다 — 앱 안에서도 사파리용 "홈 화면에 추가" 안내가 뜰 수 있고 서비스워커 등록을 시도한다.
  - **2층 (구조/프로세스 부재)**: 앞선 세션(a32db89e)이 계획서만 만들고 6시간 무응답으로 멈췄다. 맥 접근 여부가 한 번도 확정되지 않았다.
  - **3층 (체감 괴리)**: 실행계획상 "iOS 준비 중"인데 실물이 0이라 "언제 TestFlight 를 여나"를 답할 근거가 없다.
- **사용자 상황**: 상민님이 iOS 지인 베타(T066)를 열려면 이 프로젝트가 있어야 한다. 앱 사용자는 앱 안에서 웹과 똑같은 화면을 봐야 하고, 이미 설치한 앱에서 "설치하라"는 안내를 보면 안 된다.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축**: INFRA (기반·도구)
- **[본질]**: "iOS 프로젝트가 있다"는 선언이 아니라, 저장소에서 Xcode 로 열리는 `ios/` 와 앱 안에서 웹 코드가 스스로 다르게 행동하는 배선이 **실물로** 존재하는 것. 다만 "실기기 실행"은 맥·아이폰·Apple 계정이 있어야 하는 별개 사실이다.
- **[원인]**:
  1. **원인 1**: iOS 네이티브 빌드는 macOS+Xcode 에서만 되는데 이 PC 는 Windows 다 — 그래서 착수가 미뤄졌다.
  2. **원인 2**: 웹 코드에 "네이티브 셸 안인가" 판별이 한 곳도 없다.
  3. **원인 3**: 앞선 세션이 인계 없이 멈췄고 작업 임대가 회수되지 않았다.
- **[중심]**: 윈도우에서 어디까지가 **사실로 확인 가능한가**의 경계. Capacitor 8 은 SPM 을 쓰므로 `cap add ios` 자체는 윈도우에서 된다(실측). 안 되는 것은 Xcode 빌드·서명·실기기 구간이다.
- **[핵심]**: 무너지면 안 되는 것 — (a) 기존 웹·안드로이드 동작(게이트는 "네이티브일 때만" 꺼진다, 판별 실패 = 브라우저), (b) 못 해 본 것을 "된다"고 쓰지 않는 것(스켈레톤은 미검증 표기), (c) 돈이 드는 클라우드 맥을 승인 없이 쓰지 않는 것.
- **체감 가설**:
  > *"아이폰 앱을 연 사용자가 홈에서 '홈 화면에 추가' 배너를 보지 않고, 웹과 같은 화면이 첫 실행부터 오류 없이 뜬다."*
- **기존 전체 기능 영향도**:
  - 계정/로그인: 변경 없음(로그인 흐름 미접촉). 네이티브 OAuth 딥링크 문제는 별도 티켓 사안으로 남긴다.
  - 홈/스트릭: iOS 홈 화면 추가 배너가 네이티브에서만 숨는다. 웹은 동일.
  - 기록/통계/캘린더: 변경 없음.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**: 클라우드 맥 결제(승인선 ①), 앱 화면·CSS 변경, OneSignal 네이티브 의존성을 검증 없이 프로젝트에 넣기, "실기기 실행 확인 완료" 주장, 로그인 흐름 변경.
- **해야 할 것 (Action)**: ① `ios/` 스캐폴드(`cap add ios`) 커밋 ② `js/native-platform.js`(판별) + 게이트 3곳 ③ `js/native-push.js`·`ios/App/OurgoalWidget/` 스켈레톤(미검증 표기) ④ macOS CI 워크플로는 금고 파일(`.github/**`)이라 이 변경에 담지 않고, 금고만 담은 별도 PR + 상민님 결심으로 분리한다 ⑤ 실기기 구간은 사람 손·결심으로 정확히 분류.
- **왜 이 방식이어야만 하는가**: 윈도우에서 실측으로 가능한 것(스캐폴드·게이팅·단위 검증)은 전부 하고, 불가능한 것은 증거와 함께 경계를 그어야 T064·T066 이 이어진다. 시뮬레이터 빌드용 CI 는 공개 저장소라 macOS 러너가 무료지만, 금고 변경이라 이 작업에서 만들지 않는다.

## 4. [원칙 ④] 1~3 재검토 및 보완 (Review & Edge Cases)
- **비판적 자기 검토 및 한계 인정**: 이 작업만으로는 완료 기준(Xcode 실기기 스크린샷)을 채울 수 없다 — 맥·Xcode·아이폰·Apple 서명이 필요하다. 그래서 산출물에 "실기기 미확인"을 명시하고 완료요청을 켜지 않는 쪽이 정직하다. 또 `capacitor.config.json` 의 `server.url` 이 원격이라 웹 에셋 번들(`www`)은 오프라인 폴백에 불과하며, 심사(가이드라인 4.2)에는 네이티브 기능 2개(푸시·위젯)의 실동작이 필요하다(T064).
- **기존 기능과의 충돌 검토**: `sw.js`·웹 푸시는 브라우저에서 그대로다(단위 검증으로 확인). `capacitor.config.json` 은 수정하지 않는다(안드로이드 CI 트리거 경로라 건드리면 APK 빌드가 도는 부작용).
- **엣지 케이스**:
  - 네트워크 단절/오프라인: 원격 URL 로딩이라 오프라인 첫 실행은 실패한다 → T064 이후 과제로 기록.
  - 비정상 입력값: `window.Capacitor` 가 이상하거나 판별 함수가 던져도 브라우저로 본다(단위 검증 항목).
  - 첫 방문자 vs 헤비 유저: 저장 데이터를 안 건드려 차이 없음.
