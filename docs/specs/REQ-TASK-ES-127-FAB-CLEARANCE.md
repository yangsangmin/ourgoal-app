## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
- **상민님 지시 원문**: "모듈화작업 완료됐는데, 이제 아워골 ui/ux를 획기적으로 개선해야해 지금 아워골 ui문제 전 탭에서 파악하고, 지식기반에 정체중인 티켓들이랑 문제점 파악된거랑 결합해서, 신규 티겟들 아워골 명령입력/메모장 (명령대기 & 아이디어 DB) db에 구축하자. 그 뒤에 그 티켓들 내가 검토하고 그대로 ui/ux 개선 진행할게"
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  1. 하단 내비게이션 바 중앙의 빠른 체크인 FAB(`#bottomNavFab`, `.navbtn-fab`)이 4대 테마(`focus-sanctuary`, `black`, `white`, `urban-city`)에서 `display: none !important;`로 숨겨져 있거나, 기본 테마에서 배경이 투명/흐릿하여 보이지 않음.
  2. 전 탭 하단 여백이 24px로 덮어씌워져 있어, 75px 플로팅 내비게이션 바가 스크린 맨 아래의 핵심 액션 버튼(기록 완료, 일정 추가, 최근 기록 카드, 보안 점검 버튼 등)을 가려 터치하기 어려움.
- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**: `ui.css` 내 4대 테마 오버라이드에서 FAB 버튼을 `display: none`으로 일괄 차단하고 있었으며, `#screen-*` 컨테이너의 `padding-bottom: 24px !important`가 탭바 높이보다 작아 최하단 요소가 가려짐. 타 탭에서 FAB 클릭 시 홈 탭 전환 없이 `#captureInput`을 찾으려 하여 작동하지 않음.
  - **2층 (구조/프로세스 부재)**: 테마 오버라이드 작성 시 하단 탭바를 5개 균등 배치로 단순화하려다 핵심 UX 진입점인 돌출 FAB을 말살함.
  - **3층 (시스템/유저 체감 괴리)**: 사용자는 언제 어디서든 홈 화면의 체크인으로 즉시 진입하고 싶으나 버튼이 보이지 않거나 눌러도 반응이 없고, 탭 최하단 버튼을 누르려다 탭바가 눌리는 오조작 발생.
- **사용자 상황 및 페르소나**: 아워골 모바일 앱 사용자가 어떤 탭을 보고 있든 중앙의 (+) 버튼으로 즉시 체크인에 도달하고, 탭 최하단까지 시원하게 스크롤하여 모든 기능을 온전히 누르고자 하는 상황.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축 (Essence Axis)**: `INFRA/UX` (글로벌 셸 및 뷰포트 조형 정상화)
- **[본질] (Essence)**: 아워골 앱 셸(App Shell)의 기본 골격인 내비게이션 바와 스크롤 컨테이너의 물리적 여백 정상화.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. `ui.css:8103-8111` 테마별 셀렉터에서 `#bottomNavFab`에 `display: none !important` 부여.
  2. `ui.css:6315` 기본 `.navbtn-fab` 배경이 저대비 반투명 흰색 그라디언트로 설정되어 배경 투과.
  3. `ui.css:9103` `#screen-home, #screen-goals, ...`에 `padding-bottom: 24px !important`가 강제되어 75px 탭바에 최하단 요소가 가려짐.
- **[중심] (Core Bottleneck & Anchor)**: FAB 버튼의 시각적 가시성(WCAG AA 4.5:1 이상) 및 전 탭 `padding-bottom: max(96px, ...)` 보장.
- **[핵심] (Critical Safety & Termination)**: 기존 6대 탭 버튼(홈, 목표, 일정, 기록/통계, 소통, 설정)의 정렬 비율 및 클릭 동작을 100% 보존하면서 FAB을 조화롭게 안착.
- **체감 가설 (User Experience Hypothesis)**:
  > *"사용자가 어떤 탭에 있든 하단 중앙의 에메랄드 (+) FAB을 보면 즉각 체크인 욕구가 생기며, 탭 최하단까지 막힘없이 스크롤하여 탭바 가림 없는 쾌적한 조작감을 느낀다."*
- **기존 전체 기능 영향도 분석**:
  - 계정/로그인: 영향 없음 (전체 셸 내부 렌더링 유지).
  - 홈 화면 및 스트릭: 최하단 여백 확장으로 컨디션 슬라이더 및 체크인 완료 버튼 시인성 증대.
  - 기록/통계/캘린더 탭: 하단 안전 여백 96px 확보로 최하단 요소 가림 0건 달성.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**: 기존 6개 탭의 기능, 라벨, SVG 아이콘을 변경하거나 탭바의 전체 레이아웃 구조를 깨뜨리는 행위 금지.
- **해야 할 것 (Action)**:
  1. 4대 테마 전부에 대해 `.navbtn-fab`을 `display: flex !important`로 복원하고 테마별 액센트 그라디언트 적용.
  2. 전 탭 컨테이너의 하단 패딩을 `max(96px, calc(var(--nav-h, 64px) + env(safe-area-inset-bottom, 24px) + 32px)) !important`로 일괄 확장.
  3. FAB 클릭 시 홈 탭 전환 후 `#captureInput`에 포커스되도록 핸들러 보강.
- **왜 이 방식이어야만 하는가 (Why this approach)**: 순수 CSS와 경량 핸들러 보강만으로 전역 회귀 결함 없이 셸의 물리적 안정성을 완벽히 회복할 수 있기 때문.

### 3-1. 스토리지 원장화 3대 명세 (헌법 제2조 제4항 준수)
- 본 작업은 셸 및 CSS 스타일/레이아웃 정상화 작업으로 DB 스키마 변경 사항 없음.

### 3-2. 전수 인터랙션(버튼/클릭/입력) 명세표 (Zero-Dead-Click)
| UI 요소 (ID / Name) | 위치/화면 | 사용자 액션 | 기대 동작 (비즈니스 로직) | 예외 처리 및 사용자 피드백 |
| :--- | :--- | :--- | :--- | :--- |
| `bottomNavFab` | 하단 탭바 중앙 | 클릭/터치 | 홈 탭 전환(`setTab('home')`) 후 `#captureInput` 스크롤 & 포커스 | 요소 부재 시 예외 없이 부드럽게 무시 |

### 3-3. 유저 데이터 100% 무손실 보존 규격 (Zero-Data-Loss Schema)
- 유저 데이터 변경 없음 (아바타, 목표, 기록, 설정값 100% 불변 보존).
