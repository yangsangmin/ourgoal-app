## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)

- **상민님 원문 지시사항**:
  - "아워골 ui 전면 개편필요해. 어제랑 오늘 실 사용자들 후기를 내가 받았는데, 역시 지금상태는 복잡함이 많고 앱을 처음 사용하는 사람들에게 거부감이 들 수 있어. 각 칸별로 구분이 잘 되도록 테두리 조금 더 강조하고 이런 상세관리 어플 잘 안쓰는 공간 지각력 부족한 사람도 더 쉽게, 재밌게 받아들여지는 ui 구성이 필요해. 대책마련해서 ui 개편안 이미지파일로 보여줘. 일단 홈탭만."
- **표면적 현상**:
  - 실 사용자들이 앱을 처음 켰을 때 화면이 복잡하고 답답하게 느껴져 진입 장벽과 거부감을 느낌.
  - 카드가 배경에 묻혀 어디서부터 어디까지가 한 덩어리인지 구분이 잘 되지 않음.
- **기저 층위별 심층 분석**:
  - **1층 (시각적 경계 모호 층위)**: 카드의 테두리가 `rgba(15,23,42,0.08)`의 매우 연한 8% 투명도 실선으로 되어 있어, 흰색 배경 위에서 카드 블록의 구획이 소멸되어 평면적이고 넓은 텍스트 덩어리로 보임.
  - **2층 (정보 과밀 및 인지 부하 층위)**: 홈 화면에 탑바 액션, 나만의 홈구성, 레벨 배지, 오늘의 질문, 테마 선택바, AI 피드백 티어 버튼, 오늘 레이스, 히트맵 요약, 목표 목록, 공유 버튼 등 10여 개의 요소가 한 화면에 빽빽하게 수직 나열되어 초보자가 무엇을 먼저 해야 할지 판단할 수 없음.
  - **3층 (사용자 멘탈 모델 및 공간 지각력 층위)**: 복잡한 생산성 툴(노션, 지라 등)에 익숙하지 않은 일반 사용자는 복잡한 서식형 UI에서 공간적 위계(Primary vs Secondary)를 파악하지 못해 스트레스를 받음. "게임처럼 쉽고, 재밌고, 한눈에 딱 들어오는" 모듈형 카드 경험이 절실함.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)

- **[본질] (Essence)**:
  - 아워골 홈탭의 본질은 **"오늘 하루의 성장을 1초 만에 확인하고, 부담 없이 즐겁게 딱 한 줄을 기록하는 따뜻한 실천의 시작점(E1 루프)"**이다. 결코 기능을 자랑하는 복잡한 대시보드가 되어서는 안 된다.
- **[원인] (Root Causes)**:
  - **원인 1**: 지속적인 기능 추가 과정에서 홈 화면에 신규 위젯들이 수직으로 적층되었으나, 초보자 관점의 시각적 위계 정리와 그룹핑이 부재했음.
  - **원인 2**: 카드 스타일이 미니멀리즘을 과도하게 추구하여 테두리 대비가 극도로 낮아져 카드 간 경계가 붕괴됨.
  - **원인 3**: 전문 생산성 앱 스타일의 설정성 UI(AI 티어 3단계, 테마 설명문, 레이아웃 커스텀)가 첫 진입 화면 전면에 여과 없이 노출됨.
- **[중심] (Core Bottleneck)**:
  - **"칸별 테두리 시인성 대폭 강화(Bold Modular Card)"**와 **"3단 스마트 구역화(히어로 / 간편 기록 / 퀘스트 목표)"**를 통한 인지 부하 해소.
- **[핵심] (Critical Anchor)**:
  - 공간 지각력이 부족한 초보자도 0.1초 만에 영역을 구분할 수 있는 1.5px~2px 볼드 테두리와 세련된 카드 분리.
  - 쓸데없는 설명 문구와 복잡한 버튼을 숨기고 가장 중요한 [기록창]과 [목표 퀘스트]를 주인공으로 격상.
  - 시각적 개편안을 사용자가 실물로 체감할 수 있는 정밀 UI 목업 이미지 생성.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)

- **하지 말 것 (Don'ts)**:
  - 기존 핵심 기능(체크인, 목표 관리, AI 피드백, 스트릭)의 백엔드 로직이나 데이터 모델을 파괴하지 않는다.
  - 단순히 색상만 화려하게 덧칠하는 껍데기 디자인을 지양한다.
- **할 것 (Dos)**:
  - **대책 1: 볼드 모듈러 보더(Bold Modular Borders)**
    - 카드 테두리를 `border: 1.5px solid #E2E8F0` (다크 테마: `rgba(255,255,255,0.18)`)로 선명하게 격상하고 코너 라운딩을 `18px~20px`로 부드럽게 조정하여 블록 장난감처럼 손에 잡히는 카드 모듈화.
  - **대책 2: 3단 스마트 구역화 (3-Zone Modular Hierarchy)**
    - **Zone 1 (Hero)**: 320종 아바타 + "오늘도 불꽃 연속 3일째! 🔥" 따뜻한 응원 히어로 배너.
    - **Zone 2 (Quick Action)**: "오늘 한 일 톡 적기" 입력창 + 큼직한 [기록 완료] 액션 버튼 (복잡한 옵션은 미니멀 칩으로 압축).
    - **Zone 3 (Quest Goals)**: 게임 퀘스트 형태의 목표 달성 게이지 카드.
  - **대책 3: 비주얼 UI 개편안 이미지 렌더링**
    - `generate_image`를 통해 실제 모바일 환경에서 구현될 홈탭의 완성도 높은 개편안 목업 이미지를 생성하여 상민님께 즉시 시각적 확인 제공.

## 4. [원칙 ④] 1~3 재검토 · 보완 (Critical Review & Edge Cases)

- **허점 및 약점 검토**:
  - 테두리를 너무 두껍게 하면 자칫 UI가 투박해질 위험 존재 → 1.5px 두께에 부드러운 라운딩(`border-radius: 18px`) 및 은은한 하단 섀도우를 결합하여 모던하고 경쾌한 감성 유지.
  - 기존에 제공되던 부가 기능(사진 첨부, 음성 마이크, 테마 선택 등)이 누락되지 않도록 입력창 내부 인라인 아이콘 툴바로 우아하게 통합.
- **엣지 케이스**:
  - 목표가 0개인 신규 가입자: 빈 카드 스타터 템플릿을 아바타 응원과 함께 친절히 노출.
  - 다크모드/테마 전환: 7대 테마 변수(`--card`, `--rule`, `--brand`)와 완벽 동기화.

- **순차 실행 시퀀스**:

  - [절차 4]: Tri-Sync 관제센터 저널에 작업 착수 이벤트 기록.
  - [절차 5]: 상민님께 UI 개편안 이미지 및 구조적 대책 최종 브리핑.

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)

- **SPOF 점검 및 검증**:
  - 이미지 생성 실패 가능성 검토: 프롬프트에 모바일 UI 목업, 아워골 브랜딩, 명확한 테두리, 카드형 퀘스트 구조를 정확히 묘사하여 안정적 렌더링 보장.
  - 본 작업은 상민님의 "대책마련해서 ui 개편안 이미지파일로 보여줘. 일단 홈탭만" 지시(모드 2/3)에 해당하므로, 기존 프로덕션 코드를 임의로 파괴하지 않고 완벽한 기획과 비주얼 시안으로 검증을 완결함.
