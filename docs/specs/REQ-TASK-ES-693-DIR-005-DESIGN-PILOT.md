- 앞선 초안에는 틀린 자리가 있었다: ① 창 이름의 자리를 681행으로 적었는데 그 줄은 `data-widget-label` 속성이고 보이는 글은 684행이다 ② 결심 대기의 저장 실패 줄이 「서버 동기화 실패를 255행에서 콘솔 경고로만 남긴다」고 적었는데, 조사 결과 500 · 401 응답은 예외가 아니라서 255행에 닿지 않는다(경고 0건) ③ 칩 줄 둘(커닝페이퍼 줄 · 고정 추천 칩 줄)을 하나처럼 적었다 ④ 기록 창 묶음이 저장 처리와 묶이는 까닭을 글로 짚었는데 실제는 제품 코드가 꾸밈을 직접 적는 18곳과 저장 상태 표시다 ⑤ 공용 값 묶음의 「미리 적을 자리」 둘(기록 창 자신 · `.rec-pill-btn.active`)이 재 보니 예상과 달랐다. 다섯 다 고쳤다.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심

- **본질**: 디자인을 바꾸는 일이 기록 저장을 건드리지 않게, 그리고 「모양이 명세대로 됐다」가 「저장이 안전하다」로 읽히지 않게 선을 긋는다.
- **원인**: 시범 구획(오늘 기록하기 창)의 저장 단추 뒤에 저장 실패가 조용히 지나가는 길이 있다. 디자인 지시가 그 길을 「전과 같이 작동」으로 보존하면 결함도 보존된다.
- **중심**: 측정값. 줄 번호와 숫자는 손으로 적지 않고 도구가 코드와 원본 자료에서 읽어 채운다.
- **핵심**: 상민님 원문 · 지휘 세션의 해석 · 세션끼리의 합의 · 다른 세션의 측정 · 이 작업자의 측정을 섞지 않는다.

## 3. [원칙 ③] 해결 방식

- 글틀(`reports/TASK-ES-693/text/*.md`)에 숫자를 표지 `{{이름}}` 로 두고, `tools/measure.cjs` 가 잰 값을 `tools/render-directive.cjs` 가 채워 지시함에 넣는다. 도구는 넣기 전에 지시가 기대는 사실 27가지가 지금 코드 · 원본 자료와 맞는지 보고, 틀리면 멈춘다.
- 저장 실패 조사는 볼트가 정본이다. 결심 대기 줄이 근거를 저장소 안에서 가리킬 수 있게 사본을 근거 폴더에 두었다(브라우저 재현이 진행 중이라고 덧붙였다).

## 4. [원칙 ④] 재검토

- **이 지시가 승인선을 넓히지 않는가** → 기능 삭제 · 새 상태 · 동작 변경 · 새 글꼴 · 헌 파일 삭제는 지시에 없다. 슬라이더를 나란히 두는 것은 「상민님 확인 전의 기본값」이라 적고 되돌릴 수 있게 하라고 했다. 고정 추천 칩의 합의안은 지시가 아니라 「결심 대기」 표에 올렸다.
- **묶음 ② 가 조건 없이 시작되지 않는가** → 착수 조건을 (나) 머리와 (라)에 적고 완료 기준 (5)에 넣었다. 저장 안정화 지시가 병합되기 전에는 시작하지 않는다.
- **병합 전의 목록이 기준처럼 읽히지 않는가** → 지시 · 목록의 머리 · `읽어두기.md` 세 군데에 「승인된 기준이 아니다」와 「주 가지가 움직이면 다시 찍는다」를 적었다. 도구는 목록의 기준 커밋이 지금의 주 가지와 다르면 멈춘다.
- **다른 세션의 측정을 내 측정처럼 적지 않았는가** → 「시안 담당의 측정」 · 「그 목록이 잰 값」 · 「조사 담당이 … 돌린 결과」 · 「로드맵 세션이 알린 곳(열어 보지 못했다)」로 적었다.
