## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)

- **상민님 지시 원문**:
  > *"보고했던 의도대로 구현되었다고 생각해?"* ➔ (반쪽짜리 구현 및 타협 솔직 시인) ➔ *"홉탭부터 순서대로 가자 1번 홈탭부터 요구사항정의서만 다시 작성해"*
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  1. **16개 컴포넌트 수직 과밀 적층 (Cognitive Overload)**:
     - 현재 `#screen-home`은 상단 그리팅, 커스텀 홈 레이아웃 버튼, 문장형 헤드라인, 레벨 배지 행, 투데이 글랜스 알약, 오프라인 공지, 오늘의 질문 카드(`todayMissionCard`), 히트맵 요약(`homeGrassSummaryCard`), 3초 체크인 카드(`captureCardBox`: 테마 퀵바, 커닝페이퍼 아코디언, 텍스트에어리어, 마이크, AI 모드 3단 바, 사진/불러오기 버튼, 저장 버튼), 맞춤 피드백 설정 버튼, 크루 페이싱 레이스 위젯(`crewPacingWidget`), 갓생 퀘스트 헤더, 목표 목록(`homeGoalList`), 성장 확인/자랑 액션 버튼 2개, 아워골 평가하기 거대 배너(`homeEvalBanner`)까지 무려 16개 이상의 독립 UI 블록이 한 화면에 위아래로 길게 늘어서 있음.
  2. **모바일 375px 뷰포트에서 4~5회 스크롤 마찰**:
     - 사용자가 앱을 켜고 오늘 해야 할 핵심 목표를 확인하거나 체크인을 하려면 화면을 4~5번씩 휠 다운해야 하므로, 첫 화면에서 즉각적인 집중이 불가능하고 산만함.
  3. **3초 체크인의 둔탁함**:
     - 빠르고 경쾌해야 할 체크인 폼 주변에 테마 안내 문구, 커닝페이퍼 접이식 UI, AI 모드 선택 바(기본/중간/정밀) 등이 과도하게 노출되어, 유저가 입력하기 전 수많은 시각적 노이즈를 처리해야 함.
  4. **사족 배너 및 평가 위젯의 시선 강탈**:
     - 아워골 평가하기 거대 카드(`homeEvalBanner`)와 맞춤 피드백 버튼이 상시 노출되어 \x27나의 하루와 성장\x27이라는 홈의 핵심 가치를 희석시킴.
- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**:
    - 체크인 완료 인터랙션 시 성취감과 타격감을 주는 토스식 비주얼 피드백(카드 전환, 마이크로 인터랙션)이 부족하고 정적인 텍스트 메시지에 머물러 있음.
  - **2층 (구조/프로세스 부재)**:
    - 기능이 추가될 때마다 화면 상하 공간에 병렬 적층하는 \x27개발자 기능주의 레고 블록\x27 방식으로 인해, \x27점진적 공개(Progressive Disclosure)\x27와 \x27엄지 영역(Thumb-Zone)\x27 중심 인터페이스가 결여됨.
  - **3층 (시스템/유저 체감 괴리)**:
    - 유저는 "오늘 내가 무엇을 하면 되는지"를 단 3초 만에 확인하고 1터치로 실천하길 원하지만, 화면은 온갖 위젯과 배너로 가득 차 있어 ERP 관리자 페이지 같은 피로감을 줌.
- **사용자 상황 및 페르소나**:
  - 출퇴근길 지하철이나 잠들기 전 침대에서 한 손(엄지손가락)으로 스마트폰을 쥐고 오늘 하루를 확인하고 가볍게 체크인하려는 2030 갓생러.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)

- **본질 축 (Essence Axis)**: E1 (체크인 루프) 및 성장 효능감 강화
- **[본질] (Essence)**:
  - 토스식 홈 화면의 본질은 **"오늘의 원카드 (Today Focus Card)와 1터치 쾌속 체크인"**이다.
  - 앱을 여는 순간 "상민님, 오늘 저녁 8시 5km 러닝이 기다려요"와 같이 유저의 오늘 1순위 행동이 가장 돋보이는 큼직한 원카드로 제시되고, 군더더기 없는 3초 체크인을 통해 즉각적인 성취감을 얻는 것이 홈 탭의 유일무이한 존재 이유다.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. **원인 1 (위젯 병렬 적층의 관성)**:
     - 질문 카드, 히트맵 요약, 체크인 카드, 크루 레이스, 퀘스트 목록, 평가 배너가 위계 없이 동등한 카드 박스로 수직 나열됨.
  2. **원인 2 (체크인 카드 내부의 시각적 공해)**:
     - 커닝페이퍼 예시, 테마 설명 문구, AI 모드 선택 알약 버튼이 체크인 폼 주변에 상시 펼쳐져 있어 입력 몰입을 방해함.
  3. **원인 3 (상시 배너와 관리자성 UI 잔존)**:
     - 상단의 \x27나만의 홈 구성\x27 버튼이나 하단의 \x27아워골 평가하기\x27 거대 박스가 상시 자리를 차지하여 시각적 정숙함을 해침.
- **[중심] (Core Bottleneck & Anchor)**:
  - 기존 38대 무결성 게이트와 767개 정적 버튼의 배선, 그리고 데이터 렌더러(`renderHome`, `captureSave`, `updateAppBadge`)를 단 1개도 파괴하지 않으면서, 시각적 계층을 **\x271화면 1목적: 오늘의 원카드 & 클린 체크인\x27**으로 우아하게 재편하는 외과수술적 리팩토링.
- **[핵심] (Critical Safety & Termination)**:
  - `#captureInput`, `#captureSave`, `#micBtn`, `#capturePhotoBtn`, `#importExternalBtn`, `#homeGoalList`, `#btnCustomHomeLayout`, `#btnOpenEvalModal`, `#todayMissionCard`, `#crewPacingWidget` 등 헌법 및 테스트 필수 DOM ID 100% 불변 보존.
  - 배너와 부가 옵션은 삭제가 아니라, 더보기/바텀시트로 깔끔하게 수납하거나 시각적 군더더기를 걷어내어 무결성 100% 보증.
- **체감 가설 (User Experience Hypothesis)**:
  > *"사용자가 아침에 홈 탭을 열었을 때, 어지러운 16개 위젯 대신 큼직하고 아름다운 \x27오늘의 원카드\x27와 간결한 \x273초 체크인\x27이 한눈에 들어와, 엄지손가락으로 탭 한 번에 하루의 성장을 기분 좋게 완료하게 된다."*
- **기존 전체 기능 영향도 분석**:
  - 계정/로그인: 세션, 게스트, 320종 아바타 보관함 100% 불변 보존.
  - 목표/기록/통계/캘린더: 홈 탭의 체크인 완료 시 `dispatchFullViewPropagation()`을 통해 연계 뷰 동시 전파 100% 유지.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)

- **하지 말아야 할 것 (Avoid)**:
  - 기존 필수 DOM ID 및 테스트 앵커 셀렉터 삭제/은폐 금지 (`display: none` 위헌 패턴 금지).
  - \x27잔디\x27 단어 사용 금지 (\x27히트맵\x27 단일화).
  - 아바타 \x2777종\x27 사용 금지 (\x27320종\x27 단일화).
  - 껍데기 UI 또는 미배선 버튼 생성 금지 (Zero Dead Click 100% 보장).
- **해야 할 것 (Action)**:
  1. **\x27오늘의 원카드 (Today Focus Card)\x27 전면 구축**:
     - 상단 문장형 헤드라인 아래, 유저의 오늘 가장 중요한 1순위 퀘스트(또는 당일 실천 목표)를 큼직하고 모던한 토스 스타일 원카드로 전면 배치.
     - 원카드 내에 원터치 완료 체크 및 직관적인 진행률(Progress) 바 통합.
  2. **\x27오늘의 3초 체크인\x27 클린 리팩토링**:
     - 장황한 커닝페이퍼 아코디언과 AI 모드 3단 바를 깔끔하게 접거나 시각적 노이즈를 최소화.
     - 텍스트 입력창, 음성 마이크, 사진 첨부, 저장 버튼을 모던한 1카드 레이아웃으로 일체화.
  3. **사족 배너 및 분산 위젯의 위계 정돈 (Progressive Disclosure)**:
     - 아워골 평가하기(`homeEvalBanner`)는 화면 하단 서머리 푸터로 자연스럽게 정돈.
     - 크루 달성 레이스 및 질문 카드는 투데이 원카드와 자연스럽게 조화를 이루도록 패딩 및 카드 위계 튜닝.

### 3-1. 스토리지 원장화 3대 명세 (헌법 제2조 제4항 준수)
- **1호 (원격 DB 스키마 명세)**:
  - 기존 테이블(`profiles`, `goals`, `milestones`, `checkins`, `feed_posts`, `app_settings`) DDL 변경 0건 (100% 하위 호환).
  - 순수 클라이언트 프레젠테이션 계층 정돈 및 인터랙션 강화.
- **2호 (스마트 스토리지 분기 설계)**:
  - 320종 아바타 에셋 및 유저 생성 사진(Photo)은 기존 3계층(Supabase DB / IndexedDB / localStorage 메타) 캐시 파이프라인 유지.
- **3호 (4대 뷰 전파 배선도)**:
  - 홈 탭에서 체크인 저장(`captureSave`) 또는 퀘스트 완료 시 `dispatchFullViewPropagation()` 호출을 통해:
    1. `renderHome()`: 오늘의 원카드 및 스트릭, 배지 즉시 갱신
    2. `renderRecordsScreen()`: 기록 피드 및 최신 AI 코칭 카드 동기화
    3. `renderStatsScreen()`: 당일 히트맵 셀 색상 실시간 점등
    4. `renderCalendar()`: 당일 타임라인 카드에 실천 기록 추가

### 3-3. 유저 데이터 100% 무손실 보존 규격 (Zero-Data-Loss Schema)
- **아바타 보존**: 기존 320종 아바타 보관함, 장착 엠블럼, 레벨(1~25단계), 닉네임 100% 불변 보존.

- **화면 구성 세팅값 보존**: 다크모드/테마, 홈 구성 커스텀 설정값 `localStorage` 키 불변 유지.

## 4. [원칙 ④] 1~3 재검토 및 보완 (Review & Edge Cases)

- **비판적 자기 검토 및 약점/한계 인정**:
  - 홈 탭의 사족 배너와 위젯을 단순 삭제할 경우, 기존 스크립트(`renderHomeEvalBanner`, `initFeedbackTierBar` 등)가 해당 DOM 요소를 찾지 못해 자바스크립트 크래시가 발생할 위험이 있음.
  - 따라서 DOM 엘리먼트를 제거하지 않고, **시각적 계층 구조를 토스식 미니멀 카드로 재편하고 부가적인 제어 요소는 깔끔한 접이식 및 마이크로 인터페이스로 단정화**하는 외과수술적 래핑 방식을 취해야 함.
- **기존 기능과의 충돌 가능성 검토**:
  - `smoke-test.js` 내의 335개 테스트와 `verify-all-clicks.js`의 767개 정적 버튼 목록에 홈 화면 버튼들이 대거 포함되어 있음.
  - 모든 버튼 태그와 인라인 이벤트, ID를 100% 유지하면서 CSS와 컨테이너 구조를 개편하므로 충돌 가능성 0%.
- **엣지 케이스 (Edge Cases)**:
