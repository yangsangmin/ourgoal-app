## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
- **상민님 지시 원문**:
  > "팀목표에서 내 동반자 또는 동반자가 아닌데 내가 알고있는 아워골 가입자 지인을 바로 검색해서 팀원으로 초대할 수 있는 기능이 없는게 말이 되냐?"
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  - 현재 팀 목표 카드에서 `👥 팀원 초대` 버튼을 누르면 카카오톡/문자(SMS)/링크 복사 등 외부 공유 기능만 노출됨.
  - 이미 아워골 앱 내에서 나와 함께 달리고 있는 '나의 동반자(러닝메이트)'가 존재함에도 불구하고 팀 목표 모임으로 바로 초대/영입하는 버튼이 존재하지 않음.
  - 또한 아직 동반자를 맺지 않았더라도 사용자가 이미 알고 있는 실제 아워골 가입 지인/동료를 닉네임으로 실시간 검색하여 팀원으로 즉각 초대·영입하고 동시에 동반자로 연동하는 핵심 소셜 루프가 단절되어 있음.
- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**: `openTeamInviteModal`이 단순 텍스트 클립보드 복사 및 외부 메신저 링크 발송에만 치중되어 내부 소셜 원장(동반자 목록 및 Supabase 회원 검색 API)과 전혀 배선되어 있지 않음.
  - **2층 (구조/프로세스 부재)**: 팀 초대 모달이 팀 내부 멤버십(`g.members`, `g.roster`, `groupState(gid).membersList`) 및 팀 채팅방 알림과 통합되지 못함.
  - **3층 (시스템/유저 체감 괴리)**: 아워골 가입 유저가 팀 목표를 개설하거나 운영할 때 인앱에서 동료를 초대하지 못하고 일일이 외부 메신저로 나가야 하므로 소셜 효능감과 커뮤니티 연결감이 심각하게 훼손됨.
- **사용자 상황 및 페르소나**:
  - 회사 워크숍 TF, 제주 단체여행, 마라톤 완주방 등 팀 목표를 개설하고 팀원을 구성하려는 모임장 또는 팀원.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축 (Essence Axis)**: E3 (동류 소통 및 팀 빌딩 루프) + FIX (미배선 단절 결함 정비)
- **[본질] (Essence)**: 팀 목표는 혼자 달리는 고독한 목표가 아니라 동료와 함께하는 집단 지성의 장이므로, '내 동반자 목록'과 '아워골 전체 가입자 풀'에서 원클릭으로 팀원을 영입하고 실시간 팀 톡방에 합류시키는 완결된 인앱 소셜 파이프라인이 본질이다.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. **초대 모달의 외부 공유 편향**: 초기 구현 시 외부 바이럴 유입용 딥링크만 단순 배치되고 인앱 동반자 원장 연동이 누락됨.
  2. **팀 멤버십 원장과의 비동기화**: 초대 행위가 모임 객체(`g`)의 참여 인원 및 실시간 팀 채팅 시스템 메시지로 직결되지 않음.
  3. **회원 검색 파이프라인의 팀 초대 모달 미통합**: 소통 탭의 `/api/track` 및 Supabase RPC 검색 기능이 팀 초대 모달에 재사용되지 않고 격리되어 있었음.
- **[중심] (Core Bottleneck & Anchor)**:
  - 2단 탭 UI (`[👥 아워골 친구·지인 초대 (기본)]` vs `[🔗 외부 공유]`)를 통해 내부 원탭 초대와 외부 공유를 완벽하게 조화시키고, 동반자/검색 결과 카드에서 `[+ 팀 초대]`, `[+ 팀원으로 영입]` 클릭 시 즉각 팀원 등록 + 동반자 자동 연동 + 팀 채팅방 초대 시스템 메시지 발송 3단 완결.
- **[핵심] (Critical Safety & Termination)**:
  - 이미 해당 팀에 참여 중인 유저는 `[✓ 참여 중]` 비활성 배지로 표시하여 중복 초대 원천 차단.
  - 초대 즉시 `g.members` 및 로스터, 팀 상태를 영속화하고 목표 탭 화면에 실시간 리렌더링 반영.
- **체감 가설 (User Experience Hypothesis)**:
  > *"사용자가 팀 목표 카드에서 [👥 팀원 초대]를 눌렀을 때, 나와 맺어진 동반자 목록이 즉시 뜨고, 아직 동반자가 아닌 지인도 닉네임 검색으로 바로 찾아 클릭 한 번으로 팀에 영입할 수 있게 됨으로써 팀 구성의 재미와 강력한 소셜 소속감을 체감한다."*

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**:
  - 기존의 외부 카카오톡/문자/링크 공유 기능 훼손 금지.
  - 가짜 목업 봇을 실 유저로 속이지 않고 `[🤖 AI 동반자]` 및 `[실 사용자]` 뱃지를 정직하게 표기.
- **해야 할 것 (Action)**:
  - `OurgoalTeamInviteComm.openTeamInviteModal(gid, groupsPool)` 전면 개편.
  - 상단 세그먼트 탭: `[👥 아워골 친구·지인 초대 (기본)]` / `[🔗 외부 공유]`.
  - 섹션 1: `내 목표 동반자 빠른 초대` (내 동반자 목록 순회, 참여 중 여부 실시간 판별, `+ 팀 초대` 원탭 액션).
  - 섹션 2: `아워골 가입 지인 실시간 검색` (닉네임 검색 인풋 + 검색 버튼/엔터, 2중 파이프라인 조회, `+ 팀원으로 영입` 원탭 액션 & 동반자 자동 추가).
  - 초대 즉시 실시간 팀 채팅방(`groupState(gid).chatMessages`)에 안내 메시지 생성 (`🎉 [내이름]님이 [상대이름]님을 팀원으로 초대했습니다!`).
  - 로컬스토리지 및 Supabase 프로필 자동 영속화.

## 4. [원칙 ④] 1~3 재검토 및 보완 (Review & Edge Cases)
- **비판적 자기 검토 및 약점/한계 인정**:
  - 만약 오프라인 환경이거나 백엔드 서버리스 API 장애 시 회원 검색이 멈출 수 있는 취약점 존재 -> 로컬 가입자 풀(6인) 폴백을 장착하여 네트워크 단절 시에도 자연스러운 데모/체험 및 무장애 검색 지원.
- **기존 기능과의 충돌 가능성 검토**:
  - 기존 카카오톡, 문자, 링크 공유 로직을 외부 공유 탭에 100% 동일하게 유지하여 기존 사용자 경험을 일체 해치지 않음.
- **엣지 케이스 (Edge Cases)**:
  - 검색어에 공백만 입력한 경우: 안내 문구 표출 및 불필요한 네트워크 호출 차단.
  - 이미 팀원인 사용자를 검색한 경우: `+ 팀원으로 영입` 대신 `[✓ 참여 중]` 비활성 배지를 노출하여 중복 가입 원천 차단.

## 5. [원칙 ⑤] 해결 절차 정리 (Procedure & State Propagation)
- **구체적 실행 시퀀스**:
  1. [팀원 초대 모달 오픈]: 사용자가 팀 목표 카드에서 `👥 팀원 초대` 클릭 (소요시간: 0ms)
  2. [동반자 원장 대조]: `ensureDefaultCompanions()` 및 대상 팀 로스터 대조 후 `+ 팀 초대` / `✓ 참여 중` 렌더링
  3. [초대 및 영입 배선]: 클릭 시 팀 멤버십(`g.members`, `g.roster`, `groupState`) 갱신 및 실시간 팀 톡 공지 발행
  4. [동반자 자동 연동]: 지인 영입 시 `state.profile.companions`에 자동 등록 및 영속화
  5. [목표 탭 리렌더링]: 모달 종료 및 팀원 초대 즉시 목표 탭 실시간 화면 갱신
- **화면 간 상호연동 전파 규격**:
  - 목표 탭 (`renderTeamGoalsScreen`): 팀 인원수 및 팀원 참여 상태 즉시 갱신
  - 소통 탭 (`renderCommScreen`): 신규 영입된 지인이 내 동반자 탭에도 즉각 노출

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)
- **단일 실패점 (SPOF) 점검**:
  - 서버리스 API `/api/track` 실패 시 Supabase RPC로 1차 폴백, RPC 실패 시 로컬 가입자 풀로 2차 폴백하여 단일 실패점 100% 배제.
- **가정의 타당성 검증**:
  - 사용자가 비로그인 상태일지라도 로컬 스토리지에 동반자 목록과 팀 상태가 영구 보존되도록 방어벽 구축.
- **재검증 결과 도출된 절차 수정/보완사항**:
  - 지인 검색 결과에서 영입 버튼을 눌렀을 때 동반자 추가(`ensureDefaultCompanions`)와 팀원 등록이 원자적으로(Atomically) 완료되도록 결합.

## 8. [원칙 ⑧] 막히는 지점 예상 및 재검증 트리거 (Blockers & Re-verification Triggers)
- **예상 블로커 1**: 사용자가 동반자를 초대한 뒤 모달을 닫았을 때 목표 화면에 인원수가 즉시 바뀌지 않는 문제 -> **대책**: 모달 닫기 핸들러 및 초대 버튼 클릭 즉시 `renderTeamGoalsScreen()` 호출.
- **예상 블로커 2**: 닉네임 대소문자 또는 공백 차이로 인한 매칭 실패 -> **대책**: `toLowerCase().trim()` 전수 적용.
- **재검증 트리거**: 모달 렌더링 중 오류 발생 시 즉시 원칙 ⑤의 Step 2로 복귀하여 데이터 매핑 재확인.
