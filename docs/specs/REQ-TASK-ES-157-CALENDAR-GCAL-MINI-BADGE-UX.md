## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
- **상민님 지시 원문**:
  - 1차: *"지금 구글 캘린더가 연동되었습니다 창이 너무 비효율적이고 사용자 경험을 해치는 것 같지않아?"*
  - 2차: *"1로 헌법 지키면서 병합까지 진행해. 미니구글아이콘으로."*
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  - 캘린더 화면(`#screen-calendar`)에 진입하면 상단 감성 가이드 바로 아래에 거대한 초록색 연동 알림창(`#calGoogleBanner`, 높이 약 80~100px)이 상시 노출되어 화면을 잠식함.
  - 이미 연동을 완료한 상태임에도 불구하고 매일, 매 시간 진입할 때마다 영구히 사라지지 않는 '좀비 배너'로 머물며 모바일 뷰포트에서 달력 그리드와 일간 타임라인을 화면 아래로 밀어내 스크롤을 강제함.
  - 배너 내에 자사 앱을 벗어나 외부로 이탈하게 만드는 `캘린더 열기 ↗` 버튼이 상시 노출되어 있고, 닫기(`×`) 버튼조차 없어 사용자가 숨길 수 없음.
- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**: 기능적 오류는 아니지만, 1회성 성공 안내로 끝나야 할 상태 피드백이 영구적 정적 UI 블록으로 남아 캘린더 메인 뷰의 공간을 부당하게 점유함.
  - **2층 (구조/프로세스 부재)**: 연동 상태 확인 및 수동 동기화 제어 인터페이스가 헤더의 콤팩트 인디케이터나 [설정] 탭으로 위임되지 않고, 캘린더 최상단 콘텐츠 영역에 카드 형태로 직접 박혀 레이아웃 위계를 왜곡함.
  - **3층 (시스템/유저 체감 괴리)**: 사용자는 일정을 조망하고 실천하기 위해 캘린더에 들어왔으나, 매번 이미 알고 있는 "연동되었습니다"라는 알림과 외부 링크를 마주하며 불필요한 시각적 피로와 공간 낭비를 겪음.
- **사용자 상황 및 페르소나**:
  - 구글 캘린더를 연동하여 일정을 관리하는 유저 및 신규 유저. 모바일 화면에서 캘린더 상단이 답답하게 가려져 불편을 호소하는 모든 사용자.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축 (Essence Axis)**: `E1 (체크인 루프)` / `UX (사용자 경험 개선)`
- **[본질] (Essence)**:
  - 캘린더 탭의 진짜 실체는 사용자가 나의 하루/한 주/한 달의 일정을 한눈에 조망하고 실천(체크인)하는 '시간의 대시보드'다. 연동 여부는 이 본질을 보조하는 인프라 상태일 뿐 메인 콘텐츠 자리를 차지해서는 안 된다.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. **상시 점유 카드 레이아웃**: `#calGoogleBanner`가 `div` 블록으로 달력 내비게이션 상단에 박혀 있어 뷰포트 상단 100px을 고정 잠식함.
  2. **1회성 알림의 영구 위젯화**: 연동 성공 안내와 외부 링크, 수동 동기화 버튼이 한데 뭉쳐진 채 닫기(`×`) 기능도 없이 영구 렌더링됨.
  3. **헤더 레벨 콤팩트 인디케이터의 부재**: 상단 타이틀 줄(`screen-head-l`)에 연동 상태를 작고 품격 있게 보여줄 미니 배지 인터페이스가 설계되어 있지 않았음.
- **[중심] (Core Bottleneck & Anchor)**:
  - 캘린더 화면의 본질적 시야(달력/시간표)를 100% 확보하면서도, 사용자가 구글 연동 상태를 한눈에 파악하고 필요 시 즉시 수동 동기화를 누를 수 있는 '헤더 미니 구글 아이콘 배지'로의 전환.
- **[핵심] (Critical Safety & Termination)**:
  - 거대 배너(`#calGoogleBanner`) 전면 숨김/제거.
  - 헤더 타이틀(`[일정] [나만 보기]`) 바로 옆에 컬러 미니 구글 'G' 아이콘이 포함된 콤팩트 배지(`#calGcalMiniBadge`) 배치.
  - 클릭 시 원터치 `syncAllToGoogleCalendar(true)` 및 가벼운 피드백 토스트 호출.
  - 미연동 시에도 거대 카드 대신 헤더에 작은 `+ 구글 연동` 미니 칩만 노출하여 캘린더 뷰포트 완전 개방.
- **체감 가설 (User Experience Hypothesis)**:
  > *"사용자가 캘린더 탭을 열었을 때, 답답한 거대 안내창 없이 달력과 타임라인이 시원하게 한눈에 들어오고, 상단 헤더의 미니 구글 아이콘 배지를 통해 연동 상태를 은은하고 확실하게 인지하며 원터치 동기화의 쾌적함을 체감한다."*
- **기존 전체 기능 영향도 분석**:
  - 계정/로그인(세션, 게스트, 소셜): 무관 (인증 흐름 100% 보존)
  - 홈 화면 및 스트릭: 무관 (영향 0)
  - 캘린더 탭: 상단 공간 80~100px 즉시 확보, 달력 그리드 상향 배치, 가독성 극대화.
  - 구글 동기화 파이프라인: 기존 백그라운드 무음 동기화 및 수동 동기화 100% 정상 작동.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**:
  - 캘린더 화면에 다시 거대한 박스형 알림 UI를 신설하는 행위 금지.
  - 닫기 불가능한 영구 위젯 방치 금지.
  - 인앱 완결성을 깨뜨리는 외부 이탈 링크(`https://calendar.google.com`)를 메인 상단에 상시 배치하는 행위 금지.
- **해야 할 것 (Action)**:
  - 기존 거대 `#calGoogleBanner` 비우기/숨김 처리 (`display: none` / `innerHTML = ''`).
  - `screen-head-l` 내 `calPrivacyBadge` 우측에 `#calGcalMiniBadge` 마운트.
  - 컬러 미니 구글 'G' 아이콘 (4색 SVG) + '연동됨' 텍스트 칩 탑재.
  - 클릭 시 `syncAllToGoogleCalendar(true)` 즉시 호출 및 토스트 안내.
  - 미연동 시에는 회색조 구글 아이콘 + '+ 연동' 콤팩트 칩 노출, 클릭 시 `openGoogleCalendarConnectModal()`.
- **왜 이 방식이어야만 하는가 (Why this approach)**:
  - 상민님의 직접 지시("1로 헌법 지키면서 병합까지 진행해. 미니구글아이콘으로.")에 100% 부합하며, 현대적인 모바일 캘린더 앱(노션 캘린더, 애플 캘린더 등)의 정석적인 미니멀리즘 상태 인디케이터 규격임.

### 3-1. 스토리지 원장화 3대 명세 (헌법 제2조 제4항 준수)
- **1호 (원격 DB 스키마 명세)**: 기존 `users.settings.googleCalendarConnected` 및 `googleCalendarEmail` 활용. 신규 DDL 불필요.
- **2호 (스마트 스토리지 분기 설계)**: 로컬스토리지 `ourgoal_gcal_events` 및 토큰 캐시 그대로 유지.
- **3호 (4대 뷰 전파 배선도)**: 연동 상태 갱신 시 `renderCalendarScreen()` 및 `renderSettingsScreen()` 동시 전파.

## 4. [원칙 ④] 1~3 재검토 및 보완 (Review & Edge Cases)
- **비판적 자기 검토 및 약점/한계 인정**:
  - 헤더에 칩이 추가될 경우 모바일 좁은 화면(320px 폭)에서 타이틀 줄이 줄바꿈될 수 있음.
  - **보완책**: `screen-head-l`에 `flex-wrap: wrap; gap: 6px; align-items: center;`를 적용하고, 배지 크기를 폰트 0.75rem, 패딩 2px 7px로 초경량화하여 320px 소형 기기에서도 말끔하게 1줄 또는 자연스러운 정렬을 유지하도록 설계.
- **기존 기능과의 충돌 가능성 검토**:
  - 기존 스모크 테스트의 `syncAllToGoogleCalendar(true)` 호출 단언문이 깨지지 않도록 미니 배지 클릭 시 해당 함수가 정상 호출되도록 배선.
- **엣지 케이스 (Edge Cases)**:
  - **토큰 만료/오프라인 상태**: 클릭 시 무음 모드가 아닌 인터랙티브 모드(`true`)로 호출되므로 친절하게 재인증 안내가 표시됨.
  - **게스트 상태**: 연동 시 정상적으로 클라이언트 ID 설정 모달로 연결됨.

## 8. [원칙 ⑧] 막히는 지점 예상 및 재검증 트리거 (Blockers & Re-verification Triggers)
- **예상 블로커 1**: 320px 소형 기기 폭에서 헤더 요소 줄바꿈 시 레이아웃 흔들림 -> **대책**: 컴팩트 flex 정렬 및 font-size .75rem 알약 규격 적용.
- **예상 블로커 2**: 기존 스모크 테스트 단언문과의 호환성 -> **대책**: `syncAllToGoogleCalendar(true)` 호출 구조 온전 보존.
- **재검증 트리거**: 캘린더 화면 전환 시 배지가 갱신되지 않으면 원칙 ⑤의 `renderCalendarScreen()` 렌더링 루프로 돌아가 상태 분기를 재검증한다.
