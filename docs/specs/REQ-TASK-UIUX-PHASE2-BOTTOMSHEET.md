## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
- **상민님 지시 원문**: "진행. 세션 작업 지침과 계획서에 따라 스모크/무결성 테스트를 완료하고, PR을 생성하여 GitHub 법정 심사를 청구하라. 멈추지 마라."
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  - 기존 팝업 및 상세 보기 시 화면 전체가 시커멓게 덮여 뒤 배경이 보이지 않아 모바일 사용자가 어디로 이동했는지 공간적 길을 잃음.
  - 시트를 닫으려면 작은 닫기 영역을 정확히 터치해야 하거나 뒤로가기를 눌러야 하는 인지적 마찰이 존재.
  - 중앙 팝업(alert/confirm)과 바텀시트가 혼재되어 UI 위계가 어긋남.
- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**: 제스처 기반 스와이프 다운 닫기 부재로 손가락으로 쓱 내릴 때 시트가 따라 내려오지 않음.
  - **2층 (구조/프로세스 부재)**: 44px 고대비 닫기 버튼 어포던스가 일관되지 않아 70세 어르신 사용자가 나가는 방법을 고민함.
  - **3층 (시스템/유저 체감 괴리)**: 팝업 위에 팝업이 뜨는 중복 적재 현상 발생 가능.
- **사용자 상황 및 페르소나**: 7세 어린이부터 70세 어르신까지 상세 설정이나 안내를 열어본 뒤 0.3초 만에 쉽고 직관적으로 닫고 본래 맥락으로 복귀하고자 하는 사용자.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축 (Essence Axis)**: INFRA/UX
- **[본질] (Essence)**: 기획정본 제9장에 명시된 "배경 30% 보존(Spatial Persistence)"과 "0.3초 원터치/스와이프 닫기"를 통한 심리적 위치 감각 보존.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. **원인 1**: 바텀시트 높이가 90vh로 과도하게 높아 뒤 화면의 맥락이 가려짐.
  2. **원인 2**: 터치 제스처 추종 로직 부재로 네이티브 앱 같은 스와이프 인터랙션 미제공.
  3. **원인 3**: 구형 브라우저 alert/confirm과 중앙 모달이 산재되어 일원화된 모바일 규격 부재.
- **[중심] (Core Bottleneck & Anchor)**: 전역 단일 바텀시트 엔진(`.modal-sheet`)으로 모든 팝업 및 상세 화면을 일원화하고 터치 드래그 및 44px 닫기 버튼을 통합 배선.
- **[핵심] (Critical Safety & Termination)**: 뒤로가기(popstate) 시 앱 종료 방지, 2중 모달 중복 적재 방화벽 및 12ms 촉각 햅틱 손맛.
- **체감 가설 (User Experience Hypothesis)**:
  > *"사용자가 어떤 상세 모달을 열더라도 뒤 화면이 은은하게 비쳐 위치 감각을 잃지 않고, 손가락으로 아래로 쓱 내리거나 큼직한 ✕ 버튼을 누르면 0.3초 만에 원래 화면으로 돌아간다."*
- **기존 전체 기능 영향도 분석**:
  - 계정/로그인: 모달 내 로그인 및 2FA 화면 정상 유지.
  - 홈 화면: 아바타 모달, 안내 모달 정상 연동.
  - 기록/통계/캘린더: 상세 기록 및 달력 인스펙터 바텀시트 정상 연동.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**: 기존 DOM ID(`#modalOverlay`, `#modalSheet`) 구조를 파괴하거나 불필요한 서드파티 라이브러리 추가 금지.
- **해야 할 것 (Action)**: CSS 변수 기반 공간 영속성(82vh, 30% 딤), 터치 이벤트 기반 스와이프 다운 닫기, 44px 닫기 어포던스, 바텀시트 얼럿/컨펌 엔진 구축.
- **왜 이 방식이어야만 하는가 (Why this approach)**: 순수 바닐라 JS와 현대적 CSS 트랜지션만으로 0kb 추가 의존성 없이 네이티브급 모바일 UX를 보장할 수 있기 때문.

### 3-1. 스토리지 원장화 3대 명세 (헌법 제2조 제4항 준수)
- **1호 (원격 DB 스키마 명세)**: 순수 클라이언트 셸 UI/UX 개편으로 Supabase DDL 변경 불요.
- **2호 (스마트 스토리지 분기 설계)**: 모달 상태는 메모리 및 히스토리 스택으로 관리.
- **3호 (4대 뷰 전파 배선도)**: 모달 내 변경 발생 시 기존 `dispatchFullViewPropagation`을 통해 4대 뷰 동시 전파.

### 3-2. 전수 인터랙션(버튼/클릭/입력) 명세표 (Zero-Dead-Click)
| UI 요소 (ID / Name) | 위치/화면 | 사용자 액션 | 기대 동작 (비즈니스 로직) | 예외 처리 및 사용자 피드백 |
| :--- | :--- | :--- | :--- | :--- |
| `.modal-sheet-close` | 바텀시트 우측상단 | 클릭/터치 | 12ms 진동 후 바텀시트 즉시 닫힘 | 고스트 클릭 방지 400ms 가드 |
| `modalSheet` | 바텀시트 상단 | 아래로 드래그 | 70px 이상 드래그 시 12ms 진동 후 시트 닫힘 | 70px 미만 시 제자리 복귀 |
| `#btnSheetAlertOk` | 바텀시트 얼럿 | 클릭/터치 | 모달 닫힘 및 콜백 실행 | 즉시 닫힘 |
| `#btnSheetConfirmOk` | 바텀시트 컨펌 | 클릭/터치 | 모달 닫힘 및 승인 콜백 실행 | 즉시 닫힘 |

### 3-3. 유저 데이터 100% 무손실 보존 규격 (Zero-Data-Loss Schema)
- 모달 열림/닫힘은 뷰 레이어 조작이므로 유저 프로필, 목표, 기록 데이터 100% 무손실 불변 유지.

## 4. [원칙 ④] 1~3 재검토 및 보완 (Review & Edge Cases)
- **비판적 자기 검토 및 약점/한계 인정**: 시트 내부 콘텐츠가 길어 자체 스크롤이 있을 때 스크롤과 스와이프 다운이 충돌할 수 있음 -> `sheet.scrollTop === 0`일 때만 스와이프 다운 제스처를 활성화하여 완벽 해결.
- **기존 기능과의 충돌 가능성 검토**: 기존에 인라인으로 닫기 버튼이 있는 모달의 경우 중복 생성 방지를 위해 `modal-sheet-close` 클래스 존재 여부를 사전 검사하여 중복 주입 방지.
- **엣지 케이스 (Edge Cases)**:
  - 입력창 포커스로 가상 키보드가 올라온 상태: 스와이프 다운 중 키보드 자동 블러 처리.
  - 뒤로가기 버튼 연타: popstate 가드로 중복 history.back 방지.

## 5. [원칙 ⑤] 해결 절차 정리 (Procedure & State Propagation)
- **구체적 실행 시퀀스**:
  1. `ui.css`: `.modal-overlay`, `.modal-sheet`, `.modal-sheet-close` 스타일 및 240ms 스프링 모션 선언.
  2. `ui.js`: `touchstart`, `touchmove`, `touchend` 스와이프 다운 제스처 리스너 배선.
  3. `index.html`: `openModal` 44px 닫기 버튼 자동 주입 및 다중 적재 방화벽, `openBottomSheetAlert/Confirm` 엔진 구현.
- **화면 간 상호연동 전파 규격**:
  - 모달 닫힘 시 기열려 있던 활성 탭 화면으로 무간섭 복귀.

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)
- **단일 실패점 (SPOF) 점검**: 터치 이벤트 미지원 데스크톱 환경에서는 마우스 클릭 기반 닫기 및 ✕ 버튼이 정상 작동하므로 단일 실패점 부재.
- **가정의 타당성 검증**: 브라우저 히스토리 popstate 미지원 환경에서도 `closeModal()` 기본 로직이 100% 동작.
- **재검증 결과 도출된 절차 수정/보완사항**: `closeModal` 시 `sheet.style.transform = ''`을 명시적으로 리셋하여 재오픈 시 시트 위치 오류 영구 차단.
