## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
- **상민님 지시 원문**: "이런 문제 더 있는지 찾아봐" -> 정밀 전수 조사 결과 보고 후 -> "단계별로 모두 진행해"
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  - 소통 탭의 6대 서브탭(`[📰 피드]`, `[👥 팀]`, `[🤝 동반자]`, `[💬 DM]`, `[🎁 마니또]`, `[📤 공유]`)이 1열 flex 가로 스크롤(`scrollWidth: 440px > 373px`)로 배치되어 있어, 모바일 375px 뷰포트에서 `[🎁 마니또]`가 반쯤 잘리고 `[📤 공유]`는 100% 화면 오른쪽 밖으로 잘려 숨겨져 있음.
  - 사용자가 가로로 스크롤하지 않으면 뒤쪽의 핵심 소통 도구(DM, 마니또, 공유)의 존재를 전혀 알 수 없는 심각한 시각 조형 결함 발생.
  - 피드 탭 상단에 3줄(서브탭 + 보기모드 + 11개 카테고리 필터)이 과도하게 누적되어 피드 본문이 화면 아래로 밀려나는 공간 피로도 발생.
- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**: 서브탭이 뷰포트 밖으로 벗어나 터치 인터랙션 도달성이 훼손됨.
  - **2층 (구조/프로세스 부재)**: 서브메뉴 추가 시 1열 flex-nowrap에 무차별 나열하던 레거시 패턴 방치.
  - **3층 (시스템/유저 체감 괴리)**: 사용자가 소통 탭에 들어왔을 때 DM이나 마니또를 찾지 못해 커뮤니티 활성도가 저하됨.
- **사용자 상황 및 페르소나**: 비슷한 목표를 가진 러닝메이트와 1:1 DM을 주고받거나 마니또 활동을 하고자 소통 탭에 진입한 실사용자.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축 (Essence Axis)**: E3 (동류 발견 · 소통 루프)
- **[본질] (Essence)**: 소통 탭 6대 핵심 기능(광장, 그룹, 동반자, 1:1 대화, 이벤트, 카드 공유)의 100% 가시성 확보 및 모바일 375px 무스크롤 3×2 대칭 조형 완성.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. **원인 1**: 서브탭 컨테이너가 `display: flex; overflow-x: auto; flex-wrap: nowrap;`으로 선언되어 6개 버튼 총폭(440px)이 모바일 가로폭(375px)을 초과함.
  2. **원인 2**: 기록 탭에서 성공적으로 안착시킨 3×2 그리드 조형 원칙이 소통 탭에는 아직 수평 전파되지 못함.
  3. **원인 3**: 상단 서브탭과 피드 카테고리 바 사이의 공간 밸런스 부재로 3줄 중첩 발생.
- **[중심] (Core Bottleneck & Anchor)**: 소통 탭 서브탭을 1줄당 3개씩 총 2줄(3×2 대칭 그리드)로 재구성하여, 모바일 375px 환경에서 가로스크롤 0건(`scrollWidth === clientWidth`) 및 버튼당 40px 터치 타겟을 물리적으로 보증하는 것.
- **[핵심] (Critical Safety & Termination)**: 기존 6대 서브탭 렌더링 로직(`feed`, `group`, `companion`, `dm`, `manito`, `share`) 및 DM 미확인 뱃지(`dmSubtabBadge`) 100% 무손실 보존.
- **체감 가설 (User Experience Hypothesis)**:
  > *"사용자가 소통 탭에 진입했을 때 3×2 대칭 그리드로 6대 소통 기능이 한눈에 들어와, 스크롤 없이도 DM과 마니또, 공유 기능에 1초 만에 접근할 수 있어 동류 소통의 만족도가 극대화된다."*
- **기존 전체 기능 영향도 분석**:
  - 홈 화면 및 타 탭: 영향 없음 (소통 탭 내부 조형 수술).
  - 계정/로그인: 무영향.
  - 소통 탭 내부 기능: 6대 렌더러 함수 분기 100% 정상 구동 유지.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**:
  - 기존 6개 서브탭 중 일부를 임의로 삭제하거나 숨기는 행위.
  - 1줄에 6개를 억지로 욱여넣어 글자가 깨지거나 터치 영역이 좁아지는 행위.
- **해야 할 것 (Action)**:
  - `index.html` 내 `renderCommScreen()`의 서브탭 컨테이너를 `.comm-subtabs-grid` 구조로 교체.
  - 1행: `[📰 피드]`, `[👥 팀]`, `[🤝 동반자]` (광장 및 그룹 소통 3대 축).
  - 2행: `[💬 DM]`, `[🎁 마니또]`, `[📤 공유]` (1:1 및 소통 도구 3대 축).
  - `ui.css`: `.comm-subtabs-grid` 선언 (`display: grid; grid-template-columns: repeat(3, 1fr); gap: 6px;`).
  - 모바일 375px 최적화 패딩(6px), 폰트 크기(11px), 최소 높이(40px) 보장.
- **왜 이 방식이어야만 하는가 (Why this approach)**:
  - 기록 탭(#TASK-ES-193)에서 이미 입증되었듯이, 3×2 그리드는 375px 폭에서 각 버튼당 약 110px의 넉넉한 터치 영역과 대칭적 안정감을 제공하며 가로스크롤을 원천 차단함.

## 4. [원칙 ④] 1~3 재검토 및 보완 (Review & Edge Cases)
- **비판적 자기 검토 및 약점/한계 인정**:
  - 서브탭이 2줄(3×2)이 되면 세로 공간을 약 45px 추가로 차지함.
  - 보완책: 각 버튼의 상하 패딩을 8px로 컴팩트하게 다듬고 불필요한 마진을 축소하여, 세로 공간 증가를 최소화(약 38px)하고 터치 안정성을 확보함.
- **기존 기능과의 충돌 가능성 검토**:
  - `dmSubtabBadge`의 인라인 위치가 그리드 버튼 안에서도 정확히 우측 상단에 떠 있도록 CSS `position: relative` 보장.
- **엣지 케이스 (Edge Cases)**:
  - DM 미확인 뱃지 발생 시: 빨간 점이 텍스트를 가리지 않도록 flex 정렬 보장.
  - 320px 극소형 기기: 버튼 폰트가 11px로 유지되며 줄바꿈 없이 한 줄로 깔끔하게 노출.
