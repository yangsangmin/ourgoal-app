## 1. [원칙 ①] 문제 정확히 파악
마9·마10·바9와 06 이해확인 정본을 현재 `docs/rules/OURGOAL_ABSOLUTE_INTEGRITY_RULES.md` 170·171행에 대조한다. 이 준비는 승인된 삭제를 실행하거나 제품 UI를 평가하는 일이 아니다. 정확 사용 가능은 후속074~082가 담당한다.
## 2. [원칙 ②] 본질·원인·중심·핵심
본질은 번잡한 홈 기록 경험을 단순화하고 사용자 기록을 지키는 것이다. 원인은 초기 시안·규범과 후속 삭제 결정의 간격이다. 중심은 `#smartRecommendChips`·`#sliderEnergy`·`#sliderFocus`의 강제와 원데이터 보존을 구분하는 데 있다. 핵심은 삭제 승인과 커널14.5의 전문본문 승인선⑤를 확대·축소하지 않는 것이다.
## 3. [원칙 ③] 효과적 해결방식
원source/hash/locator 및 66개 requirementLinks를 `reports/TASK-ES-K17-INPUT-NORM-01a13674/evidence.json`에 기록한다. `MINIMAL-STATUTE.diff`는 두 문장만의 검토 텍스트다. 원격 DB 테이블/컬럼/DDL·이미지 저장 분기 변경은 없다. `renderHome`·`renderRecordsScreen`·`renderStatsScreen`·`renderCalendar` 전파도 이번 제품 변경 대상이 아니다.
## 4. [원칙 ④] 재검토
`MASTER_PLAN_OURGOAL.md` 387·390행의 반복 강제와 284행 커닝페이퍼 기획, ACTIVE DIR005의 동작보존 범위를 별도 식별한다. 전문 두 문장만의 준비가 전체 규범 정합 완료라고 말하지 않는다. 원문·저장 자료·DIR006의 서버 권위·순서 예외는 변경하지 않는다.
## 5. [원칙 ⑤] 절차
격리 worktree fresh origin/main→필수 원전/후속확정→최초소견 보존→두 강제 문구/커널14.5 대조→원13칸/074~082 연결→최소diff와 승인 시 후속→되읽기/보호대상 해시→root 인계 순서다. root 외 공통계획·원장·links와 운영/원격은 쓰지 않는다.
## 6. [원칙 ⑥] 절차 재검증·반론 격파
반론1은 ‘삭제 승인=규범 승인’이고 06 원이해·14.5의 별도본문 승인선으로 범위를 구분한다. 반론2는 ‘커널에 없으니 전문 강제는 무효’이고 커널 부재와 직접 충돌을 구분해 수용하지 않는다. `FIRST-OBSERVATION.md`와 최초 독립03 원문을 보존하며 교정확인이 새 긍정 의견을 대체하지 않게 한다.
## 7. [원칙 ⑦] 단계별 실행
자기 `.claude/plan-K17-input-norm.md`를 사용한다. 기존 제품·법령·기획정본·ACTIVE·Court/게이트 파일 수정은 없다. 새 시험/전체 npm 반복은 수행하지 않는다. 요청 모델6.1-sol/high와 실제 turn_context의 model/effort·세션 관계를 evidence에 기록한다.
## 8. [원칙 ⑧] 막히는 지점 예상·성과 측정
