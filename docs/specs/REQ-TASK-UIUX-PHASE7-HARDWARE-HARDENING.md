## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
- **상민님 지시 원문**: "진행. PR #621을 GitHub main에 병합하고, 이어서 다음 모듈화 단계(조선소 블록 건조 7단계)를 중단 없이 계속 진행하라. 모든 탭이 완결될 때까지 멈추지 마라."
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  1. 모바일 환경에서 가상 키보드가 노출될 때 하단 입력창(input/textarea) 및 저장/완료 버튼이 키보드 뒤에 가려져 사용자가 입력 내용을 보지 못하거나 완료 버튼을 누르기 위해 불필요하게 스크롤해야 함 (#UIUX-57).
  2. iOS Safari 및 모바일 웹뷰에서 스크롤 시 화면 상하단이 고무줄처럼 당겨지는 바운스(elastic overscroll) 및 의도치 않은 풀투리프레시(Pull-to-refresh)로 인해 고정 헤더/바텀바 레이아웃이 출렁거리는 현상 존재 (#UIUX-58).
  3. 모든 버튼/인터랙션 요소에 대해 손끝으로 터치했을 때 눌렸음을 즉각 인지할 수 있는 네이티브 감성의 `:active` 스케일 피드백이 균일하게 적용되지 않음 (#UIUX-59).
  4. 데이터 동기화 및 저장 시 피드백이 제각각이거나 모달 창으로 시야를 가로막아 작업 흐름이 단절됨 (#UIUX-60).
  5. 고령층 사용자 또는 시력 약화 사용자가 모바일 시스템 폰트를 130% 이상 확대했을 때 텍스트 짤림 또는 레이아웃 깨짐 발생 위험 (#UIUX-61).
  6. 모바일 홈화면 바로가기(PWA) 추가 절차를 알지 못하는 7~70세 사용자를 위한 친절한 3단계 카드뉴스 인앱 안내 모달 부재 (#UIUX-62).
  7. 다크 ↔ 라이트 테마 전환 시 색상이 급격히 반전되어 눈부심 피로 유발 (#UIUX-63).
  8. 프레임워크 개편 전역 937+개 버튼의 인터랙션 데드클릭(Dead-Click) 0건 영구 유지 검증 체계 확립 (#UIUX-64).
- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**: 모바일 하드웨어(키보드, 디스플레이 주사율, 터치스크린, Safe Area)와 웹 런타임 간의 뷰포트 인터랙션 조정 부재.
  - **2층 (구조/프로세스 부재)**: 디바이스 뷰포트(`visualViewport`), 터치 피드백, 모바일 PWA 안내 등 모바일 네이티브 사용성 하드닝 전담 레이어 미비.
  - **3층 (시스템/유저 체감 괴리)**: 겉으로는 예쁜 웹 화면이지만 실제 스마트폰에서 쥐고 쓸 때 묘한 덜컹거림과 터치 지연, 키보드 가림 등 모바일 웹 특유의 이질감 유발.
- **사용자 상황 및 페르소나**:
  - 10대 수험생/20대 취준생: 스마트폰으로 빠르게 체크인하고 목표를 수정할 때 키보드가 입력창을 가리지 않고 원활히 타이핑되기를 기대.
  - 60~70대 시니어: 시스템 폰트를 크게 키워도 글씨가 겹치거나 잘리지 않고, 큼직한 3단계 그림으로 홈화면에 아워골 앱 아이콘을 쉽게 꺼내두길 원함.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축 (Essence Axis)**: `INFRA/UX` (모바일 하드웨어 물리 인터랙션 융합 및 전역 사용성 하드닝)
- **[본질] (Essence)**: 모바일 웹이 아닌 '진짜 스마트폰 네이티브 앱'을 손에 쥐고 쓰는 듯한 유기적 반응성(Zero-Latency, No-Flicker, Zero-Obscure) 제공.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. **원인 1 (뷰포트 불일치)**: 모바일 OS 가상 키보드가 올라올 때 window의 innerHeight와 실제 가시 영역(visualViewport)의 차이를 추적하고 능동적으로 요소를 올려주는 리프트업 엔진의 부재.
  2. **원인 2 (터치 어포던스 부재)**: 버튼 터치 시 즉각적인 물리적 수축(`transform: scale(0.97)`) 및 트랜지션이 빠져 있어 클릭 인지 지연 유발.
  3. **원인 3 (PWA 설치 가이드 부재)**: 크롬(안드로이드)과 사파리(iOS)의 홈화면 추가 방식 차이를 3단계 시각 카드뉴스로 안내하지 못해 앱 설치율 정체.
- **[중심] (Core Bottleneck & Anchor)**: `window.visualViewport` 연동 키보드 가림 방화벽, `overscroll-behavior: contain` 및 `:active` 스케일 전역 배선.
- **[핵심] (Critical Safety & Termination)**: 기존 937+개 버튼 100% 무파괴 Zero Dead-Click 보장 및 사용자 데이터 100% 무손실 영속화.
- **체감 가설 (User Experience Hypothesis)**:
  > *"사용자가 모바일에서 텍스트를 입력하거나 버튼을 터치할 때, 키보드가 절대 입력창을 가리지 않고 손끝에 착 감기는 탄성 반응이 느껴지며, PWA 설치 가이드를 통해 스마트폰 홈화면에 앱을 1초 만에 등록하여 매일 무저항으로 앱을 켜게 된다."*
- **기존 전체 기능 영향도 분석**:
  - 계정/로그인(세션, 게스트, 소셜): 세션 100% 보존, 영향 없음.
  - 홈 화면 및 스트릭: 키보드 팝업 시 체크인 입력창 자연스러운 리프트업으로 몰입감 대폭 향상.
  - 기록/통계/캘린더 탭: 바운스 제어로 스크롤 조작 안정성 극대화.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**:
  - 기존 레이아웃이나 컴포넌트의 HTML/CSS 전면 재작성 금지.
  - 외부 거대 라이브러리(FastClick, iScroll 등) 의존 금지 (네이티브 브라우저 API 표준 활용).
  - 기존 937개 버튼의 이벤트 핸들러 및 고유 ID 파괴 금지.
- **해야 할 것 (Action)**:
  - `window.visualViewport` 기반 가상 키보드 가림 방화벽 스크립트 구축.
  - `ui.css`에 `overscroll-behavior-y: contain`, `:active` 햅틱 스케일, 테마 전환 200ms 트랜지션, 폰트 스케일링 안전망 추가.
  - PWA 설치 안내 카드뉴스 모달 바텀시트 (`modalPwaInstallGuide`) 및 전용 버튼 배선.
  - Zero Dead-Click 937+개 버튼 100% 통과 유지.
- **왜 이 방식이어야만 하는가 (Why this approach)**:
  - 순수 네이티브 브라우저 API(`visualViewport`, CSS 토큰)를 사용하여 0ms 지연과 최적의 번들 크기를 유지하며 모든 디바이스에서 동작 보장.

### 3-1. 스토리지 원장화 3대 명세 (헌법 제2조 제4항 준수)
- **1호 (원격 DB 스키마 명세)**: PWA 가이드 확인 여부 로컬 스토리지 키 `ourgoal_pwa_guide_viewed` 활용 (원격 DB 변경 불요).
- **2호 (스마트 스토리지 분기 설계)**: 로컬 캐시 우선 읽기 및 안전 무손실 영속화.
- **3호 (4대 뷰 전파 배선도)**: 전역 하드웨어 하드닝이므로 특정 뷰에 국한되지 않고 전역 셸 및 4대 연계 뷰에 자연스럽게 동시 유효.

### 3-2. 전수 인터랙션(버튼/클릭/입력) 명세표 (Zero-Dead-Click)
| UI 요소 (ID / Name) | 위치/화면 | 사용자 액션 | 기대 동작 (비즈니스 로직) | 예외 처리 및 사용자 피드백 |
| :--- | :--- | :--- | :--- | :--- |
| `btnPwaInstallGuide` | 설정창 / 홈 헤더 | 클릭/터치 | PWA 3단계 카드뉴스 안내 바텀시트 팝업 | 12ms 햅틱 + 바텀시트 표출 |
| `btnClosePwaGuide` | PWA 가이드 바텀시트 | 클릭/터치 | 가이드 바텀시트 닫기 및 상태 저장 | 12ms 햅틱 + 부드러운 닫힘 모션 |
| `btnConfirmPwaInstall` | PWA 가이드 바텀시트 | 클릭/터치 | 홈화면 추가 확인 토스트 및 바텀시트 닫힘 | 토스트("홈화면에 추가되었습니다!") |

### 3-3. 유저 데이터 100% 무손실 보존 규격 (Zero-Data-Loss Schema)
- **아바타 보존**: 기존 아바타 100% 무손실 보존.
- **목표 데이터 보존**: 기존 목표 100% 무손실 보존.
- **기록 데이터 보존**: 기존 체크인/회고 100% 무손실 보존.
- **화면 구성 세팅값 보존**: 테마, 폰트, 화면 설정 100% 무손실 보존.

## 4. [원칙 ④] 1~3 재검토 및 보완 (Review & Edge Cases)
- **비판적 자기 검토 및 약점/한계 인정**: 가상 키보드 감지는 브라우저(iOS Safari vs Android Chrome)마다 `visualViewport` 이벤트 발생 타이밍이 약간 다를 수 있으므로, resize와 scroll 이벤트를 디바운싱 없이 즉시 처리하고 `scrollIntoView({ behavior: 'smooth', block: 'center' })` 안전망을 이중 결속함.
- **기존 기능과의 충돌 가능성 검토**: 기존 스크롤 뷰 및 모달의 기본 동작을 해치지 않도록 클래스 단위 스코핑 및 조건부 실행.
- **엣지 케이스 (Edge Cases)**:
  - 데스크톱 브라우저 환경: `visualViewport` 높이 변화가 미미하므로 키보드 리프트 로직은 모바일 뷰포트(< 768px)에서만 활성화.
  - OS 다크모드 강제 적용 환경: 200ms 트랜지션이 부드럽게 감속되어 화면 깜빡임 차단.

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)
- **단일 실패점 (SPOF) 점검**: `visualViewport` 미지원 구형 브라우저에서도 `window.innerHeight` 폴백을 통해 스크립트 에러 발생을 원천 차단 (`window.visualViewport ? ... : ...`).
- **가정의 타당성 검증**: `:active` 스타일이 데스크톱 마우스 클릭과 모바일 터치에 모두 무해하게 반응하는지 검증.
- **재검증 결과 도출된 절차 수정/보완사항**: PWA 가이드 모달에 iOS와 Android 탭 스위처를 제공하여 디바이스별 정확한 브라우저 메뉴 위치(공유 버튼 vs 점 3개 메뉴)를 직관적으로 안내하도록 강화.

## 8. [원칙 ⑧] 막히는 지점 예상 및 재검증 트리거 (Blockers & Re-verification Triggers)
- **예상 블로커 1**: 키보드 팝업 시 화면 크기 축소로 인한 레이아웃 오버플로우 -> **대책**: 바텀시트 및 메인 컨테이너에 `max-height: 85vh; overflow-y: auto;` 안전 스크롤 부여.
- **재검증 트리거**: 만약 키보드 팝업 시 입력 필드가 스크롤 중앙에 오지 않는 디바이스가 있다면 `scrollIntoView` 파라미터를 조정하여 즉각 튜닝.
