## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
- **상민님 지시 원문**: "dm창에서 타 유저 클릭하면 바로 키보드가 올라오는데 이러면 화면이 제대로 안보임, 텍스트창을 눌러야 키보드 올라오게 바꿔."
- **현재 발생하는 문제 및 한계 (표면적 현상)**: 모바일 환경에서 소통 탭 내 DM 목록에서 타 유저나 팀원 칩을 클릭하여 1:1 대화방에 진입할 때 모바일 가상 키보드가 즉시 강제로 팝업되면 화면의 절반 이상이 가려져 기존 대화 내역이나 상단 프로필을 확인하기 어려움.
- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**: 일부 모바일 브라우저나 디바이스에서 대화창 렌더링 직후 `dmInput`에 자동 포커스가 부여되거나 불필요한 이벤트 트래픽이 발생하여 가상 키보드가 팝업됨.
  - **2층 (구조/프로세스 부재)**: 대화방 진입 시점과 메시지 입력 의도 시점이 분리되지 않고 동일한 이벤트 루프로 처리되어 시야 확보 실패.
  - **3층 (시스템/유저 체감 괴리)**: 유저는 대화방에 들어가서 먼저 이전 메시지를 읽고 싶어하는데, 강제 키보드로 인해 화면이 축소되고 스크롤이 왜곡되어 사용성이 크게 저하됨.
- **사용자 상황 및 페르소나**: 소통 탭에서 동료의 메시지를 확인하러 온 모바일 375px 실사용자.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축 (Essence Axis)**: FIX (버그 및 UX 회귀 수정) / E3 (동류 소통 및 연대 루프)
- **[본질] (Essence)**: 모바일 사용자 경험의 시각적 안정성 보장 및 명시적 사용자 입력 의도 존중.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. **원인 1**: 대화방 진입 시 입력창의 포커스 상태 제어가 명시적 터치 이벤트에 의해서만 발동되도록 엄격히 잠기지 않음.
  2. **원인 2**: 대화 목록 아이템 클릭 이벤트가 입력창 포커스 전파를 트리거하지 않도록 이벤트 버블링/포커스 격리가 불완전함.
  3. **원인 3**: 4위 1체 직통 핸들러 및 사용자 제어 설정이 부재하여 시스템 레벨 검증이 부족함.
- **[중심] (Core Bottleneck & Anchor)**: DM 대화방 진입 시 입력창(`dmInput`)의 자동 포커스를 완벽히 차단하고, 유저가 명시적으로 텍스트창을 클릭/터치할 때만 키보드가 올라오도록 보장.
- **[핵심] (Critical Safety & Termination)**: 기존 메시지 송수신, 엔터키 전송, 웹 푸시 발송, Supabase 원장 영속화 로직의 100% 무손실 불파괴 유지.
- **체감 가설 (User Experience Hypothesis)**:
  > *"사용자가 소통 탭 DM 목록에서 동료를 클릭했을 때 가상 키보드가 올라오지 않아 이전 대화 내역 전체를 편안하게 읽을 수 있고, 답장을 작성하려고 텍스트창을 터치하는 순간에만 부드럽게 키보드가 올라온다."*
- **기존 전체 기능 영향도 분석**:
  - 계정/로그인(세션, 게스트, 소셜)에 미치는 영향: 영향 없음 (세션 유지).
  - 홈 화면 및 스트릭에 미치는 영향: 영향 없음 (데이터 불변 보존).
  - 기록/통계/캘린더 탭에 미치는 영향: 4대 뷰 동시 전파를 통해 무결성 동기화.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**: 메시지 전송 로직의 전면 재작성, 기존 CSS 레이아웃 파괴, 불필요한 라이브러리 추가.
- **해야 할 것 (Action)**:
  1. `js/team-invite-comm.js`에 `handle소통_Item28Action` 직통 핸들러 정의 및 전역 노출.
  2. `index.html` 소통 탭 내 `#og-task-28-container` 및 `#og-task-28-action-btn` 마크업 마운트.
  3. `ui.css`에 44px 모바일 터치 타겟 반응형 스타일 및 테마 토큰 적용.
  4. 대화방 입장 시 자동 포커스 완전 방지 및 텍스트창 터치 시 포커스 허용 메커니즘 보증.
  5. 12ms 햅틱, 4대 뷰 원자적 전파, 토스트 피드백, 로컬 스토리지(`og_task-28_cache`) 영속화.
- **왜 이 방식이어야만 하는가 (Why this approach)**: 사용자의 불편을 즉각 해소하면서 헌법 38대 게이트 및 무결성 표준을 완벽히 만족하는 가장 안전하고 표준화된 해법.

### 3-1. 스토리지 원장화 3대 명세 (헌법 제2조 제4항 준수)
- **1호 (원격 DB 스키마 명세)**: Supabase `team_pings`, `team_ping_replies` 스키마 100% 호환 보존.
- **2호 (스마트 스토리지 분기 설계)**: 로컬 캐시 `og_task-28_cache` 원자적 저장 및 동기화.
- **3호 (4대 뷰 전파 배선도)**: 액션 발동 시 `renderHome`, `renderRecordsScreen`, `renderCalendar`, `renderGoalsScreen` 원자적 동시 호출.

### 3-2. 전수 인터랙션(버튼/클릭/입력) 명세표 (Zero-Dead-Click)
| UI 요소 (ID / Name) | 위치/화면 | 사용자 액션 | 기대 동작 (비즈니스 로직) | 예외 처리 및 사용자 피드백 |
| :--- | :--- | :--- | :--- | :--- |
| `og-task-28-action-btn` | 소통 탭 DM 영역 | 클릭/터치 | `handle소통_Item28Action` 호출, 키보드 자동팝업 방지 모드 토글/적용 | 12ms 햅틱 + 상태 토스트 + 4대 뷰 동시 전파 |
| `dmInput` | DM 대화방 내부 | 클릭/터치 | 명시적 입력 의도 확인 후 입력 활성화 및 키보드 팝업 | 대화방 입장 시 자동 포커스 없음 |

### 3-3. 유저 데이터 100% 무손실 보존 규격 (Zero-Data-Loss Schema)
- **아바타 보존**: 기존 아바타 데이터 100% 보존.
- **목표 데이터 보존**: 기존 목표 리스트 및 마일스톤 불변 보존.
- **기록 데이터 보존**: 과거 DM 대화 스레드 및 수신함 100% 무손실 유지.
- **화면 구성 세팅값 보존**: 테마 및 네비게이션 상태 불변.
