## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
1. **상민님 지시 원문**:
   - *"오늘의 3초 체크인 글자를 채워넣지 말라니까? 그럼 또 지우고 사용자가 써야 하잖아? 커닝페이퍼처럼 타이핑창 백그라운드로 예시를 보여주고 참고해서 쓸 수 있게 해야지."* (`docs/rules/MASTER_PLAN_OURGOAL.md` 제6장 6.2, 메모장 [81], [88])
   - *"삶의 실천에 값을 매기지 않는다. 출석체크와 체크인 기록에는 크레딧을 일절 지급하지 않으며, 오직 스트릭(Streak), 배지(Badge) 등 정직한 명예와 내적 성취감으로만 보상한다."* (마스터플랜 제1장)
   - *"E1 (체크인 루프): 10초 만에 끝나는 침묵의 기록과 '오늘도 해냈다'는 아바타 피드백 기반의 자가 효능감"* (마스터플랜 제2장)
2. **현재 발생하는 문제 및 한계 (표면적 현상)**:
   - 홈 화면의 `quickCheckinChips` 컨테이너가 비어 있어 사용자가 무엇을 적어야 할지 막막한 '백지 공포증' 유발.
   - 기존의 빠른 입력 방식은 버튼 탭 시 텍스트가 입력창에 강제 주입되어, 유저가 미세하게 수정하려 할 때 백스페이스를 연타해야 하는 극심한 **'지움 피로도(Erasing Fatigue)'** 발생.
   - 체크인 저장 버튼에 `(+10P)` 같은 포인트/크레딧 표기가 남아있어 본질(순수 성장 명예 보상)을 오염시키는 결함 잔존.
3. **표면 아래 기저 층위 분석**:
   - **1층 (미작동/단절 결함)**: `index.html` 내 `#quickCheckinChips` DOM에 추천 칩 렌더러가 배선되지 않아 추천 기능이 사실상 마비 상태.
   - **2층 (구조/프로세스 부재)**: 텍스트 입력창과 힌트 표시 레이어를 분리하지 않고 `textarea.value` 단일 슬롯에 모든 상태를 욱여넣는 전통적 폼 처리 관성.
   - **3층 (시스템/유저 체감 괴리)**: 3초 만에 가볍게 기록하려던 유저가 텍스트를 지우고 고치는 데 15초 이상 허비하여 기록 습관 형성 실패.
4. **사용자 상황 및 페르소나**:
   - 퇴근길 지하철, 공부 마치기 직전, 운동 직후 숨을 헐떡이며 "오늘 이거 했다"를 3초 만에 툭 던지고 안도감을 얻고 싶은 모든 유저(7세 아동부터 70세 어르신까지).

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
1. **4대 요소 분석**:
   - **본질 축 (Essence Axis)**: `E1 (체크인 루프)`
   - **[가목] 본질 (Essence)**:
     - 체크인은 시스템에 데이터를 입력하는 '노동'이 아니라, **"오늘도 내가 올바르게 살아냈다"는 안도감과 즉각적인 자가 효능감(+10 EXP, 아바타 칭찬)을 3초 만에 획득하는 성장 의식**이다.
     - *무예단*: 유저가 무엇을 했는지 시스템이 함부로 단정하여 강제로 채워넣지 않는다.
     - *인지순행*: 목표를 보았으면 ➔ 힌트가 스치고 ➔ 3초 만에 손가락 하나로 기록이 종결된다.
     - *촉각적 손맛*: 버튼을 탭하는 순간 햅틱/애니메이션과 함께 아바타가 살아 움직이며 즉각 반응한다.
   - **[나목] 원인 (Root Causes 3가지)**:
     1. **원인 1**: 추천 칩 탭 시 입력창 텍스트를 강제로 덮어씌우는 파괴적 텍스트 주입 로직.
     2. **원인 2**: 커닝페이퍼형 백그라운드 고스트 텍스트(Ghost Text)와 실제 타이핑 입력창의 이중화 레이어 부재.
     3. **원인 3**: '추천 내용 그대로 원탭 저장'과 '내 실천 직접 타이핑'을 분리하지 않은 단일 버튼 통로.
   - **[다목] 중심 (Core Bottleneck & Anchor)**:
     - **커닝페이퍼 고스트 텍스트 (Cheat Sheet Ghost Guide)**: 추천 칩을 누르면 입력창 백그라운드에 연한 회색으로 예시 힌트가 은은하게 투영되며, 유저가 키보드를 치는 순간 0.1초 만에 감쪽같이 사라져 지울 필요가 전혀 없음.
     - **이원화 인터랙션 앵커**: 추천 칩 탭 시 나타나는 `[이대로 3초 체크인 ⚡]` 원탭 퀵 버튼 vs 깨끗한 빈칸에서 바로 쓰는 직접 타이핑 통로.
   - **[라목] 핵심 (Critical Safety & Termination)**:
     - 체크인 즉시 Supabase 원격 원장(`checkins`)에 영구 영속화되고, 단 1회의 디스패치로 4대 뷰(홈, 기록, 통계, 캘린더)에 동시 전파되어 단절 없는 일체감을 보장.
2. **체감 가설 (User Experience Hypothesis)**:
   > *"사용자가 홈 화면에 들어와 활성 목표 칩을 툭 누르면, 커닝페이퍼처럼 추천 문장이 은은하게 비치고 [이대로 체크인 ⚡] 버튼 하나로 0.3초 만에 레벨업과 아바타의 신나는 축하를 받으며 하루를 완주한다."*
3. **기존 전체 기능 영향도 분석**:
   - **계정/로그인**: 게스트 및 소셜 유저 모두 로컬 캐시와 Supabase 원격 원장에 완전 동기화.
   - **홈 화면 및 스트릭**: 체크인 저장 즉시 스트릭 +1 및 히트맵 오늘 셀 점등.
   - **기록/통계/캘린더**: 타임라인 최상단 즉시 추가, 주간 통계 게이지 갱신, 달력 셀 체크 마크 점등.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
1. **하지 말아야 할 것 (Avoid)**:
   - 추천 칩 클릭 시 `textarea.value`에 강제로 문자열 박아넣기 영구 금지 (지움 피로도 원천 차단).
   - 체크인에 현금성 크레딧이나 포인트 지급 금지 (마스터플랜 제1장 엄수, 오직 순수 EXP와 스트릭으로만 보상).
   - 체크인 후 모달 팝업으로 전체 화면을 가리는 행위 금지 (1초 조망 공간성 보존).
2. **해야 할 것 (Action)**:
   - 활성 목표 기반 3대 스마트 추천 칩 동적 추출 (`🏃 30분 걷기`, `📚 독서 10쪽`, `💧 물 500ml`).
   - 커닝페이퍼형 고스트 텍스트 레이어 탑재 (`.ghost-placeholder-layer`).
   - `[이대로 3초 체크인 ⚡]` 원터치 액션과 자유 텍스트 타이핑의 완벽 공존.
   - 체크인 즉시 아바타 다이나믹 리액션 (풍선말: "오늘도 해냈다 내자신! +10 EXP", 3초 후 기본 상태 복귀).

### 3.1. 스토리지 원장화 3대 명세 (헌법 제2조 제4항 준수)
1. **1호 (원격 DB 스키마 명세 - Supabase `checkins`)**:
   - 테이블: `checkins`
     - `id`: `UUID` (PK, default `gen_random_uuid()`)
     - `user_id`: `UUID` (FK `auth.users.id`, NOT NULL)
     - `goal_id`: `UUID` (FK `goals.id`, NULLABLE)
     - `content`: `TEXT` (NOT NULL, 실천 내용 1줄)
     - `theme`: `VARCHAR(32)` (default `'general'`)
     - `exp_gained`: `INTEGER` (NOT NULL, default `10`)
     - `created_at`: `TIMESTAMPTZ` (NOT NULL, default `NOW()`)
2. **2호 (스마트 스토리지 3계층 분기 설계)**:
   - `L1 (Remote Supabase)`: 실시간 네트워크 온라인 시 Supabase `checkins` 테이블에 즉시 INSERT.
   - `L2 (IndexedDB `ourgoal_vault`)`: 오프라인 상태에서도 체크인 트랜잭션 100% 무손실 보존 및 큐잉.
   - `L3 (LocalStorage `og_checkins_cache`)`: 홈 화면 즉각 렌더링을 위한 14일치 체크인 히스토리 및 스트릭 메타 동기 캐싱.
3. **3호 (4대 뷰 전파 배선도)**:
   - 체크인 완료 이벤트 발생 시 `dispatchFullViewPropagation({ type: 'CHECKIN_SAVED', checkin })` 호출:
     - `renderHome()`: 홈 체크인 박스 완료 상태 전환 + 스트릭 게이지 + 히트맵 셀 점등.
     - `renderRecordsScreen()`: 기록 탭 타임라인 최상단에 새 체크인 카드 prepending.
     - `renderStatsScreen()`: 이번 주 실천 시간 및 총 횟수 수치 실시간 재계산.
     - `renderCalendar()`: 달력 당일 셀에 실천 도장(마크) 점등.

### 3.3. 유저 데이터 100% 무손실 보존 규격 (Zero-Data-Loss Schema)
- **아바타 보존**: 체크인 시 레벨 및 EXP가 누적되어도 기존 선택된 16종 동물 및 이름 불변 유지.
- **목표 데이터 보존**: 추천 칩 연동 시 기존 목표의 진행도나 세부할일 상태 100% 보존.
- **기록 데이터 보존**: 과거 작성된 체크인 피드 타임스탬프와 AI 피드백 무손실 보존.
- **화면 구성 보존**: 홈 대시보드 사용자 맞춤 배치(커스텀 위젯 순서) 100% 불변.

## 4. [원칙 ④] 1~3 재검토 및 보완 (Review & Edge Cases)
1. **비판적 자기 검토 및 약점/한계 인정**:
   - 고스트 텍스트가 너무 연하면 어르신(70세)이 보지 못할 수 있고, 너무 진하면 이미 타이핑된 글자로 오인할 수 있음.
   - **보완책**: 고스트 텍스트 상단에 `💡 추천 커닝페이퍼`라는 은은한 마이크로 뱃지를 함께 표시하고, 폰트 명도를 WCAG AA 기준(최소 4.5:1 콘트라스트)에 부합하는 `#94a3b8`로 최적화.
2. **기존 기능과의 충돌 가능성 검토**:
   - 기존의 사진 첨부(`capturePhotoBtn`) 및 테마 선택 기능과의 충돌 여부 점검.
   - **대책**: 체크인 입력 바 하단의 사진 첨부 및 테마 선택 앵커를 그대로 보존하여 기존 기능 100% 호환.
3. **엣지 케이스 (Edge Cases)**:
   - **극단적 오프라인 상태**: 비행기 모드에서도 L2 IndexedDB에 완결 저장되며 "오프라인에 안전하게 보관됨" 뱃지 노출.
   - **1일 다회 체크인 유저**: 당일 1회차에만 스트릭 +1 및 +10 EXP 지급, 2회차 이후는 스트릭 동결(`hasCheckedInToday` 가드) 및 순수 자가 효능감 타임라인 기록만 누적(어뷰징 방지 일일 최대 50 EXP 상한 준수).
   - **한글 IME 및 키보드 입력 충돌**: 첫 자음 조합(`compositionstart`) 또는 키 입력(`keydown`) 발생 0.01초 즉시 고스트 레이어를 완전 소거하여 글자 잔상 방지.
   - **플레이스홀더 2중 겹침 방지**: 추천 칩 활성 시 `input.placeholder`를 즉시 공백으로 비우고, 칩 해제 시에만 원본 플레이스홀더를 복원하여 시각적 겹침 0건 달성.
   - **목표가 0개인 신규 유저**: 기본 일상 킬러 프리셋(걷기, 독서, 물 마시기)이 기본 칩으로 자동 공급되어 백지 방지.

## 5. [원칙 ⑤] 해결 절차 정리 (Procedure & State Propagation)
1. **구체적 실행 시퀀스**:
   - **1단계 (스마트 추천 칩 추출 엔진 구축)**: 사용자의 1순위 활성 목표에서 3대 실천 액션을 파싱하여 칩으로 렌더링.
   - **2단계 (커닝페이퍼 고스트 텍스트 레이아웃 배치)**: `<textarea>` 위에 오버레이되는 `.ghost-text-guide` 슬롯 마크업.
   - **3단계 (인터랙션 바인딩)**: 칩 탭 ➔ 고스트 점등 / 타이핑 ➔ 고스트 소거 / 원탭 ➔ 즉시 저장 시퀀스 구현.
   - **4단계 (아바타 다이나믹 리액션 & EXP 지급)**: 체크인 즉시 +10 EXP 플로팅 연출 + 아바타 신나는 말풍선 점등.
   - **5단계 (4대 뷰 동시 전파 검증)**: 홈, 기록, 통계, 달력 화면에 데이터 실시간 반영 테스트.
2. **화면 간 상호연동 전파 규격**:
   - 데이터 변경 발생: `onCheckinSuccess(newCheckin)`
   - 동시 전파 대상:
     1. 홈 화면: 실시간 활성 체크인 카드에 오늘 발자국 표시 및 히트맵 갱신.
     2. 기록 탭: 타임라인 로그 피드 1행에 실천 내용과 획득 EXP 즉각 prepend.
     3. 통계 탭: 이번 주 누적 실천 횟수 +1 갱신.
     4. 캘린더 탭: 오늘 날짜 셀에 실천 히트맵 점등.

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)
1. **단일 실패점 (SPOF) 점검**:
   - Supabase 네트워크가 끊어지면 체크인이 실패하는가? ➔ *아니다. IndexedDB와 LocalStorage에 즉시 커밋 후 UI를 선반영하므로 오프라인에서도 0초 체감 완결.*
2. **강력한 반대 논거 2가지 생성 및 반박/수용 결과 (헌법 제2조 제5항 제2호 필수)**:
   - **반대 논거 1**: *"커닝페이퍼 고스트 텍스트 방식 대신, 토스나 카카오처럼 추천 칩을 누르면 팝업 바텀시트가 열리며 '이 내용으로 등록할까요?'라고 한 번 더 확인하는 모달 방식이 더 명확하지 않은가?"*
     - **반박 및 수용 결과**: 모달이나 팝업을 한 번 더 띄우는 순간 상민님의 불변 공식인 **'1초 조망(Glance & Action)'**과 3초 체크인의 템포가 완전히 깨진다. 확인 팝업을 강제하지 않고, 칩을 누르면 입력창 자리에 즉시 [이대로 3초 체크인 ⚡] 버튼이 떠서 1초 만에 탭하거나 자유롭게 타이핑할 수 있게 하여 인지 마찰을 0으로 수용/해결함.
   - **반대 논거 2**: *"추천 칩을 누르면 입력창에 글자를 채워주는 방식이 어르신들에게는 더 익숙하고 직관적이지 않은가? 백그라운드 힌트는 눈에 잘 안 띌 수 있다."*
     - **반박 및 수용 결과**: 상민님의 명확한 지시(*"글자를 채워넣지 말라니까? 그럼 또 지우고 써야 하잖아"*)에 따라 지움 피로도를 유발하는 강제 주입은 영구 배제한다. 어르신들의 시인성을 위해 추천 칩 자체에 선명한 텍스트(`🏃 30분 걷기 완료`)를 명시하고, 칩 우측에 `[바로 기록 ⚡]` 버튼을 원클릭으로 제공하여 타이핑이나 지우기 자체를 할 필요가 없도록 완벽히 수용함.
    - **반대 논거 3**: *"유저가 한 글자도 직접 쓰지 않고 [이대로 3초 체크인]을 누르면 헌법 제1조 제4항 제7호(속빈 완주 금지)에 위배되는 것이 아닌가?"*
      - **반박 및 수용 결과**: 추천 칩은 시스템이 임의로 조작한 허위 문장이 아니라 유저 본인이 설정한 활성 목표('🏃 30분 걷기', '📚 독서 10쪽' 등)의 실제 실천 단위를 유저가 직접 식별하고 탭하는 능동적 사실 증명 행위다. 또한 체리피킹형 완주를 원천 차단하기 위해 당일 스트릭은 1일 1회만 인정(hasCheckedInToday 가드)하며, 기록 저장 즉시 4대 뷰와 소통 탭에 온전히 공개되어 동류 피드에서 상호 투명하게 증명되도록 안전핀을 결속하여 완벽히 수용함.

3. **재검증 결과 도출된 절차 수정/보완사항**:
   - 칩 탭 시 고스트 텍스트뿐만 아니라, 칩 바로 옆에 원클릭 `[바로 기록 ⚡]` 플로팅 액션을 추가하여 70세 어르신도 단 1번의 탭으로 체크인을 끝낼 수 있도록 절차 강화.

## 7. [원칙 ⑦] 단계별 실행 기준 (Success Metrics)
- 지움 피로도 0 실측: 추천 칩 탭 시 `textarea.value`에 강제 문자열이 주입되지 않고 커닝페이퍼 고스트로만 노출됨을 물리적으로 확인.
- 3초 체크인 완결: 추천 칩 원터치 또는 1줄 타이핑 후 저장까지 3초 이내 동작 검증.
- EXP 무결성: 체크인 시 오직 +10 EXP만 지급되며, 부당한 크레딧/포인트 지급 0건 확인.
- 4대 뷰 동시 전파: 체크인 완료 즉시 홈/기록/통계/달력 연계 함수가 100% 정상 발화됨을 검증.
- 헌법 린터 38개 검사 전수 PASS.

## 8. [원칙 ⑧] 막히는 지점 예상 및 재검증 트리거 (Blockers & Re-verification Triggers)
1. **블로커 1 (고스트 텍스트와 실 타이핑의 겹침 현상)**:
   - 한글 IME 조합 중 고스트 텍스트가 사라지지 않고 겹쳐 보이는 결함 발생 가능.
   - *대응*: `input`, `compositionstart`, `keydown` 3중 이벤트 리스너를 결속하여 첫 키 입력 발생 0.01초 만에 고스트 텍스트 레이어를 `opacity: 0`으로 즉시 소거.
2. **재검증 트리거**:
   - 모바일 브라우저(iOS Safari, Android Chrome) 가상 키보드가 올라올 때 추천 칩이나 입력창이 화면 밖으로 밀려나는 현상 발견 시 ➔ **[원칙 ③] 시각적 뷰포트 레이아웃**으로 즉시 되돌아가 `position: sticky` 및 키보드 회피 패딩 재검증.
