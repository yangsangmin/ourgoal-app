## 여쭙는 것 세 가지

1. **헌법 개정 승인** — 위 표대로 헌법을 바꿉니다. 승인 문구: "헌법 개정 승인".
2. **브랜치 보호 변경과 Vercel 로그아웃 승인** — GitHub 에서 법정(court) 통과를 병합의 필수 조건으로 걸고(발급 주체 고정), 이 PC에서 `vercel logout` 을 합니다. 되돌릴 수 있습니다(설정 원복·재로그인).
3. **2단 `[손 필요]` 약 15분을 지금 하실지** — AI용 GitHub 계정을 따로 만들어 AI는 그 계정만 쓰게 합니다. 그러면 채점 기준을 건드리는 PR 은 상민님 폰의 승인 없이는 물리적으로 병합되지 않습니다. 절차는 아래.

## 지금 단계(1단)가 막아 주는 것과 못 막는 것

지금 단계에서 법정이 막아 주는 것은 실수와 편법이지, 작정한 위조가 아닙니다. 법정은 AI의 주장을 다시 실행해 보므로 가짜 Before, 주석만 넣은 구현, 고장 난 부품, 지어낸 수치는 걸러집니다. 그러나 AI와 상민님이 같은 PC·같은 GitHub 계정을 쓰는 동안에는 AI가 마음먹으면 세 가지를 할 수 있습니다. 법정을 고친 PR 을 따로 올려 스스로 병합하는 것, 채팅에 법정 결과를 다르게 옮겨 적는 것, 통과 표시를 GitHub 에 직접 찍는 것입니다. 기계는 그것이 상민님이 한 일인지 AI가 한 일인지 구분하지 못합니다.

그래서 2단이 끝날 때까지 두 가지를 부탁드립니다. 첫째, 채팅만 보고 "1"을 누르지 마시고 PR 화면의 법정 표시(초록/빨강)와 판정번호가 채팅과 같은지 한 번 봐 주십시오. 둘째, "금고 변경"이라는 말이 들어간 승인 요청은 내용을 보시기 전에는 보류해 주십시오.

## 2단 절차 `[손 필요]` (가입·메일 인증·로그인은 세션이 할 수 없습니다)

1. 크롬 시크릿 창 → github.com/signup → 새 이메일로 AI용 계정 만들기(예: `ourgoal-ai`) → 메일로 온 코드 입력.
2. 원래 창(yangsangmin) → ourgoal-app → Settings → Collaborators → Add people → `ourgoal-ai` → Add.
3. 시크릿 창 → 알림의 초대 → Accept invitation.
4. 세션이 `gh auth login --web` 을 실행해 8자리 코드를 보여 드리면, 시크릿 창에서 github.com/login/device → 코드 입력 → Authorize.
5. 폰에 GitHub 앱 설치 → yangsangmin 으로 로그인 → 알림 켜기. (금고 PR 승인은 폰에서만 합니다.)
6. PC 크롬에서는 GitHub 를 로그아웃합니다(브라우저를 조종하는 AI가 승인 버튼을 누르지 못하게).

그 뒤는 세션이 합니다: 상민님 계정 토큰을 PC에서 제거, 금고 경로에 상민님 승인 필수(CODEOWNERS) 적용, 그리고 검증 3종 — ① 채점 기준 한 글자 바꾼 PR 이 "승인 필요"로 막히는가 ② 가짜 통과 표시를 찍어도 병합이 안 되는가 ③ 평소 기능 PR 은 지금처럼 승인 없이 병합되는가 — 를 돌려 결과를 세 줄로 보고합니다.

## 승인하시면 세션이 바로 하는 일 → 그 다음 열리는 것

- 즉시: PR 병합 요청(병합 버튼은 상민님 한 번), 전역 헌법 사본(`C:/Users/HP/AGENTS.md`)과 안티그래비티 전역 규칙 동기화, 버전 대장에 승인 근거(상민님 말씀 원문·시각) 기재, 빈 PR 로 법정이 GitHub 에서 실제로 도는지 확인한 뒤 브랜치 보호에 court 추가, `vercel logout`.
- 그 다음: 커맨드센터 담당 세션에 인계(상태창에 작업별 법정 판정 표시, 법정을 거치지 않은 보고는 "판정 없음"으로 표시, 무인증 승인·배포 통로 폐쇄).

## 승인하지 않으시면

법정 도구(`court/`)는 저장소에 들어가지 않고 이 브랜치에만 남습니다. 헌법은 지금 그대로입니다. 지금 구조에서는 이번과 같은 보고가 다시 나올 수 있고, 그때마다 상민님이 눈으로 잡으셔야 합니다.
