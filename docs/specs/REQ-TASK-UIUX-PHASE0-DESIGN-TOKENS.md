## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
- **상민님 지시 원문**: "전체적인 ui/ux 틀부터 고치고싶은데 관련작업 전체 목록 뽑고, 그것을 다시 안정적이고 효과적인 작업순서로 고치고, 작업단위별로 그룹화까지 진행하고 나서 일괄적으로, 단계별로 진행하자"
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  - 탭과 컴포넌트마다 폰트 크기, 마진/패딩, 버튼 터치 영역(Hitbox), 모서리 곡률(Border-radius)이 미세하게 달라 시각적 통일감이 결여됨.
  - 모바일 터치 타겟이 40px 미만인 버튼이 잔존하여 7세 어린이나 70세 어르신 사용자가 헛손질(Mis-touch)을 유발함.
  - 로딩 시 빈 흰색/검은색 화면이나 덜컹거림(Layout Shift)이 발생하여 시각적 안정감을 해침.
  - 3대 금지어('성소', '콕핏', '잔디')가 코드나 내부 주석, 속성에 잔존하여 도메인 철학에 역행할 위험이 상존함.
- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**: 전역 CSS 변수 시스템이 모듈별로 완벽히 상속되지 않고 하드코딩 px/color 값이 혼재함.
  - **2층 (구조/프로세스 부재)**: 4대 테마(성소/블랙/화이트/도심)와 44px 터치타겟, 12ms 햅틱이 전역 디자인 토큰으로 단일 강제 집행되지 못함.
  - **3층 (시스템/유저 체감 괴리)**: 유저가 화면을 볼 때 '전문적이고 정돈된 앱'이라는 감성적 신뢰감을 즉각 느끼지 못함.
- **사용자 상황 및 페르소나**: 7세부터 70세까지 모바일 스마트폰으로 아워골에 접속하는 모든 신규 및 기존 사용자.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축 (Essence Axis)**: INFRA / FIX / UX
- **[본질] (Essence)**:
  - 아워골의 궁극 목적인 "무공해 성장 도피처"를 시각적으로 온전히 구현하기 위해, 6대 탭 전체의 시각적·촉각적 기본 문법(색상, 여백, 타이포, 터치 타겟, 햅틱)을 하나의 확고한 디자인 토큰 체계로 단일화하는 일.
  - 3대 철학 심사:
    1. **무공해성**: 자극적이고 조잡한 시각 요소를 소탕하고 안정된 색감과 여백 제공.
    2. **RPG식 체감**: 버튼 터치 시 12ms 햅틱과 물리적 눌림 피드백으로 조작 손맛 극대화.
    3. **동류 연대**: 누구나 헤매지 않고 편안하게 앱에 머물 수 있는 7~70세 직관성 보장.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. **원인 1**: 장기간 다회차 개발 과정에서 컴포넌트별로 임의 작성된 CSS 인라인 스타일 및 비표준 클래스 잔존.
  2. **원인 2**: 모바일 최소 터치 타겟 44px 규격의 전역 강제 린터 및 스타일 토큰 부재.
  3. **원인 3**: 테마 전환 시 대비비(Contrast ratio)를 보증하는 1급 CSS 변수 계층의 미완비.
- **[중심] (Core Bottleneck & Anchor)**: `ui.css` 내 전역 디자인 토큰(`:root`, 4대 테마)과 `ui.js`/`js/core/store.js`의 햅틱 및 스켈레톤 유틸리티 단일 규격화.
- **[핵심] (Critical Safety & Termination)**: 기존 440개 스모크 테스트, 38개 무결성 게이트, 893개 데드클릭 제로 및 6대 메가블록의 100% 무손실 작동 보증.
- **체감 가설 (User Experience Hypothesis)**:
  > *"사용자가 앱의 어떤 화면, 어떤 버튼을 터치하더라도, 44px 이상의 넉넉한 터치 영역과 12ms 촉각 손맛, 일관된 고대비 폰트를 통해 즉각적인 조작 신뢰감과 편안함을 체감한다."*
- **기존 전체 기능 영향도 분석**:
  - 계정/로그인: 모달 및 입력창 시인성 개선.
  - 홈 화면 및 스트릭: 히트맵 14px 도트 및 카드 여백 정돈.
  - 기록/통계/캘린더 탭: 테이블, 타이머, 차트 시각 위계 향상.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**:
  - 기존 클래스명 임의 삭제나 변경(JS 템플릿 참조 파괴 원천 금지).
  - 800줄 상한선 위반하는 거대 모듈 작성 금지.
  - 헌법 승인선(규범 변경, 기능 삭제 등) 임의 침범 금지.
- **해야 할 것 (Action)**:
  - `ui.css` 상단 토큰 섹션 고도화: 4대 테마 전용 1급 변수 완비.
  - 7~70세 폰트 스케일(14/17/22px) 및 전역 44px 터치타겟(`--touch-min: 44px;`) 배선.
  - `.skeleton-card`, `.skeleton-text`, `.skeleton-avatar` 시머링 스켈레톤 CSS 탑재.
  - `triggerHaptic(ms)` 전역 12ms 촉각 손맛 유틸리티 공식화.
  - 3대 금지어 정화 확인.
- **왜 이 방식이어야만 하는가 (Why this approach)**:
  - 상위 토큰과 공통 인프라가 단단히 잡히지 않은 상태에서 개별 탭 UI를 고치면, 또다시 스타일 파편화와 중복 코드가 양산되므로 Phase 0 토큰 단일화가 필연적 선행 조건임.

### 3-1. 스토리지 원장화 3대 명세 (헌법 제2조 제4항 준수)
- **1호 (원격 DB 스키마 명세)**: 디자인 토큰은 클라이언트 CSS/JS 레이어이며 DB 스키마 변경 불필요.
- **2호 (스마트 스토리지 분기 설계)**: 테마 선택값은 `localStorage.getItem('og_theme')` 및 `state.profile.settings.theme` 원격 프로필과 연동 보존.
- **3호 (4대 뷰 전파 배선도)**: 테마 변경 시 `document.documentElement.setAttribute('data-theme', theme)` 및 4대 뷰 동시 전파 디스패처 연동.

### 3-2. 전수 인터랙션(버튼/클릭/입력) 명세표 (Zero-Dead-Click)
| UI 요소 (ID / Name) | 위치/화면 | 사용자 액션 | 기대 동작 (비즈니스 로직) | 예외 처리 및 사용자 피드백 |
| :--- | :--- | :--- | :--- | :--- |
| `theme-swatch-*` | 설정 탭 | 클릭/터치 | 4대 테마(성소/블랙/화이트/도심) 즉각 전환 | 12ms 햅틱 + meta theme-color 갱신 |
| `.btn, .tab-btn` | 전역 | 터치/클릭 | 최소 44px 터치 타겟 보장 및 active 0.97 스케일 | 12ms 햅틱 피드백 |

### 3-3. 유저 데이터 100% 무손실 보존 규격
- 기존 테마 세팅값, 아바타 320종 보관함, 목표 및 기록 데이터 100% 보존.

## 4. [원칙 ④] 1~3 재검토 · 보완 (Critical Review & Edge Cases)
- **화이트 테마 시인성 재검토**: White-on-White 결함 방지를 위해 `--card-border: 1px solid #CBD5E1;` 및 `--ink: #0F172A;` 유지.
- **블랙 테마 OLED 순수 블랙 재검토**: `--bg: #000000;` 완벽 OLED 대응 및 `--card: #0A0A0C;` 경계선 분리.
- **모바일 햅틱 미지원 브라우저 엣지 케이스**: `if (navigator.vibrate) navigator.vibrate(12);` 안전 가드로 무음 처리.

## 5. [원칙 ⑤] 해결 절차 정리 (Implementation Procedure)
1. `ui.css` 토큰 섹션 업데이트: 4대 테마 1급 변수 보강, 폰트 스케일, 44px 터치 타겟, Z-Index 위계, 스켈레톤 애니메이션 추가.
2. `ui.js` / `js/core/store.js`: 12ms 햅틱 피드백 공통 함수(`triggerHaptic`) 배선.
3. 3대 금지어 전수 스캔 및 정화 확인.
4. 로컬 무결성 테스트 실행: `npm test` (38개 게이트, 893개 데드클릭, 5개 모듈러 스위트).
5. 법정 청구서(`claims.json`) 및 시나리오 작성.

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)
- **반론 1**: 전역 터치 타겟 44px 강제 적용 시 기존 좁은 그리드(예: 캘린더 날짜 셀, 칩 목록)의 레이아웃이 깨지거나 가로 오버플로우가 발생할 위험은 없는가?
  - **반박 및 수용**: 셀 자체의 시각적 크기는 유지하되, CSS `padding` 또는 가상 요소(`::before`, `min-width: 44px; min-height: 44px;`) 히트박스 확장 기법을 적용하여 레이아웃 파괴 없이 터치 영역만 44px로 안전하게 확장함.
- **반론 2**: 테마 CSS 변수를 수정할 때 기존 인라인 스타일이나 오래된 뷰에서 예기치 않은 글자색/배경색 충돌이 발생할 위험은 없는가?
  - **반박 및 수용**: 기존 클래스명과 변수명을 100% 보존하고 결손된 변수만 상속형 기본값(Fallback)으로 보완하므로 하위 호환성이 100% 보장됨.
