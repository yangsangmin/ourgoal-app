  - 팀 목표에 참여하면서 본인의 실천 과제를 연계하고 조별로 협업하려는 팀원 및 모임장.

## 2. 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **5대 축 귀속**: `[기본값: E1/E2/E3/FIX/INFRA 대통합]` (체크인, 회고, 동류소통, 결함수술, 기반인프라 5대 축 완전 망라).
- **체감 가설**:
  - 18개 대기 과제가 전수 해결되면 사용자는 "계정 보안이 철저하고, 프로필 설정이 완벽히 저장되며, 템플릿과 목표가 1초 만에 연동되고, 팀 활동에서 내 목표가 자연스럽게 연결되는 최고의 무결성 앱"임을 체감하게 된다.
- **[가목] 본질 (Essence)**:
  - 겉으로 드러난 18개 개별 증상의 나열이 아니라, '유저의 프로필·세션·목표·소통 전반에 걸친 4위 1체 배선의 결손을 전면 치유하고 최신 조형 규격으로 일원화하는 것'이 본질이다.
- **[나목] 원인 (Root Causes)**:
  - 1. `saveProfile`과 로컬스토리지 백업 루프에서 프로필 draft 데이터(itItems, region, interests)의 누락 및 게스트 모드 판정 분기 오류.
  - 2. 기기 목록 조회 및 개별 세션 종료 RPC/Realtime 배선 미비로 인한 일괄 로그아웃 껍데기 상태.
  - 3. 템플릿 선택, 팀 연계 목표, 프롬프트 백과사전 등 신규 조형 요소가 독립된 완결 파이프라인으로 연결되지 못하고 분절된 채 대기 상태로 방치됨.
- **[다목] 중심 (Core Bottleneck)**:
  - 프로필 편집 모달의 모달 스택 교체 시 상태 보존 및 `index.html` 내 4대 연계 뷰 동시 전파의 무결성 확보가 핵심 병목이다.
- **[라목] 핵심 (Critical Anchor)**:
  - 기존 유저 데이터(아바타, 목표, 기록, 스트릭) 100% 무손실 보존(제15조) 및 개정 헌법의 6대 무결성 기준(시각 자가감사, CSS 은폐 배제, Dead Click 0건)을 단 1건도 위반하지 않는 것이다.

## 3. 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말 것 (확장 금지, 파괴 금지)**:
  - CSS `display: none !important;`로 기존 뷰를 가리는 꼼수 위헌 행위 절대 금지.
  - 임의의 더미 가상 데이터를 하드코딩하여 눈속임하는 행위 영구 금지.
  - 기존의 정상 동작하던 카카오/구글 로그인 세션 및 아바타 320종 엔진을 건드려 회귀 버그를 유발하는 행위 금지.
- **할 것 (완주, 배선, 동결)**:
  - 18대 항목을 5대 도메인(계정/보안, 프로필/설정, 홈/체크인, 목표/템플릿, 소통/팀)으로 그룹화하여 순차적이고 체계적인 4위 1체 완결 배선.
  - 스토리지 원장화 3대 명세 및 시각적 IA 배선도 100% 명시.

### [스토리지 원장화 3대 명세 (헌법 제2조 제4항)]
1. **1호 (원격 DB 스키마 명세)**:
   - `users` 테이블: `interests`, `region`, `region_public`, `it_items` 컬럼 동기화.
   - `user_sessions` / Supabase Auth Realtime: 디바이스 세션 식별자(`device_id`, `device_name`, `last_active_at`) 브로드캐스트 채널 직결.
   - 2FA 보안: `settings.twoFactorAuth` 및 해시된 PIN 메타데이터 관리.
2. **2호 (스마트 스토리지 분기 설계)**:
   - 1계층(원격 DB): `users.interests`, `users.region`, `users.it_items`.
   - 2계층(IndexedDB/로컬 백업): `ourgoal_profile_backup_<uid>`, `ourgoal_guest_profile`, `ourgoal_devices_<uid>`.
   - 3계층(localStorage 메타): `ourgoal_settings_<uid>` (테마 4종: sanctuary/black/white/city, 2FA 상태 등).
3. **3호 (4대 뷰 전파 배선도)**:
   - 프로필/목표/설정 수정 시: `renderHome()`, `renderGoalsScreen()`, `renderRecordsScreen()`, `renderSettingsScreen()` 및 `updateTopBar()` 동시 호출.

### [시각적 IA 및 시맨틱 통합 배선도 (헌법 제2조 제6항)]
1. **1호 (상하 위계 및 서브뷰 공존 설계)**:
   - 목표 탭: 상단 목표 요약/필터 -> 중앙 목표 목록 및 로드맵 -> 최하단 [현 상태로 데이터 받기] 및 신규 [데이터분석 프롬프트 백과사전] 공존.
   - 설정 탭: 테마 4종 카드 그리드 -> 계정 및 보안(이메일 정확한 연동 상태 + 활성 기기 목록 + 2FA PIN 설정).
   - 프로필 편집: 닉네임 -> 소개 -> 동네/지역공개 -> 관심 카테고리 8개 그리드 -> 내 잇템 등록 인라인 패널.
2. **2호 (기존 기능 슬롯 1:1 이식 매핑표)**:
   - `#setAccountEmail`: 소셜/게스트 정밀 분기 매핑.
   - `#logoutOtherDevicesBtn`: 활성 기기 리스트 하단으로 승계 배치.
   - `#pvAddItItem`: 프로필 모달 내 인라인 폼 슬롯으로 매핑.
   - `#promptEncyclopedia`: 목표 탭 하단 및 기록 탭 하단 슬롯 매핑.
3. **3호 (모바일 반응형 뷰포트 여백 예산)**:
   - 375px / 430px 기준 버튼 최소 터치 높이 44px 준수.
   - 테마 선택 카드 2x2 반응형 그리드, 기기 목록 리스트 간격 8px 패딩 유지.

## 4. 1~3 재검토 · 보완 (Critical Review & Edge Cases)
- **비판적 재검토**:
  - 게스트 모드 사용자가 프로필을 편집할 때 Supabase `users` upsert가 실패하더라도, 로컬스토리지 `ourgoal_guest_profile` 및 `ourgoal_profile_backup_`에 즉시 안전하게 저장되어 새로고침 시에도 100% 복원되어야 한다.
  - 카카오 로그인 시 이메일 제공 동의를 하지 않은 유저의 경우 `state.user.email`이 없을 수 있으므로, `state.profile.provider === 'kakao'` 또는 닉네임을 통해 "카카오 계정 연동됨 (닉네임)"으로 표시하여 게스트 모드 오표기를 완벽히 방어한다.
  - 2FA 활성화 시 PIN을 잊어버린 경우를 대비해 4자리 PIN 입력창과 함께 취소/재설정 안전핀을 제공한다.
  - 외부 앱 의존 링크(mailto: 등)를 절대 추가하지 않고 인앱 완결성을 보장한다.

## 6. 절차 재검증 (Procedure Verification & Anti-SPOF)
- **단일 실패점(SPOF) 점검**:
  - 만약 Supabase Auth 브로드캐스트 채널이 오프라인인 경우: 로컬스토리지 `ourgoal_devices_`를 기반으로 활성 기기 목록을 안정적으로 렌더링하고 폴백한다.
  - 게스트 유저가 프로필/잇템을 편집할 때 DB upsert 실패 시: `catch` 블록에서 무조건 `localStorage.setItem('ourgoal_guest_profile', ...)` 및 백업 키를 유지하여 데이터 증발을 100% 방지한다.
- **재검증 도출 절차 수정사항**:
  - 잇템 추가 시 기존 프로필 모달을 닫고 새 모달을 띄울 경우 input 값들이 휘발될 수 있으므로, `openProfileEditor`가 현재 입력창의 닉네임과 소개, 선택된 지역, 관심사를 draft 객체에 즉시 동기화한 후 서브 모달을 열거나 인라인으로 추가할 수 있도록 보완 절차를 확정함.

## 8. 막히는 지점 예상 및 재검증 트리거 (Blockers & Re-verification Triggers)
- **예상 블로커 1: 프로필 모달 폼 재렌더링 시 이벤트 리스너 중복 바인딩**:
  - 대응: `addEventListener` 대신 멱등성이 보장되는 방식 또는 리스너 등록 전 클린업 적용.
- **예상 블로커 2: 템플릿 1초 자동이식 시 기존 목표와의 ID 충돌**:
  - 대응: `uid('goal')`을 새로 채번하여 기존 목표를 덮어쓰지 않고 배열에 온전히 추가.
- **재검증 트리거**:
  - 프로필 저장 후 화면에 태그나 동네가 즉시 안 나타날 경우: -> **원칙 ⑤의 2단계**로 즉시 되돌아가 `renderAll()` 및 `renderProfileCard()` 전파 파이프라인 재검증.
  - 기기 로그아웃 클릭 시 반응이 없을 경우: -> **원칙 ⑤의 1단계**로 되돌아가 `device_id` 생성 및 Realtime 이벤트 구독 상태 재검증.
