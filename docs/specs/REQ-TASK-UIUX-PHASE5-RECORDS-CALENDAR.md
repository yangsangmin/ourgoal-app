## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
- **상민님 지시 원문**: "진행. PR #619을 GitHub main에 병합하고, 이어서 다음 모듈화 단계(조선소 블록 건조 6단계)를 중단 없이 계속 진행하라. 모든 탭이 완결될 때까지 멈추지 마라."
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  - 기록이 쌓일수록 스크롤이 무한정 길어져 과거 회고 시 심각한 피로감을 유발함.
  - 캘린더(일정)와 기록(타임라인)이 분리되어 있어, 내가 '언제 무엇을 실천했는지' 날짜와 기록을 대조하려면 탭을 계속 왕복해야 함.
  - 캘린더 일자 셀이 작아 사진형 일기 썸네일과 실천 마커가 뭉개져 보임.
  - 스톱워치 측정 후 실천 기록으로 1초 연계되는 경험이 매끄럽지 못함.
- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**: 캘린더 날짜 선택과 기록 타임라인 간의 공간적 분리로 인한 동선 낭비.
  - **2층 (구조/프로세스 부재)**: 기록 탭 피드의 페이징/최신순 요약 부재 및 5단위(오늘/주/월/년/기간) 회고 아코디언의 파편화.
  - **3층 (시스템/유저 체감 괴리)**: 기록을 많이 할수록 앱이 느려지고 탐색이 힘들어져 기록 동기가 감퇴하는 역효과 발생.
- **사용자 상황 및 페르소나**: 꾸준히 실천을 기록해왔으나, 수십~수백 건의 기록 속에서 지난 성취를 한눈에 조망하고 달력과 연계해 뿌듯함을 느끼고 싶은 유저.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축 (Essence Axis)**: `E2(기록 회고)` & `INFRA/UX`
- **[본질] (Essence)**: 기록이 쌓일수록 무거워지는 피로를 소탕하고, 달력과 타임라인이 하나의 공간에서 숨 쉬는 무마찰 회고 루프 완성.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. 무한 스크롤 방식 피드로 인한 시각적 정보 과부하.
  2. 캘린더와 기록 탭 간의 상호 전환 어포던스 부재.
  3. 달력 셀 규격 부족으로 인한 사진 일기 시인성 저하.
- **[중심] (Core Bottleneck & Anchor)**: 최신 3건 전면 노출 + 기간별 아카이빙 페이징 및 캘린더 ↔ 기록 타임라인 1초 융합 스위처.
- **[핵심] (Critical Safety & Termination)**: 기존 유저의 체크인 기록, 사진 일기, 스톱워치 측정값 100% 무손실 영구 보존.
- **체감 가설 (User Experience Hypothesis)**:
  > *"사용자가 기록 탭에 들어왔을 때 최신 3건을 산뜻하게 확인하고, '달력으로 보기' 버튼 하나로 76px 와이드 캘린더에서 내 사진 일기 썸네일을 보며 성취감과 기록의 가치를 실감한다."*
- **기존 전체 기능 영향도 분석**:
  - 계정/로그인: 영향 없음.
  - 홈 및 목표 탭: 기록 추가/조회 시 4대 뷰 동시 전파 완벽 호환.
  - 캘린더 탭: 캘린더 셀 76px 확장 및 사진 일기 2장 분할 프리뷰 연계.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**:
  - 기존 기록 데이터(`state.records`) 스키마 변경 또는 삭제 금지.
  - 캘린더와 기록 화면의 렌더러를 무단 통합하여 기존 코드를 깨는 파괴 행위 금지.
  - 모듈러 파일 800줄 초과 금지.
- **해야 할 것 (Action)**:
  - 8대 세부 과업(#UIUX-41 ~ #UIUX-48) 완벽 구현.
  - `ui.css`에 기록 최신 3건 카드, 융합 스위처, 76px 캘린더 셀 스타일 구축.
  - `js/tabs/records/` 및 `js/tabs/calendar/` 메가블록 도킹 및 800줄 이하 엄수.
  - `smoke-test.js`, `verify-integrity-gate.js`, `verify-all-clicks.js` 100% PASS.
- **왜 이 방식이어야만 하는가 (Why this approach)**:
  - 사용자 피로를 낮추는 최신 3건 요약과 캘린더와의 공간적 결합이 기획정본 제10장의 회고 몰입 철학을 실현하기 때문.

### 3-1. 스토리지 원장화 3대 명세 (헌법 제2조 제4항 준수)
- **1호 (원격 DB 스키마 명세)**: Supabase `records` 테이블 및 로컬 캐시 100% 보존.
- **2호 (스마트 스토리지 분기 설계)**: 최신 3건 우선 슬라이싱 메모리 캐시 + 인라인 캘린더 매핑.
- **3호 (4대 뷰 전파 배선도)**: 기록 생성/수정/삭제 시 `dispatchFullViewPropagation()` 트리거.

| UI 요소 (ID / Name) | 위치/화면 | 사용자 액션 | 기대 동작 (비즈니스 로직) | 예외 처리 및 사용자 피드백 |
| :--- | :--- | :--- | :--- | :--- |
| `btnRecViewSwitchTimeline` | 기록 탭 헤더 | 클릭/터치 | 최신 타임라인 뷰 표시 및 활성 전환 | 12ms 햅틱 |
| `btnRecViewSwitchCalendar` | 기록 탭 헤더 | 클릭/터치 | 인라인 76px 캘린더 뷰 즉시 전환 | 12ms 햅틱 |

### 3-3. 유저 데이터 100% 무손실 보존 규격 (Zero-Data-Loss Schema)
