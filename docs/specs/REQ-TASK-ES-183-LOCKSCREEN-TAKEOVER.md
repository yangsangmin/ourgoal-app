## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)

- **상민님 지시 원문**:
  - *"아니 저런 작은 알림으로 뜨는거 말고, 잠금화면 전체를 장악해야 한다고"*
  - *"1은 앱에서 실시간 라이브 연동 키는게 트리거가 되는건가? 2는 어떤식으로 작동되는거지?"*
  - *"그래서 그걸 사용자가 어떤 버튼을 눌러서 통제할 수 있게 할거야?"*
  - *"아이폰도 같이 가능한가?"*
  - *"거치대모드는 빼고 진행해"*
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  - 기존 웹 알림 방식은 안드로이드/삼성 One UI에서 작은 알림 상자나 무음 영역으로 빠져 스마트폰 잠금화면의 본질적인 전면 장악(Full-Screen Takeover)을 실현하지 못함.
  - 상민님의 명시적 지시에 따라 거치대 모드(AOD)는 제외되어야 함.
- **표면 아래 기저 층위 분석**:
  - **1층 (미작동/단절 결함)**: 웹 샌드박스 정책으로 인해 브라우저만으로는 모바일 OS의 화면 켜짐(`ACTION_SCREEN_ON`) 이벤트를 직접 가로채지 못함.
  - **2층 (구조/프로세스 부재)**: 스마트폰 하드웨어 화면 켜짐을 감지하여 폰 기본 잠금화면을 100% 덮어버리는 네이티브 백그라운드 서비스(`LockScreenService`, `FLAG_SHOW_WHEN_LOCKED`) 및 이를 앱 내에서 직관적으로 켜고 끄는 제어 스위치 구조 부재.
  - **3층 (시스템/유저 체감 괴리)**: 사용자는 캐시워크처럼 폰 전원을 켤 때마다 아워골의 살아있는 캘린더 그리드와 실시간 달성률, 다음 일정이 폰 전체를 장악하길 기대했으나, 웹의 알림 상자 수준에 머물러 심각한 가치 단절 발생.
- **사용자 상황 및 페르소나**:
  - 스마트폰 전원을 켤 때마다 작은 알림을 일일이 누를 필요 없이, 폰 화면 전체에서 이번 달 월 달력과 오늘 달성률, 다음 일정 3개를 한눈에 확인하고 밀어서 잠금해제하거나 즉시 체크인하려는 모든 사용자.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)

- **본질 축 (Essence Axis)**: E1 / INFRA (체크인 루프 강화, 잠금화면 전체 장악 네이티브 아키텍처)
- **[본질] (Essence)**: 유저가 스마트폰을 켜는 하루 수십~수백 번의 모든 순간에 나만의 목표와 일정을 무의식적으로 각인시키고 원클릭 실천으로 연결하는 스마트폰 잠금화면의 완전한 장악.
- **[원인] (Root Causes - 기저 원인 3가지)**:
  1. **원인 1 (웹 샌드박스 한계)**: 웹 브라우저는 폰의 하드웨어 전원 이벤트(`SCREEN_ON`)를 가로채지 못하므로, 네이티브 백그라운드 서비스 래퍼가 필수적임.
  2. **원인 2 (제어 버튼의 부재)**: 사용자가 앱 내에서 "폰 켤 때마다 잠금화면 장악" 기능을 직접 켜고 끌 수 있는 명확한 스위치와 기종별(Android APK / iOS 위젯) 명확한 안내가 없었음.
  3. **원인 3 (잠금해제 제스처 부재)**: 전체 화면을 장악했을 때 폰의 원래 홈으로 나갈 수 있는 '밀어서 잠금해제' 슬라이더 인터랙션 부재.
- **[중심] (Core Bottleneck & Anchor)**:
  - 앱 내 제어 버튼(`[⚡ 폰 켤 때마다 잠금화면 전체 장악 (연동 켜기)]`) ➔ 안드로이드 `LockScreenService` 트리거 ➔ `SCREEN_ON` 시 `LockScreenActivity` 전체화면 노출 ➔ `>> 밀어서 잠금해제` 또는 `[⚡ 빠른 체크인]` 루프의 완전한 직통 배선.
- **[핵심] (Critical Safety & Termination)**:
  - 유저가 언제든 원클릭으로 잠금화면 연동을 해제할 수 있어야 하며, 화면이 멈추거나 폰을 사용할 수 없게 되는 락 상태 방지. 슬라이더 잠금해제 및 뒤로가기 보장.
- **체감 가설 (User Experience Hypothesis)**:
  > *"사용자가 앱 내에서 [⚡ 폰 켤 때마다 잠금화면 전체 장악 (연동 켜기)] 버튼을 누르고 폰을 끄면, 다시 전원을 켤 때 즉시 아워골의 풀스크린 캘린더/목표가 화면을 가득 채워 번거로운 진입 없이 하루 목표를 마주하게 된다."*
- **기존 전체 기능 영향도 분석**:
  - 계정/로그인(세션, 게스트, 소셜)에 미치는 영향: 기존 세션 불변 유지.
  - 홈 화면 및 스트릭에 미치는 영향: 홈 화면에서 원터치로 허브 모달을 열어 제어 가능.
  - 기록/통계/캘린더 탭에 미치는 영향: 기존 탭 기능에 영향 없이 독립 작동.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)

- **하지 말아야 할 것 (Avoid)**:
  - 거치대(AOD) 모드는 상민님 지시에 따라 전면 배제.
  - 가짜 목업이나 동작하지 않는 버튼 배치 금지 (Zero Dead Click).
  - 기존 320종 페르소나 및 데이터 원장 손상 금지.
- **해야 할 것 (Action)**:
  1. 거치대 모드 없이, **[⚡ 폰 켤 때마다 잠금화면 전체 장악]** 중심의 직관적 제어 패널 구축.
  2. 5종 세부 선택(달력 그리드, 달성률 바, 3개 일정 말줄임표, 스트릭, D-Day)과 **0ms 즉각 시뮬레이터 연동 유지**.
  3. 스마트폰 잠금화면 전체를 장악하는 **안드로이드 네이티브 서비스 및 액티비티 구조(`android/` 아키텍처) 완비**.
  4. 시뮬레이터 내 실제 작동하는 **`>> 밀어서 잠금해제 (Swipe to Unlock)` 제스처 슬라이더** 배선.
  5. 기종별(안드로이드 APK 원클릭 다운로드 안내 / 아이폰 정품 위젯 200% 활용) 분기 가이드 확립.
- **왜 이 방식이어야만 하는가 (Why this approach)**:
  - 사용자의 "알림 창 말고 전체 화면 장악" 요구를 만족하려면 안드로이드 네이티브 서비스가 불가피하며, 사용자가 명확히 제어할 수 있는 직관적 온오프 스위치와 탈출 제스처가 동시에 제공되어야 완벽한 UX가 완성되기 때문.

## 4. [원칙 ④] 1~3 재검토 및 보완 (Review & Edge Cases)

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)
- **단일 실패점 (SPOF) 점검**:
  - 안드로이드 백그라운드 서비스가 배터리 절전 모드로 종료될 경우 부팅 완료 브로드캐스트(`BOOT_COMPLETED`) 리시버와 `START_STICKY`를 통해 자동 재시작 보장.
- **가정의 타당성 검증**:
  - 사용자가 앱 내에서 설정을 켰을 때 즉각적인 시각적 피드백이 없으면 켜진 것인지 알 수 없으므로, 버튼 문구 및 상태 배지가 0ms로 즉각 바뀌도록 설계함.
- **재검증 결과 도출된 절차 수정/보완사항**:
  - 상민님의 "거치대모드는 빼고 진행해" 명령을 반영하여 거치대 모드를 완전히 제거하고 오직 '잠금화면 전체 장악'에만 집중하도록 수정 완료.

## 8. [원칙 ⑧] 막히는 지점 예상 및 재검증 트리거 (Blockers & Re-verification Triggers)
- **예상 블로커 1**: 사용자가 브라우저에서 '왜 당장 내 폰 전원을 껐다 켰는데 안 뜨지?'라고 느낄 수 있음.
  - **대책**: 시뮬레이터를 통해 100% 동일한 화면을 미리 체험하게 하고, 안드로이드 APK 설치 안내 및 iOS 위젯 안내를 명확히 분기 제공.
- **예상 블로커 2**: 슬라이더 제스처 터치 이벤트 충돌 가능성.
  - **대책**: 클릭 이벤트와 터치/마우스 드래그 이벤트를 모두 지원하여 어느 환경에서든 원활하게 작동하도록 설계.
- **재검증 트리거**:
  - 시뮬레이터 반응 지연이나 버튼 클릭 무반응 발견 시 원칙 ⑤의 시퀀스 2~3으로 즉각 복귀하여 이벤트 배선 재검증.
