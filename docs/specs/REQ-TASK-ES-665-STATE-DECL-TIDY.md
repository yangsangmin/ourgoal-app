## 4. [원칙 ④] 재검토 (반례·부작용)

- **뒤 선언이 「되돌리는 대입」인가** → 아니다. `var` 선언은 끌어올려지고, 실행 시점에는 `이름 = 초기값` 대입 둘이 차례로 돈다. 앞 대입(2940·2941행)과 뒤 대입(2945·2946행) 사이에 도는 최상위 문은 `var _subtabTplDomain = 'personal';` 과 `var _subtabTplType = 'ai';` 뿐이고(글자 값이라 부르는 것이 없다) 그 이름에 값을 넣지 않는다(`token-diff.json` `duplicateDeclarations` 에 사이의 문을 그대로 실었다). 그 구간보다 앞에서 누가 값을 바꿨더라도 앞 대입이 이미 초기값으로 되돌린다. 그래서 뒤 대입은 같은 값을 한 번 더 넣는 줄이다.
- **실행 글자가 그 밖에 바뀌지 않았는가** → 기준·작업의 인라인 IIFE 를 파싱해 맞댔다: 작업의 토큰열 = 기준의 토큰열 − 겹친 선언 두 문의 토큰 10개. 주석은 종류·글자·순서가 같다. IIFE 스크립트 밖의 글자는 같다. 줄 수 같음(+8 −8).
- **시험이 이 줄들의 글자를 붙잡는가** → 고치기 전에 `git grep` 으로 여섯 선언의 글자와 주석 글자를 tests/ · scripts/ 에서 찾았다 — index.html 을 읽어 붙잡는 시험은 없다(`tests/guest-null-client-es377.test.js` 의 `var FEED_POSTS_CACHE = null;` 은 시험이 자기 몸통에 직접 적은 글자다). 고친 뒤 시험 119개를 하나씩 돌린 결과와 npm test 가 기준과 같다.
