## 1. 추진 배경 및 문제 진단

### 1.1 배경
아워골은 사용자가 목표를 수립하고, 이를 잘게 쪼갠 마일스톤과 구체적인 세부 할 일(Task)을 실행해 나가는 **실행 중심 목표 관리 서비스**입니다.  
그러나 최근 기능 추가(마감일시, 참고자료 칩, 우선순위 태그, 결과입력 뱃지, AI 종합상황 분석 등)가 이어지면서 **목표 상세 화면의 세로 스크롤이 지나치게 길어지고 공간 활용이 극도로 비효율적**이라는 문제가 발생했습니다.

### 1.2 현행 UI 공간 낭비 정밀 진단 (4대 결함)

```
[현재 구조: 모바일 화면 1개에 마일스톤이 0~1개만 보임]
┌──────────────────────────────────────────────┐
│ [메타 스트립] 마감일 · 공개범위 · 달성률 68%   │ (40px)
├──────────────────────────────────────────────┤
│ [최종 결과 입력 버튼] (목표완료시)             │ (36px)
├──────────────────────────────────────────────┤
│ ┌─── 현재 종합상황 (AI 요약) ──────────────┐ │
│ │ 🤖 기록을 쌓으면 AI가 목표·마일스톤...   │ │ (85px - 큼직한 카드)
│ └──────────────────────────────────────────┘ │
├──────────────────────────────────────────────┤
│ [필터 바] 전체(3) 진행(1) 대기(1) 완료(1) [접기]│ (42px)
├──────────────────────────────────────────────┤ ▲ 상단부만 총 203px 차지!
│ ▼ 마일스톤 #1 (카드 1개 높이: 약 110px)       │
│  ├─ 1행: [▼][상태원][우선순위][완료율]  [결과] │ (38px - 가운데 텅 빔)
│  │                                    [달력] │
│  ├─ 2행: 마일스톤 제목 텍스트 단독 행          │ (34px)
│  └─ 3행: 마감일시 + 참고자료 + 결과라인        │ (36px)
│      ├─ 할 일 1: 제목 + 마감일 + 버튼...      │ (65px)
│      └─ 할 일 2: 제목 + 마감일 + 버튼...      │ (65px)
└──────────────────────────────────────────────┘ ▼ 마일스톤 1개+할일 2개면 화면 초과!
```

1. **상단 비핵심/요약 영역의 과도한 뷰포트 점유 (Above-the-Fold 잠식)**:
   - 목표 상세 화면 진입 시 상단의 `메타 스트립`, `최종 결과 버튼`, `현재 종합상황(AI 카드)`, `마일스톤 필터 바`가 합쳐져 **모바일 화면 높이의 절반 이상(200~250px)**을 차지합니다.
   - 정작 사용자가 지금 당장 확인하고 실행해야 할 **마일스톤 본문이 화면 맨 밑으로 밀려나 첫 화면에 1개도 채 보이지 않거나 1개만 간신히 노출**됩니다.
2. **개별 마일스톤 카드(`ms-row`)의 3단 수직 적층(Vertical Stacking) 및 가로 공간 낭비**:
   - 제목과 버튼 겹침을 해소하는 과정에서 `1행: 컨트롤/상태 바`, `2행: 제목 단독 행`, `3행: 메타 바`로 3단 분할되어 카드 1개의 순수 높이만 100~110px에 달합니다.
   - 특히 1행의 가운데 영역은 넓은 공백으로 낭비되고 있으며, 우측의 수직 적층 버튼(달력+결과입력)으로 인해 상단 바의 높이가 불필요하게 늘어납니다.
3. **하위 세부 할 일(`task-row`)의 무분별한 다단 줄바꿈**:
   - 할 일 항목 내부에서 제목, 마감일, 참고자료 버튼, 결과 뱃지가 각각 다른 줄로 분할되어 할 일 1개당 60~70px을 차지합니다. 할 일이 3~4개만 달려 있어도 마일스톤 1개가 모바일 스크린 전체를 뒤덮어 전체 목표의 진행 맥락을 잃어버립니다.
4. **시각적 계층감(Visual Hierarchy) 약화**:
   - 마일스톤 카드와 하위 할 일 간의 구분이 모호하고, 너무 많은 뱃지와 버튼이 분산 배치되어 있어 사용자가 어디를 눌러야 할지 인지 부하가 증가합니다.

## 2. 개편 목표 및 핵심 성과 지표 (KPI)

1. **마일스톤 첫 화면(Above the Fold) 노출 수 대폭 확대**:
   - 현행: **최대 1개** ➔ 개선 후: **최소 3~4개 마일스톤 즉시 조망 가능 (300% 향상)**.
2. **마일스톤 카드 기본 높이 45% 슬림화**:
   - 현행: 카드당 약 **108px** ➔ 개선 후: **58px 이내** (2단 스마트 인라인 그리드).
3. **하위 세부 할 일(Task) 높이 50% 압축**:
   - 현행: 건당 약 **65px** ➔ 개선 후: **32px 단일 행(One-Line)** 완전 정돈.
4. **정보 접근성(Reachability) 100% 보존**:
   - 공간을 줄이되 기존의 상태 변경, 마감일시, 구글 캘린더 연동, 결과 입력, 참고자료 첨부 기능은 단 하나도 누락 없이 **원탭/스마트 팝오버**로 유지.

## 3. 세부 화면 재설계 및 기능 요구사항

### 3.1 [개선 1] 상단 AI 종합상황 카드의 '스마트 미니바(Mini-Bar)' 개편

- **현행**: 상단에 큼직한 박스 형태(`div.card`)로 고정 노출되어 본문을 85px 이상 아래로 밀어냄.
- **개선안**:
  - 기본 상태를 **1줄 스마트 알림 바 형태(높이 34px)**로 슬림화:
    `[ 🤖 AI 요약: 마일스톤 2건 완료! 순항 중입니다 ▾ ]`
  - 사용자가 탭할 때만 아래로 부드럽게 펼쳐지는 접이식(Accordion) 토글 적용.
  - 마일스톤 필터 바(`전체/진행/대기/완료`)와 `전체 펼치기/접기` 버튼을 한 줄로 깔끔하게 밀착 배치.

### 3.2 [개선 2] 마일스톤 카드의 '2단 고밀도 인라인 그리드 (Compact Grid)'

마일스톤 카드를 3단 적층에서 **기능 집약적 2단 인라인 구조**로 전면 재배치합니다.

```
┌─── [TO-BE] 마일스톤 카드 구조 (높이 약 56px) ──────────────────────────┐
│ [1행 메인]  (▶) [상태] 마일스톤 핵심 제목이 시원하게 노출됩니다    [2/4] [D-3] │
│ [2행 메타]  높음 · 9/20 마감 · 📎자료(2) · 📝결과  │ 📅캘린더 (수정/삭제) │
└────────────────────────────────────────────────────────────────────────┘
```

- **1행: 타이틀 & 핵심 상태 바 (높이 32px, flex align)**:
  - **좌측**: 하위 할 일 접기/펼치기 토글(`▶` / `▼`) + 상태 전환 원(`○` 대기 / `◐` 진행 / `✓` 완료) + **마일스톤 제목 (가로 최대폭 확보)**.
  - **우측**: 하위 할 일 진행률 미니 칩(`2/4 완료`) + 마감 D-day 미니 뱃지(`D-5` 또는 `D+2`).
  - 제목을 터치하면 인라인 즉시 수정 가능(편집 모드).
- **2행: 스마트 인라인 메타 바 (높이 24px, 여백 최소화)**:
  - 좌측에 우선순위 칩(`높음`/`보통`/`낮음`), 마감일시 텍스트(`9/25 18:00`), 참고자료 카운트(`📎2`), 결과 뱃지(`📝결과`)를 한 줄 인라인으로 컴팩트하게 나열.
  - 우측에 구글 캘린더 반영 버튼(`📅`) 및 편집 모드 이동/삭제 버튼 배치.
  - 메타가 없는 항목은 2행 자체의 여백을 최소화하여 단 38px로 극단적 슬림화.

### 3.3 [개선 3] 하위 세부 할 일(Task) '원라인(One-Line) 인라인' 정돈

- **현행**: 제목, 마감일, 참고자료 버튼, 결과 뱃지가 각각 줄바꿈되어 3~4줄 차지.
- **개선안**:
  - **완전한 단일 행(One-Line Flex, 높이 32px)**으로 정돈:
    `[✓ 체크] 할 일 제목 텍스트 (가로 최대폭) [9/15 마감] [📎] [결과입력] [×]`
  - 마감일은 미니 텍스트 칩으로 우측 배치.
  - 참고자료나 결과가 있을 때만 미니 아이콘 뱃지로 인라인 표시.
  - 탭하면 바로 수정되고, 우측의 간섭 없는 버튼으로 깔끔하게 완료/결과 입력.

### 3.4 [개선 4] '간결 뷰(Compact)' vs '상세 뷰(Detailed)' 밀도 전환 토글 (권장)

- 마일스톤 필터 바 우측에 **보기 밀도 전환 버튼** 구비:
  - **간결 뷰(기본값 권장)**: 1행(상태 + 제목 + 진행률/D-day) 중심의 고밀도 스키밍 모드. 한 화면에 5~6개 마일스톤 노출.
  - **상세 뷰**: 2행(참고자료 칩 풀텍스트, 상세 마감일시, 결과 상세 요약)까지 모두 펼쳐 보여주는 분석 모드.

## 6. 보완 권장사항 및 상민님 의사결정 요청 사항

### 💡 [보완 권장 1] 상단 '현재 종합상황(AI 요약)'의 슬림 배너화
- **현재 상황**: 매번 큰 카드 박스로 노출되어 정작 실행해야 할 마일스톤 목록을 아래로 밀어냅니다.
- **권장 제안**: 기본은 1줄짜리 슬림한 상태 배너(`🤖 AI: 2건 진행 중 · 달성률 68% ▾`)로 표시하고, 터치하면 원래의 자세한 분석 텍스트가 아래로 펼쳐지도록 하여 상단 여백을 60px 이상 확보하는 방식을 강력히 권장합니다.

### 💡 [보완 권장 2] 하위 세부 할 일(Task)의 1줄 인라인 정돈
- **현재 상황**: 할 일 1개당 마감일, 참고자료 버튼, 결과 뱃지가 각각 줄바꿈되어 4줄씩 늘어납니다.
- **권장 제안**: 가로폭이 좁은 모바일에서도 `[체크] [제목 (가로 채움)] [우측: 미니뱃지들]` 형태로 깔끔하게 1줄 인라인 플렉스로 정돈하여, 할 일이 5개 있어도 마일스톤 카드가 스마트폰 한 화면을 벗어나지 않도록 권장합니다.

### 💡 [보완 권장 3] 뷰 밀도 모드(간결 모드 vs 상세 모드) 도입
- **권장 제안**: 마일스톤 수가 많은(5~10개 이상) 헤비 유저나 기획자형 사용자를 위해, 1행만 슬림하게 훑어보는 `간결 모드`와 메타데이터까지 다 보는 `상세 모드` 토글 버튼을 마일스톤 필터 바 우측에 작게 배치하는 것을 제안합니다.
