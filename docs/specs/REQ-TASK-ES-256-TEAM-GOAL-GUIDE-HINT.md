## 1. [원칙 ①] 문제 정확히 파악 (Problem Identification)
- **상민님 지시 원문**:
  > "팀목표에서 팀목표 200% 활용 가이드 오른쪽에 3포인트 작게 ‘* 팀 목표를 생성하면 사라짐’ 안내문구 표시하자."
- **현재 발생하는 문제 및 한계 (표면적 현상)**:
  1. 팀 목표 탭에 신규 진입한 유저가 '팀 목표 200% 활용 가이드' 카드를 보았을 때, 이 거대한 카드가 상시 고정 노출되는 것인지, 아니면 팀 목표를 개설하면 사라지는 온보딩 안내인지 인지하지 못해 시각적 압박감을 느낌.
  2. 선행 간이 작업(ES-149)에서 기본 문구 배치가 일부 시도되었으나, 3pt 축소 폰트 규격의 모바일 가독성 및 375px 반응형 줄바꿈 시 레이아웃 정합성 검증, 독립 단위 테스트 스위트 부재 및 법정(court) 정식 판정 미비로 노션 생각 메모장 [11]번이 미완결 상태로 잔존함.
- **기저 층위 심층 분석**:
  - **1층 (인지적 불확실성)**: 가이드가 언제까지 화면을 차지하는지 모르면 유저는 가이드 영역을 닫으려고 하거나 불필요한 조작을 시도함.
  - **2층 (시각적 위계 부재)**: 헤더 제목과 안내 힌트 문구 간의 크기 대비(3포인트 축소)와 색상 대비(`--ink-faint`)가 명확해야 본문과 안내의 역할이 구분됨.
  - **3층 (조건부 소멸 상태 불일치 방지)**: 실제로 팀 목표가 1개 이상 생성되거나 가입되면 이 가이드가 깨끗하게 소멸되고 실제 팀 목표 목록이 화면을 주도해야 함.
- **대상 사용자 페르소나 및 발생 상황**:
  - 아워골에 처음 가입하여 팀 목표 탭을 처음 방문한 모든 신규 유저 및 팀을 아직 개설하지 않은 유저.

## 2. [원칙 ②] 본질 · 원인 · 중심 · 핵심 파악 (Essence, Causes, Core & Anchor)
- **본질 축 (Essence Axis)**: `[UI/UX & E3]` (동류 소통 루프 및 온보딩 마찰 최소화)
- **[가목] 본질 (Essence)**:
  - 1. **투명한 예측 가능성 (Predictability)**: 유저에게 '이 가이드는 팀 목표 생성 시 사라진다'는 것을 명시하여 심리적 안도감 제공.
  - 2. **시각적 위계질서 (Visual Hierarchy)**: 가이드 제목('팀 목표 200% 활용 가이드')을 해치지 않도록 3포인트 작고 은은한 톤으로 힌트 배치.
  - 3. **무결한 상태 연동 (State Integrity)**: 팀 생성 시 가이드가 실제로 자동 소멸하는 온보딩 파이프라인 무결성 보장.
- **[나목] 원인 (Root Causes)**:
  - 초기 기획 단계에서 온보딩 가이드의 성격(임시 온보딩 가이드)이 제목 옆에 명시되지 않아 영구 고정 UI로 오인됨.
- **[다목] 중심 (Core Bottleneck)**:
  - `renderTeamGoalsEmptyGuideHtml` 함수 내 헤더 영역의 플렉스 정렬(`align-items: center; gap: 8px; flex-wrap: wrap;`)과 3pt 축소 힌트 클래스(`.guide-vanish-hint`)의 정확한 렌더링.
- **[라목] 핵심 (Critical Anchor)**:
  - `* 팀 목표를 생성하면 사라짐` 문구 정확도, 폰트 크기(`0.8125rem` / 13px vs 제목 `1.0625rem` / 17px), 팀 가입/생성 시 조건부 숨김 동작 보증.

## 3. [원칙 ③] 효과적 · 효율적 해결방식 결정 (Effective Solutions)
- **하지 말아야 할 것 (Avoid)**:
  - 가이드 텍스트 전체를 재작성하거나 기존 레이아웃 박스를 깨뜨리는 과도한 리팩토링 금지.
  - 별도의 팝업이나 모달을 띄워 유저 인터랙션을 방해하는 행위 금지.
- **해야 할 것 (Action)**:
  - `renderTeamGoalsEmptyGuideHtml`의 제목 헤더 바로 우측에 `<span class="guide-vanish-hint" style="font-size:0.8125rem;color:var(--ink-faint);font-weight:400;">* 팀 목표를 생성하면 사라짐</span>` 구조 확립.
  - 375px 모바일 뷰포트에서 가로 스크롤 오버플로우 0px 보장 (`flex-wrap: wrap;`).
  - 팀 목표가 0개일 때는 노출되고, 1개 이상 생성/가입 시 자동으로 소멸되어 실제 팀 목표 화면이 나타나는 조건부 렌더링 유지.
  - 독립 단위 테스트 `tests/team-goal-guide-hint.test.js` 작성.

## 4. [원칙 ④] 구현과정 가상 시뮬레이션 (Simulation)
1. **시나리오 A: 가입한 팀이 0개인 신규 유저가 팀목표 탭 진입**:
   - `renderTeamGoalsScreen()` 호출 ➔ `myTeams.length === 0` 감지 ➔ `renderTeamGoalsEmptyGuideHtml()` 렌더링.
   - 제목 우측에 `* 팀 목표를 생성하면 사라짐` 문구가 제목보다 3포인트 작은 은은한 글씨로 표시됨.
2. **시나리오 B: 유저가 팀을 생성하거나 기존 팀에 가입 완료**:
   - `myTeams.length > 0` ➔ `renderTeamGoalsScreen()` 재호출 ➔ 가이드가 완전히 사라지고 팀 목표 목록 카드가 표출됨.
3. **시나리오 C: 팀 가입 후 상단 [가이드 다시보기] 버튼(#btnShowTeamGuideModal) 클릭**:
   - 모달 팝업으로 가이드가 재호출되어 언제든 내용을 다시 열람 가능함.

## 5. [원칙 ⑤] 예외 · 엣지케이스 · 실패조건 대비 (Edge Cases)
- **엣지케이스 1: 320px~375px 초소형 모바일 화면**:

- **엣지케이스 2: 다크 모드 및 고대비 테마 전환**:
  - 하드코딩된 색상이 아닌 CSS 변수 `var(--ink-faint)`를 사용하여 다크 모드, 고대비 모드에서도 완벽한 시인성 유지.

## 6. [원칙 ⑥] 절차 재검증 (Procedure Verification & Anti-SPOF)
- **단일 실패점 (SPOF) 점검**: 가이드 힌트 마크업이 손상되더라도 팀 목표 탭 전체 렌더링이 중단되지 않고 독립 span으로 안전하게 렌더링됨.
- **가정의 타당성 검증**: 폰트 크기 `0.8125rem`은 제목 `1.0625rem` 대비 4px(약 3pt) 작아 상민님 지시를 정확히 충족함.
- **재검증 결과 도출된 절차 보완**: 단위 테스트(`tests/team-goal-guide-hint.test.js`)와 스모크 테스트를 모두 가동하여 향후 UI 변경 시에도 회귀 결함이 발생하지 않도록 2중 방어선 구축.
