## 지시 원문(로드맵 행의 세부 절차·완료 기준 그대로)

1. AI 체크인 첫 사용 전 모달: 사용 AI 제공자명, 전송 데이터(목표 텍스트), 보관 기간, 동의/거부
2. /privacy: 수집 항목(이메일·목표 텍스트·기기), 목적, 보관, 제3자(AI 제공자·Supabase·PostHog), 삭제 방법
3. /support: 이메일·오픈채팅 링크·FAQ 5개
4. 푸터·설정 화면에 링크
5. 완료 기준: 3개 페이지 URL 200 응답, 모달 동작 스크린샷

## 1. 문제 정확히 파악 (원칙 ①)

- 겉: 배포 전에 필요한 세 화면(동의 모달·방침·지원)이 없다. 처리메모(2026-09-16)의 실측대로 앱 안 방침 모달·약관·1:1 문의(mailto)는 있으나 AI 고지 동의는 코드에 0건, `/privacy`·`/support` URL 은 없다.
- 층위: (1층) 목표·기록 텍스트가 동의 없이 Google Gemini 로 전송된다 — `requestAIFeedback` 외 8개 AI 호출 지점 모두. (2층) 앱 안 방침 제4조는 위탁처를 Supabase·Vercel 두 곳만 적어 실제 전송처(Google, PostHog)와 어긋난다. (3층) 스토어·지인 배포가 요구하는 "URL 로 열 수 있는 방침"이 없다.

## 2. 본질·원인·중심·핵심 (원칙 ②)

- 본질: 사용자가 자기 글이 어디로 가는지 알고 고를 수 있어야 한다. 무공해(과시·도파민 없음) 철학에 맞게 고지는 조용하고 정직해야 하며, 거부해도 기록·핵심 기능은 그대로다.
- 원인: AI 기능이 하나씩 붙는 동안 호출부마다 전송 경로가 생겼고 중앙의 동의 지점이 없었다(배선 부재). 방침 문서는 AI 도입 전 문안 그대로였다.
- 중심(병목): "동의 전에는 어떤 AI 호출도 나가지 않는다"를 함수마다 손으로 지키는 구조 → 한 곳이라도 빠지면 고지가 거짓이 된다.
- 핵심(앵커): ① 동의 판정 함수 하나(`aiConsentGranted`)를 모든 AI 호출부가 쓴다 ② 거부해도 체크인 저장·로컬 피드백은 그대로 ③ 고지 문구는 코드에서 읽은 사실만(제공자 Google Gemini, 서버 DB 미저장 등).

## 3. 해결방식 (원칙 ③)

- 할 것: 동의 저장(`ourgoal_ai_consent`, 기기 localStorage, 버전 필드) · 동의 모달(첫 체크인 저장 직후·AI 로딩 전) · 모든 AI 호출부 첫 줄 게이트 · 설정의 동의 확인·변경 버튼 · `privacy.html`·`support.html` · `vercel.json` 재작성 · 푸터·설정 링크 · 앱 안 방침 제7조 추가 · 서비스워커 캐시명 갱신 · 우회 방지 시험.
- 하지 말 것: 기존 방침 조문(제1~6조) 수정(같은 시기 열린 PR #357 이 제5조를 고친다 — 충돌 방지), 서버 API 수정, 30일 유예·탈퇴 흐름 변경, 오픈채팅 링크 지어내기.
- 필연: 동의 판정을 한 함수로 모으고 "AI 로 나가는 fetch 앞에 그 함수가 있다"를 시험이 읽어 검사해야 이후 새 AI 기능이 붙어도 우회가 생기지 않는다.

## 4. 재검토·보완 (원칙 ④)

- 기존 사용자는 다음 체크인에서 모달을 본다. 그 전까지 배경 AI 기능(오늘의 미션·목표 상태 요약 등)은 기기 안 문구로 대체된다 — 의도된 동작이며 dev_log·PR 에 적는다.
- 모달을 바깥 탭·뒤로가기로 닫으면 "이번만 AI 없이"로 처리하고 선택을 저장하지 않아 다음에 다시 묻는다(동의 없이 통과하는 길을 만들지 않는다).
- 동의는 기기 단위다(계정 단위 아님) — 방침에 기기 저장이라고 명시. 계정 단위 저장은 DB 스키마가 필요해 범위 밖.
- 약점: `api/goalagent.js` 가 요청 문장을 서버 로그(`console.log`)에 남긴다. 방침에 사실대로 적었고 코드 수정은 범위 밖으로 남겼다(아래 8).
- 약점: 오픈채팅 링크는 실물이 없다(T007 미완) — 지원 페이지에 "준비 중"으로 표기하고 죽은 링크를 만들지 않는다.

## 5. 해결 절차 (원칙 ⑤)

1. 실측: AI 호출 지점 전수(`grep` 결과 9곳), 제공자명(코드의 모델 목록·엔드포인트 = Google Gemini), 기존 방침(docs/legal, 앱 안 모달), 푸터·설정 위치.
2. `privacy.html`·`support.html`·`vercel.json` (실행 주체: 세션, 20분).
3. 동의 로직 + 게이트 9곳 + 모달 + 설정 행 (25분).
4. 링크·앱 안 방침 제7조·캐시명 (5분).
5. 시험: 우회 방지 시험 신설, 스모크·무결성·전수 클릭, 브라우저 실측(모의 서버로 AI 호출 수 측정), 스크린샷 (20분).
6. 티켓·dev_log·주장 파일·초안 PR, 로드맵 행 증거 기입.

## 6. 절차 재검증 (원칙 ⑥)

- SPOF: 동의 저장소(localStorage)가 막힌 환경 → 선택 없음으로 취급해 AI 미전송(안전한 쪽). 모달이 안 떠서 영구 무동의가 되는 경우는 설정의 변경 버튼이 대안.
- 가정 검증: 체크인 저장 뒤 로딩 시트가 열리기 전에 모달을 띄우면 두 창이 겹치지 않는다 → 브라우저 실측으로 확인. Vercel 이 `privacy.html` 을 `/privacy` 로 내려주는지 → 재작성 규칙 명시(`cleanUrls` 는 전역 영향이라 쓰지 않음).
- 재검증 결과: 첫 시험에서 우회 가능 지점 2곳(`requestServerAIFeedback`·`requestGeminiFeedback` 직접 호출)이 발견돼 게이트를 추가했다.
