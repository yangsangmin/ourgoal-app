# 조직 개발 사이클

1. `git status --short`가 깨끗한지 확인한다. 아니면 멈추고 알린다.
2. 노션 감사 로그(`collection://4ca58863-a71c-405c-9091-d54fd6bda1b8`)에서 `조직개발 반영 = 미검토` 행 수를 센다. 0건이면 "검토할 감사 로그가 없습니다"로 끝낸다. 1~2건이면 사용자에게 "표본이 적어 개별 프롬프트 수정만 가능합니다. 진행할까요?"를 묻는다(§5 예외 — 조직 변경이므로).
3. `org-developer` 서브에이전트를 띄운다(백그라운드 아님). 프롬프트에 포함: 미검토 행 수, 이전 개발 로그 중 `병합됨` 항목의 재검증 계획 재채점 지시, "한 PR에 한 개선안" 규칙, 보고 양식.
4. org-developer의 🔧 조직개발 보고를 그대로 전달하고, PR 병합은 사용자에게 맡긴다.
5. 사용자가 채팅으로 특정 PR 병합을 지시하면 `gh pr merge --squash` 후 `grep -rn "^<<<<<<<" .`·`node scripts/smoke-test.js`를 돌리고, 해당 개발 로그 행 `상태 = 병합됨`, 근거 감사 행 `조직개발 반영 = 반영`으로 갱신한다.
