# 법정(court) — 한 장 설명서

근거: 헌법 제7조 제10항 [판정 분리], 제8조 제3항 [보고의 정본은 법정 판정서다]. 배경은 `docs/specs/REQ-TASK-ES-200-VERDICT-SEPARATION.md`.

## 1. 법정이 하는 일

**작업자(사람이든 AI 든)는 "됐다"고 주장만 쓴다. "됐다"고 판정하는 것은 법정이다.**

예전에는 일한 쪽이 시험 문제도 내고, 채점도 하고, 성적표도 썼다. 그래서 아무것도 안 재도 "100% 통과"가 나왔다.
법정은 작업자가 고칠 수 없는 곳(GitHub)에서, 고치기 전 앱과 고친 뒤 앱을 **나란히 실제로 띄워 놓고** 다음을 직접 본다.

| 법정이 보는 것 | 어떻게 |
| :-- | :-- |
| 되던 것이 고장 났는가 | 주장과 상관없이 항상 본다: 부품(js 파일)이 로드되는지, 앱이 뜨는지, 창 열고 닫기·탭 전환 같은 표준 점검 |
| 주장이 사실인가 | 작업자가 낸 시나리오를 법정이 **진짜 마우스 입력으로** 다시 실행한다. "고쳤다"는 주장은 고치기 전에는 실패하고 고친 뒤에는 통과해야 인정된다 |
| 채점 기준을 건드렸는가 | 금고(5절) 파일을 제품 코드와 같이 고쳤으면 돌려보낸다 |

화면 캡처도 법정이 직접 찍는다. 작업자가 낸 캡처·"N/N 통과" 출력은 증거가 아니다.

## 2. 판정 네 가지

판정서(`REPORT.md`)의 **첫 네 줄**만 보면 된다: ① 판정 ② 상민님이 하실 일 ③ 지시 항목 기준 분포 ④ 어떤 커밋을 어디서 심사했는가.

| 판정 | 뜻 | 병합 | 종료코드 |
| :-- | :-- | :-- | :-- |
| **통과** | 지시 항목을 모두 필요한 수준으로 확인했고 고장 난 것이 없다 | 가능 | 0 |
| **확인 부족** | 막을 이유는 없지만, 확인 못 한 채 나가는 것이 있다(목록이 둘째 줄에 나온다). 금고만 바꾼 PR 도 여기에 해당한다 | 가능(알고 결정) | 3 |
| **돌려보냄** | 되던 기능이 고장 났거나, 주장이 사실이 아니거나, 채점 기준을 같이 고쳤다. 작업자가 고쳐서 다시 심사받는다 | 불가 | 1 |
| **심사 못 함** | 법정 도구가 고장 나서 못 봤다. **통과가 아니다** | 불가 | 2 |

"확인 못 함"은 잘못이 아니다. 못 잰 것을 쟀다고 적는 것이 잘못이다.

## 3. 확인 수준 6단

"통과했는가"보다 먼저 "어떤 수준으로 확인했는가"를 본다. 수준은 작업자가 적는 값이 아니라 **법정이 실제로 한 일**에서 나온다.

| 수준 | 뜻 | 누가 할 수 있나 |
| :-- | :-- | :-- |
| 확인 못 함 | 아직 확인하지 못했다 | — |
| 글자만 봄 | 코드·설정에 그렇게 적혀 있는 것만 봤다 | 법정 |
| 부품만 돌려 봄 | 그 코드 조각을 따로 돌려 봤다 | 법정 |
| PC 화면에서 눌러 봄 | 실제 브라우저에서 눌러 보고 결과를 확인했다 | 법정 |
| 진짜 계정끼리 주고받아 봄 | 실서버에서 계정 2개로 주고받아 봤다 | 사람 손(`[손 필요]`) |
| 진짜 폰에서 해 봄 | 실제 폰에서 해 봤다 | 사람 손(`[손 필요]`) |

일의 종류마다 필요한 최소 수준이 있다(`grade-floors.json`). 예: 설정값은 "글자만 봄"으로 충분하지만, 화면 동작은 "PC 화면에서 눌러 봄", 남의 데이터 열람 차단은 "진짜 계정끼리", 폰 뒤로가기 버튼은 "진짜 폰"이어야 한다. 못 미치면 통과가 아니라 "확인 부족"으로 센다.

## 4. 작업자가 하는 일 — 주장 파일 쓰기

`reports/<작업번호>/claims.json` 에 **상민님 지시 항목(requirements)** 과 **주장(claims)** 을 적어 같은 PR 에 넣는다. 보고서의 분모는 주장 수가 아니라 지시 항목 수다.

주장의 종류(`kind`): `behavior`(화면 동작 — 시나리오 필수) · `static`(설정값·파일 — 최대 "글자만 봄") · `unverified`(못 잰 것 — 왜·누가·어떻게를 적는다) · `withdrawn`(철회 — 사유 필수. 돌려보내진 주장을 말없이 지우면 그것도 돌려보낸다).

`grade`·`verdict`·`outcome`·`passed`·`level` 은 적을 수 없다. 적으면 형식 오류다.

아래 예시는 **이 설명서에만** 있다. 헌법은 서식 예시를 싣지 않는다(제8조 제3항 1호). 예시의 값을 보고에 복사하지 말 것 — 그것이 이 제도가 없애려는 바로 그 사고다.

`reports/TASK-ES-000/claims.json` (최소 예시)

```json
{
  "task": "TASK-ES-000",
  "requirements": [
    { "id": "R1", "text": "새 목표 창에서 뒤로가기를 누르면 창만 닫혀야 한다" },
    { "id": "R2", "text": "안드로이드 폰의 뒤로가기 버튼으로도 똑같이 되어야 한다" }
  ],
  "claims": [
    {
      "id": "C1", "req": "R1", "kind": "behavior", "change": "fix", "symptom": 6,
      "domain": "navigation",
      "statement": "새 목표 창에서 뒤로가기를 누르면 창만 닫히고 홈에 머문다",
      "touches": ["index.html"],
      "scenario": "scenarios/modal-back.json"
    },
    {
      "id": "C2", "req": "R2", "kind": "unverified",
      "domain": "native-device",
      "statement": "안드로이드 폰의 뒤로가기 버튼으로도 창만 닫힌다",
      "touches": ["index.html"],
      "unverified": {
        "reason": "needs-real-device",
        "who": "실제 안드로이드 폰을 가진 사람",
        "how": ["폰에 앱을 설치한다", "새 목표 창을 연다", "폰의 뒤로가기 버튼을 누른다", "창만 닫히고 앱이 꺼지지 않는지 본다"]
      }
    }
  ]
}
```

`symptom: 6` 은 "고치기 전 앱에서는 시나리오의 6번째 단계가 실패해야 한다"는 뜻이다. 고치기 전에도 통과하면 법정은 "고칠 게 없었음"으로 판정한다(위반은 아니다).

`reports/TASK-ES-000/scenarios/modal-back.json` (최소 예시)

```json
{
  "id": "modal-back",
  "title": "새 목표 창을 열고 뒤로가기를 누르면 창만 닫힌다",
  "steps": [
    { "do": "goto", "path": "/index.html" },
    { "do": "waitFor", "selector": "#homeAddGoal" },
    { "do": "click", "selector": "#homeAddGoal" },
    { "expect": "visible", "selector": "#modalOverlay.active" },
    { "do": "back" },
    { "expect": "notVisible", "selector": "#modalOverlay.active" },
    { "capture": "after-back" }
  ]
}
```

시나리오는 정해진 낱말만 쓸 수 있다. 하는 일(`do`): `goto` `waitFor` `click` `type` `key` `back` `setViewport` `setOffline` `seedLocalStorage` `wait`. 확인(`expect`): `visible` `notVisible` `textContains` `count` `hasClass` `rect` `noHorizontalOverflow` 등. 임의 코드 실행은 없다 — 버튼을 실제로 누르지 않고 함수를 직접 불러 결과 화면을 연출할 수 없다. 사용자 행동이 없거나, 행동 뒤에 화면을 확인하지 않는 시나리오는 "시험 미제출"로 친다.

## 5. 금고 — 채점 기준은 같이 못 고친다

`vault.json` 이 목록이다. 요지:

- **동결(frozen)**: `court/` 전체, 헌법 정본과 `AGENTS.md`·`GEMINI.md`·`CLAUDE.md`, `.github/`, `.githooks/`, `scripts/verify-*.js`, `package.json` 의 `scripts` 등. 제품 코드와 **한 PR 에서 함께 바뀌면 돌려보낸다.** 금고만 바꾸는 PR 은 "확인 부족 — 상민님 결심 필요"로 표시되고, 승인 문구는 "금고 변경 승인"·"헌법 개정 승인"이다("1"·"진행"으로는 승인되지 않는다).
- **추가 전용(appendOnly)**: `scripts/smoke-test.js` 등 테스트. 검사를 **더하는 것은 자유**, 있던 검사를 지우거나 고치면 돌려보낸다.
- 작업과 함께 새로 만든 검증 스크립트의 출력은 증거로 받지 않는다(자기가 낸 시험).

법정이 틀렸다고 생각되면 법정을 고치지 말고, 주장 칸에 이의를 적고 별도 PR 로 올린다(제7조 제10항 3호).

## 6. 내 PC 에서 돌린 것은 판정이 아니다

| | 내 PC (예비 점검) | GitHub (판정) |
| :-- | :-- | :-- |
| 실행 | `npm run court` · `npm run court:quick` · 푸시 전 자동(`.githooks/pre-push`) | PR 을 올리면 `court` 검사가 자동 실행 |
| 어느 법정으로 | 내 작업 폴더의 `court/` (내가 고칠 수 있다) | **main 에 있는** `court/` (PR 이 고쳐 와도 쓰이지 않는다) |
| 효력 | 없음. 판정서 맨 위에 "작업자 PC 에서 돌린 예비 점검입니다. 판정 효력이 없습니다"가 찍힌다. 어디에도 "통과"라고 옮겨 적을 수 없다 | 있음. 브랜치 보호의 필수 검사이며, 결과가 PR 에 고정 댓글로 게시된다 |
| 쓰임 | 올리기 전에 돌려보낼 것이 뻔한 것을 미리 거른다 | 상민님께 가는 보고의 첫 블록 |

상민님께 보고할 때 첫 블록은 `node court/chat.js <PR번호>` 의 출력을 그대로 붙인다. 이 도구는 아무것도 계산하지 않고 GitHub 에 찍힌 판정(발급 주체가 GitHub Actions 인 `court` 검사 + 법정 계정이 단 댓글)만 읽어 온다. 판정이 아직 없으면 "법정 심사 전 — 아래는 전부 작업자 주장입니다"가 나온다.

GitHub 쪽 구성: `.github/workflows/court.yml`(심사 — 읽기 권한만, PR 코드는 법정의 격리 실행 안에서만 돈다, 포크 PR 은 심사하지 않고 실패로 남긴다) · `court-publish.yml`(게시 — PR 코드를 받지도 실행하지도 않는다).

## 7. 법정을 처음 들여오는 PR 은 법정 심사를 받지 못한다

GitHub 의 심사는 "main 에 이미 있는 워크플로와 법정"으로 돈다(그래야 PR 이 잣대를 같이 고쳐도 소용없다). 그런데 법정을 **처음** 들여오는 PR(#TASK-ES-200) 시점에는 main 에 법정도 워크플로도 아직 없다. 그래서 그 PR 에서는 `court` 검사가 아예 돌지 않는다.

그 한 번은 다음으로 갈음한다: 법정 자가시험(`npm run test:court` — 가짜를 주입해 전부 걸러내는지 확인) 전수 통과 + 독립 검수 + 상민님 결심. 이것은 그 PR 1건뿐인 예외이며 선례가 되지 않는다(제7조 제10항 8호). 같은 이유로 브랜치 보호의 필수 검사에 `court` 를 넣는 일(`docs/rules/branch-protection.json`)은 그 PR 이 병합된 **뒤에** 적용한다 — 먼저 넣으면 돌지 않는 검사를 기다리느라 그 PR 이 영영 병합되지 않는다.

`docs/rules/branch-protection.tier2.json` 은 2단(AI용 GitHub 계정 분리)이 끝난 뒤에 쓰는 사본이다. 그때부터 `.github/CODEOWNERS` 가 효력을 가져, 금고를 바꾸는 PR 은 상민님 계정의 승인 없이는 병합되지 않는다.

## 8. 명령 모음

| 명령 | 하는 일 |
| :-- | :-- |
| `npm run court -- --head <커밋>` | 예비 점검 전체(화면 점검 포함). Chrome 과 Node 22 이상이 필요하다 |
| `npm run court:quick` | 빠른 예비 점검(금고 + 부품 로드). 화면은 보지 않는다 |
| `npm run test:court` | 법정 자가시험 — 법정이 가짜를 걸러내는지 |
| `node court/chat.js <PR번호\|커밋>` | 보고 첫 블록 출력(GitHub 의 판정을 그대로) |
