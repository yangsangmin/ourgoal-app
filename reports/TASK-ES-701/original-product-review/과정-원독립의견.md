고정 원제품 bc61의 실제 실패 UI와 입력 의도 사이 두 간극, 기존 profile 저장 호출의 계정 경계 한계를 확인했다. 원 과정10 의견은 이번 한 번만 남긴다.

| 식별자 | 100자 이내 지적 | 근거 구분 |
| --- | --- | --- |
| SP10-01 | 실패 뒤 textarea·미리보기는 고친 문구를 보여주지만 같은 ID retry는 첫 문구를 보낸다. | 실제 익명 DOM + 공개 intent fixture + source 연결 |
| SP10-02 | lockInput이 기존 취소 버튼을 함께 잠가 실패 뒤 취소 클릭을 할 수 없다. | 실제 익명 DOM·소스 |
| SP10-03 | profile await 뒤 guard는 기존 saveProfile 중간의 B목표→A귀속 쓰기를 막지 못한다. | 실제 inherited public saveProfile fixture·원source 읽음 |

SP10-01: #shareCaptionInput은 textarea인데 helper lockInput selector는 input/select/button만 잡는다. 실제 익명 source 화면에서 실패→키보드 문구 변경→preview가 변경 문구를 표시했다. 공개 createIntent.submit fixture는 첫 준비 입력을 재귀 freeze해 retry의 새 문구를 쓰지 않았다. 같은 ID 원입력을 유지하는 요구는 지켜도 화면에서 다른 문구를 고칠 수 있다고 보이면 다음 게시 내용과 불일치한다. 실제 browser는 CORS/외부 요청 차단으로 feed POST를 기록하지 못했으므로 그 화면에서 SDK payload를 봤다고 쓰지 않는다.

SP10-02: 실패 controls raw의 cancelDisabled=true다. lockInput은 shareCancelBtn도 잠그고 실패 뒤 caller는 submit만 다시 푼다. 원 Cancel listener는 남아 있지만 사용자 클릭이 막힌다. 다른 닫기 방식·새로고침은 이번에 시험하지 않았으며 전체 modal 탈출 불가로 일반화하지 않는다. 기존 취소 기능의 실제 클릭 보존 조건이다.

SP10-03: 새 caller는 accepted/current 후 old account cache에 post를 넣고 await saveProfile을 호출한다. 실제 core/home-cockpit.saveProfile은 uidVal=A를 저장한 뒤 users upsert await 후 현재 L.state.profile을 다시 읽는다. 이 사이 profile을 B로 바꾸는 fixture는 B의 goal ID를 user_id=A로 upsert 인자로 만들고 saveLocalSettings(A,B settings)를 호출했다. 새 after-await guard는 뒤의 global feed cache/toast를 막았다. 즉 그 guard의 좁은 효과는 있고 callee의 중간 owner 혼합은 남는다. 실제 서버/RLS가 이 인자를 수용했다는 주장은 아니다.

core/home-cockpit.js는 db8과 byte 동일한 기존 공유 source이며 TASK701 편집 소유 밖이다. SP10-03은 이번 새 guard가 전체 경로 계정 안전을 증명하지 못하는 실행 한계이지 새 core 코드 회귀가 아니다. 담당 source owner 또는 실제 caller의 안전 접점에서 별도 보완해야 한다. 다른 owner 제품을 이 reviewer가 고치지 않는다.

읽음: 실제 loader는 원 share-to-feed 태그 바로 앞 같은 줄에 helper를 넣었고 능력 등록부를 통해 현재 L과 intent를 연결한다. RLS/throw/지원 없음은 초안 저장·성공 cache를 만들지 않고 명시 same-open-intent로 남는다. 과거 pending/extra는 새 frame으로 재분류하지 않는다. 이 읽기는 일반 운영 성공/권위/행 readback의 실측이 아니다.

한계: 실제 로그인·새 게시물 DB 쓰기·행 readback·실기기·다른 기기·운영 deployment는 null이다. 익명 실제 DOM은 state injection0/remote0이고 intent/profile은 local SDK fixture다. 원13항목과 작성자 별도 post-profile-await child48892는 작성자 범위의 주장이고 이 원의견을 대체하지 않는다.
