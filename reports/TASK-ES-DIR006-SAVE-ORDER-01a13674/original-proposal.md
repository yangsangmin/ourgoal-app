# DIR006 저장 순서 한정 예외 — 대표 검토용 최소 추가 문구

상태: **적용 없는 초안**. 규범 실제 수정·발행·병합 없음. 기존15.1 원문, 모든 원계약·원의견은 보존한다. 별도 승인선⑤와 헌법14.3의 발효 조건이 열리기 전 현행 규범을 이 글로 대체하지 않는다.

## 정확 추가 문구

대상은 `01_OURGOAL_SUPREME_CONSTITUTION_FULL.md`의 `<clause id="15.1">`이다. 현재 첫 문장을 글자 그대로 남기고 다음 문장만 추가하는 안이다.

> 모든 상태 변경은 서버 원장 우선(Server-First)으로 저장 및 반영한다.
>
> 다만 DIR-006의 저장 안정화에 한하여, 기기 보존 자료와 재전송 항목을 계정·대상·변경 세대별로 서버 호출 전에 쓰고 되읽어 확인할 수 있다. 그 확인 뒤에는 보존된 부분의 입력 비움·잠금 해제와 경험치의 기기 반영·축하·AI 피드백 요청을 서버 반영 확인을 기다리지 않고 진행할 수 있다. 이때 기기 보관과 원격 미확정을 원격 반영 확인과 구분하며, 경험치의 원격 확정도 해당 서버 원장의 확인으로만 판단한다. 원격 원장의 최종 권위·동기화·무손실·경험치 중복 지급 방지와 기존 승인선은 그대로 유지한다.

이것은 Server-First의 뜻을 device-first로 다시 정하는 안이 아니라, DIR006에 한정한 저장/후속 순서 예외를 **새로 명시하는 개정안**이다. 전문의 기존 오프라인 큐·백업 허용을 없애거나 다른 기능 전체의 예외로 확대하지 않는다.

## 적용 조건과 상태별 영향

| 항목 | 이 문구가 여는 범위 | 계속 지킬 원계약·영향 |
|---|---|---|
| 기기 먼저 쓰기 | DIR006의 data+outbox를 동일 계정/대상/세대로 복구 가능하게 쓴 뒤 되읽기 확인 | 자료만/목록만 남은 중단을 보존·복구. 원격 동기화를 제외한 로컬 단독 원장은 허용하지 않음 |
| 기기 실패 | 예외 적용 불가 | 입력·사진을 남기고 해당 성공 후속 없음. 일부 보존은 본문/사진 등 부분별로 사실대로 표시; 저장 실패를 성공으로 바꾸지 않음 |
| 미확정·timeout | 기기 보존이 확인된 부분은 후속 가능 | 요청 취소≠서버 되돌림. HTTP 성공/0행/읽기 거절/늦은 응답을 원격 반영 확인으로 합성하지 않음 |
| 입력 비움 | 기기 보존 확인된 부분만 서버 답 전 비움 | 보존 안 된 사진/첨부를 함께 버리지 않음. 이 조건은 원계약의 '본문만 보존'과 '아무것도 보존 못 함' 구분에 근거 |
| 단추 잠금 해제 | 기기 확인 뒤 원격 대기와 독립적으로 해제 | 중복 제출 ID/계정/세대와 저장 중 잠금 방어 유지. 다른 입력에 늦은 답이 닿지 않도록 기존 이벤트 계약 유지 |
| XP·축하 | 기기 반영/축하를 먼저 진행 가능 | XP 원격 확정≠기기 수치 증가. 서버 XP 원장 확인·기록 하나에 한 번 보장 필요; 기기 표식만으로 여러 탭/기기 중복 방지를 주장하지 않음 |
| AI 피드백 | 기존 범위의 요청 시작 시점만 기기 확인 뒤로 허용 | 늦음/실패는 기록 저장 실패와 별개. 새 비용·개인정보/사진·피드백 원격 보존 확대 권한을 만들지 않음 |
| 원격 정본 | 최종 반영 권위 그대로 | 계정/id/자료형/반영 행수/정규화 값/변경 고유 ID·세대 확인. 확인된 세대만 outbox에서 제거 |
| 삭제/충돌 | 새로운 삭제 권한이나 서버 보장 없음 | 오래된 요청·두 기기 고침·지움 충돌에는 실제 서버 조건부 쓰기 계약/증거가 필요. 원격 서버 보장 미확인을 문구로 해소하지 않음 |

사진/피드백 등 기존 원격 보존 대상 밖 자료는 현재 기기 보존 경계를 유지한다. 이 예외는 그 자료를 서버로 보내거나 새 DDL/SQL을 실행하는 허가가 아니다. 원계약의 상태 여섯·호출 경로·P0→A→B→C 순서·출시 차단 기준은 그대로이며, 이 문서는 출시/사용 가능 판정이 아니다.

## 기존 승인으로 이미 해결됐다고 할 수 없는 이유

kernel14.1~5는 커널 우선·명시 개정·대표의 「헌법 개정 승인」 뒤 해당 PR 원격 main 병합을 요구한다. DIR006 원문은 안정화 착수의 병합 승인과 제한된 운영 시험 승인이다. #967의 변경 파일에 커널은 없고 전후 kernel bytes가 같다. #925는 CELL_SPLIT arguments 한 곳, #881은 전문 위계/11.1 정합으로15.1은 같다. 후속66 이해확정의 바5/바13/바16은 위임 병합/의미 확인/서버 수정 시각 확인 범위이며 이15.1 순서 예외를 승인한 원문은 확인되지 않았다. 이력상 '승인이 절대 없었다'가 아닌, 수집한 정확 자료에서 해당 승인·발효를 입증하지 못했다는 결론이다.

## 승인 대기와 독립 작업

K18 전체를 멈추지 않는다. 승인 대기는 A의 **기기 먼저 저장 순서 활성화 및 서버 확인 전 완료성 후속 배선**에만 건다. P0 기존 백업·pending archive·본문 불일치 읽기 guard·계정 경계·확인 세대만 제거·실패/미확정 결과 분류는 저장 순서를 바꾸지 않고 계속 준비·구현할 수 있다. 실제 운영 시험/SQL/로그인·원예산 재사용은 별도 금지대로 유지한다. 제품 단독 writer/source/CAS를 root가 먼저 확인한다.
