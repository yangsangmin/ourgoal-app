#### 2. 사이드 이펙트 및 위헌 리스크
- **데이터 영속성 영향**: 현행 원격 원장·캐시·보존 키를 변경하지 않았다. 제안은 DIR006 한정 순서 예외이며 최종 원격 권위와 동기화를 남긴다. 사진/피드백 원격 보존 확대·개인정보·새 AI 비용·영구삭제·운영 SQL 권한을 포함하지 않는다. 실패/부분보존/미확정/XP원장 확인 각각의 정확 영향은 MINIMAL-AMENDMENT-PROPOSAL.md 표에 있다.
- **기존 방어 코드 영향**: 기존 pending/archive/readback/account/generation/CAS·원시험 기대값/원실패/원독립 의견을 그대로 두었다. 기존 제품의 메모리 XP 선반영을 새 승인 증거로 사용하지 않는다. 이 비교는 과거 병합 적법성을 새로 Court 판정하는 문서가 아니다.

한계: 명시 승인 기록을 찾지 못했다는 것은 모든 대화에서 승인이 절대 없었다는 증명이 아니다. 현재 정확 원격 정본·병합/대장/REQ·인수/확정 원문에서 이번 예외 승인을 입증하지 못했다는 판단이다. 가장 강한 양립 가능성과 그 한계를 함께 보존한다. 실제 운영/use/effect/Court는null이며 새 E2E나 SQL 검사를 실행하지 않았다.

#### 3. 추천 구현 방향 및 선택지
- **선택지 A**: 기존15.1 문장은 보존하고 DIR006 data+outbox/readback/입력·잠금·XP기기반영/축하·피드백에 한정한 예외만 추가한다. 원격 확정과 기기 상태를 분리하면서 확정된 사용자 흐름을 열 수 있다. 승인선⑤와 실제 후속 검증이 필요하다.
- **선택지 B**: 현행15.1 유지, DIR006 정상 저장 순서·입력/XP 조건을 서버 확인 뒤로 재합의한다. 예외 개정은 줄지만 병합 지시 UX를 바꾸고 미응답 문제를 따로 해결해야 한다. 세션이 임의로 지시를 덮지 않는다.
- **최종 권장안**: A의 검토 가능한 최소 추가 문구를 root에 인계한다. 대표의 할 일은 정확 범위의 「헌법 개정 승인」 결정이며 구현 재허락/코드 편집은 필요 없다. 초안/필요source/발효절차는 docs 정본에 있다. 그 결정을 기다리는 범위는 위 A 순서/후속 배선에 한정하고 P0·기존 원격 보존·계정/읽기 guard·pending archive는 담당/source 충돌 확인 뒤 계속한다. 이번 계획은 비교 문서 완성만이며 제품 사용 가능·효과 확인으로 승격하지 않는다.
